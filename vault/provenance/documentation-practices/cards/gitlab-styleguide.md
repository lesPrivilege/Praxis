# Documentation Style Guide

来源：[原始页面](https://docs.gitlab.com/development/documentation/styleguide/) · 状态：`verified`

用途：GRAMMAR / DOCUMENTATION

## 摘要

GitLab 将文档的职责、类型、补缺和反馈放进同一维护方法：入口不是把作者知道的内容尽量写全，而是成为产品信息的可复用权威位置，并让缺口通过变更和反馈回流。

## 证据与使用边界

可借鉴单一维护位置、可复用链接和反馈回流；不宣称 Praxis 的所有知识都应成为类似产品文档的绝对 SSoT，也不复制 GitLab 技术写作者审批流程。 本次未保存 GitLab 页面、其仓库源码或反馈后台；页面的 SSoT 与反馈主张只针对公开方法说明。

## 何时重访

同一规则在多个 README 中出现分叉。 消费者通过复制粘贴而不是稳定链接获得答案。 修订没有记录缺口来源、反馈、维护者或最后核验。 GitLab 更新 topic type、docs-first 或反馈机制。

来源身份、核查日期、支持主张与选型状态见 [catalog](../catalog.json)。
