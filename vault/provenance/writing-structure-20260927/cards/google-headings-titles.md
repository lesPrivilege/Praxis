# Headings and titles — Google developer documentation style guide

来源：[原始页面](https://developers.google.com/style/headings) · 状态：`verified` · 访问：2026-09-27

用途：GRAMMAR / WRITING / HEADING / NAVIGATION / HTML

## 是什么

Google 把 heading 作为阅读和导航的语义结构：使用描述性、sentence case 文本；任务标题可用 bare infinitive，概念标题可用名词短语；每页只用一个唯一 h1，并按 h1/h2/h3 层级组织，不能跳级或使用空 heading。页面第 50–58、61–71、137–145 行支持这些主张。

## 取用

编辑 README、Kit 入口或报告 HTML 时，先让标题说明读者要完成的任务或要理解的概念，再检查 heading 层级是否反映内容结构。需要在 Markdown 与 HTML 之间迁移时，保持标题层级语义，不用更高或更低等级只换视觉尺寸。

## 限制

这是英文 Google 开发者文档的编辑指南，不是 Praxis 的标题规范、中文翻译规则或 HTML 运行验收。`sentence case`、bare infinitive 和单 h1 的适用性要结合目标语言、渲染器和文档类型判断；本批没有验证消费者完成任务的效果。

## 何时重访

修订 Kit/README 或 report HTML 的 heading grammar、需要决定标题是否承担任务路由、目标语言或渲染器变化、Google 页面更新层级或标题建议时重读原页面。
