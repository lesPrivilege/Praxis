# Paragraph structure — Google developer documentation style guide

来源：[原始页面](https://developers.google.com/style/paragraph-structure) · 状态：`verified` · 访问：2026-09-27

用途：GRAMMAR / WRITING / PARAGRAPH / SCANNABILITY / RESPONSIVE

## 是什么

Google 把 paragraph 视为围绕一个想法的最短表达：拆分长段以便扫描，先放关键事实，不用硬换行制造版式。五六句以上只是提示可能需要重写，不是绝对上限；单句段落或围绕单一想法的较长段仍可能合理。证据见页面第 45–55 行。

## 取用

编辑 README、Kit 说明或 report HTML 时，检查每段是否只有一个主要想法，是否把决定性信息放在开头，是否让浏览器和不同屏幕自然换行。段落过长时先删去重复内容或拆分主题，再考虑视觉间距。

## 限制

页面是英文技术文档的结构建议，不提供中文段落长度、行数、字体或版式标准。五六句是诊断提示，不是 Kit 的硬规则；列表、注释和法律/规范文本可能需要不同结构。

## 何时重访

README 或 report HTML 出现信息墙、需要把要点前置、渲染器或字体改变导致硬换行/窄屏/放大阅读问题、Google 更新 paragraph structure 页面时重读原页面。
