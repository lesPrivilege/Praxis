# Lists — Google developer documentation style guide

来源：[原始页面](https://developers.google.com/style/lists) · 状态：`verified` · 访问：2026-09-27

用途：GRAMMAR / WRITING / LIST / HTML / SEMANTIC-STRUCTURE

## 是什么

Google 按内容目的区分 numbered、bulleted 和 description list：有顺序的步骤、阶段或优先级用 numbered；非顺序集合用 bulleted；术语及解释用 description list。列表通常由完整句子提供上下文，项目尽量保持平行；多段列表项用 `p` 而不是 `br`。证据见页面第 50–57、63–141、197–214 行。

## 取用

写作或制作 HTML specimen 时，先问内容是否有顺序、只是集合，或是术语—定义对。需要列表项承载多段内容时保留段落元素；引入句应说明列表在回答什么问题，不把半句留给列表项补完。

## 限制

类型、HTML 元素和标点来自英文技术文档语境，不能直接变成中文标点、UI 文案或固定列表长度规则。Google 页面明确将 prose documentation 与 Material Design UI text 区分，UI 文案应另查规范。

## 何时重访

需要在 list/table/description list 间选择、新增多段列表项或嵌套步骤、中文本地化改变标点和大小写、Google 更新 list 类型或语义 HTML 建议时重读原页面。
