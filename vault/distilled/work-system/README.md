# Work System / Field Ops

这是第三个独立消费入口：个人驻场工作的工作系统、会议/文档 intake、Agent hands、Review Space、工具控制面和设备/订阅边界。它承接 `enterprise-topology` 的现场现实，也为 Courtwork 的 Review/Attention 产品语义提供真实 trace。

3. [`control-surface.md`](control-surface.md)：API/CLI/MCP/Skill/GUI 优先级、动作级别和 registry。
4. [`domain-grammar.md`](domain-grammar.md)：FDE 现场、Enterprise/Legal/Finance grammar、Entry Playbook 与可筹备 fixture。
5. [`lifecycle.md`](lifecycle.md)：Kit、Demo、客户 Project、Worktree 与 distill 回流。
6. [`source-vault.md`](source-vault.md)：企业 Source Vault、Project 引用和 sanitized Projection/Fixture 边界。
7. [`field-ops.md`](field-ops.md)：录音、转写、文档处理、研究采集、设备与订阅/data plane。
8. [`naming-evolution.md`](naming-evolution.md)：r2 命名轮的精确消息追溯与当前命名裁决。
9. [`turn-manifest.json`](turn-manifest.json)：原完整 5 轮/10 条消息的稳定追溯。
10. [`../../intake/work-system-increment-r2.json`](../../intake/work-system-increment-r2.json)：新增 4 轮/8 条消息的独立增量登记。

12. [`r4/README.md`](r4/README.md)：新增 1 轮/2 条消息的规范收敛与抗折旧边界；[`r4/governance-and-durability.md`](r4/governance-and-durability.md) 区分 Praxis、Courtwork/runtime 和 post-training。

## 边界

用户明确提出的是探索成熟工作方式/软件编排、让 agent 执行日常工作、设计会议后的抽取和个人 workspace，并登记办公软件的 MCP/Skill/CLI、驻场设备和效率工具订阅（T1/U、T3/U、T4/U、T5/U）。

历史回答中的具体厂商、版本和外部能力是候选参考，不是当前安装或采购决定；原 5 轮的外部引用占位与未核验产品主张见 [`../../intake/work-system-materials.json`](../../intake/work-system-materials.json)，r2 的引用与覆盖见 [`../../intake/work-system-increment-r2.json`](../../intake/work-system-increment-r2.json)。本轮没有安装工具或执行自动化。

r3 只消费新增前 10 轮/20 条消息；其外部引用占位、待验证边界与增量登记见 [`../../intake/work-system-increment-r3.json`](../../intake/work-system-increment-r3.json)。

r4 只消费新增首轮 2 条消息；无外部 citation，占位与规范边界见 [`../../intake/work-system-increment-r4.json`](../../intake/work-system-increment-r4.json)。
