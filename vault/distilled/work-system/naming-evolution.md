# 命名与范围演进

来源：工作系统 r2 的精确命名轮，用户消息 `b07d113d-71cc-43cf-8c48-cfa1f14e2952` 与历史回答 `feb0a931-556e-430d-98cc-053bc584e216`，见 [增量登记](../../intake/work-system-increment-r2.json)。此前的命名预览仍作为备查登记，不替代精确 archive。

## 消费结论

- 用户要一个能涵盖个人驻场、办公控制面、Agent hands、workspace schema与review grammar的长期名字。
- 历史assistant建议Praxis（实践）作为总体名字；Apparatus更贴基础设施，Fieldcraft更贴现场方法，Bureau更贴事务中心。
- 历史assistant把Oracles留给提供专门判断的能力，不承担整个工作系统。这是命名建议，不是已实现模块。
- Field/Workplace/Workspace/Tools/Loops/Review表达个人工作系统的六个关注面；它们不自动覆盖Enterprise和Reporting的全部范围。

## 本repo裁决

用户随后提供Praxis远端。Astra采纳总名Praxis，保留Enterprise、Reporting、Work System三个消费入口，将六个关注面留在Work System内部。参见 [ADR-005](../../../docs/decisions/005-naming-proposal.md)。

变化是范围表达与命名，没有改变来源ID、移动旧快照或开启工具自动化。以后新工作域出现时仍可调整目录，按 [增量机制](../../../docs/governance/evolution.md) 记录理由。
