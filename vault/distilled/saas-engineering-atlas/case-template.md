# 案例模板

复制以下骨架为包内 `<case-id>.md`。填写有实际内容的解释，删去提示文字；字段名留在结构 JSON，正文让对象和动作自然连接。来源与验证历史放 `evidence.json` / `CHANGELOG.md`，正文在主张附近保留公共链接和 claim ID 即可。

## 工作与第一性原理

一句话说清谁向谁承诺什么、为什么需要软件协调、完成意味着什么。给出可手算的 synthetic 小故事，标注单位、对象数量和时间假设。列出边界、非目标和专业判断接管点。

## Actor、object 与状态

说明各 actor 的目的、权限和冲突。列出对象身份、system of record、关键约束及关联对象；原词首次出现给中文解释。逐个对象写状态、触发、guard、持久化结果、拒绝与补偿；不要用一条阶段轴抹掉并行生命周期。

## 拓扑与数据流

从人到 UI、service、store 和 provider 画一条可追踪链。每条边对应 JSON 中的 typed relation，写 payload、同步/异步、租户与权限边界、不变量、失败与回查点。区分实物流、现金流、承诺与信息；缺少外部确认时保留 unknown。

## 一次交互如何改变后端

解释列表、详情、表单、预览、提交、等待、成功与冲突各自展示的事实。一个按钮绑定一个有权限的动作；重复点击、换页、断网和迟到回执都能找回同一尝试。给出持久化、查询投影、接口边界和 audit trail 的概念职责，不写源码教程。

## 计算过程

选择 `algorithm_ids` 中相关家族。写输入、输出、朴素办法、改进办法、规模变量、代价、人工演算、反例；若近似，写误差方向和不能使用的决策。provider 未公开的算法只能作为合成设计。

## 性能、并发与恢复

写 workload、测量边界和性能目标。解释 cache key/失效、热点/限流、公平性、对象版本、幂等身份、外部未知结果、补偿/对账。把优化计算和保证副作用可靠执行分别说明。

## Eval 与端到端检查

列出 given/when/then、观察点、证据与期望不变量。覆盖 happy path、重复、乱序、并发、租户隔离、未知结果与恢复；按领域增加部分完成、退款、撤销、放行或人工拒绝。AI 如适用，增加有分母的错判/漏判/拒答/修正指标及留出样本；不适用时说明原因。

## 迁移与演示

说明该机制可迁到哪个案例、必须保留什么、哪些前提改变会使迁移失效。列出可操纵参数和一个能看出因果的交互；给本地 Claude 自由选择 HTML/motion 的空间。文末只链接包内证据与记录，不夹带获取流水账。
