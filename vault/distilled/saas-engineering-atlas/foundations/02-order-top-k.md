# 2 · 顺序与候选：需要全部排好，还是只看前几项

沿用 `ALG:top-k`。H01 要找金额最大的待核对项目，H06 要找最久未响应请求，V21 要安排运输。前两题主要是在已有规则下挑选，最后一题还要满足容量与时间窗；同一个排序按钮可能隐藏完全不同的问题。

## 识题：先写比较规则

合成待办为 A=8、B=3、C=8、D=5、E=10，数字为优先分数，分高在前；平分时 ID 较小在前。完整顺序为 E、A、C、D、B。明确第二关键字能使翻页、导出和重复运行一致。稳定排序只是保留相等键的输入次序；若两次输入顺序不同，稳定排序本身不能保证跨请求一致。

## 解法：减少不需要的顺序信息

全排序适合完整导出、后续反复二分或按序遍历。归并排序把输入分成两半，各排好后像合并两排队伍一样，每次取较前的一项；每层处理 n 项，共约 log n 层，通常 O(n log n) 时间、O(n) 辅助空间。快速排序围绕枢轴分区，常见实现平均 O(n log n)，坏分区可能 O(n²)；实际采用语言或数据库已有实现，不必为工作台重写排序库。比较排序的模型和归并递推参见 [MIT Sorting，Merge Sort](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/6d1ae5278d02bbecb5c4428928b24194_MIT6_006S20_lec3.pdf)（`FND-SRC-mit-sort`）。

只要前 k 项时，可维护一个容量 k 的堆：**堆顶是当前入选者中最差的一项**。新候选更好才替换堆顶，没必要把所有落选者互相排好。堆只保证父子局部顺序，数组本身不是全排序。二叉堆上浮/下沉沿高度调整，更新 O(log k)，看堆顶 O(1)。参见 [MIT Binary Heaps](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/40d4851e550507ca14dc778b9b2266cc_MIT6_006S20_lec8.pdf)（`FND-SRC-mit-heap`）。

## 演算：五项输入，只留下两项

| 读到 | 保留集合 | 决定依据 |
|---|---|---|
| A=8 | A | 未满 |
| B=3 | A、B | 未满；B 最差 |
| C=8 | A、C | C 比 B 好；C 在平分时比 A 差 |
| D=5 | A、C | D 比 C 差，不换 |
| E=10 | E、A | E 替换 C |

最后把这两项排序，输出 E、A。扫描 n 项，维护堆约 O(n log k)，存 O(k)，最终排序 O(k log k)。当 k 接近 n 时，全排序可能更合适；k=1 只需记住最大项。若只想要第 k 大的阈值、数据可在内存中重排，可研究选择算法；随机快速选择平均 O(n)，却不自动给出有序前 k 项，也没有普通实现的最坏线性保证。Python 的 [heapq](https://docs.python.org/3/library/heapq.html) 对小 k、合并有序流和优先队列有成熟接口（`FND-SRC-python-heap`）。

## 验算：结果必须来自完整候选集

先用小输入全排序作为参照，验证 Top-K 与其前 k 项相同。还要检查：输入重新排列后结果不变；每个入选项都不差于任一落选项；k=0、k>n、全相等、重复业务记录都有约定。重复事件不应凭重复次数增加待办分数，候选身份须先处理。

反例一：前端只下载第一页 20 条，再取金额最大的 5 条，不能称为全库 Top-5。服务端需要在权限过滤后的完整候选集合上选择。反例二：只按金额做 offset 分页，用户翻到第二页前新增一张大额账单，位置整体移动，可能重读或漏读。使用固定快照，或把排序字段与唯一 ID 一起放入游标；排序字段变化时仍需声明浏览一致性。

## 变式：从排名走到公平与约束

练习一：一直有高分请求到来，低分请求永远不处理，堆是否算错？答案：堆可能完全正确，业务公平策略却不合适。可研究等待时间加权、分队列配额或最迟开始时间；规则改变后重新定义比较器及验算。

练习二：V21 车辆容量 5，候选货物重量 5、3、2，收益 8、6、5。按单件收益取第一件得 8，选后两件得 11。Top-K 只比较单项，不能解不可分资源组合；转入优化课。以“已选中”在 UI 显示建议，以“已预留资源”显示服务端确认，避免把算法建议误画成执行完成。

研究方向：先用标准库或数据库 `ORDER BY … LIMIT`，测排序是否落盘、索引能否提供所需顺序、服务端过滤是否正确，再决定是否需要流式堆。对于 q 路已排序日志，可用容量 q 的堆每次取最早记录，处理 N 条约 O(N log q)；各路输入必须先按同一规则排好。
