# 把业务问题算清楚

这本小教材写给已经能让 AI 做出页面、正在学习判断系统是否做对事的 vibe coder。先从一张订单、一段时间、几条依赖边开始，用纸笔得到答案，再决定数据放在哪里、请求怎样执行、失败怎样恢复。学完应能给 AI 一份可验算的任务，而不只是一个界面愿望。

每课沿同一条路线展开：**识题**找出输入与约束；**解法**说明为何选这种方法；**演算**逐步处理小输入；**验算**用不变量和反例检查；**变式**改变一个前提，判断方法是否仍成立。复杂度中的 n 是输入条数，k 是要保留的结果数，V/E 是图的点数/边数，L 是键的长度。数字均为合成教学输入，案例编号沿用 [33 案例目录](../case-index.json)。

## 渐进路线

| 顺序 | 读完能够做什么 | 入口 |
|---|---|---|
| 0 | 把一次点击拆成可计算的问题和可确认的工作 | [先写题目，再选算法](00-problem-model.md) |
| 1 | 分清等值、范围、边界和前缀查找 | [查找与索引](01-lookup-indexes.md) |
| 2 | 决定全排序、Top-K、稳定顺序与分页 | [顺序与候选](02-order-top-k.md) |

第一遍按顺序阅读，每个算例先遮住答案自己算。第二遍从自己的产品出发：写出“给定什么，要求什么，绝不允许什么”，选择最接近的课，换一组输入重做。上一层的 [共同企业图景](../learning-path.md)、[架构](../architecture.md) 和 [H01 示例](../example-h01.md) 说明业务对象与权威系统；本书补足其中的计算方法与验证思路。

研究定位与批次记录放在本目录的 evidence、CHANGELOG 和 handoff 文件中；正文只保留学习所需的来源指针。后续可视化可重新编排章节、选择例子和设计交互，数值前提、身份、权威与证据强度应保持可追溯。
