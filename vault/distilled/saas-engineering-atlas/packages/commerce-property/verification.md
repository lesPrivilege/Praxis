# P05 检查范围与观察

本包的交付是教材、拓扑和可执行教学模型。结构契约、原文核查、手算、局部程序运行、真实系统端到端行为分别记账，不能相互替代。

## 已执行的教学模型

从仓库根目录运行：

```bash
python3 vault/distilled/saas-engineering-atlas/packages/commerce-property/synthetic_checks.py
```

[脚本](synthetic_checks.py)只使用 Python 标准库，固定合成输入，不联网、不读取账号、不安装依赖。运行输出保存于 [synthetic-results.json](synthetic-results.json)。16 项检查全部满足断言，其中包含 819 组小规模折扣分配输入、主动拒绝的非法状态、故意错误计算产生的反例，以及两个本地 SQLite 场景。这里的“通过”表示预期的不变量成立或预期的错误确实被发现，不是说故意错误的方案也正确。

| 检查组 | 实际观察 | 能支持的结论 |
|---|---|---|
| V04 金额与数量 | 优惠 1,001 分分成 858/143，单位优惠 286/286/286/72/71；退款 4,642、教学净额 8,097；非法超发、超退、负数量被拒绝 | 固定快照下金额与数量守恒。把累计交接减去退货会错误重开欠交数量 |
| V04 有限输入遍历 | 819 组整数权重与总额均保持总额、零权重不分配、相对精确有理数份额的误差小于一分；3 种非法输入被拒绝 | 给定范围内的最大余数分配性质；不证明所有业务分摊政策公平 |
| V05 拆账与支付尝试 | 两张账单 3,887/3,512；现金 3,000 后卡 4,399 unknown 占额，第二次普通收款被拒；成功后旧 unknown 被忽略；确认失败才释放重试额度 | 有限状态模型能区分未决、成功与明确失败，不将超时当成零效果 |
| V06 房夜与连续配房 | 日历三夜；当地午夜到午夜 73 小时，计划抵离间隔 69 小时；每晚有空房却没有全程同房；半开边界相邻不冲突 | UTC 时长不能替代日历夜数；逐夜容量不能替代连续配房 |
| V06 费用与授权 | 总额 46,000 分，实收预付款 10,000 后欠 36,000；capture 8,000 后欠 28,000；公司承担房费时个人应退 4,000 | 预授权、实收与债务路由不能合并为一个已付款数值 |
| V15 图与计量 | 共享 variation 只遍历一次；依赖环与重复有效批准来源被拒；批准 6,000，累计签证 3,400/5,750，本期增量 2,350、已签证未付 350、未签证 250；累计变更 21 米被拒 | 路径去重、修订选择和累计转增量是不同规则。直接相加累计签证得到错误的 9,150 |
| V16 责任与押金 | 3,000 分为扣除 500、争议 600、可退 1,900；首退款 unknown 后仍预留；争议裁定后只新增可退 300；最终扣除 800、已退 2,200；已签未来租期即使尚未入住也拒绝重叠承诺 | 支出不能直接变成扣款责任，未决退款也占用可分配余额 |
| SQLite 旧版本竞争 | 两条真实连接先读到版本 0，再依次提交条件更新；影响行数为 1 和 0，最终库存为 0 | 确定性交错能发现漏掉版本或余额 guard 的风险；并非真实高并发负载测试 |
| SQLite 故障、重复与隔离 | 提交前注入异常使本地 effect 回滚；事务提交后关闭再打开数据库，effect 和消费标记仍在；重复 effect 被唯一约束拒绝；T1/T2 同业务号各读正确金额 | 本地原子事务与复合身份的局部验证；无 tenant 条件会匹配两条，反例已复现 |

图修订与维修责任另有少量独立小 fixture，脚本在对应函数标明范围；它们不冒充正文主线或真实 provider 数据。SQLite 的异常模拟不是电源故障、进程杀死或磁盘损坏测试，外部付款也没有加入 SQLite 事务。

## 端到端验收仍需实现

各 case JSON 的 `checks` 是给后续实现者的固定验收契约，包含正常、重复、乱序、并发、租户隔离、结果未知与恢复，以及领域专属反例。脚本没有执行这些 UI→API→provider→用户反馈全链路。实际实现应分别保留请求身份、授权拒绝、事务结果、外部受理与核对证据、投影及对账结果；只有 API 返回 200 或列表出现绿色状态不足以判定通过。

以下未执行：网页与键盘交互、设备与 KDS/打印机、真实 PostgreSQL、provider sandbox、webhook 签名实现、支付/退款及银行到账、负载 p95/p99、权限服务和缓存访问控制、实际照片与设计附件、法律政策与财务合规、AI 评估。V16 的照片建议评估是后续设计，当前没有模型、样本或准确率结果。

## 人工审读与结构校验

主编逐段读完五例正文，复算每个主线例子与练习；重点检查 V04 退货不抹去累计交接、V05 消费份额不新增制作任务、V06 房夜与实体房间及付款人的区别、V15 累计计量与本期金额、V16 支出/责任/退款的独立身份。评阅后补明住宿年份与房晚占用键，避免 DST 与容量模型歧义；跨包设计版本迁移指向 V07，并明确影响分析采用 derived_from 的反向邻接；未来租约在签署时预留整段独占区间，planned 状态也占用承诺。主编未声称进行了读者研究或界面可用性评估。

来源由各研究者重新打开官方公开页面，对照 locator 记录支持范围；主编核查证据结构与正文对应关系，并自行读取 PostgreSQL 与 Stripe 相关章节。没有保存网页全文快照，未来页面变化时需按 evidence 中的 locator 与重访条件重新查证。

仓库和 atlas 检查的命令、结果与遇到的问题集中记录在 [CHANGELOG.md](CHANGELOG.md) 与 [handoff.md](handoff.md)。初次写入章节导航时仓库检查发现十个目标文件尚未生成的链接；这些属于工作中的缺项，不能将该次运行记为通过。最终检查在所有案例、证据与记录落盘后执行。
