# V10 · 资产信号怎样成为可关闭的维护工作

一台泵的振动升高，只证明有一项值得检查的信号。它尚未说明故障原因、谁可以停机、哪个技师可以拆卸，也不能证明修完后可以重新投运。资产维护软件协调的承诺是：把一项异常交给有权处理的人，在许可范围内完成工作，再用维护证据和接收确认关闭责任。V07 关心产品能否交付，V10 关心仍在使用的资产怎样恢复可用；两者都需要证据，结束条件却不同。

以下工厂、阈值、许可、状态、计算和技术方案均为 **synthetic 教学设计**。工厂有两台泵 P-17、P-18，共用隔离阀组 G-2；P-17 产生连续异常，工作包括更换轴承和试运行。案例不提供现场安全操作规程；隔离是否充分、试验条件是否安全，由具备相应责任的人依据现场制度确认。软件保存这些确认的身份和适用范围，不替代其专业判断。`V10:claim:policy`

## 把异常、许可、工单和资产拆开

资产是长期对象，维护工单是一次承诺。停机和重新投运会改变资产运行状态；工单可以在停机后仍等待备件，也可以在技术工作完成后等待接收。告警解除只表示观测条件变化，不能将工单一并关闭。维护许可还可能同时约束多张工单：共同隔离点未交还时，一张工单完成不意味着整个设备组可以复电。

| 对象与权威 | 独立状态和触发条件 | 留下什么依据 |
|---|---|---|
| Asset / 资产，资产台账服务 | `operating → isolated → verification → operating`；现场授权人确认隔离，接收人确认投运 | 资产、位置、隔离范围版本与确认人；资产报废另开流程 |
| Signal case / 异常事件，信号服务 | `open → acknowledged → linked → resolved`；分析员认领、关联工作，复核信号后解除 | 原始样本引用、规则版本、事件时间；`resolved` 不关闭工单 |
| Permit / 工作许可，许可负责人 | `draft → active → closed` 是签发后正常交还；`active` 也可转 `suspended` 或 `expired`，暂停恢复须重新授权 | 获准任务、资产集合、有效期、现场确认、修订关系 |
| Work order / 维护工单，维护服务 | `proposed → authorized → in_progress → technically_complete → closed`；也可进入 `blocked` 或在开工前 `cancelled` | 工作范围版本、许可引用、工时与材料、试验结果、独立接收确认 |
| Booking / 人员时段，调度服务 | `planned → started → completed`，也可取消 | 技师、技能、时间与工单引用；一个工单可以有多次到场 |
| Maintenance confirmation / 维护确认，维护服务 | `draft → submitted → accepted/rejected` | 具体任务、使用部件批号、测量值、执行人与附件摘要；提交后修正形成新版本 |

这里的状态表不是厂商枚举。Microsoft 的 [Work order architecture](https://learn.microsoft.com/en-us/dynamics365/field-service/field-service-architecture) 分开描述 Resource Requirement、Booking、技师执行和经理复核；同一 requirement 可以生成多个 booking。它说明“预约”和“工单”是有关联的不同对象。`V10:claim:field-service-objects` IBM 的 [Maximo 状态转换说明](https://www.ibm.com/support/pages/maximo-support-desk-allowable-status-changes-work-orders) 则列出随当前状态变化的允许目标，其中 `COMP` 可走向 `CLOSE`，关闭后不能随意改回工作状态。该支持文章的规则不能直接充当所有 Maximo 版本与客户配置的完整契约。`V10:claim:maximo-transitions`

计划员能提出任务和排期，许可负责人能批准或暂停许可，技师能上报执行事实，接收人能接受或退回维护确认。技师不能通过编辑状态字段给自己发许可；列表中隐藏“关闭”按钮也不能代替服务端权限。关闭使用最新版本的工作范围和许可，不取打开页面时缓存的许可快照。`V10:claim:authority-separation`

## 从曲线到工单，再到真实确认

异常列表首先展示资产、异常开始时间、样本新鲜度和现有工单。分析员打开 P-17 的曲线，看到告警规则及原样本，不只看到红点；点击“提出维护”后预览任务、停机影响、所需技能和备件。接口 `POST /work-orders` 接收资产身份、异常引用、范围版本及 operation ID，保存 `proposed` 和审计记录。重复点击返回同一 operation；两位分析员针对同一异常同时提单，由“租户 + 异常 + 工作范围”唯一约束提醒合并或明确拆分任务，不靠标题相似度静默去重。

调度员安排时段并不授予现场施工权。技师到场后点击“申请开工”，`POST /work-orders/{id}/start` 在一个事务内核验：当前工单版本、技师范围、有效许可、资产身份、所需前置确认。本例许可与工单是逻辑模块，共用 PostgreSQL 事务边界，开工时锁定并核验许可版本；若拆成独立数据库，必须另设计许可确认协议，不能继续假设跨服务原子性。返回明确的 `started` 才表示后台接纳开工记录。若客户端未收到响应，它显示“开工记录待核对”，使用同一 operation ID 查询，不能用新的请求身份补一条记录。

施工后表单按任务要求收集部件编号、完成时间和试验测量，区分“已保存草稿”“待同步”“已提交”“已接受”。离线设备可以缓存任务和录入完成证据，但本例不允许离线刷新已过期的开工许可。PWA 的 Service Worker 与 IndexedDB 适合可控设备上的离线录入；若设备管理、相机和稳定后台同步更重要，可选 Flutter 或原生移动客户端，代价是独立发布和多端维护。离线记录必须带设备记录 ID、事件时间、基准版本与附件摘要，服务器收到后重新核验权限和许可时间，不把手机时间当作唯一权威。

关系链在结构数据中用 `commands`、`emits`、`delivers`、`owns` 等边表达：传感平台发送测量事件，持久接收库保存它；信号服务形成异常对象，维护服务管理工单，许可服务管理许可。界面只是这些对象的投影。附件进入对象存储，数据库保存内容摘要与访问范围；照片上传成功不等于维护确认已被接收。核心可选 React/TypeScript 工作台加 ASP.NET Core 或 Spring Boot 命令服务；前者利于表单与可视化组合，后两者可承载授权与事务边界，团队熟悉度比产品标签重要。PostgreSQL 保存工单版本、许可与操作记录，时序分区表或专门时序库保存大量样本。低量先用数据库 outbox 和任务 worker，确需独立消费与重放再引入消息平台；这些均为可选教学实现，未推断 Microsoft、IBM 或 IFS 内部采用此栈。

## 用事件时间发现问题，用依赖图安排工作

P-17 每分钟一个振动值，单位 mm/s。合成规则是五个连续、无缺失的事件分钟中至少三个值大于 7.0，才提出异常。输入 09:00—09:04 为 `[4.0, 7.2, 7.4, 3.8, 7.3]`，高值计数是 3，因此得到一个异常。09:02 的样本重复送达，仍只能占一个槽；09:01 的样本迟到时应按事件分钟补入，再重算受影响窗口。每个样本先按 `(tenant, asset, channel, event-minute, source-revision)` 找到版本。滑动窗口维护五个槽及高值数，每个已排序样本更新 O(1)，空间 O(w)；乱序输入若先排序需 O(n log n)，不能把两者都称为常数成本。`ALG:windows`、`ALG:lookup`。

持续高值会让相邻窗口反复命中，但不能每分钟新建一张工单。本例对同一租户、资产、通道和规则版本保留一个尚未解除的异常 episode；后续命中向它追加样本依据，异常复核解除后才允许新 episode。接收水位允许两分钟迟到；超过水位的样本仍补入历史并产生待复核项，不自动撤销已经获准或已经执行的维护。事件时间可以修正信号解释，不能改写过去实际发生的工作。

反例是三个高值分别出现在 09:00、09:10、09:20：直接累计“今天三次超标”会违反连续窗口定义。另一个反例是把缺失分钟补零；零读数和未知读数表达不同事实。本例窗口有缺失时显示数据不足，并保留缺失事件，不把“未触发告警”写成“设备健康”。这个规则只是教学阈值，不是振动诊断标准，也不构成自动检修依据。

维护工作又是另一项计算。任务 A 隔离确认 10 分钟，B 更换部件 30 分钟，C 检查接线 20 分钟，D 试运行 15 分钟；依赖是 A→B、A→C、B→D、C→D。假定 B、C 各有一位合格技师且可同时进行，最早完成时间为 `10 + max(30, 20) + 15 = 55` 分钟。只有一位技师时，两任务还受资源互斥约束，下限变成 `10 + 30 + 20 + 15 = 75` 分钟。拓扑排序和前向计算在 DAG 上为 O(V+E)，能找依赖下限；它不能自动解决技能、共享隔离区、备件到货与时间窗的组合排程。环 A→B→A 应报告不可排，不应输出一张漂亮甘特图。`ALG:scheduling`；`V10:claim:computation`

异常检测计算的是“需要关注什么”，排程计算的是“条件满足后何时可做”，两者都不产生现场完成事实。动画若把阈值变红直接连到工单绿色关闭，就删掉了本例最重要的责任边界。

## 正常路径与两个失败现场

正常轨迹是：五分钟样本形成异常 S-1；计划员创建 W-1；许可负责人对 P-17/G-2 与任务版本 3 签发 P-1；两项 booking 被安排；技师逐项提交确认；接收人核对两个必需任务及试运行，保存接受记录；W-1 关闭。资产重新投运和告警复核解除各自留证，不要求与关闭同一秒发生。财务若要据此收费，仍需单独的计价与账单规则。

第一种失败发生在许可变更。技师打开页面时 P-1 仍有效，许可负责人随后暂停 P-1。开工请求携带旧版本到达，服务器拒绝并显示“许可已暂停，需重新确认”，不是把后台错误变成通用网络提示。若已经开工才收到暂停，工单进入 `blocked`，保留已完成步骤；现场负责人按制度确认停工和后续条件。系统不能承诺一条异步消息立即改变物理设备状态。

第二种失败发生在维护确认同步。技师提交 C-1 后断网，服务器其实已保存；重传 C-1 返回原结果。若附件丢失，确认保持 `submitted` 但不能接受。若两个 booking 只完成一个，工单仍显示另一个未完成；告警信号恢复正常也不会解除这个缺口。关闭之后才发现记录错误，追加更正记录并建立跟进工单，不无痕修改原接受依据。这是保留执行历史，不是声称故障已经物理“回滚”。

合成容量基线为 100 个租户、每租户 1,000 个资产、每资产每分钟一个样本，即每日 1.44 亿条、平均约 1,667 条/秒；还要单测 10 倍断网补传峰值及大租户占半数流量。拟测目标是正常网络下持久接收 p95 < 500 ms，告警投影在允许两分钟迟到后 30 秒内更新，50 个并发操作员的工单查询 p95 < 300 ms；均为待测目标。按租户与资产分区限流，避免一个断网工厂的补传挤压全部开工请求。曲线可以降采样以便显示，开工与关闭必须查权威许可和完整任务集合；缓存 key 含 tenant、对象和版本，许可变更使相关读模型失效。

## 怎样验证闭环没有偷换

| 检查输入与动作 | 应观察的证据和结果 |
|---|---|
| 五个规定样本，许可有效，两项任务均完成并接受 | 一个 S-1、一个 W-1；关闭记录引用接受的确认版本，许可和资产状态可分别追溯 |
| 同一异常和 C-1 各重复投递两次 | 接收日志可显示重复；业务工单与确认各一份，材料耗用不加倍 |
| 09:02 样本先到，09:01 后到；旧许可投影也晚到 | 窗口按事件时间更新；旧版本不能恢复暂停许可 |
| 连续十分钟高值；再补入超过两分钟水位的低值 | 同一未解除 episode 只追加证据；迟到修正进入复核，不撤销已经执行的工作 |
| 许可暂停与开工并发 | 同一事务线性化点决定接受或拒绝；拒绝有明确版本冲突，已开工者转待处置 |
| 两租户都有 P-17、W-1 | 列表、附件、曲线缓存和 operation 查询均不能返回另一租户数据 |
| 服务器保存确认后响应丢失 | UI 显示未知；按同一 operation 查询找回 C-1，不产生第二次耗用 |
| 接受已保存、关闭 worker 崩溃；或附件缺失 | 重启仅完成一次关闭；缺附件者仍不可关闭，待办和审计均保留 |

上述是验收设计；可执行纯计算检查与实际执行结果单独记录，不把表格当测试通过凭证。AI 不是闭环必需条件。Anthropic 的 [IFS 案例](https://claude.com/customers/ifs) 描述 Resolve 使用图像与传感信息辅助现场诊断；这是供应方发布的案例叙述，不能证明所有工厂的诊断准确率。`V10:claim:ifs-assistance` 若加入建议助手，输出需绑定资产型号、手册版本和证据片段，只能起草诊断与任务。冻结模型版本、提示词、检索索引和工具配置；由两名领域复核人按“必须升级、可建议检查、证据不足”标注并裁决分歧，训练和提示调试不得使用留出答案。评测使用 200 个独立标注的留出案例，其中 40 个需立即人工升级，逐项统计漏升级数/40、无依据建议数/200、越权自动开工数/200，并记录人工修正率与拒答率；测试集中加入错型号、过期手册、模糊图像和传感矛盾。任何未经许可的执行建议必须被规则边界拦截。这是拟定 eval，未执行模型评测。

## 改变前提后的练习

**练习一：两个工单共享 G-2，W-1 已完成，W-2 仍有技师作业。能否因 W-1 关闭而把 G-2 交还？** 短答：不能。本例新增“隔离范围下所有仍依赖它的工作都已解除占用，且负责人确认”这一交还 guard。保持的不变量是许可覆盖实际工作范围；第二张工单仍在执行，实际触发了前文已有的共享范围约束；“一个工单完成就足以交还”的简化条件不成立。反例是按任意工单完成触发投运。检查 fixture 让 W-1 完成、W-2 为 `in_progress`，应拒绝交还并显示阻塞工单，不能只显示计数 1。

**练习二：断网两小时后技师上传一份记录，其填报时间在许可失效前，手机时间却被调慢一小时。能否自动接受？** 短答：不能只凭设备时间。原始记录与签名身份仍保存，但新鲜度和时间可信度前提改变；由授权人核对现场证据后另作接受决定。不变量是接受能追溯到适用许可。失效条件是用客户端时间绕过已撤销许可。检查调整设备时钟后，记录应进入复核队列，审计同时保留事件时间、接收时间、设备时间偏差和最终理由。

`TR:V10:V20:booking-completion` 可把“多次到场证据汇总后接受”迁到现场服务；客户签收不能自动替代资产投运许可。`TR:V10:V07:execution-evidence` 可迁移“计划、执行、验收分离”；生产订单的合格数量守恒并不能直接判断维修是否有效。`TR:V10:V11:observed-versus-authorized` 可共享原始信号与经处理结果的版本链；VEE 数据通过不是施工授权，维护许可也不是电费计量依据。

本地演示可提供样本乱序、技师数、共享许可和断网四个开关，让曲线、许可、booking、工单分别变化。证据与边界见 [evidence.json](evidence.json)，可消费拓扑见 [V10.json](V10.json)，实际检查记录见 [CHANGELOG.md](CHANGELOG.md)。
