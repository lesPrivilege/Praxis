# A01 · 同一内容，四种阅读关系

状态：specimen，2026-10-02，Opus 5.5 主会话制作并看图。内容是合成夹具 F1，活动与地点均不存在。打开 [index.html](index.html) 即可，本地单文件，不加载远端资源，不需要脚本。

这件样张回答包内 [A01 提案](../../../snapshots/local/design-grammar-atlas-20261002/briefs/atomic-reading-brief.md)的问题：风格名带来的差别，究竟来自构成关系，还是只来自换字体和颜色。做法是让五个样张共用同一份 HTML 结构，只换样式表；再把标题和导语加长，看哪种关系先失效。

## 五个样张

| 样张 | 关系 | 借自 | 处置 |
|---|---|---|---|
| 甲 · 共同轴 | 标题、导语和四项事实从同一条竖线起排 | VL01 Swiss / International（H01、H02） | 保留 |
| 乙 · 行动放大 | 何时、何地、怎么参加占最大的字和最靠上的位置 | 不借历史条目；G01、G11 的问题 | 保留，限读者已知主题的场合 |
| 丙 · 时长成形 | 三个环节共用一条时间尺，段长等于分钟数 | VL02 Bauhaus 的“同一元素只改一个变量”（H03，转译推断） | 保留，限时长有差别的日程 |
| 丁 · 轮廓分组 | 粗轮廓切块，主题和参加方式各垫一层硬偏移 | VL04 Neubrutalism（H18，本轮未能重访） | 留作对照 |
| 戊 · 只换皮 | 甲的结构不变，只换衬线、底色和强调色 | 无 | 反例，不算另一种关系 |

做法遵循 [问题地图的检验方法](../../../../kit/design/foundations/relations.md)。条目编号见 [视觉语言参考](../../../../kit/design/references/languages.md)，来源编号见 [逐源卡](../../../provenance/design-grammar-atlas-20261002/cards/README.md)。每个样张的自由选择、先读到什么和加长后的表现写在页面末尾的记录表里，数据源是 [variants.json](variants.json)。

## 三条可带走的观察

1. 换字体和颜色没有改变先读什么。戊与甲的阅读顺序相同，差别只在气质。支持包内“登记关系而不是整套 token”的主张。
2. 最先失效的是中文标题断行。`text-wrap: balance` 按宽度切，把加长标题断成“重新寻／找”；同一结构换衬线后断点又落回词间。本机 Chrome 154 的 `word-break: auto-phrase` 对这段中文无效。现在由夹具用 `title_phrases` 标出允许断行的词组边界，样式用 `word-break: keep-all` 只在这些位置里选。这条扩展了包内 G13，本地 Kit 还没有对应规则。
3. 系统字体栈里汉字的粗细到 600 为止。画布像素计数显示汉字在 600–900 的着墨量相同（5399），数字从 5076 升到 6712。丁想要的“展示字与正文强弱反差”靠字重做不出来，样张里的粗体因此一律停在 600。测量环境是应用内浏览器（Chromium 152，macOS），其他系统和字体未测。这条只适用于用系统字体栈的网页；印刷或指定了字体的页面有没有更重的字重，要看那套字体。

三条都只有这一件样张支持，按 [ADR-002](../../../../docs/decisions/002-promotion.md) 仍是场景内观察。

## 已检查与未检查

已检查：十个样张的文字与夹具逐字一致；1440 和 375 两种视口、禁用脚本下无横向滚动、越界或裁切；主会话看过全部十二张截图，并按截图改过三处（标题断行、乙的两条横线对齐、粗体字重）。

未检查：读者测试、读屏器、键盘、200% 缩放、打印分页、深色模式、Windows 与 Linux 的字体退化、375 与 1440 之间的中间宽度、更长的环节名、更多环节。“先读到什么”是制作者看图后的判断。

乙的视觉顺序与 HTML 顺序不一致：HTML 里标题在前，画面上事实块在标题之上。页面没有可聚焦的控件，读屏顺序没有实测。

## 借用边界

只借了关系的文字描述，没有复制任何原作的图像、字体或配色。H02 的海报与 H18 的配图都没有看过；丁的依据来自包内台账的读取记录，本仓库没有独立读到原文。
