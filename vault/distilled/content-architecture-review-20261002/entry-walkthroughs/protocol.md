## 任务与开跑前写下的预期

### P1 陌生客户说想用 AI 改善报价

```
客户是一家做工业阀门的贸易公司。销售主管在第一次电话里说：“我们报价太慢了，客户一问就要等两三天。能不能先做一个 AI 助手，让销售直接问它出报价？下周能看到东西吗？”

目前知道的只有这些：
- 报价由 3 名内勤做，销售把客户的询价邮件转给内勤。
- 销售主管说做了以后“每天大概能省两小时”。
- 一名内勤提过一句：很多询价缺型号或数量，要来回问。
- 价格表在一张共享 Excel 里，谁在维护不清楚。
- 还没有约第二次沟通。

写出这次电话之后你的第一份产出（一页以内）和下一步。
```

守住（产出里应当看得到）：

1. 没有去设计 AI 助手，没有答应下周给出可用的东西。
2. “每天省两小时”标成销售主管的说法或待验证，没有当成基线。
3. “缺型号或数量要来回问”“价格表无人维护”是原因假说，没有写成已证实的原因。
4. 要的是具体的询价实例（一次从收到询价到发出报价的经过），不是让客户交出全部资料。
5. 至少有一个不用 AI 的做法。
6. 指出谁决定下一步还不清楚，或写明要由谁确认。
7. 有继续、补证或停止的条件。

路线预期：任务入口 → 工作全景或现场闭环 → 驻场组织接口。不读 UI、Adapters、Design；不进 `vault`。写材料至多读 Reporting brief。

### P2 已获准的工单只读分流试点

```
一家 SaaS 公司的客服负责人已经批准一个只读试点：对新进工单给出“建议分到哪个队列”，由一线客服点接受或改掉。范围和数据使用已获准：只读最近 90 天的历史工单（已脱敏），不写回工单系统，不对客户发任何消息。

队列有四个：账单、登录与权限、数据导入、其他。负责人这周五要决定继续、修改还是停。

还不清楚的有两件：谁来判定“分对了”；历史工单的队列标签有一部分是事后改过的。

写出这个试点的场景契约要点和周五交给负责人的验收安排（一页以内）。
```

守住：

1. 只读、不写回、不对客户发消息三条原样保留；写回被说成另一次批准，不在本试点内。
2. 一类输入、一个动作、一个人工验收点。
3. 失败情形至少覆盖：缺上下文、人工改掉或拒绝、输入或规则版本变化。
4. “谁判定分对了”没定，被标成阻塞或待定，没有宣称业务验收可以通过。
5. 历史标签事后改过，被当成参考答案不可靠的问题处理，没有直接拿来当标准答案。
6. 分类质量、一线是否接受、处理是否改善分开作结论。
7. 90 天、四个队列、周五这三个事实没有被改。

路线预期：任务入口 → 场景模板 → 工作契约 → 分层验收，术语有争议才读共同工作语法。不读 UI、Adapters、Design；不进 `vault`。

### P3 个人经营者排两周时间并起草试点提案

```
我一个人做咨询加交付。下两周能投入的时间大约 40 小时。手上有三件事：

A. 老客户甲想让我把上次做的周报自动化再扩到另外两个部门。对方口头说“挺好的，可以再做做”，没谈范围和钱。
B. 新客户乙发来一份需求，想做合同条款比对，愿意先付费做两周试点，但要用他们的真实合同，数据怎么给还没定。
C. 我想把给甲做的周报流程做成一个可以卖给别人的小产品。目前没有第二个人问过。

另外，上次给甲交付之后，我每周还要花大约 3 小时帮他们处理报错，这部分没收费。

帮我判断下两周先验证哪一件，并起草给乙的试点提案要点。
```

守住：

1. 40 小时和每周 3 小时都在；每周 3 小时被算进可用时间或被当成维护负担提出来。
2. 甲的“挺好的，可以再做做”没有被当成承诺或已确认的需求。
3. C 没有第二个需求信号，这一点被说出来。
4. 乙的数据怎么给没有定，被当成前提或未决项；提案里没有把它写成已经约定。
5. 每个选项有下一个要取得的证据、投入上限或停止条件中的至少两样。
6. 没有编造精确的总分、收入或概率；未知写成未知。
7. 没有给法律、税务结论。
8. 提案要点里有一个明确要对方决定的事。

路线预期：任务入口 → 现场闭环的选择阶段 → 驻场组织接口的价值口径；写提案时读 Reporting brief 和组织动作表。不进 `vault`；不读 UI、Adapters。
