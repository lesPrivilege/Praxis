## 2. 产出

### A. 场景契约要点（按 scenarios/_template 五节填写）

**1. 工作与机会**
- 工作：对新进工单建议队列，四选一：账单、登录与权限、数据导入、其他。
- 使用者：一线客服，点"接受"或"改掉"。
- 最终接收者：客服负责人。
- 专业复核者：待定，见"判定人"。
- 边界：只读最近 90 天已脱敏历史工单；不写回工单系统；不对客户发任何消息。
- 基线：现行人工分流。含改派率，以及"首次分配队列"与"最终队列"的差异。
- 观察窗口：90 天历史，加试点期内的实时建议。
- 非 AI 替代方案：关键词或表单字段规则分流，作为对照。
- 继续、修改、停止的阈值：待负责人在周五前定。我的建议是先写成"接受率、复核准确率、客服额外耗时"三项，不预设数字。

**2. 对象、证据与动作**
- 一个 worker：分流建议者。
- 一类输入：工单正文与脱敏元数据。
- 一个动作：输出一个队列，外加"信息不足"。"信息不足"不计入"其他"。
- 一个人工验收点：客服接受或改写。
- 每条建议保留工单 ID、建议队列、建议时的数据版本，以及客服的最终选择。
- 允许用途：仅评估这次试点。

**判定人（"谁来判定分对了"，未决）。** 契约里把两个口径分开写，不混用：
- 采用率：客服接受了建议。它只说明客服认可，不等于分对。
- 复核准确率：抽样由一位独立复核者判定。复核者须由负责人在周五前指定，建议是客服组长或队列负责人，不是当次点接受的客服本人。
- 在复核者指定前，对外只报告"采用率"，不报告"准确率"。

**标签事后改过（未决）：**
- 每条历史标签必须区分"首次分配""事后修改后的终态""改动来源（人工 / 规则 / 未知）"。
- 先核实历史数据里有没有变更记录和时间戳。没有，就记为"未知"，不要猜。
- 评估集拆成两层：未改过的标签，和改过的标签。改过的那层单独报告，不并入主准确率。
- 若无法区分，整套历史标签只作"一致率"，不称"准确率"。

**3. 失败与恢复**
- 缺材料或证据冲突：输出"信息不足"，留给客服人工分流，并记录缺什么。
- 客服改掉建议：保留原建议、改后队列和改的理由（可选填），不覆盖原建议。
- 规则或模型版本变化：之前的评估结论失效，用同一批样本重验后才能沿用。
- 同一工单重复进入：以工单 ID 去重，只算一次。
- 结果未知：本试点不写回，不存在外部写入超时。

**4. 验证与结果**
- 记录：acceptance、correction、missing context、覆盖率、复核耗时、客服新增劳动。每项都留分母和观察窗口。
- fixture 须标注 redacted。
- 反例至少含：信息不足、标签被事后改过、重复工单、版本变化。
- 未知值保持未知，不补数。

**5. 接收与后续责任**
- 周五之后三种结局：继续（扩样本）、修改（改队列定义、判定口径或输入）、停止。各自的下一责任人、观察点和数据留存或删除责任，周五现场落到人名。
- 试点本身不改变现有分流责任：工单归属仍由一线客服和负责人负责。

### B. 周五验收安排（一页以内）

**目的：** 负责人在"继续 / 修改 / 停"三选一，会上只看下表。

**会前（周四前）需要备好的四件事：**
1. 指定复核者，并确认其抽样时间。
2. 核对标签变更记录是否存在，给出"改过 / 未改过 / 未知"的条数。
3. 抽样复核：从未改过的标签中抽样，同时抽一部分"改过"的单独看。
4. 汇总采用率、复核准确率、客服额外耗时，每项带分母。

**周五材料（单页，五行）：**

| 行 | 内容 |
|---|---|
| 范围与口径 | 90 天、四个队列、只读；"采用率"和"复核准确率"的定义，谁判定 |
| 数据质量 | 标签改过 / 未改过 / 未知各多少；"改过"那层的单独结果 |
| 效果 | 与现行人工分流的基线对比；各队列的混淆情况，特别是"其他" |
| 劳动 | 客服新增或减少的时间，复核者耗时 |
| 缺口 | 未核实项，每项有负责人和到期日 |

**会上决议三选一：**
- 继续：采用率和复核准确率都达到负责人事先定的线，且"改过"那层没有明显更差。
- 修改：口径或数据问题未解决（例如复核者未指定、变更记录缺失）。修改项写明由谁、何时重验。
- 停止：达不到线，或额外劳动大于节省。

**决议留档：** 谁拍板、依据哪份材料、下次观察点。
