浏览器 DOM viewport 为 1188 × 761 CSS px；工具输出原始截图实际为 1173 × 751 JPEG，故截图像素与 DOM 坐标不宜直接混算。保留未改动截图（可见鼠标光晕属于捕获环境，不是站点设计）。

## 可直接迁移的视觉规则（观察 → 转译）

### 1. 首页稀疏，工作区克制密集，两者不要混用
- 首页视觉实测观感：导航很轻；大范围留白包围 OCU 图形；大黑标题、两行解释、两个并列黑色胶囊按钮；陶土色只留给几何点缀和更新提示。这里的“高级”来自强层级和低干扰，不是铺满渐变。
- 文档会话页明显更密：固定顶部导航、左边分类导航、顶部章节进度行、右边主内容；组件和说明分框排列。它是文档 shell，不是聊天 sidebar，不能直接套作案件导航。
- 转译建议：营销首页 1 个主要信息命题＋1 个主要 CTA；法律 agent 工作区改为“案件/任务—证据—输出”三层，而不是复制 OCU 图形或站点文案。

### 2. 不给每条内容都套卡片
- 截图 02：用户消息右对齐浅灰气泡，附件独立小卡；助手回复直接放在白画布上。模型名、时间、思考行都退为小号灰色。代码块才使用强对比黑底。
- 结果：注意力跟随“用户输入 → 助手结论 → 结构化产物”，而非每一层都争抢边框。
- 转译建议：法律结论正文不必套重卡；条款原文、引用证据和拟议修改有独立边界。不要让“风险标签”比风险理由更抢眼。

### 3. 留白应服务于状态与工具层次
- 截图 03：输入上半部是文字区域，下半部是附件、模型、Thinking、发送。工具是小按钮，发送独占右端；空态发送明显弱化。
- DOM 实测普通 textarea：15px 字号 / 21px 行高，初始 48px 高、708px 宽；富输入框：15px / 21px、44px 高、642px 宽。普通框 padding-left 6px，富框 8px。这些是演示站具体状态的 computed style，不是官方规范。
- 页面对输入框 14px 圆角、48–384px 自适应高度、IME 500ms 守卫的陈述，仅属于项目说明；本轮未实际验完这些机制。
- 转译建议：先用任务明确的 placeholder，发送前可见附件、作用域和权限。留白不是空，而是区分“内容区”与“控制区”。

### 4. 输入能力渐进暴露，不把全部功能做成长工具栏
- 截图 05 实际输入 `/` 后，出现悬浮在输入框上方的五项菜单：/help、/compact、/model、/plan、/clear。每行包含小图标、短命令、右侧解释；当前项用灰底和陶土色文字，而不是大面积品牌底色。
- 头部明确上下箭头、Enter/Tab 操作提示。弹层与输入框同一左边界，宽度约占输入宽度的 2/3（视觉估计）。
- 转译建议：法律 agent 使用 `/审查`、`/比较`、`/证据清单` 等领域动作，但同时提供可发现的可见入口，不强迫新用户记指令。这里是设计建议，不是站点现有功能。

### 5. 权限卡片要解释“做什么”，不能只有两个按钮
- 截图 07：最上层是工具名 read_file、来源 mcp://filesystem、pending 状态；中间可读入参 JSON；底部是拒绝 / 始终允许 / 单次批准。陶土细边和轻光晕凸显等待决定，不用整块警报红。
- 转译建议：法律业务应优先单次批准，明确文件/案件/收件人范围；“始终允许”不得等价于无边界永久授权。涉及提交法院、发送客户等不可逆动作，应加结果预览和明确权限范围。此处为产品安全设计建议，并非演示站已具备。

### 6. 字级形成可追踪的密度阶梯
本轮 DOM 实测文档页：顶部 header 高 64px；章节 header 高 41px；侧栏宽 268px；主文章可用宽 852px；h1 32/40px；h2 24/32px；sidebar 14/20px；输入文本 15/21px。站点 font-family 首选 Inter，再列系统与 CJK 字体。不要将声明的 family 当作每个汉字实际使用的字体。

可借用其“标题明显大于正文、辅助状态低于正文”的关系，不必逐值照搬。中文长条款更需要正文可读性和行宽控制；不能为了截图精致把证据文字缩成 12px。

## 已验证交互与未验证部分

已验证：公开链接正常；章节锚点导航；空输入禁用发送、填字后后续 DOM 不再标 disabled（即时截图 04 发送颜色仍浅，不能以该图颜色单独判断）；输入 / 显菜单；深浅色按钮改变页面主题。只观察默认 pending 工具卡片，未决议。

未验证：实际聊天后端、IME、Enter/Shift+Enter、键盘 roving、响应式、移动端、无障碍对比度、动画精确时长、滚动 pinning、sidebar 在真实会话应用中的行为、失败恢复、产物 split-pane。可引用源码或站点说明，但必须标“项目声称/实现意图”，不能写成本轮交互测试结论。

## 陌生化的执行方式

保留关系：低饱和基础面＋有限强调色；用户输入/系统输出非对称；权限/证据/产物有各自边界；按需露出高级能力。

替换表层：不用 Claude 名称、OCU 图标、相同问候语、相同陶土主色组合；选择自己的语义色、字体组合和案件对象模型。所谓“高级感”应落实为任务清楚、证据可追溯、层级稳定、操作可预期，而不只是外观像某个品牌。
