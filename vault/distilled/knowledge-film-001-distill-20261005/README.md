## 结论

**Dogfooding。** Kit 在这次制作里被读了一次：开工后第 13 秒到第 55 秒，主会话读了八份文件（L29、L59），此后三小时五十六分钟里，主会话和十二个子代理都没有再打开 `kit/`、`docs/` 或 `vault/` 下的任何文件。产物与读到的规则一致的地方有三处：证据身份的标注、合成内容的标注、如实写明没有人看过和听过成片。没有被消费的是写作一支的审阅方法、交付前的分工核对、Vault 里已有的 anti-slop 提炼和运动研究。用户在冻结后指出的两个问题（文案容易认出是模型写的，结构化短文本写成了平铺的陈述）正落在这几处。

**Distill。** 经过这次施工验证、以后会再出现的做法有五类：配音先行并把画面锚在旁白的词上；每一帧只由时间决定；研究任务书把“我记得的说法”列为待核对项并要求“可以说／不能说”清单；自查通过之后派没有参与的代理按要求复查；听不了声音时用测量值代替并写明量不到什么。同样确定的是十六条失败记录，其中三条造成了实际损失：一条被管道掩盖的渲染失败让成片晚出四十分钟；选角试音用完了当日配额，一条配音线因此作废；冻结包里的旁白阅读版是改稿之前的旧稿。

**Architecture。** 不需要新的层或目录。三十二条做法与事实里，属于规范正文的有四条：其中两条（成文审阅的目标、结构位置的取形）已由用户在本页写作期间裁决并落地为 ADR-027；另两条是候选。其余留作参考、样例、失败记录或不进入。ADR-027 改的是条文，这次制作的第一层原因是条文没有被消费：审阅方法一次也没有被打开，写屏幕文字的子代理没有拿到任何 Kit 规则。这一层还需要四处增补。

- **入口路由。** 主会话从 `kit/README.md` 走到 Write、Write/Motion、Design/Motion、成文原理和证据契约，用了 42 秒，没有读维护文档（L29、L59）。这是 [ADR-019](../../../docs/decisions/019-expression-owners-and-entry-paths.md)要的结果。

- **证据身份。** 出处表把每一行标成主会话亲核、代理核查、推论或自撰，另列没采用的说法和没核到原件的地方；第二章全程标“合成案例”，示意图标“示意，不是实验结果”。这与 [证据与来源](../../../kit/write/shared/evidence.md)一致。归因没有对照。

### 哪些 friction 暴露出来

- **口播没有入口。** [成文原理](../../../kit/write/prose/grammar.md)第 3 行写明默认用于对外中文技术成文。Write/Motion 给的是分镜的语义契约，没有旁白的语体。主会话读完能用的只有四条底线。
- **审阅判准与用户的原话相反（制作当时；现已由 ADR-027 改回）。** 审阅方法第 16 行写“不以‘更像人写的’代替判准”，第 11 行写结构位置“名词短语与完整陈述都可以使用”。这两处是 2026-10-03 依据一份转述改的，[回执](../../../docs/verification/writing-review-20261003.md)第 7 行写明没有取得原话。原话在 2026-09-23 答卷会话的日志里：用户说裁决的“指标依然是更接近人类作者和人类语言”（该日志 L1060），说表头和字段口语化、“孤悬”、“显然是 llm 语言”（L1139）。仓库自己的记录也是这样写的：[答卷验收](../ai-capability-assessment/rendered/verification.md)第 128 行“裁决标准由用户确定：更接近人类作者写的中文”，第 113 行“表头改为并列的名词短语”。2026-10-05 用户对这部片子说的是同一件事（L1559）。
- **交付前的核对没有触发点。** Kit 的入口让读者“读到输入、约束和完成标准都清楚就开工”。验收页在交付时才用得上，那时没有东西把制作方带回去。
- **共用的检出。** 另一个会话有未提交的改动，主会话因此不动 `demos/README.md`、`CHANGELOG.md` 和根 `.gitignore`。成品没有进任何索引，仓库校验照样通过：校验不检查 demo 是否登记。
- **凭据。** Kit 没有处理环境变量文件的做法。42 分钟的往返之后，主会话才写出只报告密钥形状的自检脚本。

### 哪些规范过重

- **每个目录一份 README。** 成品目录有 17 份，其中 8 份只有三行，写的是“这里是生成的音频”一类。校验脚本不看 `.gitignore`，过程目录 `pipeline/_review/` 的每个子目录都被报缺 README（L851）。主会话在交付前把过程目录整个删掉（L1452），画面审片依据的约 120 张联络表和各分镜代理交回报告里引用的联络表都不在了。删除与校验的关系是推断；结果是审校的图像证据没有留下。
- **Demo 准入要求先完成场景契约。** 这次按工单“不因已有架构限制作品”直接跳过，没有造成问题。这一条对作品型的 demo 不适用，准入表没有区分。
- **逐 URL 登记。** 研究笔记里有 151 个不同的 URL，一个也没有进 Vault，主会话把入账留给了第二阶段。照 [入账规范](../../../docs/governance/intake.md)逐条建卡，工作量与片子本身相当。片中实际用到的是出处表里的 23 行。

- **文件所有权。** 每个分镜代理拥有一个 JS 和一个 CSS，类名带本章前缀，空文件事先建好并接进页面。五个代理并行，没有一次文件冲突。
- **共用工具只读。** 画线工具有一个缺陷（线帽在描线前露出一个点），三个代理各自在本地绕过，交回报告里各报了一次，主会话在 13:16 才统一修掉（L782）。
- **后台任务。** `( … ) &` 起的链在调用返回时被终止；`a | grep | tail && b` 的退出码是 `tail` 的。两件事各造成一次无声的失败。
- **权限分类器。** 读 `~/.zshenv` 被拒绝（L288），此后主会话只按变量名、长度和形状检查。这道拦截起了作用。

## Architecture

### 八种去向在 Praxis 里的落点

|---|---|---|
| core | Kit 的规则正文 | 用户裁决；涉及术语、目录或晋升规则时写 ADR |
| extension | 只对一类产物生效的约定。现有的落点是 [Genres](../../../kit/write/prose/genres/README.md)和项目自己的施工约定 | 出现第二个同类消费者之前留在项目里 |

| external index | `vault/references`、`vault/provenance` 的来源记录 | 逐 URL 登记 |
| example | `demos/` 下的项目，以及 [样张索引](../../../kit/design/references/specimens.md)里的条目 | 项目自带说明和验收范围 |

| archive | `vault/archive/chat` 与 `vault/snapshots` | 只读保存 |
| 不进入 | — | — |

### 判断的理由

去向已经写在上一节各表的最后一栏。这里说明不那么显然的几条。

- **属于 core 的只有四条（W3、W4、M1、RV1）。** W3 和 W4 有用户在两件互不相关的任务上说的同一个意思，仓库里又有过一次照此执行的记录；用户已经裁决，见 Δ1。RV1 在三件独立的作品上重复出现。M1 在三套各自独立写成的运行层里重复出现。这两条仍是候选。其余的做法只有这一次的证据。
- **配音先行的整套做法（W1、M2）是 extension，不是 core。** 它只对有旁白的片子成立，现在只有一个消费者。Kit 写明不维护 renderer API，这一点不必改。
- **部件（C1–C3、R1–R2）留作 example。** ADR-002 规定第一次使用留在项目里。可以晋升的是 M1 那一条契约，不是代码。
- **色彩、字体、字号这些参数（V1、V2、V5、M4）不进 Kit。** Design 入口写明配色、字体和密度在消费者项目里决定。
- **渲染器的选择不进入。** 这次没有做过比较，只能说这条路走通了。
- **社区列表和外部项目保持 external index。** 这次制作一个也没有打开，没有施工证据说明它们该升或该降。

### ADR-027 没有覆盖的部分

ADR-027 解决了“做了审阅也查不出”这一层。这次制作里先发生的是另一层，它没有动。

- **条文没有被走到。** 主会话读过的叙事交接页有指向验收页的链接，验收页要求交付前核对文字是否经过 Prose 审阅；这条路在 `4927795` 上已经通，没有人走。审阅方法改得再准，做片子的人不打开它，结果一样。Δ2 的那一段要写在 Write/Motion 里，因为那是这次确实被读到的地方。
- **子代理拿不到规则。** 新的第 5 条把画面上的短文字算作结构位置，审阅第 6 步也点了视频画面。这次的屏幕文字由五个子代理写，任务书是它们唯一的输入。条文里没有“交给别人写时把这一条带上”。
- **口播的语体。** 成文原理开头仍写着默认用于对外中文技术成文。旁白是说出来的，哪些口语算正常、哪些算偏差，新条文没有说；偏差表里“口语情态”一行仍以技术答卷为准。
- **“按当时的条文也查不出”是推断。** 当时没有人做过审阅，这句话没有被试过。新条文也还没有在真实任务上用过，ADR-027 自己写明了这一点。文档结构契约第 73 行要求说规则起作用之前留一个对照：改这部片子的稿时，可以让一位审阅者只拿 `4927795` 上的旧条文，另一位拿新条文，各出一份意见再比。
- **计数口径。** ADR-027 的回执按段数：86 段里对照否定 16 段。本页按句数：148 句里 18 句，另有 30 句不超过八个字。两个数出自各自的脚本，互不冲突，都没有经过用户逐条确认。
