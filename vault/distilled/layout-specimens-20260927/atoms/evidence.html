证据与解释

本家族帮助读者回查：一条主张凭什么成立、证据是什么身份（测量、观察、原话、转述、推断、假设、构造）、离主张多远、强度有多大。原子按“读者要回查的对象”划分：一段原话（V01）、一段记录摘录（V02）、一张截图的局部（V03）、一次计算（V04）、一个完整展项的各成分分工（V05）、来源/脚注/方法三种附注（V06）、同一主张的多个来源（V07）。

边界：图表主体的编码（柱、线、分布）归“数量与关系”；本页只借一个简单周柱图作为展项主体，关注它周围的 description、annotation、caption、source、method 怎样分工。V05 实为组合性质（它装配 V06 的附注和一个数量主体），保留在本家族是因为“成分职责”本身需要被单独比较；V07 是本次新增的原创原子。全页统一用一个小的身份标签写明证据身份，形状随身份不同，文字始终在。

V01 · atom · 证据与解释

引文 · Quotation

读者要判断：这句话是谁在什么场合说的原话，它能代表多少人，有没有相反的声音。

输入、适用与失败
输入
必需：原话、定位（问卷编号/题号/回收时间）、身份；可选：反向引文、与比例数字的关系、省略与插入标记。
适用
需要让读者听到具体读者的语气、或给比例数字一个可感的实例。
不适合
用单条原话证明比例或普遍性；原话需要大量编辑才能读通时应改为转述并标明。
容量
一条 ≤ 60 字最稳；两条可并置对照；三条以上转为摘录列表或回到数量。
已见失败
拿掉定位的 pull quote 被读成结论；省略号改变原意；反向引文被删。

V01-a 块引＋定位行 baseline single · stack · linear

左侧细线只标出“这是别人的话”，定位行紧贴在下方，与引文同属一个 figure。身份标签“原话”区别于转述：没有改写。成立条件：引文短、只有一条、正文另有比例数字承担代表性。

V01-b 正反并置 editorial pro-con · juxtapose · compare

两条都是 n = 642 份问卷里的单条回答，不代表比例。比例见：81% 愿意继续（95% CI 78–84%）；27% 提到希望周日开放。

衬线大字和悬挂引号给“声音”以分量，但把两条放在同一基线上、同等字号，反向意见不被降级成脚注。底部一行把单条原话接回比例数字，防止读者按引文强度推断普遍性。成立条件：确实存在一条有代表性的反向原话；若只能找到零星反对，不宜制造对称。

V01-c 正文内嵌＋边注定位 spatial claim-evidence · main-margin · adjacent

夜间开放吸引了一批过去难以到馆的读者：夜间首次持证读者占 22%，日间为 9%。一位读者在问卷里写道：下班后终于能来自习a。也有读者认为闭馆前提醒过多b。

  1. a原话 #Q-0417，后半句「希望周日也开」未引。
  2. b转述 据 #Q-0233：「九点半以后广播太频繁，影响看书。」

引文退回正文句子里，只截与主张相关的半句；定位和被省略的部分放到同一视线高度的边注（宽屏右侧、窄屏落到段后）。b 的正文是转述，边注补原话——正文与边注的身份标签不同，读者能看出哪句是改写。成立条件：主张由数字承担，引文只作例证；若引文本身是主要证据，用 V01-a。

V01-d 长引文：省略、插入与上下文 stress long · exception · linear

暴露的问题：长引文里同时有支持（周日也开）和批评（广播频繁），前两个变体的“一条一个立场”结构装不下。编辑符号必须在图注里解释，否则 [ ] 和 …… 会被读成原文。省略的内容说明写在定位行里，比“详见附录”更短也更可核。

V01-e 无定位的 pull quote 充当结论 failed single · span · graphic

读者心声

“希望周日也开。”

读者普遍期待周日开放

失败原因：① 没有编号和回收时间，无法回查；② 前半句「下班后终于能来自习」被删，意义从“夜间有用”变成“要周日”；③ 引文下的一行把单条原话推成“普遍期待”，而实际只有 27% 提及且未在试点验证；④ 反向意见 #Q-0233 消失。大字本身不是错，错在视觉强度超过证据强度。

V02 · atom · 证据与解释

证据摘录 · Record excerpt

读者要判断：记录原文写了什么、哪天哪个馆、摘录是否保留了原意；哪些内容是记录里的，哪些是解读者加的。

输入、适用与失败
输入
必需：记录原文、记录类型、日期、地点、条目定位；可选：上下文条目、解读、缺失项说明。
适用
运营记录、日志、工单这类“有时间戳的原始记录”支撑一个具体事实。
不适合
用单晚记录代表整个试点；把解读写进引号里。
容量
1–3 条原文最宜；更多时改为带选中标记的上下文块（V02-d）。
已见失败
转述冒充摘录；时间轴把未记录的时刻画成确定点。

V02-a 记录头＋原文 baseline single · stack · linear

与引文（V01）的区别：身份头在前，因为读者先要知道“这是什么记录、哪一天”，再读内容；时间戳用等宽数字作为行首锚点。条目号是本页补充的 synthetic 定位。

V02-b 主张在主列，摘录挂在旁边 spatial claim-evidence · main-margin · adjacent

推断 主张

闭馆前仍有相当数量的读者在馆，闭馆流程需要预留清场时间，不能按 22:00 整点关灯计算班次。

主张与摘录左右并置，中间一根带端点的连接线表明“这条摘录支持左边这句”。两侧身份标签不同（推断 vs 观察），范围说明紧贴摘录，读者在同一视线里看到强度上限。窄屏时摘录落到主张下方、缩进并保留左侧连接线。

V02-c 摘录落在时间条上 graphic certain-uncertain · embed · missing

时间条让“已知时刻”（实心点）和“只知时长不知位置”（悬空的虚线段，不贴任何刻度）在形状上区分。它暴露了原文的信息缺口：清场到几点结束并不知道。成立条件：记录里有两个以上时间信息；若只有一个时刻，时间条只是装饰。

V02-d 带上下文的摘录（选中＋省略） stress dense · exception · drill

暴露的问题：带上下文后，读者能确认摘录没有被断章，但密度上升：略去的条目必须保留编号（02、04–06）才能回查，否则“显示 4 条/共 7 条”无法核对。第 07 条缺时刻，用“—”并在文字里说明，不用 00:00 或留空。选中行靠边线＋“摘录”字样标出，不只靠底色。

V02-e 转述冒充摘录 failed single · stack

失败原因：引号里的句子不是日志原文，而是解读（“困难”“严重”“隐患”都不在记录里）；12 分钟清场完毕的事实反而消失；没有日期和条目，读者以为是日志的一般结论。外形与 V02-a 几乎一样——这正是危险所在：摘录的视觉外壳会把推断包装成观察。

V03 · atom · 证据与解释

截图与局部标注 · Screenshot with callouts

读者要判断：截图里哪一块是证据、那块显示了什么值、截图本身是真实系统还是合成界面。

输入、适用与失败
输入
必需：截图、截图身份（真实/合成）、时间与系统定位、至少一个标注及其文字；可选：放大局部、原始接口调用。
适用
证据只存在于界面状态里（某时刻的占用数）；需要让读者“看到”位置关系。
不适合
数值能直接从数据导出时——导出表更可靠；标注超过 5 个时改为分图。
容量
1–4 个标注；每个标注 ≤ 2 行 HTML 文字。
已见失败
说明文字烤进图片、标注遮住证据、合成界面不标身份、从截图推出的比例没有分母。

V03-a 编号钉＋图下编号说明 baseline whole-part · stack · drill

截图当作“图片”：画面里的界面文字不承担论证，所有说明是图下的 HTML 列表，可选择、可重排、可朗读。编号钉用实心圆＋数字，区域用虚线框，不遮挡读数。synthetic 身份以边框上一条斜纹标签呈现：比正文小、颜色弱，但位置固定在画面框上，截取或转发画面时一起带走。

V03-b 画面＋侧栏标注对齐 spatial whole-part · main-margin · adjacent

宽屏时标注按画面中的纵向位置排在右侧栏，读者横向扫一眼即可对应，不需要在图与列表之间来回跳。编号按画面自上而下排，说明里各自带身份：2 是观察＋计算、3 是假设。窄屏时侧栏回落为图下列表（与 V03-a 同构），位置对齐失效但编号仍在。成立条件：标注 ≤ 4 且纵向位置彼此分开；标注在同一高度扎堆时会重叠——本样张的 1、2 两钉纵向只差约 12%，第一版就叠在了一起，最后手工把第 2 条下移（--y 手填，不随内容自动避让），这是该编排无法自动化的地方。

V03-c 全图缩略＋放大局部 graphic whole-part · juxtapose · drill

缩略图交代“局部在哪里”，放大图交代“局部是什么”，两者用同色框/同色边连接。关键读数再以大号 HTML 数字重述，截图退为佐证。成立条件：证据是界面上一块很小的区域（一个读数、一个状态），整图缩到正文宽度时读不清。

V03-d 截图被截断的长 token（S7） stress mixed-script · long · drill

暴露的问题：截图会截断长 token，而被截掉的恰好是时间和时区——这是判断“哪个时刻”的关键。标注必须把完整 token 作为可选择文本给出；overflow-wrap:anywhere 让它在 375 宽断行，但断点落在括号和引号中间，复制时仍完整。钉 2 贴在画面右缘，窄屏时与面板文字挤在一起。

V03-e 说明烤进图片 failed embed · graphic

失败原因：① 说明“满座率高达 78%！夜间座位严重不足”是画进图里的文字，不能选择、不能随窄屏重排、读屏只读到 aria-label；② 红色色块压住了座位图，证据本身被遮挡；③ 78% 没有分母和时刻，一个 20:30 的快照被说成“夜间”整体；④ 没有 synthetic 标记，读者会当成真实系统截图（本页 chrome 已声明全站合成，但画面被单独转发时身份丢失）。

V04 · atom · 证据与解释

示例推算 · Worked example

读者要判断：“每次到馆成本 ¥116”由哪几个数、按什么口径算出，换一个口径结果会变多少。

输入、适用与失败
输入
必需：每一步的输入值（带单位与来源）、运算、中间结果、最终结果与取整规则；可选：替代口径与敏感度。
适用
一个派生指标要进入决策比较（夜间 ¥116 对日间 ¥38）。
不适合
读者只需要结果且口径无争议；步骤超过 6 步时拆为附录。
容量
3–5 步；每步一个运算。
已见失败
只给公式名不给数；隐含假设（按计划时段、两馆等时）不写出。

V04-a 逐步列式 baseline sequence · stack · linear

推算 夜间每次到馆成本 ¥116 如何得出

  1. 开放时长2 馆 × 26 周 × 5 晚 × 3 小时= 780 馆·小时
  2. 运营成本780 馆·小时 × ¥1,860 / 馆·小时= ¥1,450,800
  3. 每次到馆¥1,450,800 ÷ 12,480 人次= ¥116.25 ≈ ¥116

口径：按计划时段计，未扣除第 14 周东坡停开 5 晚和第 26 周少开 1 晚；¥1,860 是两馆每小时成本（¥1,720、¥2,000）的等权平均。

三列对齐：步骤名、算式、结果。结果列右对齐等宽数字，读者可以竖着核对。口径说明紧跟最后一步，因为它直接决定 ¥116 是否可比。本推算是本页用 fixture 数字复原的（身份：推算），fixture 只给出了结果。

V04-c 正文推导＋每个数的边注出处 editorial claim-evidence · main-margin · revisit

夜间开放的每次到馆成本约为 ¥116，是日间 ¥38 的三倍。算法并不复杂：两馆在 26 周里计划开放 780 馆·小时，按每馆·小时 ¥1,860 计，运营成本 ¥1,450,800；除以 12,480 人次，得 ¥116.25。

  1. 780 = 2 馆 × 26 周 × 5 晚（周二至周六）× 3 小时（19:00–22:00）。计划值，未扣停开。
  2. ¥1,860 夜间每小时运营成本；河湾 ¥1,720、东坡 ¥2,000 的等权平均。
  3. 12,480 19:00 后闸机进入计数，同一读者多次进入分别计数。

正文保持完整句子和论证节奏，读者不愿核算时可以一口气读完；想核算时，每个数带上标号，边注给出它的构成。与 V04-a 的差别在阅读路径：先结论后回看，而不是先步骤后结论。“三倍”这一比较在正文里，日间 ¥38 的口径（是否同样按计划时段）本页未知——这是编辑化写法容易掩盖的缺口。

V04-e 只有公式名 failed single · inline

每次到馆成本 = 运营成本 / 到馆人次 = 116（日间 38）

失败原因：没有单位（元？每人次？）、没有时间范围、没有输入值，读者无法复算；“日间 38”并排给出却不说明两者口径是否一致；没有标明这是推算而非账面记录。

V05 · atom（组合性质）· 证据与解释

展项框架 · Exhibit frame

读者要判断：这个图/表回答什么问题、看的是什么范围、该注意哪里、能得出什么限定过的结论、数据从哪来怎么算。

输入、适用与失败
输入
标题（问题或判断）、description（看什么、范围、口径）、主体（图/表）、annotation（例外、方向）、caption（使展项可独立理解的结论或限定）、source（身份、时间、定位）、method note（影响判断的计算与覆盖条件）。按需出现，不要求每项独立成块。
适用
任何作为主证据的图、表、截图或示例。
不适合
正文里一个顺带提及的数字（用内联数值即可）。
容量
主体 1 个；annotation ≤ 3；caption 1–2 句。
已见失败
caption 重复标题；来源缺失；annotation 只靠颜色；方法说明远离主体。

V05-a 纵向装配 baseline whole-part · stack · linear

成分自上而下按阅读需要排列：先问题，再“看什么”，再看图，再看例外，最后结论、来源、方法。来源与方法共用一行小字，但各自带标签，因为二者回答不同的问题（从哪来 / 怎么算）。图内只保留轴、目标线和编号钉，文字标注全部在 HTML。

V05-b 主体居中、成分分到两侧栏 spatial whole-part · main-margin · adjacent

左栏放“读图前要知道的”（范围、来源、方法），右栏放“读图后要记住的”（例外与结论）。位置本身编码了阅读时机。成立条件：舞台宽 ≥ 约 900px；窄屏回落为 左栏 → 图 → 右栏 的纵向顺序，恰好等于 V05-a 的顺序，因此两种装配可以是同一份标记的两个断点。

V05-c 展项解剖：成分职责标在页边 editorial whole-part · offset · scan

这是给筛选者和作者看的“解剖视图”，不是给读者的交付形态：左侧页边用衬线小标题写出每个成分的职责（取自 kit/write/publish/exhibits.md 的职责表并缩写）。它让“哪些成分缺了、哪些在重复”一眼可扫。成立条件：审稿、模板说明；对外交付时去掉页边标签即回到 V05-a。

V05-d 同一框架、主体换成表 baseline whole-part · stack · scan

主体换成表后，annotation 从“图上钉”变成“行内记号＋表下注”，其他成分原样保留——证明框架不依赖主体类型。但汇总表引入了新的方法条件（阶段划分、平均方式），method note 必须变长。阶段周均由 fixture 周数据算出：起步 1,442/4、爬升 4,102/9、平稳 6,405/12，取整。

V05-e 长标题＋缺失分馆（S1、S3） stress long-title · missing · linear
