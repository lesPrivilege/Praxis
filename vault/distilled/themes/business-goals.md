# 业务目标与边界

## 一句话提炼

这段对话把 Enterprise kit 定位为：以高管提出的业务问题为入口，在法律、金融及供应链等专业场景中，用一个可验收的窄工作循环识别 AI 提效点；把跨客户重复出现的 schema、evaluator、证据、人工复核和工作面能力沉淀为 Kit，而不是先建设一个完整企业平台。

这句话是对多轮对话的归纳，不是源线程中用户逐字作出的正式命名。具体意图与建议分列如下。

## 用户明确意图

- 需要整理可持续消费的 GitHub repo、设计系统、传统 SaaS 和类似成熟实践，先做可复用索引（T1/U）。
- 工作重点是梳理业务规则、寻找提效或 AI 插入点，而不是用 AI Build 工具修传统工作流的 bug、读日志或长期维护后台（T2/U）。
- 计划先做一个 Enterprise Demo Kit：它应容纳外部选型索引，让后续开工不必临时编排；demo repo 还需要治理，前端要与企业中台样式对齐（T3/U）。
- 不要求掌握每个前后端实现细节，但要求掌握这些系统的 grammar，以便测试和运行 demo 时读懂其语言（T4/U）。
- 希望在不依赖非常完善的数字化和组织基建的条件下，优先从法律、金融场景触达大型行业/供应链公司（T5/U）。
- 仍要探索企业中台常见技术栈和设计软件，以形成图景（T6/U）。这表示“理解边界”有价值，不表示已经选定某一套技术。
- 当前内部缺平台、外部缺客户/场景了解，因此可能由客户高管作为首要需求入口；驻场梳理业务时保留可泛化部分，供长期维护和二开（T7/U）。
- 即使领域细分，也希望利用语言模型舒适区和外部成熟实践逆向学习；目标不是孤立地为单一企业建知识（T8/U）。
- 法律和金融可能更适合：字段稳定、可泛化；演示应有最小实验和替代方案，强调合规覆盖面，不以裁员为叙事（T9/U）。
- 若客户数据与组织治理混乱、无法接触核心 worker flow，需要找到 dirty worker 场景中的第一个小循环（T10/U）。

## 原 assistant 提出的工作方向

以下是历史回答中的建议，需由后续项目或负责人裁决：

- 将角色从传统 IT/FDE 维护转为“业务建模 → AI capability mapping → workflow redesign → prototype validation → reusable primitive extraction”（T2/A）。
- 以 `Document → Schema → Rule → Finding → Evidence → Human Decision → Trace` 作为跨场景候选 grammar（T2/A）。
- 让高管提供业务优先级、风险边界和组织授权；让真实 worker 暴露材料、判断习惯和例外（T7/A）。
- 采用“客户特有层 / 可泛化层”的双层抽取：阈值、模板、组织权限留在客户 overlay；文档摄取、schema、规则检查、证据、人工确认、trace 等候选进入 Kit（T7/A）。
- 用“扩大专业覆盖面”而不是“替代专业人员”表达价值，优先证明覆盖率、复核时间和可追溯性（T9/A）。
- 把第一单压缩成一个 worker、一类文档、一个高频动作和一个人工验收点，并观察至少一段连续真实使用轨迹（T10/A）。其中“50 次”是回答中的示例目标，不是本线程已裁决的 KPI。

## 目标边界

### 在范围内

- 业务对象、规则、判断、证据、状态流转的结构化梳理。
- 专业人员工作中的局部 AI 插入点：抽取、分类、比较、检查、摘要、检索、建议、草拟和解释。
- 最小可演示/可验收的工作面：列表或队列、对象详情、审查/比较、人工决策、状态变化、审计轨迹。
- 从第一个项目中识别可跨客户复用的产品 grammar、fixture、contract、adapter、evaluator 和 trace 能力。

### 暂不作为首个目标

- 复制或替换 ERP、SRM、PLM、MES、QMS 等 system of record。
- 一开始接管完整核心 workflow、跨多个部门改组织流程，或先做全量数据治理。
- 仅为“像企业”而堆叠完整登录、组织架构、消息中心、审批中心、Kubernetes、Kafka、Temporal 或全量 IAM。这里的重基础设施禁入是 assistant 建议，不是用户明确禁止（T3/A、T10/A）。

## 待核实与待裁决

- 首个客户、首个具体场景、可取得的材料类型和可接触的 worker 尚未确定。
- “法律/金融字段稳定且可跨客户泛化”是有价值的工作假设，应以公开/脱敏样本和 eval 验证；不能直接作为行业事实。
- 高管入口、驻场 discovery、平台抽取的组织机制仍需在真实客户中验证。
- “合规覆盖面提高、人工复核时间下降、重要问题不丢失”是候选成功标准，阈值与测量方法尚未定义。
- 原回答涉及 Scale、SAP、Oracle、Coupa、Ariba 等外部实践；本次只消费对话表达，具体主张不在此确认为事实，引用缺口见 intake。
