# Motion ceiling · 2026-10-04

一份关于“用代码做高表现动态作品”的研究与施工交接的提炼。原件是用户交来的一份 Markdown（[快照](../../snapshots/local/motion-ceiling-handoff-20261004/motion-ceiling-handoff-20261004.md)，转运副本），登记见 [intake](../../intake/motion-ceiling-20261004.json)，逐源记录见 [来源卡](../../provenance/motion-ceiling-20261004/README.md)。状态：来源 `partial`，知识全部是候选，没有进 Kit；六件作品里做了第一件。

## 是什么

交接方（自述为 Codex 主代理）在 2026-09-22 至 10-04 的窗口里读了 17 个仓库或索引、18 个页面，把看到的做法整理成四样东西：

- 一张运动语法表，按“所指对象及其真实关系 → 时间与输入控制 → 画面与声音表达”三层组织，不按特效名分类；
- 六件完整作品的 brief（MC01–MC06），各有读者、问题、正常与失败输入、验收；
- 十二个原子候选（A01–A12），每个是一条“在什么误读风险下用、要守住什么、什么可以自由决定”；
- 一份与技术栈无关的施工合同，以及六组合成输入。

交接稿自己划了证据边界：最强的现场证据是一件作品的局部交互和少量抽帧，没有一部长片被完整连续地看过或听过；目录统计和模型归属都是作者自述或编者转录。

## 本仓库取用了什么

取用的是问题的组织方式和施工要求，不是任何来源的代码、构图或素材。

| 取用 | 去向 | 状态 |
|---|---|---|

运动语法表的九行和技术选栈表没有逐行验证，留在快照里，用到哪一行再读哪一行。

## 边界

- 35 条外部来源里，本会话只用 GitHub API 核对了 16 个仓库的身份（仓库与固定提交存在、创建与推送日期、许可字段），1 个仓库不可达，18 个页面没有打开。来源里“某作品效果成熟”“某作者用某模型一次生成”一类说法，本仓库没有任何独立证据。
- 交接稿写于 main `9514ce4`，其中两条已经过时：可编辑原生 SVG 包已并入 main；研究分支 `research/motion-ceiling-20261004` 和 ZIP 不在本机。
- 交接稿里的命令没有执行。它不授权安装、付费、调用外部模型、发布或读取私密材料，本会话也没有做。
- 归属沿用 [ADR-019](../../../docs/decisions/019-expression-owners-and-entry-paths.md)：可见关系与状态的运动归 Design / Motion，随时间展开的叙事归 Write / Motion，不新设目录。
