# 材料分类与驻场组织接口

本卡把用户目标与历史 assistant 建议分开保存。历史建议是候选提炼，不能单凭原聊天证明行业事实或效果；已采纳的工作契约以 [ADR-008](../../../docs/decisions/008-artifact-field-governance.md)、[Reporting grammar](../../../kit/reporting/grammar.md) 和 [驻场组织接口](../../../kit/work-system/field-governance.md) 为准。

当前消费边界是：材料先按工作语义路由，再填写六项最小 brief；八类工作目的只作为可扩展标签，不创建八套空目录；证据姿态说明论述的主要承重方式，不代表证据等级；演示、采用、净减负和经营改善分开证明；Value Ledger 与 Asset Ledger 分开记录。具体文体、行业模板和共享实现仍需真实任务与晋升门槛验证。

## 用户意图

### 材料分类与逐步对齐

用户希望为驻场工作的文档和 PPT 类材料，按需求、对象、内容和开发阶段做更细的预先登记。稳定的不是 Word、PPT 等文件格式，而是每份材料承担的语义；同一语义将来可以选择不同呈现形式。用户明确不希望现在过度设计，而是先固定分类轴和边界，等真实任务出现时再探索具体写法。对象层级、对象水平以及材料偏数据或偏叙事，都会影响表达方式，但不应混成一套未经区分的体系。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=2f579b05-6f9e-4a0c-8d3a-981b130dae51`

第一性原理是回应对方期待，并用双方能对齐的语义推进；先锁定局部问题和共识，再处理分歧，使争论落到可讨论的变量。用户没有要求现在完成全部文体、目录或模板。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=2f579b05-6f9e-4a0c-8d3a-981b130dae51`

### 驻场交付与组织接口

用户指出真实企业场景的阻塞可能来自各层组织：高层只有模糊的提效、降本或裁员愿望；中间层拿不出可靠数据或流程；一线担心 AI 取代自己，因而不愿提供 workflow、权限或真实材料。用户希望取得高层背书，同时以开放、合作的姿态与业务人员工作，核心愿望是节省时间、减少额外劳动，而不是以替代人员为项目目标。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=ab21e6c5-7399-47f5-97c2-079c33123245`

用户还要求面对 Demo 与真实价值之间的落差：可演示不代表一线采用，采用也不代表工作显著变轻。项目可能受数据和组织工程限制，需在现实条件下收敛、减少内耗、对接不同层级，并让交付留下可推广、抗折旧的资产。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=ab21e6c5-7399-47f5-97c2-079c33123245`

## 历史 assistant 建议的结构化提炼

### Artifact Registry 与六项最小契约

历史回答建议先登记材料为何存在、给谁看、希望发生什么，再选择 PPT、HTML、Memo、Dashboard、Excel 或 Demo。建议的六项原名为：`Audience`、`Expectation`、`Decision`、`Stage`、`Evidence`、`Tension`。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

当前采纳的 brief 保留同一个六项位置，并把 `Decision` 落实为 `Ask`，即读者看完需要批准、选择、修改或执行的决定/行动；这不是增加第七项。六项及问题如下：

| 字段 | 要先回答什么 | 当前边界 |
| --- | --- | --- |
| `Audience` | 谁读、业务与 AI 熟悉度怎样、有什么期待或疑虑 | 同一事实可改变解释深度和 ask 顺序 |
| `Expectation` | 对方为什么看、希望解决什么 | 与可证明内容的差距要显式写出 |
| `Ask`（历史名 `Decision`） | 看完需要发生什么决定或行动 | 写清对象、动作和后果 |
| `Stage` | 项目处在 discovery、pilot、validation 还是 scale | 未知与待验证假设不能被阶段名掩盖 |
| `Evidence` | 本次主要由什么材料支撑论述 | 仍需逐条记录来源、时间、口径和缺口 |
| `Tension` | 哪个局部约束、分歧或判断标准尚未共识 | 未决项保留在材料中，不用整套方案覆盖 |

这套契约是上游路由层，不预先锁定所有行业 grammar。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

### 工作目的与阶段

历史回答按工作目的提出八个路由词：`align`（建立共同语境）、`discover`（还原现实）、`decide`（请求决定）、`design`（设计方案）、`deliver`（交付）、`review`（复盘）、`escalate`（升级阻塞或分歧）、`transfer`（培训与移交）。当前只把它们当标签；不因为标签建立八套目录，也不把它们当完整文体清单。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

历史回答还提出一条候选材料链：现状认知 → 问题定义 → 机会地图 → Pilot Proposal → Pilot Review → Scale Decision → Rollout Review，并把 Discovery、Pilot、Validation、Scale 分别理解为“知道什么/不知道什么”“最小闭环如何验证”“假设哪些成立或失败”“如何扩大为组织能力”。当前保留阶段语义，具体 registry 和文体组合等真实任务出现后再校准。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

材料中的共同理解可按以下顺序逐步锁定：

```text
事实共识 → 问题共识 → 约束共识 → 判断标准共识
→ 方案空间 → 局部分歧 → 决策或明确保留项
```

这使材料承担 conversation control：控制分歧在哪一层讨论，而不是一次性要求读者接受一个大结论。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

### 受众与证据姿态

历史回答建议在受众层记录角色、业务深度和 AI 深度，并同时记录 intent、requested action、evidence posture、project stage 与 tension。高管、业务、技术或一线并不自动决定文体；相同事实可以调整背景解释、细节深度、叙事顺序和行动请求。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

回答提出五种证据姿态：

| 姿态 | 主要承重方式 | 适用的历史建议场景 |
| --- | --- | --- |
| `evidence-led` | 经营、实验、使用或 benchmark 数据 | 复盘、ROI、规模化 |
| `case-led` | 具体客户、流程和成功/失败案例 | 业务发现、早期场景 |
| `demo-led` | 证明最小闭环能运行 | 0→1、原型、建立第一轮信心 |
| `model-led` | 业务模型、因果链或统一框架 | 复杂问题、跨部门、数据尚不完整 |
| `narrative-led` | 方向、愿景和组织意义 | 共识形成、方向性沟通 |

当前边界是：姿态描述“论述主要靠什么承重”，不是证据等级，也不能免除 claim 的事实核验。不同姿态仍共享事实基础；Demo 不推出采用或经营收益，叙事不能冒充事实证明。`T=2f579b05-6f9e-4a0c-8d3a-981b130dae51 / I=5c597489-15cd-4deb-93e5-33fe92780b96`

### 组织接口与上下两份契约

历史回答把这类工作命名为 `Organizational Interface / Field Governance`，并建议把高层和业务人员视为两份不同契约：

- 向上，把“AI 提效、降本、裁员”翻译成可验证的经营问题；例如单位任务耗时、积压量、响应周期、返工率、人工复核量、峰值承载能力和外包成本。项目先证明工作量、质量、风险与体验的变化，不提前承诺组织裁撤。
- 向下，以 task/workflow 为研究单位，拆开任务、判断、例外、协作和权限；优先用真实合同、邮件、报表、确认点和异常案例理解流程，让业务人员纠正理解，不要求他们先成为 AI 产品专家。专业判断与最终决定继续由原责任人掌握。

`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=2ea2aa22-18cc-4109-bb5f-64579a61d33e`

高层背书被具体化为启动条件：真实业务 owner、专家的明确时间、必要数据访问、权限与风险边界、有限流程调整授权，以及跨部门争议的裁决人。当前采纳的现场记录还包含 sponsor、检查点与缺项补齐条件；“领导支持”本身不等于这些授权已经存在。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=2ea2aa22-18cc-4109-bb5f-64579a61d33e`

### 成功强度、净减负与收敛

历史回答把容易发生的证据跳跃写成：

```text
能 Demo → 技术可行 → 可以上线 → 用户会用
→ 用户工作变轻 → 公司成本下降
```

每个箭头都要有自己的证据。`“大家用了 AI，但工作没有变轻”` 应作为正式 failure mode：AI 生成变快，人工检查、格式修改、复制粘贴、prompt、数据整理、异常处理或系统录入却可能吃掉收益。核心锚点是人最终少做了多少，即 `net work removed`，而不是 AI 做了多少。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=2ea2aa22-18cc-4109-bb5f-64579a61d33e`

当前采纳的工作口径把净减负写成：

```text
净减负 = 可比基线的人工总耗时 − 新流程的人工总耗时
```

新流程人工耗时需计入输入准备、提示、复核、纠错、格式处理、搬运、异常处理和参与成本；一次性部署/培训投入单列并说明摊销。时间释放不自动等于现金节省，质量、风险和一线体验需另行检查；未知不得填零。

若连续检查点仍拿不到真实数据、专家、权限或 workflow owner，历史建议是收敛为“现状诊断 + 一项可验证的最小实验”；连实验条件也没有，就把阻塞归因、影响和处置选项交 sponsor 裁决。合成数据或独立网页可以探索技术，不能替代真实采用证据。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=2ea2aa22-18cc-4109-bb5f-64579a61d33e`

### Value Ledger 与 Asset Ledger

历史回答建议每个项目始终保留两本账：

| 账本 | 记录什么 | 不可混同什么 |
| --- | --- | --- |
| `Value Ledger` | 客户/项目实际产生的节约时间、减少返工、吞吐、风险、体验变化及其证据 | 不能用资产数量冒充客户收益 |
| `Asset Ledger` | 可复用的 workflow schema、业务对象、数据字段、权限模型、异常分类、eval cases、adapter、prompt/tool contract、UI grammar、deployment pattern | 不能把客户特有组织政治、审批链和领导偏好直接升为平台能力 |

当前采纳的最小记录还包括基线、观察窗口、额外成本、质量/体验限制、资产适用范围、复用证据、权利/数据边界和候选状态。稳定的 schema、契约、异常分类和 eval 只有经过独立场景、脱敏/泛化及治理晋升门槛，才可成为共享实现；入账本身不等于晋升。`T=ab21e6c5-7399-47f5-97c2-079c33123245 / I=2ea2aa22-18cc-4109-bb5f-64579a61d33e`

## 即时采纳与保留候选的边界

### 即时采纳的薄契约

- 材料先填写 `Audience / Expectation / Ask / Stage / Evidence / Tension` 六项，再选择呈现形式。
- 先选一个工作目的路由标签；八个标签可扩展，但不要求建立八套目录。
- 受众版本共享同一事实基础；可以改变解释深度、顺序和 ask，不改变事实、限制和不确定性。
- 证据姿态与 claim 的证据状态分开；Demo、采用、净减负和经营改善不自动互推。
- 驻场启动记录 sponsor 授权、业务 owner、专家时间、数据/权限、风险边界、流程调整权限、争议裁决人和检查点。
- 以 task/workflow 为研究单位，记录一线参与成本并优先减少机械操作与返工；专业判断和最终责任有明确归属。
- 在缺条件时按“诊断 → 最小实验 → sponsor 裁决”收敛；不以合成 Demo 填补未取得的组织授权。
- 用 Value Ledger 记录客户价值，用 Asset Ledger 记录可复用资产，二者各自保留证据和限制。
- 净减负必须计入 AI 引入的额外人工工作，不能把释放时间直接等同现金节省或裁员。

### 继续保留的候选

- 八类目的的完整文体 registry、目录布局和全部行业模板；目前只需要路由词，不需要空目录。
- 受众 YAML 的完整字段、五种证据姿态的适用规则、现状到 rollout 的完整材料链；应由实际任务量和反馈校准。
- 具体视觉 grammar、renderer、PPT/HTML/Memo/Dashboard 等表面组合；材料语义先稳定，呈现实现后置。
- `Organizational Interface / Field Governance` 作为跨 kit 的命名与更细治理操作；当前已有启动条件、分层沟通和收敛约束，效果仍需现场验证。
- Value/Asset Ledger 的字段、资产晋升和抗折旧判断；当前只记录候选与边界，不把任何项目资产直接提升为共享实现。

## 缺口与重访

- 本归档没有外部 URL、citation placeholder、附件、客户数据或真实项目结果；不据此声称上述方法已由外部实践或现场数据验证。
- 当前没有基线、采用率、净减负、质量/风险/体验或经营改善的实测数据；这些需在真实任务中另行登记。
- 需要真实材料时，优先验证六字段是否足以路由、证据姿态是否减少误读、净减负口径是否可比较，以及双账是否能保持客户收益与可复用资产的边界。
- 现有规范不承诺裁员或 ROI，也不把组织工程必然主导所有项目写成事实；后续由检查点、证据和 ADR 修订。
