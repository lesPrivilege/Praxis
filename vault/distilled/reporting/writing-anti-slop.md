# Writing Grammar 与 Kill AI Slop

## 目标

用户明确希望汇报写作可复用，不让 AI slop carry 全场（T2/U）。历史回答把问题定义为“无信息量的完整感”：句子通顺、结构完整，却没有承载新事实、约束或推理（T2/A）。所以 anti-slop 不是一个新的口吻 prompt，而是 claim/evidence 选择、编辑、来源和 review 的治理结果。

## 写作顺序

对话中已有一条可复用 pattern：

```text
看到什么 → 问题在哪里 → 怎么切 → 实际运行 / 案例 → 外推判断
```

它是常用路径，不是每份材料都必须套用的模板（T2/A）。先确定 artifact intent、audience、claim 和 evidence，再让模型承担编排与施工。

## 生成之后的编辑规则

逐段问：删掉这一句后，后文的事实、约束、证据或动作是否改变？若不改变，应删除、合并或按需披露。

### 优先删除

- 不改变后文含义的开场和背景套话；
- 可以原封不动移植到另一个行业的句子；
- 只说“能力、价值、协同、体系、赋能”而没有对象、动作、状态或结果的抽象名词链；
- 标题说一次、正文再无条件重复一次；
- 为了“完整”强行补第三点或三栏；
- 将过程旁白（“下面我们将…”）暴露给读者；
- 没有 evidence 的结论、装饰性 chart 和没有责任人的“下一步”。

### 限制空泛模式

- 反复使用“不是……而是……”、 “本质上”、 “真正的关键”等转折和升华；
- 用 promotional fluff 替代业务结果；
- 用被动语态和抽象名词隐藏谁做什么；
- 把风险、限制和未验证环节藏到附件或小字；
- 只追求短句，删除了复杂判断必需的条件、证据和例外。

最后一条很重要：目标是承重密度，不是句子越短越好。长段落可以保留，只要每层都增加约束、证据或推理（T2/A）。

## 标题与段落

- 页面标题优先承担 takeaway 或 action；若材料仍在定义范围，可以使用准确主题标题，不强迫每页伪装成结论。
- 一个页面保留一个主要视觉主语；辅助文案解释条件、范围、口径或下一动作。
- 事实和判断尽量相邻；判断与 ask 不隔着大量背景。
- 标题不要在正文中机械复述；正文应补证据、反例、影响或约束。
- 对有争议或未验证的内容，直接写状态和缺口，不用“看起来确定”的词替代核验。

## Before / after 的自检例子

### 空泛版

> 通过智能化能力赋能业务协同，构建高效、敏捷、可持续的端到端闭环。

### 承重版（示例）

> 当前采购人员逐份检查供应商报价附件中的价格、账期和交付期；先抽取这三个字段并标出缺失或冲突项，采购人员确认后继续沿用原流程。

第二版只保留对象、动作、状态和人工边界；它仍需要真实材料和 trace 才能成为事实。示例本身不是客户结果。

## Kill AI Slop eval

可以把 anti-slop 从风格提示升级为可检查的评估：

1. **Necessity**：删掉元素后任务是否仍能完成？文案是否在解释一个结构本可表达的事实？
2. **Claim density**：每个段落/页面是否至少带来事实、约束、证据、推理或动作之一？
3. **Evidence adjacency**：结论旁边是否能找到来源或明确状态？
4. **Title honesty**：标题是否正好表达主展项证明的内容？
5. **No forced symmetry**：是否为了整齐强凑三点、三栏、等长标题？
6. **Term discipline**：对象、动作、状态是否稳定；是否出现同义词漂移？
7. **Visual necessity**：图表是否表达关系；若没有关系，是否应改成表或正文？
8. **Reader fit**：是否符合 live/pre-read、受众 altitude 与 attention budget？
9. **Edge reality**：是否暴露缺口、例外、失败和未决问题？
10. **Appendix honesty**：附件是否补证据，而不是承载主结论和责任？

历史回答还建议保留原始材料、选择与拒绝、修改历史、good/bad examples，让 grammar 与 review 消灭通用腔（T2/A）。

## 反模式清单

```text
标题：市场分析 / 方案介绍 / 项目进展
页面：背景三点 → 价值三点 → 能力三点 → 总结三点
图表：没有问题也放一张图
结论：没有来源但使用确定语气
过程：把内部编排旁白直接交给读者
状态：所有页面都使用相同 card/table 模板
语言：抽象名词链、套话、重复升华
```

这份清单用于 review 提醒；不应反过来制造一套同样僵硬的“十条模板”。
