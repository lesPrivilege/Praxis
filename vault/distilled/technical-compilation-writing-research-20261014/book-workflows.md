# 两本书的编订实践

两本官方仓库用于研究资料如何进入文稿、如何审阅与构建，不移植目录。以下“已检查”都指固定提交的静态文件；未执行上游脚本、下载构建附件或复核书中全部技术主张。逐文件固定链接在 [AI Agent 来源卡](cards/agent-book.md)与 [AI Infra 来源卡](cards/infra-book.md)，提交与文件校验值在 [history](history.json)。

本页涉及可移植文档格式（Portable Document Format，PDF）、电子出版物格式（Electronic Publication，EPUB）和超文本标记语言（HyperText Markup Language，HTML）。SHA-256 指 256 位安全哈希算法（Secure Hash Algorithm 256-bit），这里用于标识具体文件字节。

## AI Infra：从证据到教学单元

`references/README.md` 的开头规定了资料层的几个边界：保存原件与提取文本，记录获取时间、版本、内容校验值与缺口，按论证定位页码和节号，区分规格、实现和测量。它也明确网页的外部图片和脚本未必能离线使用，已下载并不等于逐页审阅。这与 Praxis 的证据分层相容。本文没有复核书目中每份材料，目录公布的总数只算上游自报，未当成本研究核实数量。

教学计划把工作单位设为读者完成一段推理的教学单元：先认识对象与问题，再理解机制、计算、条件变化和选择。它同时安排跨章定义、配图的推理职责、例题与迁移，保留技术深度，避免先统一画风再寻找正文位置。计划中的版心、字号、字体和颜色是该书样张取值，不是可直接写进 Praxis 的通用规范。它借鉴的《计算机体系结构：量化研究方法》并非作者记录中已逐页获取的原书；本研究也没有将此二手借鉴包装成对该教材的独立研究。

第 4 章全章复核则留下具体修改类型：合并重复计算，补首次定义，调整案例出现位置，保留后文新增的条件。这里的增量不是“文风更像人”，而是读者在展开新计算时能找到前提、不会把历史算例的不同工作量混在一起。以上三份指定文件分别承担证据管理、教学计划和修订回执，不能互相代替。

## 文档与实际配置

| 对象 | 文档或报告描述 | 实际检查到的文件行为 | 可以支持的结论 |
|---|---|---|---|
| 资料库 | 原件、版本、hash、缺口和论证落点 | `references/README.md` 明确规则并链接 manifest；本研究只读规则与代表索引 | 是公开的来源管理约定；不能声称其所有下载与引用都有效 |
| 全章复核 | 图、例题、实验、链接、计算与渲染通过 | `check.py` 检查连续图号、同一组图资产、节号、脚注定义、相对链接、完全重复段落及少量新算式 | 可检查机械完整性；不检测语义重复、教学前提或所有计算 |
| 复核记录 | `validation.json` 含计算检查数、PDF 页数、视觉通过等字段 | `check.py` 自身生成的字段少于该 JSON；例如视觉审阅及其他计算检查数不是此脚本直接产生 | 这些字段来自额外流程或人工记录；不能把整个报告归因于一个 checker |
| 当前适用性 | 历史回执保存 `source_sha256` | 与当前章稿字节计算所得 hash 不同，见下表 | 回执只能证明它记录的旧输入；当前稿需新的适用性检查，不能据此判当前稿错误 |
| 核心原则 | 小结、引用、图号与新增推导检查 | `verify_core_principles.py` 以特定章末标题和历史 before 稿为前提，核对图索引、练习身份及部分来源 hash | 是特定修订的检查器；固定最后标题不宜泛化为所有教材规则 |
| 网站发布 | Markdown 是正文源，构建网页并检查 | `book-site.yml` 调用 `check_no_html.py`、`build_site.py`、`check_site.py` | 配置了源文件政策和链接/资源检查；不包含全书教学判断 |
| PDF/EPUB | 同源导出，保存构建记录 | `book/build_pdf.py` 写章节源 hash 与 `source_ref`；工作流有字体预检、PDF 文本/字体检查、EPUBCheck | 提供可追溯构建机制；未在本研究实际构建 |
| 发布门槛 | 书稿有多份历史审阅工具 | 已读 `book-site.yml` 不调用第 4 章 `check.py` 或 `verify_core_principles.py`；`scripts/README.md` 还将大纲验证标为历史用途 | 文件存在与成为发布门槛不同 |
| 产物清单 | `book/README.md` 末段说 Release 只上传完整中文 PDF，前段另提三语 EPUB | 实际 workflow 的 release 上传中、英、繁中、俄四版 PDF/EPUB | README 局部说明落后于配置；消费时以固定版本配置逐项核对 |
| 可复现性 | 固定 Pandoc，记录源版本与字体 | 工作流固定 Pandoc 版本，仍从 Homebrew 安装若干依赖，部分字体从可变地址取得；书中日期为构建日期 | 可追溯重建不等于所有依赖固定或逐字节可复现 |

## AI Agent：多语言与多格式的一致性

AI Agent 的贡献说明指定中文为修订正本，其余语言随后同步；这是一种明确的来源方向，不能据多个译本存在就推断语义已经一致。`check_i18n_consistency.py` 自动发现语言，比较文件是否存在、章节数量、项目表行数与 clone 命令数等。当前 `i18n-check.yml` 确实调用该脚本、站点语言检查与参考答案覆盖测试。它们能发现缺页、结构和答案入口问题；不能证明专业词义、单位或否定条件翻译正确。

该书的图注实现值得单独看：`mkdocs_figure_captions.py` 在 HTML 生成后包裹独立图片，生成 `figure` 与 `figcaption`，避免可见图注在某种 renderer 中丢失，并保留引用块中的位置。`test_mkdocs_figure_captions.py` 同时含转换测试、Python-Markdown 集成测试和源图标签检查；集成测试在相应依赖不可用时会跳过。我们读取了这些测试，没有运行它们。所读 Pages 工作流显式运行首页测试，未显式列出该图注测试；不据测试文件存在推定这一门槛已在该工作流执行。

实际 `deploy-pages.yml` 先组装并构建 MkDocs，再对 `web-astro` 执行检查、构建与测试，最后把 Astro 放入同一站点产物。这提醒我们按实际配置检查所有输出面，不因 README 的主要阅读入口而漏掉另一种渲染。`build-latest.yml` 又独立处理电子书和字体，并在 canonical 仓库的主分支上覆盖滚动的 latest 资源。固定提交链接比 latest 下载入口更适合记录研究输入。

## 借鉴与保留意见

| 取用 | 理由 | 不随之采用 |
|---|---|---|
| 同一稿源生成不同格式，保留来源版本 | 避免网页与出版稿各自改事实 | 不指定 MkDocs、Astro 或 XeLaTeX 为 SaaS 的唯一技术栈 |
| 技术、教学、图文和构建分别留证 | 一个通过标志不能解释覆盖边界 | 不汇总成一个全书质量分数 |
| 稳定案例/实验身份与显示编号分离 | 重排目录不会切断旧证据 | 不重命名旧记录追赶新章号 |
| 保留原语言、版本、原件/摘取/已读范围 | 能核对翻译与引用支持程度 | 不把上游已归档材料一律再分发；来源版权各自判断 |
| 关键算例贯穿并改变条件 | 让读者建立可迁移的判断 | 不套用相同题型、配图数或固定章末总结 |
| 对每个实际格式核对图注和引用 | 文稿正确不能保证导出无损 | 不把 alt 与 caption 永久合并；复杂图仍需信息等价描述 |

对 SaaS 的直接落点是先冻结一条真实学习路线的语义与证据，完成两类独立审阅，再让 Claude 自由编订和可视化。完整安排见 [试用计划](saas-dogfood-plan.md)。
