# 候选 M2 · 一次只验一条可证伪的假设

状态：优先候选。泛化后的做法收在 Kit 的 [备用素材页](../../../../kit/environment/working-methods.md#原因不明时)，不是规则。来源已由主会话回读。未实测。

## 来源与原问题

superpowers 的 `systematic-debugging` 技能，固定在 `8ca22db`（2026-09-25），MIT 许可，见 [来源卡](../../../provenance/community-grammar-20261002/cards/s03-superpowers-debugging-tdd.md)。原问题是模型在压力下猜着修：一个修补不行，就在上面再叠一个。

证据强弱：技能正文和两条提交说明主会话读过。维护者报告过一次小样本消融（n=10），没有逐次记录，本仓库没有复跑。它证明的是“这套写法有人维护并测过遵循率”，不证明用了之后缺陷更少。

## 机制

现象和边界证据 → 一条带反证条件的假设 → 最小的、能撤回的干预 → 看结果支不支持 → 支持才修并复验，不支持就回去查，不在失败的干预上再叠一个。连续几次没有新增信息时停下，把判断升级给人。

| 项 | 内容 |
|---|---|
| 触发 | 出了意料之外的结果，而且原因不明；或已经试过一次修补没有成 |
| 不该触发 | 正在扩大损失的事故，按已授权的做法先回滚或隔离；原因已知、范围很小、可以撤回的修正 |
| 要保住的 | 每次只变一处；干预能撤回；试过什么、结果如何留有记录 |
| 停止与升级 | 假设被证伪就换假设；多次干预都没有带来新信息，停下找人。原文的阈值是三次，这个数不取 |
| 环境适配 | 需要能复现或能观察；做不到时写明“不能复现”，不把猜测当根因 |

## 三个例子

- 正常例：测试偶尔失败。先确认能不能稳定触发，提出“某个共享状态没有清理”，只加一处隔离去验，再决定怎么修。
- 陌生领域：客户说“报价慢”。“慢在等客户补型号”是一条假设，反证条件是“不缺信息的询价同样慢”；最小的干预是看二十份询价的耗时分布，不是先做一个助手。
- 误用：线上正在重复扣款，仍坚持先找到根因再动手。这时该先停掉扣款。

## 与本地的关系

Kit 里没有调试或测试的分支，这一条没有可以合并的规范正文，所以只作为备用素材收着。它是上一轮 [九类能力语法候选](../../content-architecture-review-20261002/README.md#九类能力语法候选)里 G1“症状与可干预问题”的一个跨领域的例子：把症状、原因假说和下一步调查分开。Reporting 的复盘文体要求“事实、原因假设、改进与验证”分开写，是同一层意思。G1 要等真实的发现过程才写深，这张卡到那时作为对照材料。

提交 `b9e75dd` 的记录另有一处可用：把论证删到只剩一行标签，压力题上的遵循从 8/10 降到 5/10，普通触发不变。本地的 [文档结构契约](../../../../docs/architecture/documentation.md)要求规则“给出适用条件与违反后果”，这条记录支持它，也提醒删短规则之前要看压力情形。只是一次小样本的维护者报告。

## 收益、代价与最小对照

预期收益：少叠无效的修补。可能的代价：简单问题上多走调查步骤；事故里延误止血。

最小对照：同一个陌生的状态污染问题，一组只给普通修复指令，一组加上面的机制；另放一个应当先回滚的事故例看会不会误停。评的是找到的原因对不对、有没有隐藏的回归、多花了多少，不是有没有说出这套话。没有做。
