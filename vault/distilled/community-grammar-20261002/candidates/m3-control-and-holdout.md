# 候选 M3 · 说一条规则起了作用之前：对照、留出、代价

状态：优先候选。做法收在 Kit 的 [备用素材页](../../../../kit/environment/working-methods.md#要说一条规则有用)；[文档结构契约](../../../../docs/architecture/documentation.md#验收)的验收把它列为默认做法。来源已由主会话回读。本仓库当日的三轮维护走读各用到其中一部分，本轮第一次三样都做。

## 来源与原问题

Anthropic 的 `skill-creator`，固定在 `b0cbd3d`（2026-03-06），Apache-2.0，见 [来源卡](../../../provenance/community-grammar-20261002/cards/s02-anthropic-skill-creator.md)。原问题是“新写的 skill 到底帮没帮上忙”。

主会话读到的：每个测试例同时起有 skill 和基线两次运行；改已有 skill 时基线是改动前的快照；记 token 与用时；分析时找两边都通过的断言和波动大的例子，并读轨迹而不只看产出。选优脚本把评测集分成 train 与 test，改写器看不到 test 分数，但最后按 test 分数挑最佳一轮。研究包据此推断 test 参与了选择，不能再当完全没见过的终测；这是研究包的方法判断，不是该项目承认的缺陷。主会话读代码后同意这个推断。

## 机制

由一次具体的失败提出一处改动 → 其他条件不动 → 同一任务跑有和没有两边 → 看产出、误触发和代价 → 换一个没参与调整的任务再看一次 → 接纳、修改或撤回。

| 项 | 内容 |
|---|---|
| 触发 | 准备把一条规则、一处入口或一张卡写进 Kit，并且要说它“有用” |
| 不该触发 | 改错字、改链接、改名；只是登记来源或状态 |
| 要保住的 | 两边都做到的不记在规则名下；调整时用过的任务不当终测；代价和产出一起报 |
| 停止与升级 | 对照已全部做到，这条规则对这类执行者拿不出作用，不写进 Kit；它若是给人看的契约或给更弱的执行者用的，另写理由 |
| 环境适配 | 需要能起独立上下文的执行者。做不到时只记“未对照”，不说有效 |

## 三个例子

- 正常例：本轮的 [对照走读](../control-walkthroughs/README.md)。不读仓库的对照把“部分成功先对账”该做的都做到了，这一行没有加。
- 陌生领域：当日工单二的冷读，三题里对照组在版面结构上的决定与读过 Kit 的相同，差别只在风格名的处理。
- 误用：在熟悉的三题上反复改措辞直到都通过，然后说规则有效。学到的是这三题。

## 与本地的关系

细化。本地已有两处相近的话：文档结构契约的验收要求“用合成任务走读正常路径和失败路径”，[参考生命周期](../../../../docs/governance/reference-lifecycle.md)要求“在独立上下文中观察是否能找到资料并实际改变判断或产物”。两处都没有说怎样才算“改变”。当日三轮走读各补了一块：工单二有对照组；ADR-019 的走读看了读取量；上一轮没有对照组，回执里记为缺口。这张卡把三块合成一条，写在备用素材页一处，文档结构契约只指过去。

固定的查询数、重复次数和轮数不取。盲序人评在主观写作与设计上需要，本仓库目前的评阅者都是改规则的人，这一点如实记为限制。

## 收益、代价与最小对照

收益：少往 Kit 里写拿不出作用的句子。代价：每条规则多两到三次运行。本轮八次运行约 46 万 token。

这条规则本身的验证只能是维护任务里照着做，看它有没有改变裁决。本轮改变了一次。
