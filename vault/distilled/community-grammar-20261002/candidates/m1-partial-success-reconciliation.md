# 候选 M1 · 部分成功之后先逐项对账

状态：优先候选。泛化后的做法收在 Kit 的 [备用素材页](../../../../kit/environment/working-methods.md#一批动作做到一半)，没有写成共同工作语法里的规则。来源已由主会话回读。做过对照走读：不读仓库的对照已全部做到。

## 来源与原问题

Aider 的编辑执行器 `editblock_coder.py`，固定在 `5dc9490`（2026-05-22），Apache-2.0，见 [来源卡](../../../provenance/community-grammar-20261002/cards/s04-aider-edit-recovery.md)。原问题是模型一次给出多处修改，有的对不上文件里的原文；整批重发会把已经改好的再改一遍。

主会话读到的：执行器逐块记成功与失败；失败的块附上文件里相近的实际行；要写入的内容已经在文件里时提示“可能不需要这一块”；末尾写明其余的块已经应用，不要重发。代码注释引了 issue 2258，那条 issue 本身没有读。

证据强弱：这是一个在维护的工具的执行器，有对应的回归测试（研究包转述，测试文件没有回读）。它说明这套回报方式被用着，不说明换一种做法会差多少。

## 机制

一批动作结束或中断之后 → 逐项查外部的实际状态，分成成立、没成立、不知道 → 不知道的先查清 → 只补没有成立的 → 后项依赖前项时先确认前项 → 对不上、解释不了就停下找人。

“不知道”这一类和项之间的依赖是研究包迁移时补的，Aider 的执行器只分成功与失败。

| 项 | 内容 |
|---|---|
| 触发 | 一批对外有影响的动作没有全部成功，或中途断了 |
| 不该触发 | 只读、可以整份重做、对外没有影响的任务 |
| 要保住的 | 不可撤回的动作不做第二次；已成立的不重放；日志和工具的回报只当线索 |
| 停止与升级 | 实际状态与日志矛盾并且解释不了；出现重复的不可撤回动作；权限被拒 |
| 环境适配 | 需要能查外部系统的当前状态。查不了时写明“无法核对”，不当作没执行 |

## 三个例子

- 正常例：四十张工单的批处理跑到一半被杀，日志里二十二张写着完成，三张报权限错，其余没有记录。
- 陌生领域：合同模板的十二处批量替换，九处回报成功，两处没找到原文，一处超时，其中一处依赖另一处新增的定义。
- 误用：每周导出一份只读报表时断了，只留下半个文件。这时直接整份重跑，逐行对账是多余的。

三个例子就是 [对照走读](../control-walkthroughs/README.md)的三个任务。

## 与本地的关系

细化。[共同工作语法](../../../../kit/grammar/work.md#不变量与反例)有“外部动作结果未知：保留尝试身份，核对影响后决定恢复”，[工作契约](../../../../kit/contracts/README.md)有“写入超时先核对外部影响；重复执行有稳定身份”。本地没有“部分成功”这一格，也没有说项与项之间有依赖时怎么办。

## 对照的结果

原打算在不变量表里加一行。先做了对照：

| 任务 | 不读仓库的对照 | 读仓库，没有这一行 |
|---|---|---|
| 批处理（八项） | 八项都做到 | 八项都做到，但全部出自通用知识；它没有到达已有的“结果未知”一行 |
| 合同替换（七项，留出） | 七项都做到 | 入口加了路由之后跑：七项做到，另从已有的不变量里取了“改了文本要重新取得批准” |
| 只读报表（近失例） | 直接重跑 | 直接重跑，前后都没有过度处理 |

对照到顶，这一行在这三个任务上拿不出可归给它的作用，没有加。备用素材页收的是泛化后的说法，标明了这个结果。

## 收益、代价与没有验证的

如果写成规则，预期的收益是少重放、少重复副作用；代价是简单任务上被带进逐项核对。走读里近失例没有被带偏，但读仓库的那次因为入口多了一行路由，多读了一个文件。

没有验证的：更弱的执行模型；真实的长任务；并发改动；项数很多时会不会漏。
