# 平台类产品 Grammar 扫盲

## 业务形态与参与者

### P01｜平台型业务（Platform business）

#### 解释

- 连接需求与供给，并用分发、交易和治理规则促成可重复的交换。

#### 例子

- 电商把买家、商家、商品、支付和履约接在同一条交易链上。

#### 边界

- 平台型业务不是一张流量页面；若平台持有库存并承担经营风险，仍需另看自营零售。

### P02｜自营零售（First-party retail）

#### 解释

- 平台或零售商自己采购、持有或控制商品，并承担定价、库存和销售结果。

#### 例子

- 超市自营仓采购牛奶后在自己的小程序售卖，缺货和损耗由零售方直接承担。

#### 边界

- 只提供商家工具和抽佣的市场平台不自动属于自营零售；同一平台可以混合两种模式。

### P03｜Marketplace 平台市场（Marketplace）

#### 解释

- 让第三方商家发布供给、获得需求并完成交易，平台通过服务费、广告或抽佣变现。

#### 例子

- 多个餐馆在外卖平台上经营自己的菜单，平台负责搜索、支付、规则和部分履约。

#### 边界

- Marketplace 不等于“没有履约责任”；平台承担的撮合、资金、客服和配送范围要逐项声明。

### P04｜本地生活（Local commerce）

#### 解释

- 交易受地理位置、服务半径、营业时间和即时供给约束的商品或服务业务。

#### 例子

- 用户在两公里内搜索今天可预约的洗衣店或可送达的晚餐。

#### 边界

- 有地址的网店不自动是本地生活；关键是消费、交付或服务需要与本地时空绑定。

### P05｜用户（Consumer）

#### 解释

- 需求侧参与者，可能浏览、下单、付款、收货或使用服务；这些身份不必是同一个人。

#### 例子

- 家长付款购买儿童餐，孩子消费，外卖员把餐送到办公室。

#### 边界

- 访客、买家、付款人、收货人和最终使用者要按事件定义，不能用“用户”掩盖角色差异。

### P06｜商家与品牌（Merchant / Brand）

#### 解释

- 商家是经营和履约主体，品牌是商品或服务的品牌权利与认知主体；两者可以重合也可以分开。

#### 例子

- 经销商在平台售卖某品牌手机，商家负责发货，品牌方可能负责授权和售后标准。

#### 边界

- 品牌曝光量不是商家成交量；招商、品牌合作、供应商和门店应按合同与交易责任区分。

### P07｜平台（Platform）

#### 解释

- 设计规则、提供基础能力并协调多方交易的运营者或产品系统。

#### 例子

- 平台规定商品审核、排序、支付、退款和商家申诉流程。

#### 边界

- “平台”可指公司、业务线、应用或技术底座；分析时要说清责任主体和观察范围。

### P08｜服务与履约参与者（Service and fulfillment actors）

#### 解释

- 供应商、门店、骑手、仓配、达人和服务商等把供给或承诺变成可交付结果的参与者。

#### 例子

- 本地家政平台连接用户、服务人员、门店和支付客服，服务人员完成上门交付。

#### 边界

- 参与曝光或带来线索不等于承担履约；责任、结算和评价应按真实动作确认。

## 需求与供给

### P09｜需求（Need）

#### 解释

- 用户希望解决的任务、问题或约束，通常先于具体商品或功能表达。

#### 例子

- “今晚快速吃饭”是需求，外卖套餐、到店消费或即时零售都可能满足它。

#### 边界

- 需求不是用户提出的方案；把“我要一个按钮”直接当成需求会跳过问题验证。

### P10｜意图（Intent）

#### 解释

- 当前行为中可推断的目标和购买准备程度，可能显式表达，也可能从浏览与上下文推断。

#### 例子

- 搜索“附近修电脑”通常比随手刷到一条维修视频有更明确的即时意图。

#### 边界

- 意图是推断结果，不是事实本身；点击或停留只能提供信号，不能直接证明会购买。

### P11｜场景（Scenario）

#### 解释

- 需求发生的时间、地点、角色、触发事件和完成条件的组合。

#### 例子

- “出差抵达酒店后，30 分钟内买到充电器”同时包含地点、时间和交付约束。

#### 边界

- 场景不是行业标签；同一用户在早餐、囤货、送礼等场景的决策和指标可能不同。

### P12｜供给（Supply）

#### 解释

- 平台可展示、可购买或可交付的商品、服务、内容、门店和能力集合。

#### 例子

- 生鲜 SKU、餐馆菜单、律师服务档期和招聘职位都可以是供给。

#### 边界

- 上架数量不等于有效供给；价格、库存、质量、覆盖和可交付性共同决定供给是否可用。

### P13｜商品层级（SPU / SKU）

#### 解释

- SPU 表示同类商品的抽象款式，SKU 表示可定价、可库存和可下单的具体规格。

#### 例子

- 同品牌某型号运动鞋（如合成型号 Runner-A）是 SPU，42 码白色组合通常是一个具体 SKU。

#### 边界

- 不同业务的商品主数据会不同；服务项目、职位和内容不能强行套成 SKU 而丢失关键属性。

### P14｜门店与 POI（Store / Point of Interest）

#### 解释

- 门店是经营或交付实体，POI 是地图或本地搜索中的地点对象，可能关联多个服务和门店状态。

#### 例子

- 商场中的某家餐厅是 POI，可挂菜单、营业时间、团购券和到店路线。

#### 边界

- POI 不是库存记录，也不是订单；同一品牌多门店要分别计算覆盖、库存和履约能力。

### P15｜库存与可售状态（Inventory / Availability）

#### 解释

- 库存是可被占用或消耗的数量，可售状态还要考虑营业、配送、权限和库存同步。

#### 例子

- 仓库有 10 件并不代表所有用户都能买到，配送半径和门店闭店可能让它不可售。

#### 边界

- 物理库存、可售库存、可预约名额和展示库存不能混用；读到“有货”要问状态与时间。

### P16｜价格与促销（Price / Promotion）

#### 解释

- 价格是交易金额规则，促销是改变价格、权益或曝光条件以影响需求和转化的机制。

#### 例子

- 原价、会员价、满减券和平台补贴共同决定用户实际支付价。

#### 边界

- 标价、成交价、商家实收和平台补贴不是同一金额；促销可能提高短期成交却降低利润。

### P17｜供给质量与覆盖（Supply quality / Coverage）

#### 解释

- 质量描述供给满足需求和交付标准的程度，覆盖描述目标区域、类目、时段或人群能否获得它。

#### 例子

- 同城有很多餐馆但晚间可送达的低价套餐很少，说明总量和有效覆盖不一致。

#### 边界

- 供给数量、曝光量和供给质量是三件事；头部商家增加曝光不等于平台覆盖变好。

## 流量与分发

### P18｜流量（Traffic）

#### 解释

- 用户或注意力进入某个页面、内容、商品或服务入口的访问机会与规模。

#### 例子

- 搜索、推荐、广告、消息和商家自有渠道都可以带来商品流量。

#### 边界

- 流量不是成交，也不是唯一价值；分析流量必须连到供给匹配、转化和长期结果。

### P19｜曝光与触达（Impression / Reach）

#### 解释

- 曝光是一次展示事件，触达是统计窗内至少被展示过的去重用户或设备集合。

#### 例子

- 一个用户看到同一商品三次，产生三次曝光但在去重触达中通常算一人。

#### 边界

- 展示是否可见、是否有效和是否去重必须写口径；曝光不代表用户理解或认可。

### P20｜UV 与 PV（Unique Visitor / Page View）

#### 解释

- PV 计页面或内容访问次数，UV 计统计窗内去重访客数，二者一起描述访问规模与频次。

#### 例子

- 100 个 UV 产生 250 个 PV，说明平均每个访客访问约 2.5 次。

#### 边界

- 登录用户、设备、Cookie 和跨端合并规则会改变 UV；PV 不能直接当成曝光或有效阅读。

### P21｜自然流量与付费流量（Organic / Paid traffic）

#### 解释

- 自然流量由非直接购买的排序、关注、分享或搜索带来，付费流量由广告、竞价或付费推广获得。

#### 例子

- 商家通过搜索排名获得自然访问，也可以购买关键词广告获得付费访问。

#### 边界

- 流量标签取决于归因规则；付费投放也可能带来后续自然访问，不能简单相加为独立增量。

### P22｜搜索（Search）

#### 解释

- 用户以查询词表达需求，系统从候选供给中检索、过滤并排序返回结果。

#### 例子

- 用户搜索“周六可预约牙医”，系统需要同时理解地点、日期和服务类型。

#### 边界

- 搜索结果页不等于推荐流；搜索强调显式查询，但排序仍可能使用个性化、商业和供给约束。

### P23｜推荐（Recommendation）

#### 解释

- 系统在用户未明确查询或查询较弱时，预测兴趣与价值并主动展示候选内容或供给。

#### 例子

- 用户没有搜索露营用品，但首页根据历史行为展示帐篷和相关内容。

#### 边界

- 推荐目标可以是点击、成交、留存或生态约束的组合；不是单纯把最热门内容推给所有人。

### P24｜排序、召回与匹配（Ranking / Recall / Matching）

#### 解释

- 召回先从大候选集中取可能相关项，排序决定展示顺序，匹配把需求与供给的属性和约束对齐。

#### 例子

- 招聘平台先召回符合技能的职位，再按地点、薪资和响应率排序给求职者。

#### 边界

- 召回多不等于匹配好；排序位置变化也可能来自库存、商业化或治理规则而非相关性提升。

### P25｜冷启动（Cold start）

#### 解释

- 新用户、新商家、新商品或新内容缺少历史信号时，系统建立初始分发和反馈的阶段。

#### 例子

- 新餐馆没有订单和评价，平台可用类目、位置、基础质量和小范围流量开始测试。

#### 边界

- 冷启动不是永久流量倾斜；必须有探索、反馈和退出机制，避免低质供给长期占位。

## 内容与购买决策

### P26｜内容供给（Content supply）

#### 解释

- 能被创作者、商家、用户或平台生产并分发的文字、图片、视频、直播和商品表达。

#### 例子

- 一条测评短视频、餐馆菜单图和职位介绍都可能帮助用户形成判断。

#### 边界

- 内容量不等于有效内容供给；相关性、真实性、可理解性和后续承接共同决定价值。

### P27｜短视频与直播（Short video / Live）

#### 解释

- 短视频是异步内容入口，直播是实时互动入口，二者都可以承载发现、讲解和交易。

#### 例子

- 用户在视频中发现护肤品，再进入直播间提问并下单。

#### 边界

- 内容形式不是业务模式；视频或直播是否可交易、是否带货、是否计入成交要按事件记录。

### P28｜商品卡与商品详情页（Product card / PDP）

#### 解释

- 商品卡是分发场景中的简短决策入口，PDP 是承载规格、价格、评价、配送和购买动作的详情页面。

#### 例子

- 推荐流中的商品卡引发点击，PDP 让用户比较尺码、运费和退货规则。

#### 边界

- 点击商品卡不等于看完商详；商品卡吸引点击但详情不兑现承诺时，短期 CTR 可能掩盖转化损失。

### P29｜购买决策（Purchase decision）

#### 解释

- 用户在需求、价格、质量、信任、便利和风险之间形成“现在购买哪一个”的选择。

#### 例子

- 两家餐厅价格相同，用户可能因评分、送达时间和退款承诺选择其中一家。

#### 边界

- 决策意向、加购、下单和支付是不同阶段；访客口头说“想买”不能当成成交。

### P30｜信任信号（Trust signals）

#### 解释

- 帮助用户判断质量、真实性、风险和履约可靠性的评价、认证、销量、保障和服务承诺。

#### 例子

- 可验证评价、品牌授权、预计送达时间和明确退款规则共同降低购买风险。

#### 边界

- 信号不是质量本身；虚假评价、刷销量和模糊承诺会让指标上涨但损害平台长期信任。

### P31｜内容场与货架场（Content field / Shelf field）

#### 解释

- 内容场以视频、直播或社区发现驱动兴趣，货架场以商城、搜索、类目和商品卡承接明确购买。

#### 例子

- TikTok Shop 官方课程以 Shop Tab 说明搜索、类目、推荐和购买的货架入口（来源：tiktok-shop-shop-tab-basics）。

#### 边界

- 这是可迁移的分析对照，不是对抖音或 TikTok 全业务的完整命名；一个入口可以同时含内容和货架元素。

### P32｜加购与结账（Add to cart / Checkout）

#### 解释

- 加购表达暂存或比较意图，结账表示用户开始确认地址、配送、优惠和支付条件。

#### 例子

- 用户把鞋放入购物车后，填写尺码和地址并进入支付页面。

#### 边界

- 加购不是订单，开始结账也不是支付成功；漏斗事件要防止重复触发和跨端断裂（来源：google-analytics-recommended-ecommerce-events）。

### P33｜购买摩擦（Purchase friction）

#### 解释

- 让用户在发现、判断、下单、支付或收货过程中额外等待、猜测、填写或承担风险的阻力。

#### 例子

- 运费到最后一步才显示、库存不实时或登录反复失败都会降低结账完成率。

#### 边界

- 摩擦不等于所有步骤；必要的身份核验或风险控制可能是约束，不能为追求转化率全部删除。

## 交易与指标

### P34｜点击率（CTR）

#### 解释

- CTR = 点击次数 ÷ 展示次数；分子、分母必须来自同一渠道、同一对象集合和同一统计窗（来源：google-ads-ctr-definition）。

#### 例子

- 20,000 次商品展示带来 500 次点击，CTR 为 2.5%。

#### 边界

- CTR 是响应代理，不是订单或利润；广告点击、搜索点击和推荐点击的事件与去重规则不能直接混比。

### P35｜转化率（CVR）

#### 解释

- CVR = 目标转化次数或人数 ÷ 约定的机会分母；必须注明转化事件是下单、支付还是完成。

#### 例子

- 1,000 次商品详情访问产生 40 个支付订单，若分母是详情访问，CVR 为 4%。

#### 边界

- “CVR 上升”没有分母就不可审查；支付用户/访客与订单/访客不是同一口径，前者还缺少每用户订单频次。

### P36｜订单（Order）

#### 解释

- 用户确认购买意图后形成的交易记录，通常包含商品、金额、状态、付款、履约和售后关联。

#### 例子

- 一次购物车结算生成一个订单，里面可以有多个 SKU 和多件商品。

#### 边界

- 下单、支付成功、已完成和已结算是不同状态；订单数不等于商品件数或付款人数。

### P37｜成交总额（GMV）

#### 解释

- 在明确订单状态、金额字段、币种和时间窗后，对交易订单商品金额的汇总指标；它不是平台收入。

#### 例子

- 固定统计窗内，状态集合相同的支付订单数 × 同集订单客单价，可得到同口径 GMV。

#### 边界

- GMV 是否含税费、运费、优惠、取消和退款必须写清；不同平台或报告口径不能直接相加或比较。

### P38｜客单价（AOV）

#### 解释

- AOV = 选定金额口径的订单金额 ÷ 同一口径订单数，表示每个订单平均金额。

#### 例子

- 1,000 个支付订单产生 120,000 元同口径商品金额，AOV 为 120 元。

#### 边界

- AOV 不是每位用户消费额；金额含不含税、运费、优惠和退款，必须与订单分母同步。

### P39｜订单量（Order volume）

#### 解释

- 统计窗内符合状态条件的订单记录数量，常用于衡量交易规模和履约负载。

#### 例子

- 日订单量从 10,000 增至 12,000，但若取消率同时升高，净完成量未必同步增长。

#### 边界

- 订单创建量、支付订单量、完成订单量和有效订单量不能互称；时间窗和去重键要固定。

### P40｜交易用户（Transacting users）

#### 解释

- 统计窗内至少完成约定交易事件的去重用户数，常与订单量一起观察人均频次。

#### 例子

- 10,000 个支付订单来自 8,000 名交易用户，简单人均订单频次为 1.25。

#### 边界

- 交易用户不是活跃用户或注册用户；匿名、家庭账户和跨端识别会影响去重结果。

### P41｜交易频次（Purchase frequency）

#### 解释

- 统计窗内订单量 ÷ 交易用户数，或对单用户订单次数做同期群统计，描述交易重复程度。

#### 例子

- 同一季度 12,000 个订单由 8,000 名用户完成，人均交易频次为 1.5。

#### 边界

- 频次高可能来自少数重度用户；必须看分布、同期群、退款和订单质量，不能只看平均数。

### P42｜收入（Revenue）

#### 解释

- 企业按会计或经营约定确认的已赚取金额，可能来自佣金、广告、订阅、服务费或自营销售。

#### 例子

- Marketplace 从商家交易中确认佣金收入，同时向商家销售广告服务。

#### 边界

- GMV 是交易规模，收入是平台或商家的确认金额；现金回款、毛利和净利润还要另算。

### P43｜抽佣率（Take Rate）

#### 解释

- Take Rate = 平台相关收入 ÷ 约定的计佣成交额或 GMV；分子不必只含佣金，必须说明纳入哪些收入。

#### 例子

- 平台从 100 万元计佣成交额确认 5 万元佣金，按佣金口径 Take Rate 为 5%。

#### 边界

- Take Rate 不是无条件等于佣金率；广告、支付、配送或补贴收入是否纳入，以及 GMV 是否含退款，都可能改变分子分母。

### P44｜投资回报率（ROI）

#### 解释

- 默认 ROI = 净回报 ÷ 投资成本；若收益是扣投资前收益，则 ROI =（收益−投资）÷投资，并须声明归因范围和时间窗。

#### 例子

- 投入 10 万元并带来扣除该投资前的 15 万元收益，净回报 5 万元，ROI 为 50%。

#### 边界

- 某组织把收入/花费用 ROI 是业务别名，必须标明并核查口径；常规 ROI 不能默认把收入当净回报。

### P45｜广告支出回报率（ROAS）

#### 解释

- ROAS = 归因广告收入 ÷ 广告花费，需固定广告渠道、归因窗、收入口径和去重规则。

#### 例子

- 1 万元广告花费带来归因收入 4 万元，按该归因窗 ROAS 为 4.0。

#### 边界

- ROAS 看广告收入，不直接代表利润或增量；ROI 与 ROAS 的收益口径和分母不同，不能互换。

## 履约与售后

### P46｜履约（Fulfillment）

#### 解释

- 把已承诺的商品或服务按约定时间、地点、质量和状态交付给用户的过程。

#### 例子

- 电商仓库拣货、发货、配送和签收共同构成一次订单履约。

#### 边界

- 支付成功只表示交易阶段完成；订单取消、缺货、延迟和退款会改变履约结果。

### P47｜订单状态机（Order state machine）

#### 解释

- 用有限状态和合法转移描述订单从创建到支付、履约、完成或售后的生命周期。

#### 例子

- 待支付订单可超时关闭，已发货订单不能直接回到待支付。

#### 边界

- 页面上的状态文案不等于账务事实；状态转移要有事件、时间、责任方和异常恢复规则。

### P48｜备货与配送（Picking / Delivery）

#### 解释

- 备货把订单需求变成可发出的商品或服务准备，配送把它送达约定地点或完成上门服务。

#### 例子

- 即时零售从附近门店拣货，再由骑手送到用户地址。

#### 边界

- 配送中不代表已签收；备货时间、出库时间、在途时间和服务完成时间要分别记录。

### P49｜预计到达与准时率（ETA / On-time rate）

#### 解释

- ETA 是对交付时间的预测，准时率是按约定阈值完成的订单数 ÷ 具备可判定结果的订单数。

#### 例子

- 系统显示 19:30 到达，最终在 19:25–19:40 约定窗口内送达，可计为准时。

#### 边界

- ETA 是预测不是承诺；准时率的窗口、取消订单、用户改约和异常天气必须明确。

### P50｜履约率（Fulfillment rate）

#### 解释

- 已完成约定履约的订单数 ÷ 进入可履约集合的订单数，分母要排除或纳入取消等状态并写明。

#### 例子

- 1,000 个可履约订单中 970 个完成交付，按该分母履约率为 97%。

#### 边界

- 履约率不是准时率或满意度；完成但严重延迟、缺件或质量不合格仍可能需要另看。

### P51｜取消（Cancellation）

#### 解释

- 订单在完成前被用户、商家、平台或系统终止的事件及其原因。

#### 例子

- 商家缺货取消、用户超时未支付关闭和平台风控取消应分别归因。

#### 边界

- 取消率不能只看总量；责任方、阶段、可避免性和退款处理决定后续动作。

### P52｜退款与退货（Refund / Return）

#### 解释

- 退款返还全部或部分支付金额，退货是商品被退回的物流或物权过程，二者可能同时发生也可能分开。

#### 例子

- 缺货订单直接全额退款，尺码不合适则收货后退货并部分退款。

#### 边界

- 退款金额、退款订单数、退货件数和退款时点不可混用；退款会影响 GMV、收入和用户体验口径。

### P53｜售后与纠纷（After-sales / Dispute）

#### 解释

- 交易完成或交付后处理咨询、投诉、赔付、退换和责任判定的服务链。

#### 例子

- 用户反馈餐品漏装，平台收集证据后在商家、配送方和用户之间处理赔付。

#### 边界

- 售后工单关闭不等于用户满意；处理时效、一次解决率、重复投诉和责任归因要分开。

## 留存与增长

### P54｜留存（Retention）

#### 解释

- 初次使用或交易的用户在后续约定时间窗再次活跃、使用或完成目标行为的比例。

#### 例子

- 5 月首购用户中 6 月仍有支付订单的用户占比可作为月留存。

#### 边界

- 留存事件和时间窗必须先定义；登录留存、购买留存和任务完成留存不能互称。

### P55｜复购（Repeat purchase）

#### 解释

- 用户在首次购买后再次完成约定购买事件，关注交易关系是否继续发生。

#### 例子

- 用户第一次买咖啡后 30 天内又下单，可计入 30 日复购。

#### 边界

- 复购是交易留存的一种；自动续费、同日多单、退款后重下单要按规则处理。

### P56｜用户同期群（Cohort）

#### 解释

- 按首次注册、首次交易或其他共同起点分组，观察各组随时间变化的行为和价值。

#### 例子

- 比较 1 月、2 月首购用户在首购后第 4 周的复购率，而不是混合全站用户。

#### 边界

- 同期群不是用户分层的同义词；起点、观察窗和是否允许回溯更改会影响结论。

### P57｜流失与召回（Churn / Reactivation）

#### 解释

- 流失是超过约定不活跃或不交易阈值，召回是通过触达、权益或产品价值让其重新发生目标行为。

#### 例子

- 连续 90 天未下单的用户收到相关优惠后再次支付，可记录为召回。

#### 边界

- 未登录不一定流失；召回订单要看增量和长期价值，不能把自然回访全算成活动功劳。

### P58｜用户生命周期价值（LTV）

#### 解释

- 预期用户关系期间带来的收入或贡献利润现值，计算必须声明预测期、成本、折现和退款处理。

#### 例子

- 用同期群的复购频次、客单价和贡献毛利估计未来 12 个月价值。

#### 边界

- LTV 是预测或估计；收入口径 LTV 不能直接当利润与 CAC 比较，GMV 也不能直接当平台 LTV。

### P59｜获客成本（CAC）

#### 解释

- CAC = 约定获客投入 ÷ 同一时间窗内新增合格用户数，分子和新增事件要匹配。

#### 例子

- 10 万元拉新费用带来 5,000 个完成首购的新客，按首购新客口径 CAC 为 20 元。

#### 边界

- CAC 不是所有营销费用的自动平均；品牌曝光、自然新增、补贴和重复用户归因要单独声明。

### P60｜增长闭环（Growth loop）

#### 解释

- 用户、供给、内容或交易产生的结果反过来带来更多需求或供给，形成可重复的增长反馈。

#### 例子

- 更多真实评价提高信任，带来更多订单，订单又产生更多评价和商家参与。

#### 边界

- “飞轮”不是增长证据；闭环要能指出触发变量、反馈路径、成本和停止条件。

### P61｜增长杠杆与补贴（Growth lever / Subsidy）

#### 解释

- 可改变增长结果的产品、价格、供给、分发或运营动作；补贴是由平台或参与方承担成本的激励杠杆。

#### 例子

- 新客券可以提升首购，但要继续观察复购、商家实收和平台贡献利润。

#### 边界

- 补贴带来的订单不自动是增量；若只是提前消费或挤压自然订单，长期 ROI 可能为负。

## 商家经营与平台经济

### P62｜商家生命周期（Merchant lifecycle）

#### 解释

- 商家从招募、入驻、上架、激活、稳定经营到留存、升级或退出的阶段链。

#### 例子

- 新餐馆先完成资质和菜单，再获得第一单，之后学习投放和提升履约。

#### 边界

- 入驻数量不等于活跃供给；每阶段应有可观察行为和明确的成功条件。

### P63｜商家激活（Merchant activation）

#### 解释

- 新商家完成代表真实经营价值的关键动作，而不是只注册或签约。

#### 例子

- 商家完成商品上架、库存同步并成功履行首单，可作为电商激活动作。

#### 边界

- 激活事件因业务而异；登录、参加培训或领取工具不能自动代表商家已开始经营。

### P64｜商家工具与自运营（Merchant tools / Self-operation）

#### 解释

- 商家用于管理商品、价格、库存、内容、活动、订单和客户关系的产品能力与经营动作。

#### 例子

- 商家在后台改价、创建优惠券、查看搜索词并调整商品详情页。

#### 边界

- 工具使用量不是经营效果；要连接供给质量、成交、履约、利润和商家留存。

### P65｜商家投入产出（Merchant ROI）

#### 解释

- 商家从广告、佣金、补贴、人员和库存等投入中获得的收入或贡献回报。

#### 例子

- 商家比较一次直播投流带来的归因毛利与广告、达人佣金和折扣成本。

#### 边界

- 平台的 ROAS 不等于商家的利润 ROI；商家真实成本和自然订单归因必须纳入。

### P66｜广告与商业化（Advertising / Monetization）

#### 解释

- 平台将流量、搜索、推荐、数据或服务变成收入的方式，广告是其中按展示、点击或转化收费的一类。

#### 例子

- 商家付费竞价搜索位，平台提供曝光并按点击或其他约定结算。

#### 边界

- 商业化收入不能只看广告；抽佣、订阅、配送和增值服务的成本与生态影响不同。

### P67｜单位经济（Unit economics）

#### 解释

- 以一次订单、一个用户、一个商家或一单服务为单位，比较收入、变动成本和可归因贡献。

#### 例子

- 外卖一单的配送、支付、客服和补贴成本高于佣金收入，说明单均经济尚未成立。

#### 边界

- 单位要与成本归集一致；单均盈利不能掩盖获客、固定成本、退款或长期生态成本。

### P68｜贡献利润（Contribution profit）

#### 解释

- 本卡把 contribution profit 定义为收入减去随订单、用户或活动增加而变化的可归因成本后的金额；比例应显式写 contribution margin ratio。

#### 例子

- 一单收入 30 元，配送、支付和活动补贴等变动成本 22 元，单均贡献利润为 8 元。

#### 边界

- 英文报表可能把 contribution margin 写成金额或比例；读报表时要核对字段定义，不能仅凭名称判断，且二者都不自动等于毛利或净利润。

### P69｜双边市场与网络效应（Two-sided market / Network effects）

#### 解释

- 平台同时服务相互影响的两类或多类参与者，某一侧规模和质量会改变另一侧的价值。

#### 例子

- 更多优质商家增加用户选择，更多真实用户又提高商家留在平台经营的意愿。

#### 边界

- 网络效应不必然为正；低质供给、欺诈、拥堵和补贴依赖也可能形成负向反馈。

## 生态与实验因果

### P70｜生态健康（Ecosystem health）

#### 解释

- 同时观察用户体验、供给质量、商家可持续经营、平台收入和风险治理的系统状态。

#### 例子

- 订单增长时一起检查退款、投诉、商家利润、供给多样性和重复购买。

#### 边界

- 生态健康不是一个万能分数；必须明确参与者、时间窗和哪些指标是结果或护栏。

### P71｜北极星指标与指标树（North Star / Metric tree）

#### 解释

- 北极星指标代表阶段性核心价值，指标树把它拆成可诊断的驱动因子和约束指标。

#### 例子

- 本地生活可把完成且满意的订单作为结果，再拆服务覆盖、转化、履约和复购驱动。

#### 边界

- 北极星不是唯一目标或团队排名；若只追一个数字，可能牺牲利润、质量或另一侧参与者。

### P72｜代理指标与护栏指标（Proxy / Guardrail metrics）

#### 解释

- 代理指标是更快可观测的中间信号，护栏指标约束优化不能伤害的体验、风险或长期结果。

#### 例子

- CTR 可作推荐相关性的早期代理，退款率、投诉率和次月留存可作护栏。

#### 边界

- 代理指标不是最终价值；护栏也不是越多越好，应事先写阈值、方向和观察窗。

### P73｜A/B 测试（A/B test）

#### 解释

- 将符合条件的单位随机分到不同方案，比较预先约定的指标以估计改动影响。

#### 例子

- 一半新用户看到新版商品卡，另一半看到旧版，再比较支付转化和退款率。

#### 边界

- A/B 测试需要随机化、稳定曝光和足够观察期；同时改多个变量可以估计整套方案效果，但不能拆出单因素贡献。

### P74｜处理组与对照组（Treatment / Control）

#### 解释

- 处理组接受新策略或功能，对照组维持基线，两组的差异用于估计相对变化。

#### 例子

- 处理组收到新客券，对照组不收券，比较同一时间窗内的首购和后续复购。

#### 边界

- 对照组不等于“什么都没有”；版本、资格、时间、污染和样本流失都要记录。

### P75｜增量与因果（Incrementality / Causality）

#### 解释

- 增量是因某动作额外产生的结果，因果判断要排除季节、选择偏差、同期活动和自然回流等替代解释。

#### 例子

- 应比较同一分母下的每用户订单率或支付率，并结合区间和统计不确定性判断差异，不能只比较两组订单绝对量。

#### 边界

- 归因订单不一定是增量订单；实验结果还要说明适用人群、时间和可能的跨组影响。

### P76｜分群与异质性（Segmentation / Heterogeneity）

#### 解释

- 分群按用户、商家、商品、地区或渠道拆分观察，异质性描述同一改动在不同群体中的效果差异。

#### 例子

- 新客 CTR 上升但老客留存下降，说明平均值掩盖了人群间的不同反应。

#### 边界

- 分群越多越容易偶然显著；应预先定义关键群体并控制多重比较和样本量。

### P77｜归因与时间窗（Attribution / Time window）

#### 解释

- 归因把结果按规则关联到触点或动作，时间窗规定触点发生后多久内的结果可以被计入。

#### 例子

- 规定广告点击后 7 天内的支付订单计入该广告，并对跨渠道重复触点设定去重规则。

#### 边界

- 归因规则是分配方法不是因果证明；改时间窗或把最后触点改成多触点会改变 ROAS 与 ROI。

## 跨平台迁移案例

### 案例 A｜电商与零售 → 企业 AI 工作流

#### 解释

- 把“供给→分发→决策→交易→履约→复购”迁移为“知识与工具供给→任务分发→建议采纳→执行→结果确认→持续使用”。

#### 例子

- 企业法务助手先解决一个真实合同审阅任务，再看任务完成、正式采纳、返工和持续使用，而不是只看调用次数。

#### 边界

- 企业 AI 的调用量类似流量代理，不等于业务价值；权限、责任人和正式工作系统的状态必须一起验证。

### 案例 B｜本地生活 → 企业 AI 服务交付

#### 解释

- 把位置、时效、供给覆盖和履约确定性迁移为客户场景、专家可用性、响应时间和交付责任链。

#### 例子

- 驻场交付按客户部门和时间窗匹配可用专家，记录从问题受理到可验证结果的 ETA 与完成率。

#### 边界

- 企业项目的“服务半径”是权限、系统和责任范围，不是简单复制地理距离或骑手调度。

### 案例 C｜内容分发 → 招聘平台匹配

#### 解释

- 把内容供给、兴趣发现、搜索意图、召回排序和转化迁移到职位、候选人、沟通、面试和入职链。

#### 例子

- 职位曝光与点击只是前段信号，还要观察合格申请、有效沟通、面试到场和入职质量。

#### 边界

- 招聘中的点击率不能替代公平、岗位质量和入职结果；候选人和雇主两侧的体验都要纳入护栏。

### 案例 D｜平台治理 → 专业工作流治理

#### 解释

- 把商家准入、质量信号、纠纷处理、实验护栏迁移为专家权限、证据质量、责任审批和可追溯审计。

#### 例子

- AI 生成法律意见前检查来源、权限和责任人，输出后记录采纳、修改、退回和最终案件结果。

#### 边界

- 平台规则只能提供治理结构的类比；专业领域的法律责任、保密和审批要求必须由真实权威主体确认。
