2. 读者要完成什么

刚搬入的住户要弄清三件事必须依次办，每一步在哪办、带什么、要等多久（只有前两步给了时长，第三步未知），并在办理时间内把三步办完。

3. 手册版结构（A5 竖版）

整体：单栏，全部左对齐、右侧参差，不两端对齐，不用卡片。左边一条窄栏（约内容宽的 1/7）只放序号；右边内容栏里，标题、导语、步骤文字、页脚全部从同一条竖线起排。单一墨色，不靠颜色传递含义（黑白印刷也成立）。

强调图例：
- «…» = 字重 600 加实线下划线
- ‹…› = 字重 600 加虚线下划线
- 正文字重 400；字重只用到 600，不再加重

```
          ┌ 内容线（所有文字的左边界）
  序号栏  │ 内容栏
          │
          │ 新住户三步办理                 ← 全页最大字，仅此一处。页面上部约 1/4 为标题加导语
          │
          │ 搬入后按顺序办完三步，才能使用门禁和车位。
          │ 前一步没办完，后一步无法受理。   ← 在原句界另起一行；字号同上句，字重 600（这是约束整串步骤的规则）
          │
          │ ← 导语与第一步之间留一个大间距
     1    │ 实名登记                       ← 步骤名：字号次大，字重 600
          │ 一层服务台现场办理，«约10分钟»。
          │ 带身份证件、租赁合同或房产证明。
          │
     2    │ 门禁录入
          │ 实名登记完成后在服务台提交，«1–3个工作日生效»。
          │ 生效前可凭临时通行单进出，临时单有效5天。
          │
     3    │ 车位申请
          │ 门禁生效后可申请。目前排队23户，‹等待时间未知›。
          │ 有空位时按登记顺序短信通知，收到通知后3天内确认。
          │
          │ ───────────────  ← 一条细线，从内容线画到右边距，页脚在它下面，贴近页底
          │ 办理时间：周一至周六 9:00–18:00
          │ 咨询：frontdesk@example.org     ← 与正文同字号，不缩小；邮箱完整印出，不做链接样式
```

块内与块间的规则：
- 序号：全页第二大的字，右对齐于序号栏右缘，与步骤名首行同基线。
- 三个步骤块：块内三行间距紧，块与块的间距相同且大于块内行距，靠留白分组，不画框、不画线。
- 三个块的高度由文字量决定，三块相近，不随时长缩放。
- 不画连接三个序号的竖线，也不画箭头：等距的线会被读成时间尺，而依赖关系已经由第 2、3 步句首的“实名登记完成后”“门禁生效后”写明。
- 三处时间说法是全页仅有的行内强调。“等待时间未知”不配任何长度、数字或破折号。
- “5天”“3天内”保持正文字重，只有这三处时间说法加强调。需要让它们也显眼时，由需求方决定。
- 断行：优先在“，”处折行。“1–3个工作日生效”“等待时间未知”“frontdesk@example.org”不拆。

与手册版的差别只有这几点：
- 窄宽下大多数句子会折成两行，所以只在“，”折行，并让折行后的行都从内容线起。

- 页脚细线、留白间距按窄屏比例，不另加容器。
- 邮箱靠文字选中复制，页面里不添加按钮或说明文字。

6. 给需求方的回复

这次三步办理做不成上次活动页那样的比例时间尺。上次三个环节在同一个钟上、各是几十分钟，所以按分钟画得出来；这次是约 10 分钟、1–3 个工作日、等待时间未知，单位不同，第三段还没有数。硬按比例画，第一段在手册上只有一两毫米，第三段只能画出一个我们并不知道的长度，读者会当成事实。所以我改成三个按顺序排的编号块：序号放左栏，标题、导语、各步文字和页脚都从同一条竖线起排，用留白分组；三处时间说法在句中加粗并加下划线，“等待时间未知”用虚线，不配长度、数字或破折号。手册和小程序用同一结构，小程序只是单列滚动、不加进度勾选。原文一字未改。要请你确认两件事：一，“目前排队23户”印进手册就会过期，能否给一个截至日期，或只放在小程序里；二，如果希望三个时间说法单列成一列便于扫读，需要把它们从句子里拆出来，要你同意才动原文。

7. 内容或媒介怎样变化时，这个方案就不再适用

- 第三步有了可信的时长，三步又在同一个钟上、量级相近，而且时刻真实、跨度短：这时才值得重新试比例时间尺（E01-b 的成立条件）。目前三步是分钟、工作日和未知，不满足。
- 步骤超过 9 个，或出现并行步骤、分支判断（E01 容量 3–9，E01-d 部分并行）。
- 步骤由不同角色交接，并且交接点是读者要看的重点（E01-c 泳道，至少 2 个角色）。
- 读者的主要问题变成“一共要多久”：第三步未知，无法加总，这个方案没有给总时长。
- 步骤名、句子明显变长，或在 375 宽以下、系统字号放大后折成三行以上：第 4 项里的序号栏加内容栏会先失效，仓库没有对这一宽度的实测。
- 需要显示进度、已办完或实时排队：这要有真实状态，按 states.md 要做状态矩阵，本方案没有状态。
- 媒介变成横向宽屏、网页或大幅远读展板：单栏轴线版式会留大块空白，强调层级也要重排（G12）。
- 手册不再只用单一墨色之外的颜色做区分，或强调字重在目标字体里区分不出来（我只知道系统字体栈的汉字到 600 为止，手册与小程序实际字体未测）。
