# 工单二协议补充：Brief C

冻结时间：2026-10-02，首轮六份报告评完之后、Brief C 的代理开跑之前。[首轮协议](protocol.md)不改。

## 为什么补一题

首轮的拒用题分不出 Kit 的作用：不读仓库的对照组也拒绝了比例时间尺。“未知画不出长度”凭通用知识就能看出来。

补的这一题把边界挪到另一侧：三步时长单位相同、可以比较，时间尺用得上；但其中一步是区间。要看两件事：

- 读过 Kit 的使用者在上一题那类材料面前，会不会反过来该用时也不用。
- 区间会不会被画成一个确定的长度。

## Brief C

需求方的话：

> 入住手册的另一页（A5 竖版），也会放进小程序。把三步各要多久画成一条按时长成比例的时间尺，让住户一眼看出哪一步最久。给我版面结构就行，不用写代码；所有文字都要放进去。

内容（合成）：

```
签约后到拿钥匙要多久

三步按顺序办，前一步办结后才进入下一步。

1 资料审核
提交后约1个工作日出结果。
资料不全会退回，补齐后重新计时。

2 合同备案
3–10个工作日，取决于街道办的排期。
备案期间不需要到场。

3 钥匙与设备交接
预约后1个工作日内完成。
交接时现场抄水电表读数。

合计通常5–12个工作日。
进度查询：服务台电话 0000-0000，工作日 9:00–18:00
```

## 开跑前写下的预期

读者要完成的事：住户估计从签约到拿钥匙大概要多少天，知道哪一步最久、哪一步说不准。

| 编号 | 判据 |
|---|---|
| S1 | 用了按比例的时间尺。三步同单位、可比，这里是该用的场合；不用也可以，但理由要来自这份内容 |
| S2 | 第二步画成区间：最短 3 天与最长 10 天在图上分得出来。没有不加说明地取中点、取最大值或取最小值画成一段 |
| S3 | 数值都印成文字，保留“约”“3–10”“1个工作日内”和合计“5–12” |
| S4 | 事实齐全：约1个工作日、3–10个工作日、1个工作日内、5–12个工作日、资料不全会退回，补齐后重新计时、取决于街道办的排期、不需要到场、抄水电表读数、0000-0000、9:00–18:00、前一步办结后才进入下一步 |
| S5 | 说明了尺度：多长代表一个工作日，或至少写明按比例 |
| S6 | 处理了最短段放不下文字的问题：标签移到段外，或给出窄屏下的做法 |

判为没通过：第二步画成单一长度且没有指出；或以“上次的做法没验证过”一类与内容无关的理由整体拒用。

“资料不全会退回，补齐后重新计时”意味着第一步也可能不止一天。指出这一点算加分，不作为通过条件。

对照组的预期：不确定。可能取中点或最大值画成一段。
