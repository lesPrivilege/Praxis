## 是什么

dot 写的一份校订意见，27,570 字节，一个文件。它审的是一份没有随文件提供的 proposal（新增 Present 或 Editorial Grammar、十条 Write Core、Core 加语言层默认加载、Profiles 与 lint 拆分），对照的是远端 `main@3417dca`。原件只读保存在 [快照](../../snapshots/local/write-present-supplement-20261002/praxis-write-present-architecture-supplement.md)，hash 见 [intake](../../intake/write-present-supplement-20261002.json)。

补充文件自己说明没有看到本地未推送的 Kit，并把结论写成条件式：本地已有相应的层就校订它，不另建。用户当日批准施工。采纳的部分落在 [ADR-019](../../../docs/decisions/019-expression-owners-and-entry-paths.md)。

## 八类问题的归属

补充文件把 proposal 的八类 grammar 逐项分了责任。对到本地的分支上：

| 问题 | 唯一正文在哪里 | 别处怎样引用 | 本次处置 |
|---|---|---|---|
| 叙事与论证顺序 | 材料层面在 [Reporting](../../../kit/reporting/grammar.md)；句段层面在 [成文原理](../../../kit/write/prose/grammar.md) | [内容编排](../../../kit/write/publish/composition.md)要求重排时保留依赖关系；[时间叙事](../../../kit/write/motion/narrative.md)管它怎样随时间显现 | 不动 |
| 证据 | [证据与来源](../../../kit/write/shared/evidence.md) | Reporting、展项、成文原理第 4 条都指过来 | 补上四条底线和“投影、改编与新增” |
| 密度 | [空间编排](../../../kit/design/composition/layout.md)的容量检查 | 内容编排只说先保关系再调密度 | 不动。没有专门规则，问题地图 G07 有一行 |
| 层级 | 内容的主次在内容编排；视觉层级在空间编排 | 两页互相链接 | 不动 |
| 图形 | [图形编码](../../../kit/design/composition/encoding.md)；内容职责在 [展项与说明](../../../kit/write/publish/exhibits.md) | 内容编排原先另写了一份箭头、长度、颜色的语义 | 去重：内容编排改为链接，独有的两句并进图形编码 |
| 强调 | 什么重要由任务和内容定；怎样强调在空间编排 | — | 不动 |
| 分页 | 内容编排（Pre-read 与 Live、页面承载的任务）；导出检查在 [验收](../../../kit/write/shared/verification.md) | — | Publish 入口补上“阅读单元、分页、密度、收起” |
| 时间节奏 | 认知任务与驻留在时间叙事；运动在 [运动判断](../../../kit/design/motion/grammar.md) | — | 运动判断补一句：补间不是观测，排序变化与数量变化不混在一段运动里 |

补充文件对这八项的边界说明（例如“不能因版面放不下就静默删掉条件”“视觉降权可能改变实际理解”）本地大多已有对应的句子，没有逐条再写。

## 十条 Write Core 对到本地八条

补充文件逐条给原 proposal 的十条规则定了等级。本地的成文原理是八条，对应关系和本地的处置：

| 补充文件的意见 | 本地对应 | 处置 |
|---|---|---|
| 一句话有可辨认的信息功能：启发式 | 第 1 条“每个成分都承重” | 标为编辑启发式；写明导航、范围、来源、限制与必要的重复都承重 |
| 具体优先于抽象：启发式 | 第 2 条“对象作主语” | 标为编辑启发式 |
| 标题、开头、结尾不复述：启发式 | 第 8 条“说完即止”的一部分 | 标为编辑启发式；任务要求的摘要与请求不算客套 |
| 关系显式且真实：真实是底线，显式是启发式 | 第 7 条“连贯靠内容” | “关系是真的”进底线；其余是启发式 |
| 术语稳定：指称一致是底线，字面是语言约定 | 审阅方法的不可损失项里有术语 | 指称一致进底线 |
| 范围和确定性准确：底线 | 第 4 条“证据强度不变” | 底线，正文归到证据与来源 |
| 结构服务内容、并列项同级 | 第 5 条里“同一列形式并列” | 并列属于逻辑对应，换语体也保留 |
| 删除无作用的元话语：启发式 | 第 1、8 条 | 同上 |
| 保留必要复杂度：不损坏推理是底线 | 审阅方法第 1、6 步 | 进底线第四条；句长不设上限 |
| 内容结束时结束：启发式或任务配置 | 第 8 条 | 同上 |

第 3 条“先回答，再说明”、第 5 条的语体、第 6 条的中文搭配在十条里没有对应，本地分别标为编辑启发式、中文语言约定、中文语言约定。八条的原文一个字没有改。

## 采纳、改写与不采纳

| 补充文件的建议 | 裁决 |
|---|---|
| Present 先不独立，沿既有 owner 校订 | 采纳。落点是 Write/Publish 与 Write/Motion |
| 四者是按任务组合的能力，不是流水线；改变意义时回到受影响的 owner | 采纳，写进 Kit 入口和 ADR-019 |
| 每条规则只保留一个规范正文 | 采纳，去掉了图形语义的第二份 |
| 区分投影、改编与新增，改编附短的变动说明 | 采纳，写进证据与来源，并做了一件 [对照样张](projection-vs-adaptation/README.md) |
| Core 要薄，语言层按输出语言取用，启发式带理由与反例 | 采纳为三种强度；底线四条 |
| lint 分可自动修、只报不改、需要判断三类 | 采纳为 [格式检查](../../../kit/write/prose/format.md)一页。本仓库没有 lint 工具 |
| 发现层、短入口、按需正文、任务中回访；区分维护与日常消费 | 采纳。根入口拆成两条路，Kit 入口写明什么时候停 |
| 四个入口的 description 文案 | 改写。没有新增 skill 元数据；什么时候用、什么时候不用进来写在入口表里 |
| Profiles：任务文体与可靠的个人或品牌风格 | 不新建。本地已有 Genres 和默认关闭的个人语体；冲突次序写进 Write 入口 |
| 用反例验收，三组指标同时看 | 部分执行。四条路线前后各走读一次，两条复跑；六个反例只覆盖了与路线重合的部分。见 [走读记录](route-walkthroughs/README.md) |
| 先做 1000 字多媒介练习 | 改写。用一份真实回执的三节（879 字）做了投影和五页改编，没有做 90 秒音频 |

## 走读的结果

四个任务要守住的内容前后都守住了，三处产出因为新规则而不同。读取量没有普遍下降：只改格式的任务从 11 个文件降到 5 个，英文改写持平，改幻灯片的任务从 13 个升到 21 个。架构与入账两份维护文档改动后没有再被读到；Kit 使用约定要等根入口的措辞再改硬一次之后，复跑的两次才没有读。详见 [走读记录](route-walkthroughs/README.md)。

补充文件把“发现负担下降”列为三组指标之一。按这次的记录，这一条只在一个任务上成立。

## 边界

- 原 proposal 没有到手，十条规则只能从补充文件的转述里读到。
- 英文只有“不套中文约定”这一条，没有英文约定本身。
- 走读每条路线每个时点一次，一种模型，评阅者是改入口的人。
- 对照样张的五页没有投出来讲过。
- 外部来源四条直接读过相关段落，一条沿用已有来源卡，见 [来源登记](../../provenance/write-present-supplement-20261002/README.md)。

## 何时重访

出现只取编排规则、不经 Write 的独立消费者；有了第二种语言的写作任务并形成约定；格式检查有了工具；原 proposal 全文到手；或走读出现“读了入口仍然加载无关分支”的反例。
