# 四条取用路线的前后走读

状态：验证记录，2026-10-02。协议、内容与评阅由 Opus 5.5 主会话完成；十次走读由 Sonnet 5.5 代理各跑一次，只读，从仓库根 `AGENTS.md` 起步。Luna 在本会话不可用。评阅者就是改入口的人，不是独立评阅。

## 结论

入口调整之后，四个任务要守住的内容都守住了，并且有三处产出因为新写的规则而不同。读取量没有普遍下降：只改格式的任务从 11 个文件降到 5 个，英文改写持平，改幻灯片的任务从 13 个升到 21 个。

维护用的架构与入账两份文档，改动前四次里有两次被读到，改动后没有再被读到。Kit 使用约定在第一轮改动后仍被四次里的三次读到；把根入口的措辞改硬之后复跑两次，都没有再读。

## 做了什么

四个任务取自补充文件的“四条取用路线”，内容是主会话写的合成材料，预期在改入口之前冻结，见 [protocol.md](protocol.md)。同一份任务书在三个时点各跑一次：

| 轮次 | 仓库状态 | 跑了哪些 |
|---|---|---|
| 改动前 | `3954ca0` 加工单二的未提交记录 | R1–R4 |
| 改动后 | 入口拆成两条路、Write 分三种强度、新增格式检查页之后 | R1–R4 |
| 复跑 | 再改两处之后：根入口写明做任务时不预读维护文档；格式检查页改了“用哪一套约定” | R1、R4 |

## 产出有什么不同

| 任务 | 改动前 | 改动后 |
|---|---|---|
| R1 | 借用了中文成文原理里与语言无关的几条，自己注明这些规则面向中文 | 引用新写的“改写英文不套中文约定”，只用底线和不可损失项约束改写 |
| R2 | 给了保留、删除、挪动三项，并说“没有删事实” | 明确写“这是改编，不是投影”，按四件事交了变动说明，包括谁因此看不到什么；在决定页重复了两个未决条件 |
| R3 | “动画中途的高度会被当成真值”列为自己的通用知识 | 直接引用新写的“补间不是观测；排序变化和数量变化不放进同一段运动” |
| R4 | 改了引用行的冒号和句末标点，并说明这一处拿不准 | 引用行整行不动，交付时说明按较大范围保留 |

要守住的字串逐字核对，结果在 [checks](checks/README.md)。十次里有两处不符：改动前的 R4 动了引用行；复跑的 R1 把 “pushed” 改成 “push”、“normally” 改成 “usually”，条件和不确定程度没有变，代理在修改表里列了这两处。

## 走读暴露并已改的两处

- 格式检查页第一版写“没有约定时沿用原文里占多数的写法”。R4 据此把原文唯一一处中英文之间的空格删掉了，而需求方点名要规范的正是这一项。现在改为：点名要规范却没说按哪一套时，先问；没法问就选一种、整篇统一，并写明另一种是什么。复跑的 R4 照此选了留空格并作了说明。
- 根入口第一版写“不必读下面的治理文档”，三次里代理仍然顺手读了。改成“做任务时不预读下一条列的三份文档”之后，复跑两次都没有读。只有两次，不能说问题已经解决。

## 限制

- 每个任务每个时点只有一次运行，一种模型。前后差别可能只是运行之间的波动。
- 任务是合成的，四个都很小。
- R3 改动后读到了对照样张里的路线数据，那张表写着本任务预期取用的分支。它在此之前已经读完了要用的规则页，但这次运行不算干净。
- 预期路线写的是“R2 不读 Motion，Design 至多读一页”这类上限；没有预先写读取量的数值目标。
- 评阅者是改入口的人。
- 补充文件列的六个冷启动反例里，这里只碰到了三个的一部分：英文、中文与原样代码并存（R1、R4）；只改格式（R4）；动画让数据多出含义（R3）。必要的重复、90 秒容量取舍、并排比较被藏进标签页，都没有走。
- 没有验证任何宿主里的自动发现，也没有真实读者。

十份原始报告在 [reports](reports/README.md)。
