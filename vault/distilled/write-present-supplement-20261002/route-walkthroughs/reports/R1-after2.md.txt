2. 改后的文本

````markdown
## Sync fails with error 409

If the sync job stops with `409 Conflict`, the local index is ahead of the server. This happens only when two devices push within the same minute.

Do not delete the `.sync/` folder: it holds unsent changes.

To fix the error:

1. Reset the index.

        syncctl index reset --keep-unsent

2. Push again.

        syncctl push

The error should usually be gone after the push. If it persists after two push attempts, contact support and attach `~/.sync/logs/last.json`.
````

3. 修改表

按严重程度排序，前两行改动较大。

| 位置 | 原文 | 改后 | 理由 |
|---|---|---|---|
| 修复段，第一句 | you should basically just run the reset command and then it will work again | 步骤 1 "Reset the index."，后接命令 | 删去 "basically just"，它只缓和语气。"it will work again" 是肯定句，与后文 "normally ... should be gone" 的把握程度冲突，所以删掉，把确定性统一放到最后的 "should usually be gone"。"the reset command" 改为动作加原样命令。 |
| 修复段，第二句 | After that is done, you can run `syncctl push` and normally the error should be gone. | 步骤 2 "Push again."，后接命令；另起一句 "The error should usually be gone after the push." | 先后顺序改成编号步骤，命令各占一个代码块，原样不动。"normally ... should" 的限定保留，"normally" 换成 "usually"，把握程度不变。 |
| 最后一句 | after two tries | after two push attempts | "tries" 指什么原文没说。我按上下文理解为两次 push。这是我的推断，需求方需确认。如果指"reset 加 push 算一轮"，要改回。 |
| 第一段，第二句 | two devices pushed | two devices push | 描述一般条件，改一般现在时。"only when" 和 "within the same minute" 原样保留。 |
| 警告句 | Do not delete the `.sync/` folder, it holds unsent changes. | 单独成段，逗号改冒号 | 逗号连接两个完整句，改为冒号。警示仍放在修复步骤之前，位置没有挪动。 |
| 最后一句 | If it's still there | If it persists | 指代 "it" 不清，改为明确的 "persists"。 |
| 最后一句 | contact support and attach `~/.sync/logs/last.json` | 不变 | 动作和路径都不改。 |
| 标题、`409 Conflict`、命令、路径 | 不变 | 不变 | 属于需求方要求原样保留的内容。 |
