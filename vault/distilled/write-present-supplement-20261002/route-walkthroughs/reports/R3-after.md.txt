2. 要改的地方

先说判断依据。四个数按 400 起算：柱长是 A 本周 120、A 上周 80、B 本周 55、B 上周 70。按真值算，A 周环比约 +8.3%（520 比 480），B 约 −3.2%（455 比 470），A 比 B 高约 14%。图上 A 本周柱是上周的 1.5 倍，B 本周柱比上周短约 21%，A 本周柱是 B 本周柱的 2.2 倍。差异被放大了五六倍。

(1) 纵轴从 400 起，柱长失真
- 问题：用柱长表达数量，却把基线放在 400。读者按柱长读比例，会把 +8% 读成 +50%，把 −3% 读成 −21%。
- 改法：二选一。
  - 柱子改回从 0 起，数值直接标在柱端。
  - 若要看的其实是"相对上周的变化"，改成画差值（A +40、B −15，0 为基线），或改成点/折线并明确标注"轴从 400 起"。
  - 如果 400 是有业务含义的值（例如常规产能线、SLA 线），把它画成带标签的参考线，不当基线用。
- 理由：见第 3 节 encoding.md 与 relations.md G10。400 有没有业务含义，仓库里查不到，需要需求方回答（见第 4 节）。
- 附带：缺失被显示成 0，而轴起点是 400。0 在这张图上本来就画不出来，要么被裁掉，要么画成负向柱，读者看到的"0"没有意义。

(2) 比较方式没有说明读者要比什么
- 问题：四根柱同时承载三种比较：同组本周对上周，A 对 B，以及两者的绝对水平。目前没有说明哪一种是主比较，也没有看到直接标值，只能从柱长估数。
- 改法：
  - 先定主任务。多数仪表板的主任务是"每组本周相比上周变了多少"，那就让同组的本周和上周相邻、顺序固定（上周在前、本周在后，或相反，但所有组一致）。
  - 全图共用一条尺度（共同基线）。
  - 每根柱标精确值，或在组内标变化量。
  - 本周和上周用有明度差的两种填充，再配直接标签，不只靠颜色。
- 理由：见第 3 节 encoding.md 与 C05。

(3) 周期可比性与口径没有交代
- 问题：数据每小时刷新，"本周"在周中只是一个未完成的周，而"上周"是完整一周。再加上周三缺数据，本周 520 和 455 很可能是缺了周三的下限值。拿它和完整的上周比，不是同口径比较。
- 改法：
  - 图的标题或引介写明：指标是什么（新建单还是关闭单）、单位、统计窗口、"本周截至何时"、最后更新时间。
  - 本周数据不完整时，比较要么对齐到同一截止时点（上周同一时点），要么在本周柱上明示"不完整"，不要让读者当成完整周比较。
- 理由：见第 3 节 evidence.md 与 encoding.md。具体怎么处理（对齐截止点还是只加标注），要看第 4 节的未知项。

(4) 周三缺失显示为 0
- 问题：缺失和零是两回事。0 是"统计过，确实没有工单"，缺失是"不知道"。显示为 0 会让周内总量偏低，推出"本周下降"的假结论，而且数据补上时会触发一次从 0 到真值的柱子增长动画，读者会把它读成"工单突然涌入"。
- 改法：
  - 缺失画成缺口、斜线填充或"无数据"标记，不是 0 高度的柱。
  - 用文字写明缺失原因（未入库、采集失败，还是确实不可得），未知就写"原因待核实"。
  - 汇总值标注"缺周三"，或不给出汇总。
  - 数据补上时，这根柱直接更新，不播放从 0 起的增长。
- 理由：见第 3 节 encoding.md、C05、foundations/grammar.md。

(5) 刷新动画：补间被读成数据
- 问题：柱子"从旧值平滑长到新值"，中间帧是不存在的数值，读者会把它当成观测。每小时一次的数据更新，实际变化多为几件到几十件，在截断轴上还会被动画放大成大幅位移。
- 改法：
  - 数值标签在刷新时直接换成新值，不做计数滚动，动画只是视觉过渡。
  - 或者干脆不要长度动画，只用一次短暂的高亮或"较上次刷新 +N"标记提示"变了"。
  - 若保留长度过渡，一次刷新只动长度一个属性，时长和曲线按真实观看速度调。
  - 新数据在动画中途到达时，动画直接转向最新值，不排队、不叠加，最终状态以数据为准。
  - 减少动效偏好下，立即更新并保留"已更新 / 更新时间"提示。
  - 刷新失败时，保留上一次的值和更新时间，不动画、不清零。
- 理由：见第 3 节 motion/grammar.md、states.md 与 relations.md G08。

(6) 刷新时同时重新排序
- 问题：长度变化和位置变化叠在同一段运动里，读者分不清是"这个组变大了"还是"这个组被挪走了"。两个组比较的是同一类别在两个时点，位置每小时都可能互换，也破坏了对象和位置的对应。按当前数据，A 排在 B 前面（本周和上周都如此），排序并不改变现状，却带来每小时位置互换的风险。
- 改法：
  - 两组固定顺序（按名称或固定约定），本周、上周在组内的顺序也固定。
  - 若排名本身是读者需要的信息，用标签或排名数字给出，不靠位置运动。
  - 如果确需重排，把"数量变化"和"位置变化"分成先后两步，且重排只在组数多到需要靠位置看排名时才用。
- 理由：见第 3 节 motion/grammar.md、comparison-continuity.md、relations.md G08。

(7) 验收方式
- 内容固定、宽度收窄到手机宽度各看一次，并用关键 case 各跑一遍：周三缺失、本周与上周数值交叉、刷新中途又来新数据、刷新失败、减少动效。
- 实际速度观看动画，不只看单帧。
- 记录通过、未通过、未执行三类，只自动检查（溢出、文字完整）不能代替人读图。
- 理由：见第 3 节 relations.md 的检验一节与 verification.md。

4. 需要但仓库里没找到的东西

- 对"有意义的零点"的判定标准：什么算有意义、400 这种阈值该怎么处理（C05 只说不能泛化为必须零起点）。我只能假设 400 没有业务含义；需要需求方说明 400 是什么。
