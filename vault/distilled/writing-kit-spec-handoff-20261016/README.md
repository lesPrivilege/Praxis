# Writing Kit 修订交接

本包供 Opus 对照现行 Kit，裁决写作要求中的实际增量，再编订相应页面。它是一份可独立审阅的候选规格，不替代现行规范，也不要求按给定步骤或固定代理组合施工。

重点是让个人学习与机制讲解先形成准确的整体认识，再逐层展开；同时保住事实、条件、证据强度和自然中文。已有的结构文字、稳定术语、限定说一次、正文与过程记录分离等规则继续沿用，不能重新包装成新增成果。

## 从哪里开始

| 当前任务 | 阅读入口 | 得到什么 |
|---|---|---|
| 判断应写成什么样 | [写作规格](WRITING-SPEC.md) | 读者、完整度、结构、语言、文字角色和内容边界的实质要求 |
| 决定哪些要改 Kit、改在哪里 | [现状与增量映射](KIT-MAPPING.md) | 已采纳能力、待裁决缺口、精确落点和不应重复建设的部分 |
| 检查改写并安排真实试用 | [审阅与试用](REVIEW-AND-DOGFOOD.md) | 语义检查、合成反例、真实消费反馈与完成条件 |
| 审阅可选的个人语体 | [作者资料候选](AUTHOR-PROFILE.md) | 单独启用的表达偏好与合成例子；不进入通用 grammar |
| 核对依据和读取范围 | [来源索引](SOURCE-INDEX.md) | 公开固定版本定位、补充一手参考及其证据边界 |
| 查看基线、覆盖与交付检查 | [快照与覆盖](SNAPSHOT.md)、[变更记录](CHANGELOG.md) | 本包实际读过什么、未读什么、检查做到哪里 |

## 给 Opus 的裁决入口

先用映射表区分“保留现有条文”和“需要新增或澄清”，再按自己的编辑判断决定最小改动。优先关注三处：机制学习的整体图景与渐进展开；缩写首用及原语言来源与中文提炼的边界；共享验收页固定故事线顺序与其他现行规则的冲突。个人语体只作为可选、单独维护的作者资料，不进入通用 grammar。

可以合并、重写或退回本包建议。裁决说明指出具体的含义、结构、读者或证据理由即可，不必为每次句式选择留下记录。若修改了现行规则，按仓库原有的短 ADR、CHANGELOG、相关入口和消费记录维护；本包本身不预占新的 ADR 编号，也不宣布 Kit 采纳。

本包只提供规格与落位建议。合并和正式规则修订由后续裁决决定。
