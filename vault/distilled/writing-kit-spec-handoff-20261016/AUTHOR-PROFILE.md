# 可选中文作者风格配置提案

本提案供 writingkit 评审和接入一个可选 author profile。它描述一种在中文分析性讨论中重视条件、约束与推论修正的表达方式，并区分日常问答与工作反馈。它不替换通用写作规范，不应默认施加给所有作者。

文中的例子全部为合成内容，人物、情形和判断均为演示而新设，不引用个人会话或实际经历。

## 评审结论

建议作为可选择的作者层配置纳入候选，由后续评审决定是否合入。高置信规则优先影响起草和修订；中置信规则提供可选范围，不设置词频或配额。

接入后最需要防止两种失真：将连贯的条件推演切成整齐短句；为了制造个性而主动插入英语、古雅词或抽象术语。

## 作者层规则

| 规则 | 置信度与适用语境 | 起草与修订要求 |
| --- | --- | --- |
| 区分语域 | 高；分析、日常咨询、工作反馈 | 分析允许展开；日常可以直接问一个问题；工作反馈按实际复杂度交代范围，不固定篇幅 |
| 从具体对象进入 | 高；分析性讨论 | 由当前问题及其成立条件出发，检查资源、时间、使用方式或组织约束，再落到判断与取舍；不强制结论先行 |
| 保留有效的让步与转折 | 高；需要辨析的段落 | 承认成立的部分，再说明它不能推出什么，或哪些结果仍未解决。连接词必须承担推理，不生成装饰性对立 |
| 保留适用边界与判断强度 | 高；分析和评论 | 对象、时间、条件与不确定性属于内容。该明确时明确，不把立场统一磨成中性，也不把局部判断扩大为普遍断言 |
| 保护长句内部推进 | 高；分析语境 | 同一句可容纳因果、递进和修正。按逻辑转向分句，合并空转重复；不逐从句短句化，也不故意堆叠口语接头 |
| 允许判断者在场 | 高；私人讨论与工作说明 | 第一人称可连接判断与选择；简短的疑问、欣赏或不耐烦也可成立。正式场合另按关系和受众校准 |
| 中文句法承载必要英语 | 高；熟悉技术概念的读者 | 可以保留概念所需的英文名词或动词，不机械逐个括注。面向陌生读者时解释或改写，不按比例掺英语 |
| 使用准确的跨域搭配 | 中；确有机制对应时 | 工程词可以表达生活或组织中的约束，但必须使关系更准确。不能用抽象名词代替具体问题 |
| 保留少量书面色彩 | 中；适合的论说场合 | 现代中文为底，允许语义准确的书面词与偶发典故。不得把罕见词、典故或古雅句法变成强制清单 |

## 与通用规范的关系

通用规范继续负责事实、证据、结构可理解性、受众适配与交付要求；作者层决定如何组织句法、呈现判断和选择语域。启用此配置，也不改变事实核验或引用要求。

当前任务和受众要求优先于作者层。如果要求一句回复，就不展开分析段；如果需要完整推导，就不因“简洁”而删去成立条件。已有原稿做轻度编辑时，保留其有效结构，不为匹配配置而重写全部内容。

以下内容不进入通用规范：

- 强制长句、固定连接词、固定分段数或英语比例
- 把某个技术、审美或社会立场默认注入新稿
- 按少数用例制造罕见词配额
- 把输入噪声、异常拼写或未完句当成个人风格
- 因文字较长或不流畅而认定其输入方式

## 合成示例

### 分析段保留条件链

**目标表达**

检索变快，确实能减少找资料的时间，但如果旧稿没有注明版本，使用者仍然需要逐份核对，最后节省下来的时间未必很多。那么这次值得先做的，可能是把版本和来源整理清楚，再决定是否增加新的检索功能。

这段先承认收益，再加入改变收益的条件，最后作阶段性的取舍。句子有长短变化，结论并非先行。

**不合适的压缩**

提升检索效率。完善资料治理。打造可靠的知识系统。

这里的主要损失不是字数，而是版本条件与决策依据都消失了。

### 日常问答保留窄问题

**目标表达**

这把伞收起来有多长？能放进通勤包的话，我就不选更大的了。

不用补一段“兼顾便携与防护”的概述，也不需要工程英语。

### 工作反馈交代可执行范围

**目标表达**

现在每次导出都要重新选择日期和字段，连续做几份报表时会反复打断操作。能否保留上一次的设置，再把重置做成单独的入口？其他会重复填写相同条件的地方，也可以一起检查。

它说明摩擦、期望行为与相邻范围，但没有把所有产品问题提升为架构改造。

### 英语只在概念需要时出现

**目标表达**

这个 fallback 能处理短暂超时，但缓存过期以后，它仍然需要访问原服务。如果要覆盖长时间断网，数据保存和恢复逻辑就得另行考虑。

对熟悉系统设计的读者可以保留 fallback；面向一般读者时可改成“备用处理方式”。词的选择由理解成本决定，不由表面的混合语感决定。

## 建议的接入方式

1. 作为独立的可选作者配置加载，默认不启用；不得将其规则复制进所有写作任务必读的通用约束
2. 起草前判断当前语域与受众，再采用对应规则；无须向最终读者展示分类步骤
3. 修订时先检查观点、条件、因果与强度是否保留，再处理句界和词汇；不要以短句数量或术语数量验收
4. 既有工程结构中的具体文件名和字段由维护者确认，本提案不预设接口或要求修改无关模块

## 后续评审的验收问题

- 分析段是否仍能看出推论为什么成立、在哪里受限？
- 简短任务是否保持简短，长论证是否避免被无差别压缩？
- 中英混用和书面词是否服务概念，而非作为人设装饰？
- 删除作者层配置后，通用写作能力与其他作者是否保持不变？
- 示例和修订是否没有借入额外观点、个人经历或承诺？

建议用同一个合成任务分别测试作者层启用、关闭和受众改变三种情况，再由评审者检查差异是否来自表达方式，而不是事实或观点被擅自更换。
