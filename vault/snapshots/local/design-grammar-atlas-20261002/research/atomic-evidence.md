## 4. 用关系解释动效和材质

### 动效

Carbon 区分任务推进与重要时刻的表达，并把跨组件编排留给产品团队；它还区分进入、离开和仍在附近等待召回的状态。这可转为“什么变化向人说明了什么”的登记方式。其曲线、时长和禁用弹跳等要求属于 Carbon 的品牌与系统范围，不能原样提升为 Atlas 的普世 taste。[E09](https://carbondesignsystem.com/elements/motion/overview/)

可选提问：什么触发改变、对象间有什么时间关系、结束意味着什么、合同是否包含中断或反转、必要信息如何静态表达。只对实际宣称的状态提供证据。先判断意图与状态是否完整，再由 Opus 决定节奏、材料感与幅度。只看静态截帧不能证实动效流畅；本轮未观看 Carbon 动画，未作其实际时序质量判断。

### 材质

Apple HIG 把材质作为前后景、功能层和内容层的关系，并给出前景辨认失败的反例。其系统材质会受平台和设置影响；不能把视觉截图中的颜色当作稳定的材质定义。[E10](https://developer.apple.com/design/human-interface-guidelines/materials)

可选提问：材质服务哪一层；背景如何影响前景；必要边界与符号如何辨认；系统/媒介能力改变时是否需要等价表达。模糊、透明、纹理、阴影只是候选实现。可选择不透明平面、线或留白，只要能更好实现声明的关系。不得把 Apple 的原生适配保证转写成 CSS blur 的保证。

## 5. 自动可测与人评 taste 分开

| 证据层 | 可做的检查 | 不能据此断言 |
|---|---|---|
| 内容 | 字段完整、顺序/对应关系、溢出和截断是否违约、事实未改 | 信息层级优雅或有感染力 |
| 状态 | 初始/成功/错误/空态转换、交互可达、取消和中断有定义 | 每种状态的情绪或节奏合适 |
| 语义 | 可访问名称、角色、标签关联、键盘路径及约定焦点行为 | 自动规则通过即完全可访问 |
| 响应式 | 指定容器/缩放/长度下无未声明信息丢失；适用时检查 reflow | 任意媒介、任意宽度都成立 |
| 视觉回归 | 固定 fixture、环境与时刻的图像差异 | 新图必然更差、旧基线必然有好 taste |
| 人工判断 | 目的契合、阅读节奏、关系张力、过度装饰、风格解释是否有说服力 | 一个人的喜好就是永久标准 |

Storybook interaction tests 能把初始上下文、模拟行为与断言放入同一 story；官方建议优先用可访问角色/标签寻找元素。其 a11y 检查是启发式检查且有需手动确认项；因此手工键盘、屏幕阅读与真实任务评估不能被“绿灯”代替。[E03](https://storybook.js.org/docs/writing-tests/interaction-testing)、[E04](https://storybook.js.org/docs/writing-tests/accessibility-testing)

WCAG Reflow 的适用条件与二维内容例外必须保留；不要用“所有东西必须一列”替代标准，也不要把某个二维内容的例外扩大到整页。[E11](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)

视觉回归的价值是发现变化并要求判断。Storybook 的官方视觉测试流程需要人工接受或修正变化；其 Chromatic 路径会把 stories 发到云端。此处只借鉴方法，未授权接入服务、上传私有内容或购买订阅。[E12](https://storybook.js.org/docs/writing-tests/visual-testing)

人评采用“观察 → 对任务的影响 → 取舍 → 是否值得保留”的短评，不把“清晰/优雅/有趣/像某风格”编码成硬 boolean。对照评审可隐去 profile 名称，先看关系是否成立，再检查历史或风格主张，降低名称先入为主。
