## 6. 复用、回归与退役是主张的生命周期

以下是治理提案，并非从来源直接推出的固定流程：

- **登记**：有目的、关系、范围和证据；允许标记为待验证假设
- **局部可用**：在一个明确任务/环境中有实现证据；不要称通用
- **候选复用**：出现不同内容或不同载体的独立需要，且复用关系能说清；不是为了凑第二个例子
- **范围内复用**：语义和状态契约可保留，存在已知失败边界和回归 fixture；人评认可其仍有价值
- **修订/分叉**：关系目的变了、媒介假设变了、反例击穿适用范围，保留旧证据并说明替代关系
- **退役**：目的不再存在、重复关系被更清楚条目覆盖、依赖/许可不可用，或失败成本持续高于价值；保留原因、替代项和迁移提示

不规定“做满 N 个 demo 自动晋升”。回归优先保留最有辨识度的正常状态、边界状态和已发生反例；从依赖关系反向查受影响的 composition。DTCG 的 `$deprecated` 提供退役信息的工程先例，但 Atlas 的晋升标准和版本治理仍是本包提案。[E05](https://www.designtokens.org/TR/2025.10/format/)

## 7. 应主动记录的失配与反例

| 失配 | 为什么会发生 | 正确反馈位置 |
|---|---|---|
| 同名 profile 做出彼此矛盾的作品 | 名称隐含了多个历史解释或不同目的 | profile 范围和 evidence；不要先封死实现 |
| 孤立 atom 好看，真实内容失效 | 未验证组合、长度、语义和状态 | grammar / composition / fixture，而非只补 CSS |
| 同一 primitive 换语义就误导 | 视觉结构不等于角色、任务与交互 | recipe 的目的与 scope |
| motion token 相同但编排生硬 | 时长与曲线不足以表达对象间关系 | choreography grammar |
| “玻璃感”在背景变化后不可辨认 | 忽略背景、前景和系统设置的耦合 | material grammar 与降级表达 |
| 所有矩阵格都完成却没有新结论 | 数量替代了假设与观察 | 删减样例、重写问题 |
| screenshot diff 通过但任务不通 | 视觉与状态/语义证据被混同 | 独立状态测试与人评 |
| profile 固定跨媒介被理解为像素复制 | 固定了实现细节而非解释 | 媒介契约与新的 primitive 选择 |

## 8. Opus 的可复用边界

Opus 可以引用某条关系而不用整个 profile，可以组合多个 profile 的不同方面，可以提出新解释、替换 recipe 或拒绝本包分类。要求只在其实际做出的主张上成立：必要内容与语义不丢、媒介约束有交代、来源与原创推断可区分、反例不隐瞒。

研究登记并不替代打样者的判断。若一个条目主要让人填表、难以帮助提出更好的构成，先缩短它。若一个成熟组件方便实现但隐藏关系，可以拿它做样本，再把可迁移关系提出来；无需为了原子纯洁性重写组件。
