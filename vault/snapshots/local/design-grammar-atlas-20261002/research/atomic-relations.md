# 关系、粒度与少量对照

description：当需要解释profile/primitive/composition/recipe关系或选少量对照时，读相关小节；不是固定schema。

可选校订意见，2026-10-02。尚未实现demo或执行eval；只对实际宣称保留相应证据。由[方法索引](atomic-methods.md)按需进入，无需全读。

## 1. 六类对象可以怎样相连

下列是本包的工作性解释，不宣称为通用术语标准，也不要求所有项目使用全部对象。

| 对象 | 记录什么 | 不等于什么 |
|---|---|---|
| profile | 对一组构成倾向的有范围解释，含出处、张力和允许偏离之处 | 固定 palette/radius/font/motion 全家桶；唯一正确风格 |
| grammar | 元素之间、层级之间或状态之间的构成关系及其目的 | token 清单或组件类型 |
| primitive | 一次可操作的局部构成职责，如堆叠、对齐、分隔、反馈映射 | 必须只有一个 DOM 节点的 atom |
| composition | 在具体内容与环境下组织起来的若干关系 | 天然可复用的大组件 |
| recipe | 为某个目的选择、连接、取舍关系的建议，以及适用和失效条件 | composition 的完整快照或固定成品模板 |
| demo / specimen | 后续某次输入、状态、环境、版本下的实现与观察证据 | 一条普遍成立的规则；本轮现有产物 |

### 多对多与“可逆”的准确含义

- 一个 profile 可由多个 grammar 解释；同一个 grammar 可服务多个 profile，也可以不借助风格标签
- 一个 primitive 可实现多个关系；同一关系可用不同 primitive、媒介与技术实现
- 一个 composition 可包含多个 recipe 的局部建议；一个 recipe 可生成多种 composition
- 一个 demo 可同时支持某些关系、挑战另一些关系；同一关系需要的证据未必都是视觉 demo
- “可逆”指能从样例追溯到关系、出处与解释，也能从关系查到采用和挑战它的样例；**不是**说可以从像素唯一还原作者意图，或从 profile 唯一生成成品

可参考登记建议检查“目的、关系、范围、依据和自由度”是否说清；可合并、删减或改名，**不规定六字段 schema**。只在实际消费需要时结构化；也不另建必须逐级继承的原子 schema。先让任务 description 自然触发一个索引入口，再按问题展开相应条目，不要求 agent 先加载所有对象定义或完成全部研究。

一个合格的关系记录可以是：

> 关系：主区与辅区相邻时，主区保持完成任务所需的空间；可用空间不足时，允许邻接关系转为顺序关系。目的：保留辅助上下文而不压缩主体。范围：可线性阅读的内容；不直接套用于地图或需要二维比较的材料。自由度：比例、方向、间距和切换方式由打样者提出。反证：切换后阅读顺序或任务优先级丢失。

这个条目借鉴 Sidebar 的问题意识，但不复制其固定参数，也不把它规定为唯一实现。[E08](https://every-layout.dev/layouts/sidebar/)

## 2. 原子任务的颗粒度

可用一个问题判断颗粒度：**只改变这项关系，是否能描述预期观察以及可能反例？**

| 太小、失去目的 | 可登记的关系粒度 | 太大、难以归因 |
|---|---|---|
| “做一个 8px 圆角” | 角部处理怎样区分可操作与静态层，并与整体形态协调 | “做一整套温暖品牌 UI” |
| “时长设为某数字” | 反馈是否与触发动作对应；离场暗示暂时隐藏还是永久离开 | “做一个丝滑 dashboard” |
| “加 blur” | 前景控制如何与动态背景分层，又不损害辨认 | “做完整 glassmorphism 网站” |
| “字号改大” | 标题、论据和辅助信息如何建立阅读优先级 | “做杂志感页面” |

原子任务也不一定只允许一个变量。若若干量共同构成一项关系，可以一起改变，但要写清它们的耦合与结果归因。若拆分只剩互不相关的数字微调，应重新检查它是否仍有助于回答原问题。

如果后续决定打样，可用这些问题校订 brief：输入是什么；哪些可变；哪些必须保持；交付什么证据；如何评审；为什么值得做；哪些来源支持、哪些只是提案。四个可选研究切片见 [atomic-task-proposals.md](../briefs/atomic-task-proposals.md)。它们不是强制工作流；后续调协、执行与视觉判断交给 Opus，本轮不预设必须做满几个。

## 3. 两个正交方向，采用稀疏小矩阵

### A. 内容固定，改变 grammar

有真实任务内容时优先使用它；需要合成对照时可取 [F1 活动信息](../briefs/content-fixtures.md#f1-活动信息与编辑层级)。内容、信息身份及任务目的保持一致；不借换图、删字、改文案偷偷赢得视觉比较。

| 同一 fixture | 关系解释 A | 关系解释 B |
|---|---|---|
| F1 原始内容 | Opus 可提出一个层级与节奏解释 | Opus 可提出另一个真正不同的关系解释 |
| F1 已给定的长标题/长导语条件 | 若需要，观察同一解释的韧性 | 若需要，观察另一解释是否保留信息 |

这不是要求实现四张完成稿。先挑最有区分度的一对；只有当不确定性指向内容长度时，才补长内容状态。A、B 不预先等同某两个 style；可以组合、发明或替换 profile。必要时加入一个有诊断价值的失配反例。

### B. profile 解释固定，改变媒介

固定的是 profile 的**解释与目的**，不是相同像素或所有 token。可取 [F3 数量关系与未知](../briefs/content-fixtures.md#f3-数量关系与未知)，比较例如网页信息区与静态演示页；Q1/Q2 实际为 42/58，Q3 实际未提供、计划为 66，不能为了图形完整补成实际或 0。

| 保持的解释 | 网页信息区 | 静态演示页 |
|---|---|---|
| 已声明的阅读优先级与节奏意图 | 可重排、可滚动、存在交互状态 | 有固定画面与观看距离，操作提示需媒介化 |
| 必要事实与来源含义 | 保留可访问内容与操作语义 | 保留事实、标题关系与可辨认的来源说明 |

跨媒介可以重新选择 primitive、比例、密度及表达方式；不得把无法迁移的交互直接伪装成静态可操作控件。若为了适应媒介必须改变 profile 的核心解释，应诚实登记新版本或替代解释，不能仍称“完全同一个”。Every Layout 的原文与示意图可支持关系跨对象组合，但不能证明一种审美可无损跨所有媒介。[E07](https://every-layout.dev/rudiments/composition/)

两轴不要一次做成全排列。[F2 结果与操作状态](../briefs/content-fixtures.md#f2-结果与操作状态) 可在确有状态表达问题时替换为输入，保留总数 24、已完成 18、待处理 4、失败 2。新增一个样例的理由应是消除某个具体不确定性，而不是填满 demo 数量；本轮不执行该矩阵或 eval。
