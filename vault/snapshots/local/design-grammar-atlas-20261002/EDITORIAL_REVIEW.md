# Design Kit 校订意见

用途：当需要让Agent从任务自然发现并按需取用Design Kit时阅读。本文是本轮主交付；后续重构、多Agent分工与绘制由Opus决定和实施。

## 建议先做的三个改变

1. 让description说「何时用、解决什么、何时去别处」，入口先出现任务词，不先出现完整风格史
2. 让index提供可停下来的短路径：任务 → 少量候选关系 → 必要content；参考与样例有明确展开条件
3. 让content只解释足以作一次设计判断的关系、依据与边界，保留taste空间；profile、原语、recipe用交叉链接联结，不固定流水线

本次没有修改仓库、调协Opus或生成设计样例。已核查的远端版本和未见范围见 [只读体例审查](research/praxis-structure-review.md)。不能据远端旧入口断定用户本地没有Design Kit。

## Description 用任务触发

建议候选文案，可由Opus结合实际Kit改写：

> 为页面、文档、图表或界面选择和调整视觉构成；在需要比较版式、层级、字体角色、色彩分工、视觉语言或引用设计参考时使用。内容论证与必要排版由Write处理；对象、权限和状态事实回到相应契约；涉及有意义的时间变化时按需调用Motion。

这段文字只解决入口发现，不试图塞入八种profile、完整流程、全部禁令。风格名可放在profile索引，保留Swiss/International等别名；目标是让用户直接说“做Bauhaus方向”也能找到入口，这需要在实际宿主验证。若宿主仅暴露description而不读取index，需要由Opus在宿主适配时检查，而不是假定目录天然可发现。

[Agent Skills官方格式](https://agentskills.io/specification)要求description同时说明用途和使用时机，且把资源作为按需层；[原作者工程说明](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)建议从实际任务轨迹迭代name/description。它们支持分层披露，但不证明任何本地Kit或模型已获得可靠召回率。

## Index 做路由 不做第二本内容大全

建议保留五类入口词：

| 任务句 | 第一站 | 需要时再展开 |
|---|---|---|
| 这页层级不清 信息太挤 | composition、type、density关系 | 对应参考与内容变体 |
| 想探索某种视觉语言 | profile索引或直接关系 | 有来源的作品、反例与组合思路 |
| 要做图表 关系图或信息页 | 数量/关系语义与布局 | 原语、数据fixture与媒介边界 |
| 换成手机 印刷 中文或RTL | 适配条件与必须保持的语义 | 对应i18n、状态和可访问性依据 |
| 动效有帮助吗 怎样体现变化 | Motion入口或静态替代 | 时间关系、触发、降级与状态检查 |

这些是可试路由，不是新目录命令。正式index用当前项目的准确链接。每一行应该告诉Agent为什么点、能拿到什么、什么时候够了；不用先读完整Design史再开始任务。

误触发时，若任务实际只是改文案或核对状态事实，应停在入口并回到Write或对应owner，不继续展开profile。

## Content 以问题和关系为粒度

一条关系笔记至少让读者能理解：问题是什么；哪两个元素/状态之间有什么关系；在哪种条件下值得试；依据实际支持到哪里；哪里留给创造与反证。可用一段话完成，无需强制六字段表单。[登记建议](GRAMMAR_REGISTRATION_PROPOSAL.md)与[模板](templates/minimal-records.md)仅供Opus评估何种形状更易消费。

历史来源的trait、当前任务的硬约束、软先验和真实实验结果分开呈现。不要给每个style预装整套palette/radius/motion；也不要把某一款官方设计系统的数值升级成普遍taste。组合建议表达「这个关系在哪一层主导，另一个关系何时辅助」，比“风格A+风格B”更可用。

## 渐进式披露的结构取舍

- 入口只保留使用时机、范围与少量路由；细节停在被需要的文件
- reference链接旁标“为何看”，如查历史边界、检验某关系、看实际作品。不要让所有参考成为前置必读
- 示例索引区分“提议打样”和“已实现/已观察”。未做样例保留planned，不用漂亮名称伪装完成
- crosslink只连接真实决策：同一语义的另一媒介、相冲突的关系、相应owner。不在每页重复整张总图
- 归档保持稳定ID、替代指向和失效原因，但不与当前推荐并排占据首屏
- 若没有合适profile，回退到任务+关系；若没有证据，就写新提案并限定宣称，不硬凑一个流派

## 冷启动取用检查建议

以下是未来验证题，不是本轮已经运行的eval。Opus可在目标Agent、实际宿主与最终入口上少量试跑；只对真实断点补内容。

| 提问 | 希望建立的证据 | 应避免的误路由 |
|---|---|---|
| “把这页信息层级理清” | 从任务词找到局部关系即可开始 | 先加载八种历史profile |
| “做一点Swiss味 但别像海报” | 找到别名与媒介边界 | 等同固定Helvetica和12列 |
| “沿用风格改成手机” | 选择内容/行为适配关系 | 仅缩小画布 |
| “这张表需要动画吗” | 可以明确选择不用Motion | Design强制接Motion流水线 |
| “只改这段文案” | 留在Write必要路径 | 被Design大全抢占 |
| “样例适合复用吗” | 找到版本、fixture、实际观察与限制 | 把截图或计划当通过证据 |

可记：找到的入口、读取的文件、停下位置、错误加载/漏读、完成判断所缺的最小信息。阅读量是诊断，不是唯一评分；更少token却选错内容不算改进。

## 给后续重构的边界

保留现有唯一owner、已采纳/提案状态和迁移机制；重复的事实、状态和可访问性规则改为引用。目录只是承载方式，不应为了本包提案新建平行权威。先修实际冷启动断点，再决定是否值得机器schema、自动索引或更细目录。

八个profile及外部研究见 [研究地图](research/RESEARCH_MAP.md)。不需要一次全读。接手说明见 [Opus handoff](OPUS_HANDOFF.md)。
