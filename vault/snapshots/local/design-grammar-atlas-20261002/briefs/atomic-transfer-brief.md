# A02 · 同一解释，迁移主辅关系

description：当同一profile解释需要跨网页与静态媒介检验时，可选F3作为合成输入。

可选校订建议，尚未执行；不是排期或命令。由[brief索引](atomic-task-proposals.md)按需进入。Opus可合并、替换或放弃本切片；只对实际宣称提供适当证据，不预锁taste参数。

**问题 / 动机**

验证一个 profile 的解释能否在不同媒介中延续，而不是把固定像素整包搬运。挑出真正可复用的邻接、顺序、留白或对齐关系。

**输入**

Opus 选定的一段 profile 解释；[F3 数量关系与未知](content-fixtures.md#f3-数量关系与未知) 或真实任务内容；两种适合该内容的载体，例如网页信息区与静态演示页。F3 的 Q1/Q2 实际为 42/58；Q3 实际未提供、计划为 66。若两个载体承担不同任务，应先改写问题，不能假装同一目的。

**可变项**

primitive 选择、主辅位置、视觉比例、重排方法、字体尺寸、空间节奏和媒介化表达。可为两种媒介用不同的实现技术；recipe 只记录目的和关系，不打包成共用大组件。

**必须保持**

已声明的解释核心、必要事实与阅读目的；F3 不把计划当实际、不把缺失当 0、不虚构趋势或完成。网页的操作语义不可在静态稿中伪装成可操作控件；源媒介不适用的行为要标成转换或省去行为，而不删除其必要信息。

**交付**

一对足以说明关系保留/变化的样本，或指出不可迁移并提出替代解释；短记录：“保留什么、重新表达什么、哪项声明被反证”。无需先实现设计系统或 shared package。

**评审**

- 自动：网页侧内容完整、容器适应和适用的 reflow；静态侧必要文本与来源是否存在。不同媒介用不同检查，不强行统一
- 人工：解释是否仍能识别；主辅关系是否帮助任务；迁移是否为媒介服务；是否应登记新 profile 版本

**引用与限制**

[Every Layout Composition](https://every-layout.dev/rudiments/composition/)、[Sidebar](https://every-layout.dev/layouts/sidebar/)、[W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html)。作者示意支持关系再组合；不保证任何 profile 无损迁移。
