# career-kit

求职材料的单一工作仓库。简历、面谈准备、项目事实入口与投递记录各自维护；先按任务找到入口，再展开原文。

## 从哪里开始

| 当前任务 | 入口 | 继续读取 |
|---|---|---|
| 查看或修改简历 | [底稿目录](00-底稿/README.md) | 唯一文字源 → 编译 HTML / PDF / 网站版 |
| 准备面谈、处理开放问题 | [弹药库入口](10-弹药库/README.md) | 评价维度 → 叙事原子 → 临场路由 → 岗位侧重 |
| 演示合同 Workflow + AI | [LNG 定本](10-弹药库/地基/LNG合同全周期合成案例/README.md) | 八页 HTML + 点对点讲演稿；追问按需展开 |
| 制作企业汇报 | [企业汇报图式库](10-弹药库/地基/企业汇报图式库/README.md) | 阅读任务 → 图式 → 数据与视觉检查 |
| 补齐技术概念 | [技术扫盲](10-弹药库/技术扫盲/README.md) | 先通用栈，再读具体专题 |
| 核对项目能力或数据 | [项目索引](30-项目索引/README.md) | 指向各 repo 当前事实源 |
| 处理 JD、投递或面试档 | [投递入口](20-投递/README.md) | 市场信号与确认面试分开登记 |

## 文件责任

- `00-底稿/` 保存唯一简历文字源、编译器及产物。项目事实从 repo 流入，不从合成案例或岗位需求反写。
- `10-弹药库/` 保存可跨岗位复用的准备。地基是经历、案例与判断；技术扫盲是概念与取舍；内部机密目录按原披露纪律使用。
- `20-投递/` 保存岗位上下文和接触记录，引用通用准备，不建立另一份事实母本。
- `30-项目索引/` 只定位事实源，不复制 repo 文档。
- `_archive/` 保存被替代材料、研究原件和治理留痕，不参与默认召回。历史文件不作为当前操作指令。
