## 当前组织与消费规则（2026-09-15）

本节更新此前相同事项的约定。先读README，再按任务进入目录；不默认加载全仓。

- 面谈准备由`10-弹药库/地基/面试组织/`四份主文组织：评价维度、叙事原子、临场路由、岗位侧重。新Chat与本轮裁决优先，通用准备保持自足、可review；不新建巨型FAQ。
- 对外措辞与基本定位以简历唯一底稿为准。保护性、阶段性、核验与否等旁白不进入公开面；用准确行动与能力描述承重，保留必要术语与数字限定。

- 根目录原40-参考、未命名研究、第三方书籍及临时产物已退出活跃路径。旧文件移动保留原文和哈希，归档不等于删除。
- CLAUDE.md只指向本文件，目录README只承担入口，不重复项目数字。项目事实仍按repo→索引→底稿单向流动。

## 投递期分界（2026-07-18 定）

**2026-07-18 起为投递期，此前为调研筹备期。** 此前 18 条 JD 记账（见 `20-投递/市场口径校准台账.md`）是调研期市场口径校准的产物，作为历史保留在同一文件里，文件内以分界线标注阶段；投递期新记账续写在分界线之后。纪律不变（记账不改稿、信号过阈值才提修订案），变的只是阶段标签。

## 纪律

1. **数字限定词不许丢**：「约 1/3（受控实验）」不可写成裸「省 66%」；「两轮 6/6」不写「100%」。
2. **诚实边界显式标注**：阴性结果、缺口、未验证的环节照常写入，不省略。
3. **单口径单一文字源**（2026-08-19 重排：企业经历为信用底座，Courtwork 为产品主承重，Motto 为唯一 harness 身份与第二承重；历史 context / compaction 实验只作 harness core 证据，不形成研究线或公开入口）：简历只从 `00-底稿/简历-底稿-模块化.md` 编译，不在 HTML 里直接改文字；上游/下游只调投递物与首讲顺序，不再分版。旧双口径存档 `_archive/`（冻结 2026-07-12）。
4. **项目叙事走索引**：`30-项目索引/` 只做一页速查 + 指向，repo 内的 README / docs 是事实源，不在本仓库复制。
5. **数据单向流**：数字宣称只随项目新数据更新，顺序为 repo docs → `30-项目索引/` → `00-底稿/` → 编译，不许反向改。
6. **冻结即冻结**：曾用于 `40-参考/` 的这条纪律现并入弹药库通用规则——已标注冻结日期的文件不再编辑；如需更新，在活跃目录新建替代文件，旧文件留原处。
7. **机密分级不因合并降级**：`10-弹药库/项目展开-内部机密/` 内容（原 50-四层材料）永不入任何公开仓、永不 mirror；目录名本身即警示，文件头部纪律照旧保留，双重保险。

## 编译流程

2026-07-06 起改为脚本自动化（`00-底稿/build.py`），不再手动打印另存 PDF：

```bash
python3 ~/Projects/career-kit/00-底稿/build.py   # 一次产出三件：孙广昊-简历.html / .pdf / 简历-网站版.txt
```

Pipeline（2026-07-13 定稿）：**md 是唯一文字源，三件产物禁手改**。
1. 改文字只改 `00-底稿/简历-底稿-模块化.md`（PDF 层 / 网站层各就其位）
2. 跑 `build.py`：PDF 层 → HTML → PDF（分层 A4，页数服从内容；当前两页，扩展时增加版式页，不缩字删句）；网站层 → 原样导出 txt
3. 校验：限定词清单在 HTML 与 txt 双侧全过；PDF 文字与底稿 diff 零删改
4. 分发：PDF 投递 / txt 粘贴个人站；旧产物一律视为过期

build.py 已完成单目标改造（md → HTML → PDF 与 txt 一次产出），历史改造 prompt 存档于 `_archive/治理收敛-2026-09-15/退役材料/00-底稿/build-prompt.md` 供追溯。
