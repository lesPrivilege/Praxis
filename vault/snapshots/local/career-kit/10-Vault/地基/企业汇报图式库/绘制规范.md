# 企业汇报绘制规范

2026-09-14。通用规则唯一维护源。用于企业方案讨论、经营复核和案例宣讲，不规定特定行业、产品或技术架构。

先确定听众要判断什么，再列支持判断所需的对象、事实与动作，最后选择图式。图式的数量不是质量指标。资料没有支持的结论，不能通过排版、精确数字或图形补出来。

## 0. 先选页面任务，再选图式

| Slide Job | 阅读任务 | 常用候选 |
|---|---|---|
| Orient | 了解范围与全貌 | Panorama / Architecture |
| Explain structure | 理解对象、层级、系统关系 | Architecture / System map |
| Explain flow | 理解动作与责任交接 | Process / Swimlane |
| Explain change | 识别变化及影响 | Timeline / Variance / Before-after |
| Compare | 在共同口径下比较 | Bar / Table / Matrix |
| Decide | 根据依据选择行动 | Decision matrix / Evidence |
| Monitor | 查看状态、责任与下一步 | Operating review / Table |
| Prove | 追溯判断依据 | Document excerpt / Evidence |
| Evaluate | 判断质量与效果 | Quantitative chart / Control matrix |

选择顺序为 **Slide Job → Exhibit Family → Container → Notation**。九种样张是组合配方，不是九个互斥、穷尽的基础类别。比如Decide可用矩阵或证据对照，Explain structure可用大圆或分层；不因标题出现“平台”就自动画圆。

## 1. 页面层级

| 层级 | 职责 | 默认约束 |
|---|---|---|
| L0 画布 | 页面与章节环境 | 白或极浅灰，不包进 Card |
| L1 标题 | 判断或直接业务主题 | 左上第一行；不强迫所有标题写成结论句 |
| L2 主展项 | 本页主要阅读任务 | 通常占主体55–70%；仅一个视觉主语 |
| L3 辅助证据 | 例证、定义、局部记录 | 明显从属于主展项，不与其等权 |
| L4 元数据 | ID、版本、单位、来源 | 小字号、低权重；影响判断的状态不能降级到不可读 |

标题、展项标题、正文、元数据四级文字足够。主边界和辅助线分档；深蓝主结构、钢蓝次结构、灰色外围、amber风险。优先通过大小、位置、对齐和分组建立层级。

## 2. 容器语法

| 容器 | 边界 | 使用条件 |
|---|---|---|
| Open Section | 标题、间距与对齐 | 连续说明、架构主体 |
| Bounded Card / Frame | 完整细框 | 合同记录、版本、审批范围、系统边界、表格 |
| Raised Card | 无边框、极轻阴影 | 可以被独立讨论的方案、证据包、专业判断 |
| Tinted Panel / Callout | 极浅底色，通常无阴影 | 一组架构能力、政策、异常、特殊状态 |

一个 Card 对应一个语义对象。内部用标题、字段、字重与间距组织，不再 Card 套 Card。阴影只是独立工作对象的阅读提示，不赋予任何实际权限或状态。

## 3. Elevation

- Level 0：画布，无阴影。
- Level 1：分组与架构带，用浅背景或间距，无阴影。
- Level 2：独立对象，统一轻阴影；每页通常不超过1–3个。

常规阴影可采用 `0 3px 12px rgba(24,49,72,.08)`；强调档仅在明确需要时使用，不能成为默认。圆角0–6px；无玻璃、模糊、渐变、彩色投影和装饰图标。表格、控制边界不以阴影替代完整边界。

## 4. 与图式正交组合

Evidence + Card；Decision + Card；Architecture + Open；Chart + Panel；Table + Frame；Exception + Callout。图式决定回答什么问题，容器决定内容是否属于独立对象，二者不能绑定为单一组件模板。


## 5. 图形语义

- 边界表示范围或独立记录；只有业务真实存在交接、依赖或因果时才画箭头。
- 平台环是围绕核心对象的能力分组；统计环是整体占比；生命周期环必须有真实循环，不混用。
- 表格用于精确核对，数量图用于揭示差异，架构图用于界定范围，流程用于说明执行与责任。
- 状态色与阴影语义是本库设计约定，不是外部行业标准。边框不证明权限受控，阴影不证明对象可操作。
- 金额、时间、比率必须有单位、分母、基准与来源；合成设定和实测结果保持区别。

## 6. 生产顺序

1. 写出页面阅读任务与必须保留字段；选取既有图式或说明为何不足。
2. 将每页L1–L4和主展项画成灰盒；用Slide Sorter检查连续页是否重复同一种阅读动作。
3. 确认材料完整后填入业务内容，再应用容器、色彩与字体规范。
4. 实际渲染整页检查文字、线条、比例、状态与页间节奏；浏览器CSS词频不代替渲染检查。
5. 记录已验证实例与限制。通过一次实例不等于图式适用于所有业务。

## 7. 验收

主图是否回答页面问题；辅助材料是否抢占视觉主语；关系线是否表达真实关系；记录的版本/状态/责任是否保持；统计单位和分母是否清楚；是否存在文案旁白、卡片嵌套、无意义阴影；缩到投屏尺寸是否仍能读出主要字段。面积55–70%为选型起点，不作为删减必需信息或压小文字的硬指标。

## 8. 视觉记号

定量尺度、线条、状态、颜色与容器边界统一维护于[视觉记号](视觉记号.md)。

## 定本规则：数据性质决定表现形式

Diagram 负责结构，Chart 负责数量，Table 负责查数，Card 负责独立工作对象。数量图使用共同尺度、轴、网格、图例与直接标签，不使用进度槽组件替代柱图。分组百分比柱共用 0–100% 轴，构成比较使用堆叠柱，维度明细保留在表中。

普通结构、表格、外部系统用 1–1.5px 线；受治理边界用 2px；3px 仅用于极少数主边界。L3 不继承 L2 的重量。编号小标题可用粗体和间距，不默认铺背景。案例身份一次说明，数量页保留数据口径；生成方式与测量状态集中附录，不能将输入设定写成实测业绩。
