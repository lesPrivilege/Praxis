## Synthesis for the paper

**Verified pattern:** Across selected legal-information, records, provenance and data-catalog examples, information is made reusable by giving it identifiable objects, typed or shared metadata, relationships, lifecycle/version information and machine-readable interfaces. Retrieval systems also treat exact fields, lexical search and semantic similarity as distinct signals. This pattern is older than current Agent runtimes. It is visible in standards and vendor documentation, but the sources above cover separate domains and do not imply one universal work schema.

**Design inference:** Agent systems can consume that accumulated semantic work if the durable record remains distinct from the current model context. A stable owner and versioned Schema can express what an object is, its scope, status/time, relationships and provenance. Search indexes, chunk embeddings, summaries and a Run’s compiled context are retrieval/projection mechanisms that can be refreshed or rebuilt from governed inputs where the source system permits. The Schema constrains which objects and versions may be considered; lexical/vector search estimates relevance among eligible candidates; reranking orders candidates; Context compilation selects and labels material for a particular task. These are responsibilities, not a mandatory globally fixed pipeline order. Authority, access and temporal validity cannot be inferred from semantic similarity.

**Economic inference, not observed result:** If a recurring class of work has stable, high-value semantics, capturing and reviewing those semantics once can reduce repeated per-task interpretation and rediscovery. The investment pays only when reuse across tasks exceeds the cost of initial curation, ongoing version/permission maintenance, correction of bad metadata and retrieval/verification. The source set contains no cost data or Agent benchmark for this break-even claim. Preserve it as a mechanism and a testable hypothesis, not as a measured efficiency result.

**Portable-runtime inference, not compatibility evidence:** Standards and catalog interfaces show durable metadata made available to multiple information consumers; they motivate placing work meaning and its accepted state outside any single model call. They do not prove that a Work Contract survives arbitrary Agent/runtime replacement unchanged. That claim must remain aligned with PI-20’s compatibility boundary and be tested against the same versioned work semantics and outcomes.

## Scope, non-claims and open checks

- The strongest use case is a repeated class of work with stable, high-value fields and an identifiable owner. Unstructured and novel material remains searchable and may need human or Agent interpretation; it does not invalidate structured treatment of the stable subset.
- “Traditional systems already govern everything” is not supported. The examples cover selected legal-publication, records-management, data-catalog and search practices. Fragmented storage, duplicate copies, stale metadata, inconsistent permissions and missing relations remain possible; existing structure can be incomplete or contradictory.
- Legal standards, records metadata and data catalogs are precedents for durable identifiers, typed metadata, relations and lifecycle—not direct proofs that one legal/data ontology should be reused for matters, evidence, review or work commitments.
- Schema validity is not truth; provenance is not evidentiary support; a successful query is not scope authorization; a high similarity score is not authority; a compiled Context is not proof of completeness. These are already explicit boundaries in PI-18 and PI-21.
- No new experiment, retrieval benchmark, Courtwork product verification, cost study or user study was conducted for this snapshot. The existing Courtwork research packages are used as indexed source collections, not as evidence that Courtwork has implemented or accepted every listed mechanism.

**Minimal proposition for Astra’s adjudication:** Persistent, versioned and scoped work semantics can serve as reusable infrastructure for Agent systems, while retrieval ranks relevant material and Runtime-specific Context presents an authorized view of it. Stable semantics may amortize repeated interpretation costs across tasks and execution runtimes; the net benefit and migration compatibility remain empirical questions. Existing SE concepts—Schema, State, Authority, Evidence, Context Projection and the Runtime compatibility boundary—appear sufficient to express this proposition; this snapshot provides no basis for a new ontology or benchmark.
