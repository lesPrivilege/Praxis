# 从功能诉求到可审查的决定｜Claude Design 首次打样交接

请把“业务方已提出一个功能，研究者还必须判断什么值得做”变成第一次接触现场工作的读者能理解、讨论或操作的作品。你负责审美、形式与 taste 裁决，可以激进探索 Design grammar 和 motion。内容身份、决定边界及实际验收要求见下文；版式、颜色、字体、参数与镜头不预定。

**交接状态：原报告相关内容已与本机规范对齐，方法仍为项目候选。** 本轮只交付 Markdown 和合成输入，没有设计实现或视觉验收。后续制作与私下审阅由协调者安排；本交接不自行调用 Claude，不授权公开发布、外发、连接真实客户或发送催单。

## 真实沟通问题

功能诉求容易提前锁定研究方向：当运营负责人说“希望 AI 每天自动催未处理订单”，一份漂亮的方案或访谈题单可能跳过尚未作出的业务决定。此次作品要让证据改变下一动作的关系可见，并让补证、改方法、小范围试验和暂缓都成为可以解释的选择。

目标读者是准备进入陌生业务的产品、工程或研究参与者。读者应能指出：

1. 当前请求背后还有哪个决定没作。
2. 现有材料支持什么、不能支持什么。
3. 下一步为何可能是取证、改方法、小试验或不做功能。
4. 谁作决定，agent 的产物为何不能代替人的授权与证据。

这是本次沟通目标，尚未通过目标受众测试。Palantir 提供研究主题和有归属的现场经验语境；本次方法依据限于 Portigal 第二版第一章，不能包装成已验证的 Palantir 公司方法或全书总结。

## 方法卡：收到功能诉求后，先确定要作的决定

适用情形是业务方指定功能、访谈或短期 demo，却还不清楚证据要支持什么决定。最小产物是一页可由业务负责人和研究者复核的研究计划，或有依据的补证、改方法、停止建议。

### 一个可检查的关系

每个“要知道什么”都应说明它会改变哪个决定，以及何种材料可以支持判断。实际对参与者说的话是取证手段，不能直接替代研究未知。以下字段、状态与案例是本项目的操作化设计，不是作者原文 schema：

| 记录项 | 要回答什么 | 不合格的替代 |
|---|---|---|
| 本次决定 | 谁在什么边界内决定启动、改变、暂缓或停止什么 | 只写“了解用户” |
| 研究未知 | 哪些解释尚待区分，什么新信息会改变选择 | 只问“大家是否喜欢 AI” |
| 已有材料 | 来源、范围、时间、许可与缺项 | 把方案说明当用户证据 |
| 取证方式 | 哪种观察、回放、访谈、日志或试验能区分解释 | 先定访谈人数，再找理由 |
| 现场提问/动作 | 怎样取得具体经历或获准的工作过程 | 把内部抽象研究问句直接念给人 |
| 证据与推断 | 分开保存观察、当事人陈述和研究者推断，并附定位 | 将 agent 补全的原因写成访谈原话 |
| 下一决定 | 谁接收，材料还不能证明什么，怎样补证或停止 | 因访谈完成就宣告应上线 |

这些关系可反复调整，保留原问题及改动理由。不同解释可以共存，也不要求所有工作按同一线性流程进行。记录完整与决定/方法匹配分别判断；填满表格不足以证明研究计划成立。

### 人与 agent 的分工

人提供或确认可改变的决定、受影响者、允许接触的资料和负责裁决的人。Agent 在获准材料内提出最少的研究未知、匹配方法及当前方法无法回答的问题。人确认范围与专业边界后，再进行获准的研究。

Agent 可以整理来源定位、遗漏和互相冲突的陈述；不得假装访谈过人、补造观察或自行发送邀请。可以建议不做功能；业务决定由相应负责人作出。私密原件留在获准范围，通用表达不携带真实身份或原文。

Steve Portigal，Interviewing Users 第二版，2023，[官方 Chapter 1](https://rosenfeldmedia.com/interviewing-users-second-edition-sample-chapter/)：

- A High-Level Research Plan 区分业务问题、研究问题、研究方法与参与者提问；Aligning on the Research Plan 要求方法产出所需信息，信息服务待作决定，允许从不同入口开始。

## 可以直接取用的合成材料

**以下组织、角色、请求、陈述和演练记录全部为 synthetic 虚构材料。** 不是采访摘录、企业日志、真实授权或测量。合成标注须随内容进入成品。

### 初始状态 S0

运营负责人提出：“希望 AI 每天自动催未处理订单。”

当前待作决定：本周是否批准一个有边界的“减少订单等待”试点。现有证据只有请求本身；等待原因、提醒权限、收益与成本均未知。初始功能仍是候选。

### 材料 E0–E4

| ID | 合成材料 | 能支持什么 | 不能推出什么 |
|---|---|---|---|
| E0 请求卡 | 上述功能诉求 | 一名合成角色提出了请求 | 方案已批准、原因已知或已获发送授权 |
| E1 订单甲回放卡 | 经办人说还缺必填附件；演练记录的附件栏为空 | 这个案例有缺件证据，陈述与记录分别保留 | 所有等待均由缺件造成，或总体中缺件占多数 |
| E2 订单乙回放卡 | 附件完整；经办人说不知道下一位接手者；记录只显示前一动作结束 | 接手责任有待澄清，现有陈述与记录不能完整解释等待 | 直接判定遗忘，或证明系统没有任何提醒 |
| E3 约束卡 | 没有自动发信授权，也没有获准读取全部订单历史 | 当前动作与取证边界尚不满足 | 缺项已解决、可以读取全量记录或自动催单 |
| E4 替代做法卡 | 获准人员先整理缺件与待接手清单，再判断是否需要自动提醒 | 一项可讨论的人工方案 | 实测收益、已采用或比自动提醒更优 |

### 更新状态 S1

材料至少提示两种不同的等待解释；初始功能仍为候选。现在可以准备窄范围取证或人工试验计划，尚不能凭总体发生率作批量自动催单决定。

待补问题：谁接收下一动作？是否允许对应提醒？哪些对象与时间窗口形成可比基线？新增复核和操作成本怎样计算？缺项由谁补齐？这些答案仍未知，不能填成零、默认获准或已指定责任人。

### 取证与分支

研究未知包括：等待发生在哪个动作之前？可能涉及遗忘、缺件、未到审批、权限限制或尚未到处理时间。这些是待检验解释，不能作为已知原因或诱导式选项。

可在获准的最近案例中，请实际经办人回放状态变化、依赖与已有提醒。例如：“请带我看最近一次未按预期推进的订单，从上一个动作开始，之后发生了什么？”需要判断发生比例时，另找有分母与时间窗口的记录。

| 条件或新材料 | 可以讨论的下一动作 |
|---|---|
| 证据支持可避免的遗忘，提醒获授权且可验收 | 定义可比基线、成本和停止条件后，提出单类小范围提醒试验 |
| 证据提示审批、资料或接手依赖尚未解决 | 回到依赖与责任，先做获准的人工整理 |
| 没有取证权限或可用样例 | 明确缺项、影响与补件责任；不模拟真实结论 |
| 预期价值不足以覆盖新增复核与操作成本 | 建议不做该功能或暂缓；保留业务裁决 |

作品可允许补证后试行、人工整理或暂缓，不强迫唯一答案。可以增删合成材料强化表达，但须记录变动；所有候选比较时使用同一输入版本。机器可读材料见包内 fixture.json；单独阅读本文已包含完整案例。

### 必须保留的反例

“访谈五个人，四个人说愿意用，所以 80% 的订单可自动化”是**合成错误推理示例**。它混淆了受访者表态、总体比例与技术/组织可自动化边界。保留表态身份，不将这个数字画成采用率，也不据此执行外部动作。

容量规划、总体发生率和因果收益需要与问题相配的证据；少量回放或访谈不足以单独回答。必要时采用日志、计数、对照或其他方法，并由相应研究/业务专家判断。

## 准确性不变量

- 作者经验、作者建议、章节方法、项目推断、合成材料和未知分别标识；任何图形或语气都不能升级证据身份。
- 功能诉求、研究未知、现场提问、观察/陈述、推断和决定可辨认，表达可以突破表格。
- 访谈完成、意愿表态、实际采用、上线条件和经营收益各有证据；合成数字始终保留合成身份。
- 来源、对象、版本、范围、时间、单位和分母随改编保留；缺失与零分开。
- 关键条件、失败边界和停止选项在读者需要判断之前可见，不只出现在悬停、折叠、片尾或瞬时镜头。
- 业务裁决、资料权限与外部动作授权分别成立；按钮只模拟，不发送催单、不连接客户，也不从真实资料目录取数据。
- 箭头、位置、进入顺序与运动只表达有依据的关系，不暗示不存在的因果、概率、必经流程或确定性。
- 不因动效结束、导出成功或页面精美宣称理解改善、方法有效或业务收益；每项验收记录实际范围。
- 原 Chat、私人身份、真实客户数据、网页全文和完整书稿/PDF不进入作品；公开可读性不赋予全文再分发许可。

## 激进的视觉与 motion 探索

形式、taste 和审美取舍交给你。可以改变视角、密度、尺度、空间组织、字形、材料感、转场、节奏及交互机制；也可选择克制的文字形式。无需仿制公司品牌，不把某次历史样张的颜色、版式、卡片、玻璃面板、镜头或固定参数当作模板。

每个实际候选说明要解决哪项沟通困难。实质差异可以来自阅读动作、空间关系、证据组织或时间叙事；仅换色不足以形成新方案。候选数量随探索需要决定，保留可比较的替代方向及淘汰依据。

运动可表现状态、位置、关系或判断随材料变化；也允许明确的表现探索，须保持信息可读。界面检查真实状态同步、中断、取消、反向操作和减少运动替代。视频的镜头语言单独裁决。数值补间的中间帧是过渡；不要让它被读成观测，也不要让排序和数量变化混在一起。

## 依据沟通目的裁决媒介

形式是候选，不要求凑齐文件。可以提出表外形式；若选择多媒介，各自应解决不同沟通困难。

| 目的 | 可试形式 | 首要验收问题 |
|---|---|---|
| 亲手选择并理解证据如何改变下一动作 | 交互网页、可操作原型或情景推演 | 重选、证据不足和停止分支是否成立；反馈是否明确模拟 |
| 同时比较请求、未知、证据和选择 | 静态图解、展板、会议 Slides | 比较口径与条件是否同时可见；关系线是否有依据 |
| 深读方法、异议和来源 | 编辑式长文、PDF 或印刷样张 | 连续推理是否完整；限定能否回查 |
| 理解 S0→S1 的认知变化 | 动态说明、分镜或带旁白演示 | 驻留、节奏、暂停/重播、字幕和静音路径是否足够 |
| 找到缺口及下一责任 | 轻量索引或工作卡 | 是否保留未知与补件，而不假造完成状态 |

本机 Design 规范按 Foundations、Composition、Interaction、Motion 分支维护；时间叙事先明确每个 beat 的认知任务、文字、证据与必要声音，再决定运动。不预加载所有参考，不预设通用 renderer 或已验收组件库。

选定形式后，先固定内容与输入版本，明确使用者、合成身份、模拟动作、人工验收点、失败/返回/停止路径、接收者和未决责任，再创建实现。实际目录与最小文件集随作品决定。

每项验收保留对象、版本、日期、执行范围、证据和通过/未通过/未执行/不适用结果：

| 层面 | 必须实际检查 |
|---|---|
| 内容 | C1–C3、D1、E0–E4、S0/S1、选择和反例逐项映射到成品；来源身份与限定在改编后仍成立 |
| 静态 | 阅读最终导出或实际渲染的全部页面；检查目标尺寸、文字、表格、长标题、相邻关系和关键限定，保留样张与版本 |
| 交互 | 实际打开，走正常选择、证据不足、返回、重选和停止；检查键盘、焦点、适用窄屏及模拟动作边界 |
| Motion | 以交付速度完整观看，核对文字驻留、字幕、快慢节奏、音画关系、暂停/重播；必要时记录代表帧与时间码，单帧不足以验证播放 |
| 可达性 | 关键内容可通过颜色之外、运动之外和声音之外的表达取得；按目标情境实际检查缩放、减少运动或静态替代 |
| 理解 | 先由实际使用者或人工 review 判断表达是否准确可用；若要声称改善理解且证据不足，再选择适合的受众比较或留出。未做受众验证时如实写明，不将其作为打样开工关卡 |
| 代价 | 记录阅读/观看时间、交互负担、维护和导出成本，说明复杂形式带来的价值 |

若要求离线、打印或特定播放环境，则实际核对依赖与输出。失败项有定位、影响及修正/淘汰决定。当前只有 Markdown 内容与包结构检查，没有任何视觉、交互、播放或受众通过结论。

## 交付与复用边界

后续打样交付以下实际产物，规模随媒介决定：

- 能打开、阅读或播放的作品，相应源码或可编辑源文件、最小资源与运行/导出说明；依赖、字体、图像及权利边界有清单。
- 与版本对应的渲染样张、导出物或样片，以及真实看过成品后的验收记录。
- 实际探索的其他候选、关键差异与淘汰理由；不为“多变体”制造装饰副本。
- 简短设计取舍：目的、读者动作、grammar 与 motion 的作用，哪些是 taste，哪些保护内容语义，哪些仍未解决。
- 来源、内容映射与改编说明：保留、删改、新增了什么，为什么，读者因此看不到什么。
- 复用说明：可迁移的关系与检查方法、依赖场景的参数、素材/风格/节奏、权利及客户特有边界；后续验证与接收责任。

可复用发现只作为候选反馈。一次作品不自动成为通用组件、全局视觉规范或已采纳的 Palantir 方法。方法实际使用时记录任务、取用或绕过理由、成本、输出、错误和下一检查点；没有反馈前不升为默认步骤。
