# Praxis 独立架构 review · 2026-09-19

基线：`8ab22610d3eb91d7942ad498fa478bcb756369cd`。范围：工作图景、知识架构、grammar、应知内容、研究边界与长期维护。执行：本轮主代理独立审阅与编订；未调度或声称 Luna 已完成新研究。

完整修订文件及补丁见同名文档包；正文中的代码路径均以仓库根目录为基准。

## 结论

保留现有架构骨架，补强从外部工作期待到任务消费的连接。当前仓库已把“材料怎样保存、追溯和采纳”组织得较清楚；下一层应让陌生使用者知道“当前工作需要什么知识、什么条件下适用、怎样验证、谁接手、何时重访或退出”。

本轮采用工作全景、共同工作语法、现场闭环和研究问题清单，不增加顶层目录，不扩 runtime，不再建设一份厂商或来源百科。完整知识覆盖与小实现面可以同时成立。

## 主要发现及处置

### P1 · 常用入口没有形成完整工作链

依据：根 README 的任务入口侧重环境、demo、汇报、个人整理与材料查询；Kit 入口（`kit/README.md`） 原本按能力面排列；架构入口（`docs/architecture/README.md`） 重点是资料、裁决与实现依赖。发现、机会选择、采用、移交和退出之间缺少连续的规范入口。

处置：增加 工作全景（`kit/landscape.md`） 与 现场闭环（`kit/work-system/field-loop.md`），将根与 Kit 导航改为先回答当前任务。单独写作和个人整理仍可直接进入，不被迫执行完整客户项目流程。

### P1 · 共同 grammar 的约束强度不足

依据：原 grammar 入口（`kit/grammar/README.md`） 只有九问及简要说明。研究层 product-grammar（`vault/distilled/themes/product-grammar.md`） 已有丰富 UI、后端、流程和 AI 词汇，因此问题并非仓库“完全没有词汇”，而是跨域定义、组合、不变量与反例未形成常用规范。

处置：增加 work grammar（`kit/grammar/work.md`），连接工作项、对象、证据、规则、提议、决定、产物和影响；说明状态归属、授权、版本、结果未知、例外与交接。九问保留为企业工作面检查，不当作所有工作统一状态机。

### P1 · demo 验收与现场结果、后续运营之间缺少接续

依据：场景模板（`scenarios/_template/README.md`） 原本主要定义 worker、材料、AI 动作、review 和测量。组织接口（`kit/work-system/field-governance.md`） 已正确区分演示、采用、净减负及经营改善，也已有双账本；尚需将这些规则接到机会选择、试点、接收与后续责任。

处置：场景模板增加 baseline、非 AI 替代、条件、接收者和停止项；Verification 分开文档、知识、材料、系统行为、业务影响和运营条件；现场闭环补齐移交、扩展和退出。净减负公式与双账本不复制、不改口径。

### P1 · 演进机制偏重入账，消费者生命周期需要补齐

依据：evolution（`docs/governance/evolution.md`） 已有新材料、冲突、ADR、重访和修订记录；缺少明确的条目 owner/适用边界、下游兼容、固定版本消费、停止推荐及迁移操作。原 状态词表（`docs/governance/status-vocabulary.md`） 主要面向来源与采纳，不能单独描述能力的使用证据与实现情况。

处置：增加任务驱动增量、唯一维护位置、正反例、使用证据、兼容与弃用规则。保持原来源字段不变，不迁移 catalog；新增知识先用 Markdown 表达，不制造第二套机器登记系统。

### P2 · 应知范围需要成为可使用的能力地图

依据：企业拓扑研究（`vault/distilled/themes/enterprise-topology.md`） 已有系统与切入面，工作/汇报研究亦存在；但这些分散材料没有共同说明需要掌握多深、能够产出什么、哪些职责必须交给他人。

处置：以十二个知识面连接商业价值、业务发现、组织合作、企业拓扑、数据知识、AI 评估、集成、UX、权限治理、交付运营、沟通与个人环境。目标优先是识别、使用与评审，不自动扩张为全部实现职责。

### P2 · 晋升摘要容易被误用到所有文档

依据：ADR-002（`docs/decisions/002-promotion.md`） 已明确共享运行组件门槛及治理层例外；kit/Agent.md（`kit/Agent.md`） 原摘要没有重复限定“共享运行组件”，容易被独立阅读为任何知识都必须经过三个场景。

处置：只收窄摘要措辞，保留 ADR-002 的独立场景、contract、fixture 与验证要求。知识可以先解释或形成治理约定，现场效果另行验证；没有降低共享实现门槛。

### P2 · 生成器存在批次耦合，记录边界但本轮不重构

依据：build_registry.py（`scripts/build_registry.py`） 显式列出若干 intake 文件，并匹配 work-system 增量及 material-classification。此处并未判定当前登记错误，问题是新来源类别持续增加时，聚合逻辑会继续承担批次知识。

处置：在 evolution 规定显式输入登记、类别 adapter、生成物与人工内容分离的目标边界；下一新来源类别或生成器重构再处理。本轮不修改脚本，不重建来源卡或总账。

### P2 · 目录描述与现有用途存在小幅偏差

依据：根 README 原先把 templates 只描述成未来 demo 蓝图，实际 Reporting brief（`templates/reporting/README.md`） 已承担可用的写作入口。

处置：将目录说明改为任务/材料模板与未来 demo 蓝图；明确阶段、组织动作、呈现形式是独立维度，避免用一种目录或状态承载三类语义。

## 保留的架构决定

Goal 与六条第一性原理不变；Enterprise、Reporting、Work System 三个消费域及共享 Environment 保留。Kit 保存长期知识与契约，Skill 保持薄入口。研究与当前规范、组织 Source Vault 与 Kit 研究 Vault、工作状态与运行上下文继续分开。

保留 ADR-002、ADR-006、ADR-007、ADR-008 的边界；不重审既有发布材料，不改变“当前不存在企业数据”的基线。对 Courtwork 的运行实现仍是跨项目消费，不由 Praxis 文档宣布已交付。

## 外部参照的使用范围

[GOV.UK Service Standard](https://www.gov.uk/service-manual/service-standard) 将理解用户、完整问题、跨渠道、成功指标与可靠运营放在共同服务要求中。本轮借它校准工作覆盖，不将公共服务标准宣称为企业项目的强制要求。

[Diátaxis](https://diataxis.fr/) 区分教程、操作指南、参考与解释四种文档需要。本轮借它区分扫盲、任务、契约和理由，未建立四套镜像目录，也不将命名框架当成完成标准。

[NIST AI RMF](https://www.nist.gov/itl/ai-risk-management-framework) 将可信性与风险考虑放入 AI 产品的设计、开发、使用和评估。本轮据此复核责任与生命周期覆盖，不作任何符合性认证，也不把来源核查等同于系统风险验证。

以上是少量架构审阅参照，未补充或校验仓库来源索引；具体研究仍由问题清单路由。

## 语义演练

| 合成任务 | 检查结果 | 暴露的错误泛化 |
|---|---|---|
| 材料完整性复核 | 可定位对象、清单、证据、缺项、review 与下一站 | 未找到材料不能自动推出对象不合格；接受报告不等于批准业务动作 |
| 会议更新事项 | 可区分来源、候选变化、已确认状态与后续责任 | “可以考虑”不能登记成已决定；一次导入不能重复创建义务 |
| 试点结果汇报 | 可区分基线、实测、预测、质量、成本及 ask | 图表、演示或采用不能自动证明净减负与经营收益 |

这是本轮文档层的人工语义检查，没有执行模型实验、运行系统或真实业务试点，也未测量查阅耗时与现场改进。

## 实际交付与检查边界

交付为固定基线上的文档补丁与完整修订文件包。GitHub 连接可读取但没有写入动作；容器直接 clone 因无法解析 GitHub 主机失败，因此没有完整仓库 checkout，也没有远端 commit、push 或 PR。

已从连接读取原文件并按 Git blob SHA 验证其字节身份，再构建只包含被修改文档的局部基线。检查结果：

| 检查 | 结果 |
|---|---|
| 被修改原文件的 Git blob 身份 | 17 / 17 与远端返回的 Git blob SHA 一致 |
| 改动范围 | 17 份既有文档修订、6 份新增，共 23 份；无新增目录 |
| 补丁应用及重建内容一致性 | 在精确原文件构成的局部基线上 apply --check、实际应用、23 份字节比对及反向还原均通过 |
| 新增或改动的相对链接目标 | 117 处新增链接、34 个不同目标通过；68 处原有链接不在复核范围 |
| Git whitespace 检查 | git diff --check 与 git apply --whitespace=error 通过 |
| 来源记录、快照与脚本变更 | 无 |
| 全仓 validate_repository.py | 未运行；没有完整 Vault 与仓库 checkout |
| 外部索引复核、运行/业务验收 | 本轮未执行 |

相对链接检查使用已读取文件、远端目录树与修订文件，不重新验证旧索引。局部 patch 检查不等于完整仓库验收；应用到真实 checkout 后仍需运行原仓库检查。历史验收记录的数量与限制保持原样。

## 后续消费

本地应用修订后先运行原仓库验证，再按 研究问题清单（`docs/governance/research-agenda.md`） 选择有消费目标的任务。第一批优先补发现/机会/采用、数据证据到评估、移交与退出；不默认整表开工。

下一实现节点仍来自一个明确场景、可取得输入、可判断产物和实际责任人。工作地图用于提高起点，不把全部领域变成待开发功能。
