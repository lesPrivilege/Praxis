## 1. 问题定义：什么是 AI Slop？

**AI slop** 指大模型在缺乏审美约束时，收敛到训练语料统计中心的那一套可识别视觉默认值。它不是“写不出代码”，而是**看起来像代码，却没有人**。

社区共识中最常见的视觉签名（2022–2026 两波）：

| 时代 | 标志物 |
|------|--------|
| 2022–2024 | 紫→蓝渐变、玻璃拟态、霓虹 glow、dark + cyan |
| 2025–2026 | 同上 + cream/beige「品味默认」、Instrument Serif 斜体大标题、01/02/03 编号脚手架、em-dash 文案节奏 |

### 1.1 为什么会收敛？

Adam Wathan 2025 年自嘲：五年前 Tailwind UI 默认 `bg-indigo-500`，结果全世界 AI 界面变紫——训练语料被 demo 污染，模型学到的规则是「现代 = 紫按钮」。

LLM 不是设计师，是**模式匹配器**。你说「做个 landing page」却不给约束时，它填的是：

> 2019–2024 间 GitHub 上 Tailwind 教程的中位数

### 1.2 功能层 slop（比视觉更糟）

- 表单无校验、无错误态、无必填提示  
- 无焦点样式 / 无键盘路径  
- 占位图、空 `src`  
- 动画 width/height 导致 layout thrash  
- 文案是「Supercharge your workflow」一类空洞 SaaS 套话  

**视觉 slop 可被替换；功能 slop 直接伤人。**

## 3. 有品味个人站的共同结构（反 slop DNA）

跨站对照后，**好站共享一套「非模板」原则**，而不是共享一套皮肤。

### 3.1 内容架构：人 > 区块

| Slop 模板 | 有品味站 |
|-----------|----------|
| Hero + 3 Features + Pricing + CTA | 一段自我介绍 + 现在在做什么 + 作品/写作入口 |
| 「Full Stack Developer \| AI Enthusiast」标签堆 | 具体机构、具体产品、具体贡献 |
| Lorem / 空洞 value prop | 第一人称、可验证事实、可点击证据 |
| 项目卡 icon + 三行 | 案例叙事 或 链接到真实产物 |

**Paco**：Crafting interfaces → Building / Projects / Writing / Now  
**Delba**：正在找什么工作 → Work 列表 → Personal  
**Lee**：一段 bio → 最喜欢的文章列表 → 联系方式  
**Andy**：研究主张一段话 → 工作历史  

没有人在首页放「01 About 02 Process 03 Pricing」。

### 3.2 视觉：克制比正确更重要

1. **单一主色或近乎单色**，强调色只用于交互与焦点（Brittany 的 `#64ffda` 只点缀）。  
2. **字体有配对或有个性**，但不堆 4 套 Google Fonts。  
3. **间距有节奏**：相关元素紧、区块之间松——不是全局 `gap-4`。  
4. **圆角有上限**：卡片 4–12px，不是 24–32px 软 blob。  
5. **动效有目的**：页面进入 staggered reveal 一次够用；禁止 bounce 弹窗。  
6. **深色不是默认酷**；深色需要控制对比与 glow。  

### 3.3 工艺：材料即界面

Rauno 的原话（Lovers Magazine 访谈）：

> Work with the material. If you aspire to be really good at making websites, the materials you need to master are **HTML, CSS, and JavaScript**, not design or vibe coding tools.

Paco：

> Typography, motion design, copywriting, performance—the web is an endless medium…

**反 slop = 回到材料**：语义 HTML、可读 measure（65–75ch）、真实焦点环、可感知加载、性能预算。

### 3.4 声音：一个人的句子

Slop 文案节奏：em-dash 连打、aphorism（「Not a feature. A platform.」）、theater framing（「growth theater」）、buzzword。

好站文案：短、具体、可引用。

- Rauno 首页：*Make it fast. Make it beautiful. Make it consistent… Make it.*  
- Commissioner：个人引用 + 非设计语境的兴趣（车、猫、电影）作为人设材料  
- Maggie：*makes visual essays about programming, design, and anthropology*

## 4. AI Slop 反模式总表（设计层）

浓缩自 Impeccable（46 patterns）与社区共识：

### 颜色
- [ ] 紫/蓝渐变铺满按钮、标题、orb  
- [ ] dark + 霓虹 glow 当默认「酷」  
- [ ] cream/beige 当默认「品味」却无品牌理由  
- [ ] 渐变文字标题  

### 字体
- [ ] 全站只有 Inter / Geist / Space Grotesk / Instrument Serif（**无决策的默认**；Paco 历史版也用过 Inter，但有完整 token/节奏——禁的是偷懒，不是字本身）  
- [ ] 标题与正文同一字族、字号级差 < 1.25  
- [ ] 长标题用展示字号（整句 display）  
- [ ] 正文 all-caps 或 tracking > 0.05em  

### 布局
- [ ] Hero + 三等分 icon 卡片  
- [ ] cards inside cards（cardocalypse）  
- [ ] 侧边粗色条 rounded card  
- [ ] 01 / 02 / 03 编号 section 脚手架  
- [ ] 重复 uppercase kicker（FEATURES / WHAT YOU GET）  
- [ ] 全局等距 spacing  

### 组件
- [ ] 大 icon 容器 > 文案  
- [ ] 玻璃拟态无层级理由  
- [ ] border-radius ≥ 24px 小卡片  
- [ ] hairline border + 宽软阴影同时用  

### 动效
- [ ] bounce / elastic 弹窗  
- [ ] animate width/height  
- [ ] 图片 hover scale 默认  
- [ ] 到处 micro-interaction、无一处高冲击  

### 文案
- [ ] Supercharge / empower / world-class  
- [ ] em-dash 滥用  
- [ ] 反驳式短句套话  

完整检测清单见 [`../05-可执行工具/09-检测清单.md`](../05-可执行工具/09-检测清单.md)。

## 5. 反制策略（可执行）

### 5.1 流程：约束在代码之前

```
1. 一句话人设 + 禁止清单（字体/色/布局）
2. 选 2–3 个参考站，写下「为什么好」各 3 条
3. 定 tokens：色、字、间距阶、圆角、easing
4. 先写真实文案与信息架构（无 lorem）
5. 再让 AI 实现，并在 prompt 里贴 `05/10-Prompt工具包`
6. 对照 `05/09-检测清单` + 可选 `npx impeccable detect`
```

### 5.2 给 AI 的三维约束

来自 Anthropic frontend aesthetics cookbook + 实践：

1. **正向指定维度**：字体 / 色 / 动效 / 背景 各自一句话  
2. **参考审美语言**：「1970s ski lodge」「瑞士极简 + 运动」「日本印刷负空间」  
3. **显式否定默认**：No Inter, no purple gradients, no 3 icon cards  

### 5.3 人机分工

| 人 | AI |
|----|-----|
| 品味、参考、禁止清单、文案真实性 | 布局实现、组件重复、响应式 |
| 间距与字号最终裁定 | tokens 落地 CSS |
| 交互是否「有意义」 | 状态机骨架 |

**你没有品味时，不要让 AI「发明」品味——偷有品味的人的约束。**

## 6. 设计原则（反 slop 十二条）

1. **一个人的声音优先于设计系统演示**  
2. **禁止清单写在 tokens 前面**  
3. **字号级差 ≥ 1.25；measure 65–75ch**  
4. **强调色只服务交互与语义，不服务「好看」**  
5. **圆角、阴影、边框三选二，勿堆叠**  
6. **动效：一次编排的入场 > 十处 hover**  
7. **卡片不是默认容器；优先间距与分割线**  
8. **深色主题需要额外对比预算**  
9. **每个项目链接到可验证产物**  
10. **文案删掉后页面若仍「好看」——那是装饰站，不是个人站**  
11. **用 HTML/CSS 材料思考，而不是用 template 名思考**  
12. **迭代站点比重写皮肤更像品味**（Brittany v1–v4、Paco 多年 craft）

## 8. 从源码看到的技术选型倾向

| 站 / repo | 栈 | 设计要点 |
|-----------|-----|----------|
| pacocoursey/paco | Next.js, CSS modules/postcss, next-themes | 极简组件、暗色主题、cmdk 同源审美 |
| bchiang7/v4 | Gatsby, styled-components, anime/scrollreveal | CSS 变量系统、焦点环、mono 点缀 |
| brianlovin/brian-lovin-next | Next + TS | 产品感个人站、模块化 |
| leerob/leerob.io | Next + MDX + Tailwind | 博客模板清晰，内容驱动 |
| 多数 craft 站现网 | Next/Astro + 自研 CSS | **少用**「三卡片 SaaS 模板」依赖 |

**反 slop 技术启示**：

- tokens 用 CSS variables，不用散落 magic number  
- 焦点 `:focus-visible` 必须有（Brittany 的 dashed green 是教科书）  
- easing 用自定义 cubic-bezier，不用 bounce  
- 字体自托管或限制 Google Fonts 请求  
- 动效用 `transform`/`opacity`，不用布局属性  

详见 [`../03-范例档案/05-源码拆解与Tokens.md`](../03-范例档案/05-源码拆解与Tokens.md) 与 [`../05-可执行工具/11-Tokens与布局配方.md`](../05-可执行工具/11-Tokens与布局配方.md)。

## 9. 结语

AI slop 的本质是 **无约束时的训练分布采样**。  
有品味个人站的本质是 **有人决定什么不做**。

社区（X、设计工程圈、Agent Skills 仓）反复证明：

- 最好的参考不是「portfolio template」帖，而是 **多年迭代、开源可学、有写作或产品背书** 的个人主页  
- 最好的反 slop 工具不是另一个生成器，而是 **参考 + 禁止清单 + tokens + skill 约束 + 确定性检测**  
- 最好的个人站不试图证明你会 AI，而证明 **你能取舍**  
- 2026 的新事实：品味正在被 **编码为 SKILL.md 与 CI 规则**——但编码不能替代你选北星
