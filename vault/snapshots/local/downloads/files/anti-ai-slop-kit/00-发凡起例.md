## 一、本包何为

近年 coding agent 与 vibe design 普及，界面出现可命名的同质化：**AI slop**——并非「代码不能跑」，而是「看起来像统计平均的 SaaS 模板，没有作者、没有约束、没有业务数据」。

本包把两批散落在 Downloads 的调研材料 **修订合并为一份自足参考**：

| 原位置 | 并入后 |
|--------|--------|
| `Downloads/anti-ai-slop-design/` | 社区、个人站、Agent Skills、checklist、prompt |
| `Downloads/Design_Analysis_Report/` | 八站冷调拆解、清洗方案、法律工作台场景、截图证据 |

**不收录**（相关但属另一项目交付，勿与本包混读）：

- `Courtwork 设计语言定稿.zip` / `Courtwork-0.1.1-polish-plan.md` — 具体产品收束  
- `FD-1产品官网设计稿.zip` / `Schema工作面排版架构典范.zip` — 项目稿  

本包只立 **问题—原则—范例—清洗—工具** 之通例，产品定稿另册。

## 二、凡例（读法与用法）

### 2.1 三条公理

1. **Slop 是分布，不是审美失败**  
   无约束时，模型采样训练语料中位：紫渐变、Inter、三卡片、玻璃、bounce、cream+衬线 hero。

2. **品味首先是禁止清单**  
   有品味的站共享的是「什么不做」，不是共享一套皮肤。

3. **工具编码品味，不能替代北星**  
   Taste / Impeccable / Pro Max 等把规则装进 agent；**选方向仍是人的工作**。

### 2.2 阅读顺序（发凡 → 起例）

```
00 发凡起例（本文）
 │
 ├─ 快用（30 分钟内动手）
 │    05/12 AGENTS规则片段 → 05/09 检测清单 → 05/10 Prompt工具包
 │
 ├─ 先懂问题
 │    01/01 问题定义与原则 → 04/07 清洗方案四大支柱
 │
 ├─ 再看范例
 │    03/04 个人站档案 → 03/06 冷调科技站拆解（含截图）
 │    03/05 源码拆解 → 02/03 灵感目录
 │
 └─ 工具与生态
      02/02 Agent Skills 生态 → 05/11 Tokens配方
      场景参考：04/08 法律工作台推演
```

### 2.3 使用场景对照

| 你在做… | 打开 |
|---------|------|
| 个人站 / 作品集 | `03/04` + `05/11` + `05/10` |
| SaaS landing（vibe coding） | `02/02` 组合拳 + `05/09` + Impeccable detect |
| 高密度 B2B / 桌面工具 | `03/06`（Linear/Raycast）+ `04/08` |
| 给 agent 写系统提示 | `05/12` 全文贴入；细节用 `05/10` |
| PR / 上线审计 | `05/09` 打印勾选 |
| 建立 design system 检索 | `data/design_styles.json` + Pro Max（见 `02/02`） |

### 2.4 证据与数据

| 路径 | 内容 |
|------|------|
| `03-范例档案/evidence/screenshots/` | 八站页面截图（拆解报告插图） |
| `data/sites.json` | 个人站结构化清单 |
| `data/design_styles.json` | 风格条目数据（分析用） |
| `references/sources.md` | 来源与方法说明 |

截图为调研时点快照，现网可能已改；**原则比像素更耐用**。

### 2.5 弱信号过滤

降权或不采信：

- 模板推广、`DM for website`、无真实域名的 portfolio 帖  
- 只喊 kill slop 却满屏紫卡片的营销页  
- 仅 star 数量、无源码可审计的「设计 skill」广告

## 三、起例（本包所立通例，摘要）

### 3.1 AI slop 的可见签名（两波）

| 时代 | 标志 |
|------|------|
| 2022–2024 | 紫→蓝渐变、玻璃拟态、霓虹 glow、dark+cyan |
| 2025–2026 | 上列 + cream/beige「品味默认」、Instrument Serif 斜体 hero、01/02/03 脚手架、em-dash 文案 |

### 3.2 反制流水线（通例）

```
禁止清单 + 2–3 参考站 DNA
        ↓
tokens（色/字/半径/easing）先于页面
        ↓
真实文案与信息架构（无 lorem）
        ↓
Agent 生成（Taste / Pro Max / frontend-design 约束）
        ↓
确定性检测（Impeccable detect + 本包 checklist）
        ↓
人工 taste 门禁（动效是否有意义、数据是否真实）
```

### 3.3 工具三巨头分工（2026）

| 工具 | 约 Stars | 通例角色 |
|------|----------|----------|
| UI UX Pro Max | ~106k | 行业 → design system 检索 |
| Taste Skill | ~64k | 生成时硬 ban + 三旋钮 |
| Impeccable | ~47k | 命令改稿 + CLI 检测门禁 |

细节与源码路径见 `02/02`。

### 3.4 范例类型学（选型）

| 类型 | 代表 | 何时用 |
|------|------|--------|
| 排版极简 | Paco, Lee, Delba | 内容硬、工程师站 |
| Craft 细节 | Rauno, Emil, Josh | 设计工程师证明 |
| 冷调产品 | Linear, Vercel, Raycast | B2B / 工具 UI |
| 叙事拼贴 | Commissioner 等 | 真有材料时 |

档案正文见 `03/`。

## 六、一句话

> **反 slop = 有人决定什么不做 + 材料（HTML/CSS/JS）诚实 + 一个人的声音；  
> 工具把规则装进流水线，范例把品味变成可指认的像素与源码。**

从 `05-可执行工具/12-AGENTS规则片段.md` 开始贴进项目，或从 `03-范例档案/04-个人站档案.md` 开始训练眼睛。
