Phase B · 第一步 — Token 全值定案提案

選向：玄墨為基 · 儀器做殼 · 素白管 L2 容器紀律。 按層綁定視覺語彙——L0/L1 chrome 用儀器精度（清晰 1px 邊界、密度、幾何圖標、無襯線 chrome）， L2 沉浸層用玄墨排印（宋體卡面與正文、容器退場）。 本頁 = 完整 token 值提案（沿用現有名錄與三層結構，逐值給出，雙主題成對）+ 五條裁決策略 + 兩幀接縫證明。 確認後即成新硬約束，再鋪 atlas 全量 + 三前瞻頁 + 雙殼證明。

五條裁決（隨 token 一併確認）
  1. 硃砂 × danger 撞色解法（雙管）：accent 移相 32→38（偏朱紅）、danger 移相 28→15（偏洋紅深緋）並壓亮度，ΔH≈23 + 亮度/飽和雙分離；同時硃砂退出一切語義場景——它只做三件事：鈐印身份（icon、方章、詞標旁）、待辦/進行中數字（due、進度、streak）、當前位置（active tab）。評分行、錯題、警示永不用 accent。
  2. 行動＝墨：主行動鍵（開始複習、提交答案、記住）一律墨底紙字，不用彩色。「墨為體」落到交互上：最常按的鍵是最重的墨。評分行定為 重来=danger（洋紅）/ 困难=rate-hard（赭黃）/ 记住=墨 / 容易=good——accent 從評分行徹底退出，撞色場景直接消滅。
  3. 字體分類修訂（修 Commit 4 政策，需記錄）：--font-zh = 內容宋體（卡面問答、閱讀正文、卡組/文檔/章節名）；--font-ui = 全部 chrome 不分文種（值補入 Noto Sans SC，中文 chrome 標籤/按鈕/tab 隨之改無襯線）；--font-disp = 詞標 + 展示數字（Source Serif 4）；--font-mono = 真數據，政策不變。「內容 vs chrome」取代「中文 vs 西文」成為分類軸——這就是殼芯接縫的字體形式。
  4. L2 容器紀律（素白的貢獻）：複習/答題/閱讀會話的內容直接排在 --bg 上，不再 bg-card 套卡；結構靠髮絲線與菱點分隔。bg-card 容器保留給 L0/L1 的列表卡與面板。角標語彙（QUESTION/ANSWER/REVERSO）刪，「答」以硃印替代。
  5. 動效新增一檔：提案新增 --motion-slow: 420ms cubic-bezier(0.2, 0, 0, 1)（翻卡、圖表入場、進度填充），補 tokens 文檔 §5 指名的缺口；quick 120 / gentle 240 沿用。§5 那 17 處硬編碼在組件回遷時向三檔就近收斂。
