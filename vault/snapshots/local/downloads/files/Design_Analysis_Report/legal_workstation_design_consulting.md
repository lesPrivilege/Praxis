# Tauri 桌面法律工作台：UI/UX 深度审计与空间管理方案报告

致：项目研发与设计团队  
作为桌面产品设计顾问，针对该款 Tauri 桌面法律工作台（三栏架构：左案件列表 / 中对话+场景卡片 / 右多面板看板）当前面临的**“AI 生成感”清理**与**右栏 5 个工作面空间管理**问题，提交以下系统性审计与方案规划。

---

## 一、 「AI 生成感」 (AI Slop) 深度审计与清理清单

AI 生成的 B2B 界面（由 v0, Galileo, Midjourney 等工具直接翻译或启发而来）往往呈现出一种“静态看起来精致，动态和高载数据下极难使用”的视觉廉价感。

以下是针对专业法律桌面工作台的 **De-slop 审计清单**，按严重度由高到低排序，并附带针对 Linear/Stripe/eDiscovery 软件的专业修正方向：

### 1. 语义色泛滥与“彩色竖线过密” (Semantic Color Overuse)
*   **AI 表现**：在每个案件卡片、对话气泡或面板左侧，无差别挂载一条彩色竖边（蓝色、紫色、绿色等）。AI 误以为这能带来“清爽的归类感”。
*   **硬伤原因**：这耗尽了法律界面宝贵的“语义色预算”。当整屏都是彩色线条时，真正代表“高风险条款”或“关键修订痕迹”的红色/橙色标记会淹没在彩带中。
*   **修正方向**：**剥夺界面非核心区域的色彩。** 案件卡片等常态容器一律采用无色单像素边框 (`border-slate-200`)。彩色竖线只能在发生特定语义状态（如“该文档存在未解决冲突”）时作为指示器**极克制地**浮现，且宽度收窄至 `2px`，置于卡片最左侧。

### 2. “万物皆卡片”与嵌套地狱 (Nested Cards Overload)
*   **AI 表现**：界面中出现“背景上有卡片，卡片里套子卡片，子卡片里再套按钮框”的多重叠加。
*   **硬伤原因**：卡片边缘和投影（Box Shadow）会吞噬宝贵的屏幕像素，导致高密度的法律工作台一屏看不了几条法规。
*   **修正方向**：**扁平化结构，引入“网格线体系”。** 学习 Linear 或 Bloomberg，放弃卡片（Cards），采用一维扁平列表（List Rows）并以极细线 (`#e2e8f0` 或 `#f1f5f9`) 隔开。只在真正可以独立悬浮、拖拽的物理面板上保留卡片投影。

### 3. “Happy Path”式排版与长文本折行溃败 (Text Overflow & Wrapping Failure)
*   **AI 表现**：Mockup 中使用的文案都是“原告：张三”、“案件 A”这类极短文本。一旦遇到国内律所真实的案件名（如“关于某某集团因某某糾紛不服一审民事判决提起上诉案……”），界面发生排版错乱、文字重叠或大面积省略号。
*   **硬伤原因**：AI 生成的 CSS 缺乏对真实法律数据“长字符、多括号、中英混排”的防御性设计。
*   **修正方向**：对所有文本显示区域强制定义 `text-overflow: ellipsis`、`white-space: nowrap` (单行截断) 或 `line-clamp-2` (双行折行)；在表格中提供拖拽调节列宽的能力，并显式为长文本配备 Hover Tooltip。

### 4. 慢速、夸张的 Hover 动效 (Slow Hover Transitions)
*   **AI 表现**：当鼠标划过表格行、案件卡片或按钮时，元素以 `0.3s` 的速度平滑放大 (`scale-105`)，或者带出长阴影。
*   **硬伤原因**：这适合消费级或营销网站，在需要快速高频点击的生产力工具中，缓慢的动效会带来严重的系统“卡顿感”与操作粘连感。
*   **修正方向**：**数据区静止。** 表格行和卡片 Hover 响应时间设定为 `0s`（无过渡瞬间切换背景色，如 `bg-slate-50`），只做背景色轻微加深，不发生位移、不发生缩放，给用户最坚实、瞬时的点击反馈。

### 5. 纯装饰性的网格点阵背景与极光渐变 (Decorative Mesh Gradients)
*   **AI 表现**：在三栏面板背景或空白区，使用 AI 标志性的波浪渐变或灰度网格点阵（Dots Grid）。
*   **硬伤原因**：在需要律师长时间紧盯文本的工作台里，这些背景点阵和渐变会造成莫尔条纹视觉干扰，加速眼部疲劳。
*   **修正方向**：背景一律回归最质朴、无杂质的冷白 (`#ffffff`) 或冷灰色 (`#f8f9fa`) 哑光背景。

### 6. 不严谨的图标家族杂交 (Inconsistent Icon Families)
*   **AI 表现**：AI 生成的界面中，有些图标是双色填充（Dual-tone），有些是粗线描边（Solid Outline），有些则是拟物化图标。
*   **硬伤原因**：图标系统缺乏统一的视觉网格和线宽，显得极为业余。
*   **修正方向**：统一强制使用单一的高质感图标库（如全站 Lucide Icons 或 Radix Icons），线宽统一规定为 `1.5px` 或 `2px`，尺寸严格限制在 `16x16 px` (小尺寸) 或 `20x20 px` (大尺寸)。

### 7. 缺乏“焦点态（Focus-visible）”与键盘导视 (Missing Keyboard Focus States)
*   **AI 表现**：按 `TAB` 键或方向键无法在案件列表、搜索框及操作菜单间切换，或者切换时没有任何高亮的边框（Focus Ring）指示。
*   **硬伤原因**：AI 生成只注重“鼠标静态看”，忽略了专业系统极度依赖的键盘无鼠操作（Keyboard Accessibility）。
*   **修正方向**：为所有可聚焦元素写明 `focus-visible:ring-2 focus-visible:ring-slate-400 outline-none`。为左侧列表、对话框等核心操作区开发键盘导航支持（`↑`/`↓` 移动焦，`Enter` 选定），并提供键帽提示（如 `⌘K`）。

### 8. 空白状态（Empty State）的过度插画化 (Over-illustrated Empty States)
*   **AI 表现**：当右栏面板没有选择案件时，展示一张巨大的、色彩斑斓的 3D AI 人物插画。
*   **硬伤原因**：插画宣宾夺主，拉低了专业软件的严肃感（ToB 信任感）。
*   **修正方向**：空白页仅呈现一行简短的说明文字（如“选择案件以查看时间线与关系图谱”）和一个灰色的虚线框占位，配以一个直达操作的行动按钮（Action Link）。

### 9. 渐变色按钮与高饱和度按钮地狱 (Gradient/High-Sat Buttons)
*   **AI 表现**：页面上的“起草”、“导出”、“修订”按钮全部采用高饱和度渐变色（如紫粉渐变、亮蓝渐变）。
*   **硬伤原因**：视觉噪点过多，界面缺乏一个清晰的“第一优先级操作（Primary Call-to-Action）”。
*   **修正方向**：采用 Geist/Vercel 的单色硬朗按钮规范。常态操作按钮为纯白底、细灰边、黑字 (`bg-white border-slate-200 text-slate-900`)；主 Action 按钮采用极简的纯黑底白字 (`bg-slate-900 text-white`)，完全不带渐变。

### 10. 忽视“骨架屏（Skeleton Loader）”与瞬间闪烁 (Flickering Transitions)
*   **AI 表现**：数据加载时，界面突然从空白卡片闪烁出内容，导致眼球反复适应。
*   **硬伤原因**：AI 只渲染“加载完毕”的状态，忽略了数据加载中的中间态。
*   **修正方向**：定制与数据行等高的纯灰色骨架条 (`animate-pulse bg-slate-100`)，在卡片加载完毕时进行淡入过渡，消除突兀的白屏闪烁。

## 二、 右栏五大工作面空间管理对比 (限定宽度下)

右栏需要同时承载：**时间线 (Timeline)**、**关系图谱 (Graph)**、**矩阵表格 (Matrix)**、**docx 修订预览 (Diff)**、**起草画布 (Canvas)** 5 个极重的工作面，宽度十分受限。

以下是 5 种不同组织方案在 **35–55 岁非科技背景律师用户** 中的评估对比：

| 组织方案 | 适用条件 | 认知成本 (35-55岁) | 交互深度与学习曲线 | 桌面法律/金融软件实际先例 |
| :--- | :--- | :--- | :--- | :--- |
| **Tab 切换 (Tab Switching)** | <ul><li>界面宽度极受限</li><li>5 个工作面无需同步对比</li><li>状态相互独立</li></ul> | **极低**<br>(用户有强烈的“浏览器/文件夹”心智模型，完全无需解释) | <ul><li>路径浅</li><li>只需 1 次点击</li><li>无任何物理操作负担</li></ul> | **Bloomberg Workspace / Relativity**<br>口碑：极佳。经典稳定，律师对选项卡切换的接受度是 100%。 |
| **手风琴折叠 (Accordion Folding)** | <ul><li>每个工作面的内容长度极短（如仅几行摘要）</li><li>需要同时预览 5 个面的概览</li></ul> | **中等**<br>(若每个折叠面板内还有滚动条，用户会产生极强疲劳感) | <ul><li>纵向空间严重内卷</li><li>容易发生“滚动条套滚动条”的灾难</li></ul> | **Nuix Discover 侧栏过滤器**<br>口碑：一般。仅用于属性筛选，极少用于承载 docx 预览或矩阵表格等重度内容。 |
| **可拖拽分割条 (Draggable Splitters)** | <ul><li>用户有强烈的“对照阅读”需求（如看着矩阵填起草画布）</li><li>屏幕为 2K 以上宽屏</li></ul> | **中高**<br>(部分不习惯精确鼠标操作的律师，经常“拖不准”或“误操作将面板拖没”) | <ul><li>双面板/多面板对照的核心</li><li>支持任意调整主副视口比例</li></ul> | **Relativity Viewer / IDE (VS Code)**<br>口碑：好评。是专业法务进行合同比对、案卷分析时的绝对刚需。 |
| **无极缩放画布 (Zoomable Canvas)** | <ul><li>5 个工作面具有极强的空间拓扑关系（如思维导图式串联）</li></ul> | **极高**<br>(35-55岁非科技用户极易“在无限画布中迷路”，常出现“我的画布怎么变成一片白了”) | <ul><li>需要熟练掌握鼠标滚轮/触控板手势</li><li>空间定位成本极高</li></ul> | **Everlaw 视觉可视化地图**<br>口碑：两极分化。年轻律师喜欢，老合伙人极度抗拒，认为不如文字列表直接。 |
| **Overview + Detail (Minimap 导航)** | <ul><li>只针对单一庞大工作面（如超大型时间线、超大关系图谱）</li></ul> | **中**<br>(用户理解“小地图”需要视觉焦点在主图和小图间反复横跳) | <ul><li>仅用于长轴或二维大图的快速滑定位</li><li>无法解决 5 个异构工作面的排布</li></ul> | **Everlaw / TradingView 历史时间轴**<br>口碑：良好。在大图滚动中是必备辅助，但不能作为多任务的统合方案。 |

## 三、 资深顾问推荐组合方案：“Tabbed Dock + Draggable Splitter”

考虑到目标用户群为 **35–55 岁非科技背景的律师**，且工作内容包含 **docx 修订与起草**（需要深度对照阅读），**无极缩放画布（Canvas）和手风琴折叠（Accordion）应坚决被否决**。

推荐采用 **“双视口 Tab 轴 + 弹性分割条 (Tabbed Splitter)”** 的桌面级布局架构：

```
+-------------------------------------------------------------+
|                     Tauri 桌面法律工作台主界面                 |
+------------------+------------------+-----------------------+
|                  |                  |   右栏 (双视口弹性 Tab 面板)  |
|                  |                  | +-------------------+ |
|                  |                  | | Tab1(时间线) [Tab2] | |
|                  |                  | +-------------------+ |
|                  |                  | |                     | |
|                  |  中栏 (主对话)    | |       视口 A        | |
|  左栏 (案件列表)  |                  | |                     | |
|                  |  [ 场景卡片区 ]   | +===================+ | <--- 拖拽分割条 (Draggable Gutter)
|                  |                  | | [Tab3] Tab4(docx) | |
|                  |                  | +-------------------+ |
|                  |                  | |                     | |
|                  |                  | |       视口 B        | |
|                  |                  | +-------------------+ |
+------------------+------------------+-----------------------+
```

### 推荐设计细则与理由：

#### 1. 结构设计：右栏分割为“视口 A”与“视口 B” (上下/左右双视口)
*   **实现方式**：右栏内部默认不分割，全屏显示当前选中的工作面（如“时间线”）。但工具栏提供一个**“分屏”按钮**。点击后，右栏由中间的分割条一分为二，变成视口 A 与 视口 B。
*   **Tab 分组**：视口 A 头部承载 5 个 Tab 标签；视口 B 头部同样承载这 5 个 Tab 标签。律师可以自由决定在视口 A 打开“时间线”，在视口 B 打开“docx 修订预览”。
*   **理由**：这完美解决了律师需要**“一边看 docx 预览，一边写起草画布”**或**“一边看时间线，一边查矩阵表格”**的典型并行工作模式。

#### 2. 分割条体验：带物理吸附的单像素分割线 (Responsive Gutter with Snapping)
*   **设计细节**：分割线采用最简单的灰色细线（`1px solid #e2e8f0`），但在鼠标悬浮时变为 `4px` 宽的抓取条，显示拖拽手势。
*   **吸附机制**：分割条支持三个物理吸附点：`30/70`、`50/50`、`70/30`。当用户拖拽至接近这些比例时，自动吸附，避免手部不够精确的年长律师反复微调。
*   **快速关闭**：在分割条中间提供一个微型的“向上/向下收起”箭头，点击直接关闭分屏，让操作面瞬间最大化。

#### 3. 终极逃生舱：“一键最大化”布局模式 (Maximized Workspace Gate)
*   **设计细节**：每个工作面右上方均提供一个“最大化 (Maximize)”按钮。
*   **动作细节**：点击后，工作面会瞬间**覆盖中栏与右栏**（甚至隐藏左栏），将软件从“三栏对话模式”切换为“沉浸式数据编辑器”。
*   **理由**：针对“关系图谱”和“矩阵表格”，右栏的局限宽度（哪怕折叠左中栏）是绝对不够的。当需要深度查看复杂的案件事实网络图谱时，必须提供一键进入大视口画布的通路，而“Tab 面板最大化”是最容易被非科技用户理解的心智。
