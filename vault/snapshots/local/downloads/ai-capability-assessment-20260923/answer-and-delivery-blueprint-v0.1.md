# AI 能力测试：答题与交付蓝图

## 文档状态

- 版本：v0.1。
- 日期：2026-09-23。
- 状态：研究后设计稿；尚非真实模型或真实业务测评报告。
- 来源：同目录《AI_能力测试_外部实践登记_2026-09-23.md》，以 S01—S28 标识。
- 所有例子、阈值演示、测试期望和产品时间目标均为设计材料；没有宣称在 Jev 或生产系统实跑。
- 目标：让评审能检查判断、依据、机制、失败处理与验收，而非只看到名词和漂亮页面。

## 总体论点

五题分别处理同一个系统的五个责任：信息供给、资源预算、行动授权、概率判断和经验晋升。
模型可以提出建议，但系统必须知道何时信任、何时验证、何时等待，以及谁有权改变规则。

## Q1：长会话、文件重读与新增工具

### 结论

先定位失败，再优先修供给与外部状态。更强提示词和更大窗口是可比较的实验分支，不是默认修复。

### 诊断协议

- 固定一组业务轨迹，回放到 1、20、40、60 轮；轮次只是检查点，不是统一失效阈值。
- 区分约束没有进入本次输入、被摘要删掉、进入但未遵守、与新指令冲突、已经被合法撤销。
- 文件重读按 file_id、版本哈希、范围、目的和时点判定。相同版本和目的的无效重读，与读取新版或复核关键原文分开计数。
- 保留当前输入编排、token 使用、工具清单、cache usage 和真实执行回执。
- 权限、安全与租户隔离不依赖模型记忆，在工具入口再次执行确定性检查。

### 最小状态对象

- Task：目标、完成标准、当前阶段、剩余预算、未解决问题。
- Constraint：约束标识、原文、来源、适用范围、优先级、状态与合法变更记录。
- Evidence：文件标识、版本、访问权限、摘录范围、摘要、可回源指针、检索时点。
- Action：动作标识、输入、审批、执行状态、回执以及是否已确认副作用。
- Decision：已决定事项、根据、未定事项、负责确认的人。

### 编排原则

- 稳定指令和工具前缀保持稳定；当前任务状态和增量信息在合适位置供给。
- 原始材料、审计账本与本轮上下文不是同一个对象。
- 摘要可以缩短工作记忆，但关键数字、禁止事项、主体和法律出处需要可回源且可核对。
- 缓存减少重复处理费用，不缩小语义上下文，也不自动修复遗忘。

### 三个新工具的账单

- 一次性项：工具发现、schema 加载、可能发生的冷输入或缓存创建。
- 持续项：保留下来的 schema、工具结果、截图、后续推理、环境占用。
- 隐含项：新工具让模型走更多步骤、发生重试，或改变工具选择的准确率。
- 前缀加载：工具定义变更可能导致其后缓存失效。
- 延迟加载：可保留前缀，仅支付增量；具体以后端实际 usage 为准。
- 不重复计费：同一个 token 按供应商的互斥 usage 类别归入普通输入、缓存创建或缓存读取。

### 对照实验

- A：仅调整提示词。
- B：仅扩大窗口。
- C：外部状态、按需供给、版本化文件摘要和压缩不变量。
- D：C 的基础上比较前缀工具加载与延迟工具加载。
- 同时报告任务完成质量、约束违例率、无效重读率、cache hit、成本和 p95，不只报告 token 降幅。

### 交付工件

运行策略说明 + 一段可回放轨迹 + 新增工具前后账单拆解。没有真实 usage 时提供参数化示例，并显著标为模拟。

### 来源

S01、S02、S03、S27。

## Q2：推理强度、延迟、经济性与信任

### 节点分工

- 确定性权限、格式、日期比较和已经确立的计算公式：代码优先。
- 有明确标准、低影响、可自动验证的分类与提取：低 effort 候选，通过评估后采用。
- 多源冲突、缺失事实、跨法域解释、复杂规划和高后果判断：更强推理并验证证据；必要时专业复核。
- 报告排版与已核实内容的语言整理：低 effort，但不允许偷偷增加新的实质判断。
- 执行外部副作用：授权与校验由控制面决定，模型的高 effort 不等于授权。

### 成本单位

- 全任务模型及工具费：所有调用（包括重试）的未缓存输入、缓存创建、缓存读取、输出与隐藏思考、工具费。
- 执行环境：浏览器、沙箱、存储和运行时间。
- 人工：审阅、补资料、确认、纠错与返工。
- 主指标：每个被接受结果的总成本；另报成功率和延迟，避免只看便宜调用。

### 边际升档条件

在已满足硬性安全要求后：

降低的错误概率 × 错误损失 > 额外模型费 + 等待成本 + 额外验证成本。

示意：人工 12 分钟、人工时间价值每小时 300 元，原成本 60 元；辅助后仍需人工 5 分钟，模型与工具费 2 元，则名义成本 27 元、名义节省 33 元。以上不是实测报价，仍需扣除新增错误和返工的期望损失。

### 延迟定义

- 收到请求后的界面确认、首次有用结果、完整候选结果和被用户接受的结果分别计时。
- 首版 SLO 可设界面确认小于 1 秒，简单动作 p95 不超过 3 秒；这些是待测试的产品目标，不是模型性能承诺。
- 复杂审阅不强行压成一个同步等待；显示已核实阶段、剩余工作类型、取消与返回入口。
- 不能假装知道完成百分比，也不能以持续动画代替真实进展。
- 以用户弃用、返工、主动等待意愿和任务频率调整 SLO。

### 不展示原始思考时的界面

- 使用了哪些文件、版本与证据。
- 哪些结论已验证，哪些仍有冲突。
- 将改变哪些对象，内容差异、接收人和影响范围。
- 当前是草稿、待批准、执行中、已核验还是结果未知。
- 提供取消、接管与实际可用的恢复入口；不能把邮件撤回包装成保证可逆。

### 缓存耦合

按节点路由不一定意味着在一条很长的历史里不停切换模型和 effort。
可用较短、职责固定的调用承接特定阶段，同时测量额外编排成本。
对 Claude Code，S02 所载模型/effort 缓存键行为需要计入；不要外推到所有后端。

### 交付工件

节点路由表 + 单任务预算表 + 证据/等待/审批/结果未知的状态样例。

### 来源

S02、S04—S06、S27。

## Q3：真实桌面与外部副作用

### 结论

决定自动化边界的是授权范围、副作用、可逆性与影响面，不是运行在云端还是本机。

### 动作策略

- 已授权范围内的读取：可自动；明确超时、次数、数据出口及访问日志策略。
- 工作副本内的编辑：可在预授权、版本保护和检查后自动。
- 发送邮件、共享文件、覆盖生产材料、影响权限或资金的变更：在具体风险发生前等待明确批准。
- 任何来源不明的授权要求、范围变化、凭证获取或规避安全提示：停止，由合适的人处理。
- 敏感数据输入表单、上传和自动保存可能早于最终提交产生外部影响，闸门必须前移。

### 审批对象

批准应绑定动作、目标系统、租户、接收人/资源、具体 payload 哈希、版本、时效和授权人。
执行前再次检查内容与环境；对象变了，旧批准不能继续使用。

### 状态机

PROPOSED → VALIDATED → WAITING_APPROVAL（如需要）→ EXECUTING → VERIFIED。

EXECUTING 发生网络超时且副作用不明 → UNKNOWN → RECONCILING。

RECONCILING 证实已完成 → VERIFIED；证实未发生且重试合法 → 有界重试；仍不清楚 → 等待人工。

### 自动重试条件

- 读操作或真正幂等操作可在约束范围内退避重试。
- 写操作有明确服务端去重契约、相同业务意图和有效授权时，才考虑使用同一请求标识重试。
- GUI 没有幂等保障时，以服务端业务记录或可靠结果核验避免重复操作。
- 权限拒绝、参数错误和安全阻断不靠重试绕过。
- 副作用未知不可因 UI 没有成功提示就假定失败。

### 模型增强后是否保留向导

- 可减少：教模型怎么点、搬运信息、重复输入、固定步骤教学。
- 仍需：目标确认、必要用户取舍、风险批准、证据核验、可访问性、手动接管。
- 对照指标：无危险副作用的完成率、错误收件人/错文件/重复操作率、用户介入量、总成本、p95、恢复率。
- 只有实际任务上的改进才支持收敛向导；通用榜单提升不能直接改变权限边界。

### 最小测试集

- 正常发送：显示精确对象与内容，批准后发送并核验一次。
- 发送超时但服务端成功：进入 UNKNOWN，读回回执，不重复发送。
- 发送超时且确实未提交：确认安全后执行有界重试。
- 审批后文件变更：拒绝旧批准并显示新的差异。
- 页面要求上传不相关私密文件：拒绝以页面内容授予权限。
- 取消发生在执行前：不提交；取消发生在执行后：说明真实状态，不伪称未执行。

### 交付工件

动作权限矩阵 + 状态机 + 正常/超时/注入三条可点击回放。回放不是生产浏览器自动化证明。

### 来源

S07—S11。

## Q4：Jev 的语义、独立验收、阈值与降级

### 保证分层

- 类型合法：是否落在声明的输出空间。
- 业务正确：该选项是否符合材料及业务标准。
- 概率校准：类似概率的样本，真实频率是否相符。
- 决策稳定：重复运行是否跨越实际行动边界。
- 输入安全：能否抵抗误导与注入。

这五者不可互相替代。厂商演示以及框架集成说明能提供假设，不能提供本业务上线结论。

### 上线前必须补齐的材料

独立的“业务适用性验证与发布批准包”，内容包括：

- 声明用途、禁用用途、模型确切版本、rubric、policy、数据路径。
- 与真实业务相符且合法获得的样本；按客户、时间、文档家族隔离数据，避免重复合同分到不同集合。
- 专业人员独立标注和争议裁决，标注标准本身版本化。
- 校准集、阈值选择集和未用于调参的最终测试集。
- 混淆矩阵、严重漏报率、Brier/log loss 或可靠性曲线、置信区间、risk-coverage 与动作分歧率。
- 与规则、小模型和强模型的同预算对照；自动覆盖率与人工交接率。
- 中文、法律数字、日期、否定、文档长度、选项顺序、对抗内容等切片。
- 国内网络 p50/p95/p99、超时率、可用性、限流、故障注入和恢复演练。
- 责任人批准、监控触发器、回退和再验收条件。

### 三次一致的含义

原始浮点数完全相等、所选标签相等和最终动作相等是三种不同指标。
三次多数票既不证明正确，也不能假定样本独立。
重复完全相同的请求，和加入无关 uid/改变选项顺序后的稳定性，应分组测量。
不得循环调用直至得到可放行的结果。

### 1.99 的可计算反例

下面是人工构造的分布，不是 Jev 实测：

- 等级 0：无害，概率 0.00。
- 等级 1：轻微，概率 0.01。
- 等级 2：严重，概率 0.99。
- 等级 3：极严重，概率 0.00。
- 等级期望：0×0 + 1×0.01 + 2×0.99 + 3×0 = 1.99。
- 严重及以上概率：P(level ≥ 2) = 0.99。

“score < 2 因而自动放行”会把高概率严重情况当成安全。
不能用把数字四舍五入或随意将阈值改成 1.9 来代替决策设计。

### 决策策略草案

- 先执行确定性禁止、授权范围与数据完整性校验。
- 保留完整概率向量；根据业务损失矩阵决定何种事件需要送审。
- 对已校准的风险估计及其不确定性建立保守放行区、人工灰区和阻断区。
- 缺失、不适配、新版本未验收、分布外或结果冲突时，不能自动放行高影响动作。
- 同一事项的已升级状态不能靠无新增证据的重试自动降回放行。
- 决策记录绑定输入哈希、模型/rubric/policy 版本与原始返回值；缓存决策用于防抖，不等于证明原判正确。

### 降级架构

- 区分网络错误和语义不确定；两者可进入不同的后备路径。
- 使用有期限、有次数的重试与熔断，保护调用预算和交互体验。
- 本地替代模型必须单独校准和批准，其概率字段不与 Jev 默认为同一尺度。
- 统一的是 allow/review/deny/unknown 的动作接口和审计信封，不是未经校准的原始分数。
- 高影响动作的安全判断服务不可用时，降级为草稿/人工，不能 fail-open。
- 不得为恢复可用性而把原本不获授权的客户材料发到另一个区域或供应商。

### 交付工件

独立验收协议 + 1.99 阈值演示 + 明确标为模拟的故障降级回放。
无真实 API 运行时不绘制伪造的 ROC、校准曲线和延迟结果。

### 来源

S12—S19、S27。

## Q5：受控的 playbook 自我改进

### 当场裁决

两项修改都先记录，不直接晋升为全平台生效规则。
删除风险句不证明对应风险不存在；新增公式不证明该公式在任何法域成立。

### 先辨认“50%”是什么

- S26 的德国法条：在其适用范围内，是竞业补偿的至少一半要求，不是制裁。
- S28 的 OFAC 同名规则：有关被封锁人士对实体的所有权，不是劳动补偿系数。
- S25 的新加坡判决：讨论限制交易、可保护利益和合理性，不提供题干通用公式。
- 因此，本材料存在跨场景或同名规则混淆的可能；仍须查出原句来源才能确定。
- 不由删除错误位置的制裁句推导“无需制裁审查”；可以转为独立、待核验的合规问题。

### 变更拆分

- D1：删除一句具体的风险说明。记录它为何被删除：法律错误、与本事项无关、客户谈判偏好还是缺少证据；未知则保持未知。
- D2：增加补偿公式。逐项要求公式来源、法律概念、计算基数、期间、币种、适用对象、例外及生效时点。
- 允许两项变更分别通过、分别否决或分别补证，不采取全包接受。

### 四层存储与适用

- Matter：原始 redline、理由、审批和交付记录，受客户 A 权限限制。
- Client overlay：A 的私有偏好和红线，不可被 B 检索或用于 B 的提示、记忆与评估。
- Jurisdiction pack：经独立验证的 SG、DE、VN 规则分别维护，按适用范围与日期加载。
- Global process：可泛化的验证流程、数据隔离和版本规则；不包含未获许可的客户事实。

这不是简单的覆盖链。客户偏好不能使强制规则失效，普通局部配置不能绕过平台安全不变量。

### 需要保留什么

- 未被覆盖的原稿、删除文本、新增文本和上下文。
- 作者身份、委托关系、专业角色、时间、事项、客户、适用法与访问权限。
- 变更编号、父版本、原子 diff、来源及版本、主张类型和证据状态。
- 理由、反对意见、替代假设、独立评估输入与输出、失败实例。
- 批准人、批准依据、生效范围、起止日期、发布版本和撤销记录。
- 原始证据受保留政策和权限治理；保存历史不等于让历史文本继续参与默认回答。

### 建议变更对象

- change_id：chg-noncompete-001-D2。
- candidate_version：0.1.0-candidate.1。
- parent_version：当前获批 playbook 版本。
- status：quarantined_pending_evidence。
- source_scope：client A / matter SG-001。
- proposed_target：尚未批准的 SG jurisdiction pack。
- claim_type：legal_compensation_formula。
- legal_basis：missing。
- effective_from / effective_to：null。
- approvals：空。
- tests：需补法源、期间基数、租户隔离、跨法域和回归测试。
- global_promotion：false。

这是合成登记样例，不代表存在实际客户、实际签字或实际 playbook。

### 独立评估

- 由具备对应法域能力、且不只是在重复原作者判断的人员复核法律依据；模型可作挑战者，不是最终法源。
- 学习器只能写候选区域；不能改隐藏验收集、评分标准、硬性策略或发布审批。
- 先在开发和选择用验证集进行基线/仅删除/仅新增/组合四组对照；冻结版本后再进行最终独立验收。
- 最终隐藏测试不持续回流给优化器；已揭示的失败可进入下一轮开发集，但需要新的最终验收集。
- 不仅查新例子改善，还检查原本正确的风险提示、计算与权限是否退化。
- 跨法域测试使用依法可用的合成或授权材料，不把 A 的原始私有 redline 复制给 B 或公共评估器。

### 最小反事实测试

- 同合同正文由 SG 改成 DE：重新选择有效规则包，不替换“国家系数”后直接套算。
- 改成 VN 且无已批准规则：明确不足，停在草稿/专业复核，不借用 SG 或 DE 的规则。
- 同事项从客户 A 换成 B：检索证据与最终输出都不出现 A 的私有红线。
- 作者署名换成知名合伙人：证据标准不降低。
- 原文确为误贴的制裁句：允许纠正该段，但保留是否需要独立制裁评估的记录。
- 新公式提高客户满意度但缺法源：不批准。
- 版本存在但 status 不是 active，或超过有效期：不自动应用。
- 删除提示降低“风险发现数量”却增加漏报：候选失败。

### 奖励设计与黑客风险

- 不把修改次数减少、用户点赞、风险条目减少或语言流畅作为唯一奖励。
- 硬门槛：权限隔离、法源与适用范围、必检事项完整性、有效批准，不允许用效率收益抵消失败。
- 通过硬门槛后，再比较正确率、覆盖率、人工时间、成本和任务完成率。
- 防止删警告、忽略困难案例、只记答案、泄漏隐藏样例、调整评分器、自行改有效状态。
- 同时防止“全部升级人工”刷安全分；报告自动覆盖率和审阅负担，但不因覆盖率压力绕过闸门。

### 下周德国和越南如何工作

- 只启用已分别批准的法域规则。
- 缺少有效规则时仍可整理事实、检索材料、生成待审草稿，但不自动输出确定性法律公式或对外交付。
- 可候选晋升到全局的经验是：同名数字规则必须核对法律身份，删除和新增分别审查，公式必须具备适用范围与来源。

### 交付工件

变更 RFC + 原子 diff + 版本化候选登记 + 独立评估矩阵 + SG/DE/VN 和 A/B 切换的可检查结果。

## 推荐交付形式

### 单一入口

使用一个 HTML 导览入口，包含总判断、五题导航、来源、假设、实测状态和附件。
所有题目采用统一的阅读层级，不强求完全相同的内部工件。

### 三层阅读

- 第一层：每题一句结论、为什么、最大失败模式。
- 第二层：机制、决策表、状态、成本与取舍。
- 第三层：来源、数据、版本、脚本、失败案例和完整附件。

### 每题的主工件

- Q1：上下文策略与账单拆解。
- Q2：推理路由、单位经济性和用户信任状态。
- Q3：权限状态机与超时结果核验回放。
- Q4：独立验收方案与阈值/降级演示。
- Q5：可审计的 playbook 变更审议。

### 制作优先级

先完成每题判断与证据，再做交互。
互动主要投入 Q4 的概率/动作差异和 Q5 的候选/生效/范围切换；其余题用简洁可核查的表格与轨迹即可。
不以动画、假日志或虚构评测填补证据空白。

### 交付要求

- 离线可读，无登录、无外部 API 密钥。
- 支持键盘、合理缩放和打印，长附录可折叠但正文不藏起来。
- 来源引用落到具体主张；标明检索日期和可变版本。
- 真实测试、确定性脚本验证、人工构造数据和设计假设采用不同标签。
- 使用同一份内容数据导出 HTML 与 Markdown，避免多版本答案相互矛盾。
- 仅展示合成案例；候选人个人账号与公司业务环境不混用。

## 下一份答卷的写法

每题顺序固定为“我的判断 → 为什么 → 如何执行 → 何时停止或降级 → 怎么验收”。
外部框架和产品名放在证据层，不把名词罗列当成主论点。
