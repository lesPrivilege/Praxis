Agent 第一性原理

不是让模型负责一切，而是在模型之外建立工作秩序。

Courtwork 的主线不是“Agent 有多少功能”，而是从概率模型如何承担真实工作责任倒推产品结构：谁提案，谁验证，谁裁决；什么叫完成；失败如何显式、恢复与验收。

Probabilistic Model理解、生成、候选
→
Work Order验证、边界、裁决

Agent 的核心不是 autonomy，而是 responsibility；产品的核心不是 conversation，而是 work。

讲法：整场先从责任问题开始。模型越强，越不能把生成、验证、授权、完成判断全部交给同一个概率主体。Agent 产品的第一性问题是职权与责任如何分配。

谁有资格决定什么

Agent 设计的核心，是 authority allocation。

“能不能由模型做”不是充分问题；“谁最有资格做这个决定”才是。Human-in-the-loop 也不是到处加确认框，而是对 decision rights 的建模。

Model模糊理解、归纳、生成、规划候选

擅长在开放空间提出可能方案

System格式、范围、权限、引用、计算、状态

能确定性裁决的部分不让模型猜

Harness失败检测、重试、恢复、续行

让长任务在中断后仍可追溯与恢复

Human价值判断、专业责任、不可逆决定

真正需要承担后果的裁决不被自动化偷换

模型生成，系统裁决，人类定夺；Harness 对失败与恢复负责。

讲法：市场谈 Agent PM 时常用 autonomy、HITL、eval。Courtwork 的回答更具体：把职权拆开。模型不能既写答案、又证明自己正确、又批准自己的权限、再宣布任务完成。

从回答质量到工作完成

Chatbot 的单位是 turn；Agent 的单位是 persistent work。

Agent 不只优化一次回答。它要对持续存在的目标负责，因此必须管理状态、权限、行动、验证、失败与恢复，最后交付一个可验收的结果。

Goal→State→Observe→Act→Verify→Recover→Deliver
Chat一轮回答是否像样
Agent一个目标是否完成
Requiredjournal · artifact · permission · resume

没有持久状态、验证、恢复与交付，Agent 很容易退化为“会调用工具的 chatbot”。

讲法：这里把 resume、journal、artifact、workspace 放回产品本质，而不是工程附件。只要基本单位从 turn 变成 work，这些机制就自然出现。

概率性是架构输入

不要把概率模型假装成确定系统。

更稳健的结构，是把概率性限制在允许概率性的区域：读入可以宽，提案可以丰富；写入、行动与完成判断逐层收窄。权威接口失败时显式标记未核验，不静默回退为模型猜测。

Rich Context读取完整材料与复杂世界
→
Structured Proposalschema、证据、显式不确定性
→
Validated Action权限、确定性门、人工裁决
Trust = Provenance + Observability + Reversibility + Recoverability
不是按钮存在、流程能跑
而是场景 → 行为 → 结果
还包括失败场景 → 预期失败行为

Agent PM 不只拥有 roadmap，也必须拥有 quality model、failure taxonomy 与验收标准。

讲法：“读宽写窄”把 structured output、sandbox、permission、typed action、confirmation 串成同一个原则。Eval 也不是上线前 QA，而是产品定义的一半。

垂类套壳清缴之后

被淘汰的是产品形态，不是工作知识。

第一波垂类 AI 把聊天壳、场景菜单、prompt、workflow 与专用页面绑成独立产品。Courtwork 的归档演化显示，这些形态会折旧；稳定留下的是工作对象、判断结构与验收标准。

SHELLVertical Chatbots

一个行业一个壳、一个导航、一组 prompt

FLOWWorkflows

把专用页面收敛成可重复流程

SCENEScenes

场景降为自然语言意图的 shortcut

CONTRACTWork Contracts

schema、source policy、tools、confirmation、renderer、eval

SYSTEMAgent + Extensions

一个 Work Agent；垂类知识作为可加载、可移除的契约包

Competitor feature → 去 UI → 去 workflow ceremony → 去 prompt → Work Contract

第一波垂类套壳潮即使产品形态折旧，也完成了一次昂贵的需求标注：枚举了值得结构化的工作面。

讲法：风险清单、时间线、对照、证据矩阵并不等于四个页面。把视觉工作面剥掉后，真正耐久的是 artifact schema、证据策略、确定性规则、人工裁决与 eval。

实现变便宜之后

“能不能做”失去区分度，“该不该存在”成为核心问题。

Coding cheaper 主要降低首次实现成本，没有自动消除集成、验证、维护、认知与产品承诺。技术门槛下降，反而让产品减法更重要。

Implementation显著下降

UI、workflow、tool binding 与数据结构更快生成

Integration仍然存在

入口、状态、权限和既有工作流会相互作用

Verification仍然存在

必须证明行为有效，也必须证明失败会被看见

Maintenance持续累积

每项功能都形成兼容性与长期承诺

Cognitive + Promise用户承担

新概念、第二入口与错误预期消耗注意力和信任

Capability ≠ Feature ≠ UI Entry
人人反复需要默认行为

无需再做一次入口选择。

重要但无需理解内隐机制

compaction、recovery、context projection 由 harness 承担。

有明确用户意图简单动作

“审查合同”“验证策略”是用户可理解的产品词汇。

偶发高级需求渐进披露

不污染多数人的主路径。

没有真实需求不做

开发便宜，不构成存在理由。

讲法：“功能便宜所以多做”是错误推论。能力可以存在于系统内部、extension、渐进披露或开发者面，并不都要变成用户入口。减法不是资源不足，而是用户注意力昂贵。

新的上游—下游关系

下游未必需要拥有自己的智能。

模型 API 之后，Frontier provider 连 Agent runtime 也可作为基础能力开放。规划、工具调用、computer use、长任务恢复和多 Agent 协作的上游升级，可以直接变成下游的能力红利。

GEN 1Model API

下游自建 prompt、tools、loop、memory、runtime

GEN 2Agent Runtime

直接消费可读文件、调工具、长期执行、恢复任务的 Agent

GEN 3Work Product

下游拥有用户与智能之间的工作协议

Cuser = Cintent + Cagent-literacy + Csupervision + Cverification
保留意图入口
保留不可替代的人类判断
保留最终工作对象

Frontier 提供 Agent；产品提供“怎样工作”。下游主要降低的是 Agent literacy、监督与验证成本。

讲法：这不是把下游价值缩成 UI。恰恰相反：底下可以永远换最强 Agent，产品层必须拥有 intent compilation、work contract、defaults、guardrails 和 human decision surface。

泛化悖论

Agent 越通用，普通用户越需要一个有主见的产品。

通用 Agent 必须面对“用户可能想做任何事情”。能力数量增长时，组合空间与配置负担同步增长；MCP、skill、plugin、connector、memory 是构建 Agent 的概念，不是完成用户工作的概念。

Choice Compression：复杂度没有消失，而是从用户侧移动到产品侧。

讲法：“能力全量、暴露最小”不是删能力，而是把能力编译成少数可靠路径。好的 consumer 产品主动提高自己的产品判断成本，降低用户的技术决策成本。

Curated agency

普通用户要 outcomes，不要 primitives。

股票与算命性质不同，却共同说明：消费级 Agent 产品的体验差异来自领域数据或叙事传统、用户上下文、记忆连续性、预先包装的判断与极低摩擦，而不是再造一个更大的 Agent 控制台。

DATA-RICH + CONTEXT-RICH

股票

权威数据 + 确定性计算 + Agent 解读 + 个人上下文。模型生成，系统裁决；研究与回测可以自动化，交易决定保留为人工动作。

CONTEXT-RICH + NO AUTHORITATIVE FORECAST

算命

传统解释 + 用户历史 + 叙事连续性。价值在个人化叙事体验；定位为娱乐或文化解释，不把不可验证预测包装成事实。

普通用户得到连续性，而不是一套 memory management console；session/context 不应成为用户要管理的对象。

讲法：这页补齐会话里的 memory 讨论。产品从行为与修正中形成可撤销、可审计的规则，用户感知到“它记得我”，而不是被要求配置 risk_tolerance、context window 或 memory slot。

Feature = packaged judgment

“帮我看看合同”，不是一个完整任务。

通用 Agent 给出能力；产品把含混意图编译成可执行、可验证、可裁决、可交付的工作契约。Extension 的合理定义也不是插件小应用，而是 Work Contract Package。

INPUT
合同正文 + 交易背景 + 用户角色
ARTIFACT
RiskList：条款、问题、严重度、理由、修订、证据
EVIDENCE
事实须带来源；模型给 quote，系统铸造 coordinate
CALCULATION
金额、期限与比例走确定性工具
HIGH RISK
逐项人工裁决，不批量自动接受
REVISION
原件只读，修改形成 RevisionEvent 与 tracked changes
RECOVERY
journal、resume、partial success 与 coverage 显式
COMPLETION
风险已审、选择已落、修订件可交付
Feature = Capability + Defaults + Guardrails + Contract + Presentation

产品功能不是一个 button，而是一组被提前完成、持续维护并可验收的判断。

讲法：这页是全场最具体的落点。所谓 schema engineering，是把自然语言中的隐含标准显式化，为非代码工作制造一个弱编译器：模型可写，系统可验，人可读改签。

最后的边界

垂类 Agent 未必有护城河；垂类工作契约可以有。

上游会吸收昨日的判断，下游也会快速复制上游的新范例。静态功能的独占期持续缩短；真正耐久的是契约语料、eval 语料、可信数据与工具、用户修正历史，以及持续做取舍的产品判断。

Harness+Contract Corpus+Eval Corpus+Trusted Data / Tools+Human Revision History+Distribution
Successful useful work÷User decisions required
任务高频且可命名需要

用户会反复说“看持仓”“审查合同”，不是一次性开放问题。

默认值可沉淀需要

数据、口径、风险和交付方式可以由领域判断预先固定。

上下文会复利需要

对象状态、用户偏好、机构知识与修正历史能改善下一次工作。

完成态可检验需要

结果不是“聊过了”，而是有出处、算过、裁过、可恢复并交付。

Frontier Agent 负责让更多事情成为可能；下游产品负责让普通人无需理解 Agent 也能完成工作。
