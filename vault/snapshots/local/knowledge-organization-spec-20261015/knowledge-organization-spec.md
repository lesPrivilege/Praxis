# 知识组织与解释性写作规范

**个人学习用 · 从宏观图景到概念、论证与源流 · 重写版 2.0**  
2026-10-15

> 先用短文交代问题与全貌，再沿需要逐层展开。每一层都保留足以成立的关系、理由与条件；每次深入，都增加能够解释、判断或迁移的知识，而不是增加同义句。

<a id="overview"></a>
## 00　全篇概览

这套规范把学习写作视为三件相连的工作：**组织知识、解释知识、检验理解**。先确定想弄清的问题与已有基础，写出一个可独立阅读的全景；再以一致的分类维度展开分支，把概念、关系、论证与历史脉络分别说清；最后回到原始材料核对，并用脱稿重建、反例和新情境检验所学。短文负责定位，展开负责解释，来源负责复核，练习负责暴露理解缺口。

它适用于个人自学、领域入门、主题综述和长期概念笔记。文章、视频与播客可以共享这份知识底稿；本文不讨论媒介制作、商业定位、平台传播与增长。

### 九条核心规则

| 规则 | 写作时要做的事 | 最短检验 |
|---|---|---|
| 1. 以问题定范围 | 明确本篇要解释什么、默认已经知道什么 | 能否用一句话说清本篇的任务？ |
| 2. 先给可成立的全景 | 提供对象、核心关系、主要分支和关键限制 | 只读开头，会不会形成错误印象？ |
| 3. 同层同轴，关系明说 | 在同一级沿同一维度组织；说明节点之间的关系 | 这些项目为何并列，又如何相连？ |
| 4. 逐层保真，按需展开 | 上层概括，下层补机制、证据、区分或条件 | 下一层增加了什么，是否推翻了被省略条件的上层？ |
| 5. 顺着理解依赖解释 | 先补必要基础，再说明新概念与推理 | 哪一步需要调用尚未解释的知识？ |
| 6. 用例子与反例定边界 | 以具体实例落实抽象关系，并说明不适用处 | 换一个相近情境，还能正确辨认吗？ |
| 7. 让主张匹配证据 | 交代根据、推理桥梁与结论强度 | 这份材料究竟支持到了哪一步？ |
| 8. 分清分类、论证与源流 | 区别“属于什么”“为何成立”“怎样形成” | 有没有把逻辑相似写成历史继承？ |
| 9. 删繁而不省理，以重建验收 | 删除套话、重复与装饰；保留必要解释 | 合上材料，能否复述结构、理由与边界？ |

日常使用只需抓住一条主线：**问题 → 全景 → 必要展开 → 核对 → 重建**。其余章节是遇到困难时查阅的解释与工具，不是每篇笔记都要执行的手续。

<a id="purpose"></a>
## 01　目标：减少理解所需的总成本，而非只减少字数

**好的学习文字，应让学习者较快形成一个正确但有分辨率限制的理解，并知道继续深入的入口。** 精简不是把专业术语排列得更紧，而是让每句话完成明确的解释工作。

### 1.1　把“较少篇幅”改写为一个可用标准

一段只有一百字的术语堆积，可能要求读者额外查询十个词；一段三百字的解释，可能已经把最关键的关系讲清。这里优化的是阅读、补前置知识、查出处、来回跳转和重新组织材料的**总成本**，而非局部字数。这个标准是本规范提出的编辑取舍，不是现成的心理学计量公式。

可以删的是：同义反复、没有落实的评价、重复预告、装饰性故事、与当前问题无关的材料。不能靠删去必要定义、关键中间步骤、决定结论的条件来制造简短。

全文不设统一字数、分支数量或段落句数。复杂性确实需要展开时，允许展开；某个分支不影响当前理解时，允许暂存为链接。

### 1.2　区分三种“完成”

**资料齐备**，表示已经找到了足以回答问题的材料；**解释成形**，表示材料被组织成可以理解、可以复核的文字；**学习发生**，表示自己能够重建、辨别和运用所学。三者不能互相代替。

关于“写作促进学习”，Graham 等人的元分析汇总了 56 项实验，研究对象为一至十二年级学生，报告了写作活动对学科学习的平均正向作用。它支持把写作当作学习活动，却不能直接证明成人个人学习中的任意笔记格式同样有效。[[9]](#ref-09)

关于“感觉懂了”，Rozenblit 与 Keil 的研究表明，人们可能高估自己对机制的解释深度。因此，本规范把解释链检查与脱稿重建列为验收动作，而不以成稿的流畅度代替理解。[[10]](#ref-10)

### 1.3　发生冲突时的取舍顺序

**事实与必要条件优先，其次是可理解的关系与推理，再其次是表达经济，最后才是形式整齐。**

为维持三个并列项目而合并不同范畴，为一句漂亮结论而隐藏争议，为压缩篇幅而把“在条件 C 下成立”写成“总是成立”，都应返工。反过来，也不必为了形式上的周全，把所有例外和远缘知识放进开头。

学习者已有知识仍然重要。这里保留的是“我已经会什么、容易误解什么、此次要补什么”，而不是人口画像。已有知识既可能帮助，也可能干扰新知识的学习；这也是先检查基础而非只调整文风的理由。[[4]](#ref-04)

## 02　方法来源：汲取什么，不照搬什么

**没有一个框架同时包办知识分类、因果解释、论证、思想史与学习检验。** 较稳定的做法是按任务吸收它们的局部价值，而不让某个流行名称成为所有内容的统一模具。

本文使用三类依据：**研究**指实验、综述或元分析；**实践**指原作者的方法说明、机构编辑规范及创作者的一手经验；**综合**指本规范据此提出的操作规则。研究结论只支持相应机制，不自动验证本文的九条规则、四层结构或评分表这一整套组合。

### 2.1　方法取舍表

| 方法或实践 | 本规范保留的部分 | 不作通用要求的部分 |
|---|---|---|
| 金字塔原理 | 上层形成概括，下层给出组织有序的支持；检验分组是否产生了真正的判断 | 所有主题都必须先给唯一结论；每篇都必须分成三个理由。原作者也强调不能把“有三个理由”本身当作洞见。[[1]](#ref-01) |
| SCQ 问题框架 | 用情境、变化或困难定位真实问题 | 为了制造悬念而人为添加冲突；已经明确的问题无需再铺陈一遍。[[1]](#ref-01) |
| MECE 式分组检查 | 检查是否重复计数、漏掉关键类别或混用分类轴 | 将交叉领域强行分为互不相交的盒子。本文将它作为分组启发式，不作为知识世界的本体假设 |
| 先行组织者 | 先给能连接已有知识与新内容的上位关系，而不只是目录标题 | 凡是放在开头的摘要都自动有效。早期元分析观察到总体学习收益，也报告了与原理论预测不一致的变量模式。[[22]](#ref-22) |
| 概念图 | 以明确关系连接概念，允许跨分支连线 | 有节点和连线就代表理解；把每条关联都当作同一种关系。[[3]](#ref-03) |
| 学术百科的分层编排 | 概览可以独立阅读，复杂细节另行展开，主题以问题和思想组织 | 逐个罗列名人与文献，或将所有材料压进一条线性长文。[[2]](#ref-02) |
| 认知负荷研究 | 留意陌生要素及其相互依赖，减少与学习无关的处理负担 | 用“每层三点”“每段五句”等固定数字冒充普遍认知定律。[[5]](#ref-05) |
| 自我解释 | 说出隐含步骤，把新信息接到已有知识上 | 仅把原文换几个同义词，或把“像给小孩讲”当作所有主题的唯一标准。[[6]](#ref-06) |
| Toulmin 论证分析 | 区别主张、证据、推理根据、限定与反驳条件 | 把全部段落写成六个标签；论证结构完整也不意味着证据真实。[[16]](#ref-16) |
| 解释性文档 | 交代背景、选择、约束、替代方案与关系 | 用操作步骤代替“为什么”，或把参考资料堆砌误当成解释。[[11]](#ref-11) |
| 常青笔记 | 围绕可反复使用的概念或判断写作，在使用中修订与建立联系 | 为“原子化”拆碎所有内容，或先建设庞大的分类系统再开始思考。[[13]](#ref-13) |
| 检索练习 | 离开原文后主动重建，再对照纠错 | 把熟悉感、反复阅读和排版完整当作学会；也不据单一实验宣布某种组织工具完全无用。[[7]](#ref-07) [[8]](#ref-08) |

### 2.2　三组需要保留的张力

**结论先行与具体经验先行。** 当学习者能够理解结论里的概念时，先给概括很有效率；若结论本身由陌生术语组成，先给一个可观察的实例，再抽象出原则更合适。全篇可以先给全景，局部却从具体问题开始，两者并不矛盾。Julia Evans 的实践特别提醒了抽象起步、缺少例子和前置知识假设不一致的问题。[[12]](#ref-12)

**层级结构与知识网络。** 学术百科需要一条可读的进入路径；概念图与常青笔记则提醒我们保留跨领域联系。因此，本规范把目录当作进入知识的路线，把交叉引用当作补充关系，而不要求所有知识只能有一个父节点。[[2]](#ref-02) [[3]](#ref-03) [[13]](#ref-13)

**历史理解与当下重构。** 恢复一个作者当时在说什么，和分析其论证在今天意味着什么，是两个不同问题。Skinner 强调历史语境，Blau 则讨论如何兼顾作者意图与论证的延伸含义。本文据此要求将“历史陈述”和“今天的分析性比较”分别标明。[[17]](#ref-17) [[18]](#ref-18)

## 03　核心规范：九条可执行的写作规则

**每条规则都针对一个常见的理解障碍。** 它们是编辑默认值：一旦某条形式要求妨碍当前问题的准确解释，应保留解释，而调整形式。

### 3.1　以问题定范围

先写一个可回答的问题，再决定需要哪些材料。主题名负责标识领域，问题负责约束内容。“缓存”是主题；“缓存为什么能减少重复工作，却可能返回旧结果”才足以指导一篇解释。

开写前只需交代三件事：此次要弄清的疑问，默认已有的知识，完成后应能做出的判断。将不影响当前问题的旁支移到延伸入口。文档范围与必要前置知识可以简短列出，不需要长篇自我说明。[[15]](#ref-15)

**检验：**每一节是否推进同一个主问题，或明确服务于某个必要的子问题？删掉一节后，若主问题的回答完全不受影响，它可能属于附录或另一篇。

### 3.2　先给可成立的全景

开头应直接提供理解，而不是只承诺后面会解释。一个合格全景至少让人知道：讨论的对象是什么，关键问题在哪里，主要关系如何组织，结论受到什么重要限制。

“本文从定义、机制、案例三个方面介绍二分查找”只是目录。“二分查找利用有序关系，在每轮比较后排除一半候选；比较轮数因此增长较慢，但总成本仍取决于数据访问和维护方式”才给出了初步理解。

概览可以不包含证明细节，却必须保留会改变适用判断的条件。若某个领域没有统一结论，全景就概括主要分歧和各自依据，不必虚构一个总答案。

**检验：**只读开头，能否说出主题的基本关系，并避免最常见的一种误用？

### 3.3　同层同轴，关系明说

同一级标题应回答同一种问题。“组成部分”“历史阶段”“解释路径”“实施步骤”是不同的组织轴。确需切换时，说明为什么切换。

例如，把“定义、速度、学派、未来”直接并列，很难形成可比较的结构。可以先按学习任务组织为“它是什么—为何成立—何时适用”；在“何时适用”内部，再按成本或约束比较。这里追求的是层级职责清楚，不是全篇只允许一种分类法。

在节点之间写出关系词：属于、组成、依赖、导致、约束、支持、反驳、类比、继承、改写。概念图的关键也在于连线有含义，而不仅仅是把概念摆在一起。[[3]](#ref-03)

**检验：**能否补全一句话：“以下各项都是这个问题的____，它们之间的关系是____。”

### 3.4　逐层保真，按需展开

上层是对下层的可靠概括，下层负责增加机制、理由、证据、区分、例外或历史背景。展开应改变理解的分辨率，而不随意改变主题。

“所有情况都适用”不能在下层悄悄变成“只在一种狭窄条件下适用”。正确写法是在上层保留这个条件，在下层解释条件的意义。新的证据确实改变判断时，则同步修订上下层，并记录这次变化。

不是所有分支都要同样深。已经熟悉的定义可以短写；决定判断的分歧可以长写。只有一个有意义的子节点时，通常不值得另起一级标题。

**检验：**将每个子节的首段拼接起来，能否支持父节的概括？展开之后，读者新获得了哪一种解释或判断能力？

### 3.5　顺着理解依赖解释

研究发现的顺序不必等于成稿顺序。研究时可以反复试探；成稿时应把必要定义、对象关系和中间步骤放到读者需要它们的位置。

发现一个解释依赖尚未介绍的概念时，有三种处理：就地给出最小解释；先讲必要基础；明确指向前置条目。只有当该概念不影响当前判断时，才适合推迟到深层材料。

例如，“因为满足单调性，所以可以二分”对不熟悉单调性的读者没有完成解释。应先说明：一旦某个位置满足条件，其后所有位置也满足，因此一次判断就能排除一个连续区间。随后再给这个性质命名。

**检验：**沿解释链逐步追问“为什么能走到下一步”，是否会遇到只用新术语替代旧疑问的地方？

### 3.6　用例子与反例定边界

例子要体现正在解释的关系，而不是仅与主题有关。优先选择变量少、能够手工跟随的实例；复杂案例在关系清楚后再引入。

反例负责揭示条件。说明二分查找时，排好序的数列展示如何排除区间；打乱顺序的数列展示为何不能只看中间值就排除另一半。两者围绕同一个关键条件，比多给几个相似成功例子更能完成概念辨别。

类比只搬运指定关系。用翻词典解释“通过顺序排除候选”可以；把词典的所有特点映射成算法部件就没有必要。Evans 建议将类比限制在一个明确想法上，讲完后回到对象本身。[[12]](#ref-12)

**检验：**例子换掉表面情节后，所解释的关系是否仍然成立？类比在哪一点开始失效？

### 3.7　让主张匹配证据

重要判断要让人看见三件事：根据是什么，这份根据为什么支持判断，支持到什么范围。证据不是引文的装饰位置，推理也不是添加“因此”就自动成立。Toulmin 的分析可用于检查这座推理桥梁。[[16]](#ref-16)

例如，某学习活动在一项实验中优于对照，支持的是该材料、对象与任务下的比较，不能直接写成“这就是所有人最好的学习方法”。同样，一个真实案例可以证明某种现象存在，却不能单独证明它普遍发生。

将事实陈述、来源作者的观点、自己的解释和暂定假设分开表达。只在会改变判断处说明不确定性；同一条件在同一连续论述中不必反复辩护。

**检验：**若移除作者名与权威头衔，剩下的证据和推理是否仍可检查？

### 3.8　分清分类、论证与源流

分类回答“它与哪些事物属于同类”；论证回答“为什么接受这一判断”；源流回答“它在何种问题背景下形成，又如何被继承、批评和改写”。三条线可以互相补充，但不可混用。

两个方法结构相似，并不自动说明一个源于另一个；某个思想较早出现，也不自动说明它导致了后来的制度或技术。历史性的联系需要传播、引用、版本、作者陈述或其他相关证据。

在个人学习笔记中，可以提出有启发性的当代比较，只需把它写成“可用来比较”“本文据此重构”，而非“历史上正是由此发展”。

**检验：**每个“源于”“继承”“首次”“导致”后面，是否有与这类主张相称的材料？

### 3.9　删繁而不省理，以重建验收

完成初稿后，不先润色形容词，而先检查哪些段落没有增加理解。删除无信息的预告和收束，合并同义判断，将一处解释过的条件改为必要的短回指。

一个段落尽量完成一个连贯的解释任务，但“一个任务”不等于“一句话”。Google 的段落指南既强调中心明确，也提醒过度碎片化会破坏组织；本文吸收的是这个功能原则，不照搬其经验句数。[[14]](#ref-14)

然后合上材料，写出主问题、核心关系、成立理由和重要边界。重建失败时，应回到对应的概念或推理，而不是只给原文加粗。检索练习与自我解释是这里的依据，但本文不将它们与某种固定笔记软件或模板绑定。[[6]](#ref-06) [[7]](#ref-07)

**检验：**能否在新的情境中用对这个知识，而不仅是复述原文的句式？

<a id="architecture"></a>
## 04　分层架构：一份底稿，多种阅读深度

**分层不是为同一主题写四篇重复的文章，而是让一份底稿允许不同深度的进入。** 上层承担整体定位，分支承担局部理解，深层承担复核与进一步推导。

### 4.1　四种深度及其职责

| 深度 | 回答的问题 | 保留的内容 | 可以后置的内容 |
|---|---|---|---|
| 全景 | 这是什么领域，核心关系是什么？ | 问题、范围、主结论或分歧、主要分支、关键条件 | 详细案例、完整推导、次要争议 |
| 分支 | 这个局部在整体中解决什么？ | 局部问题与回答、内部结构、与邻接分支的关系 | 每个机制的细节和全部证据 |
| 解释 | 为什么如此，怎么辨别？ | 定义、因果或推理过程、具体例子、边界 | 完整文献史、补充测试、替代推导 |
| 溯源 | 根据何在，是否还有其他解释？ | 精确来源、版本、分歧、证明或复核材料 | 不影响当前问题的资料全集 |

四种深度是本文的工作结构，不是知识的四个客观等级。一个短条目可能只有全景与解释；一个领域综述可能在若干分支下继续递归。深层也不必总是更抽象：原始例子、史料与测量记录往往更具体。

### 4.2　每个节点先交付一个局部答案

一个可展开节点不应只写“还有以下三个方面”，而应先说明这个分支的实质判断，再提示展开方向。

可用这样的自然段完成：

> **本节回答的问题是 Q。** 在范围 C 内，关键关系是 A；它与上一层问题的联系是 B。理解这一关系，需要继续区分 X 与 Y。暂不展开的 Z 不改变此处判断，详见相应条目。

这是构思检查，不要求把 Q、A、B、C 作为成稿标签逐个写出。实际表达应像普通文章，而不是数据表的口头朗读。

### 4.3　“局部自足”不等于“每节从零开始”

局部自足是指：在明确的前置知识下，当前解释能够闭合。它不要求每个分支重复全部基础定义。

首次介绍共享概念时，完整解释；后续使用时保留一句关系提示，必要时链接到定义。若把某个小节单独导出、分享或交给另一位学习者，则将影响判断的前提与限定一并带出。

重复有不同功能。为了定位而复现短定义，为了重建而主动复述，均可保留；连续几段以不同措辞重复同一结论，则应合并。判断依据是它是否完成了新的认知任务。

### 4.4　目录树之外，至少辨明两类联系

**前置依赖**决定学习顺序，例如解释复杂度之前先让人理解比较次数随规模变化；**横向关联**帮助迁移，例如某种“先证明可以排除，再缩小范围”的思路也能用于其他搜索任务。

链接旁应写明关系：“此处需要先理解……”“这是……的一个特例”“两者解决相同问题，但依赖条件不同”。孤立的“相关阅读”列表不能替代这种说明。

大型领域可以有多条进入路线，如按问题、历史或应用组织，但应指定当前文章使用哪条路线，并把其他路线作为交叉索引。无需复制同一段内容来满足多个目录。

### 4.5　何时停止展开

当当前学习问题已经有可成立的回答，关键术语已有定位，必要推理没有缺步，重要边界已经显现，并且来源可继续追查时，这一层即可停下。

若下一层只是增加名字、案例数量或实现细节，却不改变当前理解，可以暂不写。反之，若一段话读起来流畅，却仍无法说明“为什么”，则应继续展开，不能用篇幅目标作为完成理由。

## 05　解释单元：按所缺的理解选择写法

**泛化的方法不是固定文体，而是识别当前缺了哪一种解释。** 不同段落可以分别承担定义、机制、论证、比较、源流或操作说明；无需每段都回答所有问题。

### 5.1　概念：先给辨认标准，再给术语位置

一个概念至少需要让人辨认“什么算它、什么不算它、它与最相近的概念差在哪里”。只有近义词替换的定义通常没有完成这项任务。

可用结构：

> X 是用于／指向……的概念。判断某对象是否属于 X，关键在于……。例如……。它与 Y 都涉及……，但 Y 不要求／另外要求……。

分类性定义可以采用“上位类别＋区别特征”；操作性概念要说明如何观察或测量；存在学术争议的概念，应列出正在使用的定义及替代定义。不要为追求一句话清爽，把仍有争议的界定写成唯一事实。

**示例。**“查找某个值”和“寻找插入边界”都可以使用二分思路，但结果并不相同：前者询问目标是否存在，后者询问目标应位于哪里。即使返回了一个有效位置，也不能直接断言目标已经存在。[[21]](#ref-21)

### 5.2　机制：把变化过程中的中间环节补出来

机制解释需要对象、初始条件、作用过程与结果。“它提高了效率，因为采用高效算法”没有增加信息；“每轮比较都能排除不可能包含目标的一半区间，因此无需逐项检查”则提供了可跟随的过程。

可用结构：

> 在条件 C 下，对象 A 发生变化 X；因为关系 R，这会改变 B 的状态，继而产生 Y。若 C 不满足，某一步不能继续，所以 Y 不再有保证。

不要把时间上先后出现直接写成因果链。社会与历史问题可能包含多种作用路径，需要说明哪条路径有证据，哪条只是可能解释。没有找到机制证据时，可以准确描述规律，而不编造一个顺耳的故事。

### 5.3　论证：写出从材料走到判断的桥梁

论证不是把结论写在前面，再堆几条引文。关键是解释材料为何足以支持这一结论，以及在什么条件下不够。

可用结构：

> 主张是 A。材料 E 显示……。从 E 推到 A，依赖前提 P；P 的根据是……。现有反例 R 限制了 A 的范围，因此当前能成立的表述是 A′。

数理论证依赖定义、前提和有效推导；经验判断依赖相应观察与研究设计；文本解释依赖具体语句、上下文和解释原则；规范性判断还需要说明价值前提。不能将“最好给个百分比”当作所有论证的共同标准。

**示例。**“某方法在一次实验中表现较好”与“所有人都应采用它”之间，至少隔着对象可比性、任务可比性、成本和目标等前提。写出这些前提之后，可辩护的结论往往更具体，而不是仅仅更保守。

### 5.4　比较：统一问题，统一尺度

比较的第一步不是制作表格，而是确认双方是否在回答同一个问题。若一项方法重在呈现结论，另一项重在发现新关系，将二者直接排名为“谁更好”就混淆了任务。

可用结构：

> A 与 B 都处理问题 Q。沿同一维度 D 比较，A 依赖……，B 依赖……；两者分别保留了……，付出了……。在条件 C 下优先考虑 A，在条件 C′ 下优先考虑 B。

比较维度要与学习问题相关，例如解释目标、假设、适用对象、证据或失败条件。对每一方呈现其有力版本；不必平均分配字数，但应说明材料或讨论的权重为何不同。

### 5.5　数理与模型：先说变量和假设，再做推导

公式应回答一个已经提出的问题。引入符号时，解释它代表什么、单位是什么、哪些量固定、哪些假设被简化；推导结束后，用自然语言说出结果允许怎样判断。

可用结构：

> 要估计的是 Q。令 n 表示……，暂定 C。每一步使……，因此得到关系式 R。由 R 可知……。这只是对……的模型，未包含……。

不用公式不等于可以跳过推理。反过来，也不必把能够直接解释的关系包成公式。将真实世界的所有问题都追溯到所谓“第一性原理”，可能抹掉历史条件、约定和经验知识；更稳妥的做法是明确此处采用哪些基本前提，以及为何采用它们。

### 5.6　操作：交代输入、改变与结束条件

当学习目标包括“会做”，可以添加操作单元。步骤应说明每一步改变了什么、为什么需要它，以及完成时如何判断成功，而不是只罗列动作。

可用结构：

> 输入与前提是……。先做 A，以建立……；再做 B，使……。当条件 C 满足时停止，得到结果 R。遇到 F 时回到……或改用……。

操作与解释可以相邻，但职责要分清。Diátaxis 将理解导向的解释与任务导向的操作指南区分开来；本文据此避免让完整教程淹没概念说明。[[11]](#ref-11)

### 5.7　语言编辑的最低标准

句子中的对象和动作要清楚；代词应有明确指向；同一个概念尽量保持同一名称。将“显著提升了系统的整体能力”改为“减少了哪种等待、错误或额外操作”；将“具有重要意义”改为“改变了哪个判断”。

标题优先揭示问题或关系，但不强制所有标题都是断言。定义条目可以直接用术语，比较章节可以用问题句，探索中的命题可以保留问号。措辞应与认识状态一致。

新术语第一次出现时，先给直观定位，必要时保留标准原名以便检索。中文技术表达不必为了“专业感”不断换用英语，也不必把存在明确含义的术语全部换成漫长口语。

同一限定在连续正文中说明一次即可；若摘要或条目会被单独使用，则随该版本保留必要条件。缩短的应是重复，不是条件本身。

## 06　辨章学术，考镜源流：把资料组织成可追查的关系

**“辨章”在此落实为区分概念、问题、主张及学派之间的关系；“考镜”落实为追查这些关系依据何在、如何形成与变化。** 这是本文采用的工作解释，不把它等同于一套已经完成的古典目录学研究。

### 6.1　三张不同的关系表

| 关系表 | 主要问题 | 适合记录的内容 | 不能据此直接推出 |
|---|---|---|---|
| 概念关系 | A 与 B 是什么关系？ | 上下位、组成、依赖、类比、交叉范围 | 历史上的影响或继承 |
| 主张与证据 | 为什么接受 A？ | 材料、推理、前提、反例、结论范围 | 作者真实意图或完整时代背景 |
| 问题与源流 | A 为什么在此时被提出？ | 原问题、语境、关键文本、回应、变体、传播线索 | A 今天是否成立或更优 |

三张表不一定真的制成表格。其作用是提醒：知道一个概念属于哪类，尚未解释它为何成立；知道它由谁提出，也尚未完成对其主张的评价。

### 6.2　源流不以年代与人名为骨架终点

一段有用的源流说明，应交代：此前存在什么困难；某种新表述改变了哪个概念、假设或方法；它解决了什么；后续批评针对什么；不同变体又保留或放弃了什么。

可用结构：

> 在背景 C 下，原问题是 Q。文本 A 用概念 X 回答它，但依赖假设 P。后续讨论指出在条件 R 下该回答不足，于是出现了调整 Y。今天的用法 Z 与原问题仍有……联系，也在……处改变了含义。

这是需要用材料填实的结构，不是可以自动生成的历史。若没有找到明确传承证据，只写“在分析上相近”“可以对照理解”；若只能确认一个较早文本，写“本次检索中可核对的较早表述”，而不是“最早发明”。

### 6.3　真实示范：历史解释与当代分析如何并置

以“阅读思想史文本时，应该恢复作者原意，还是分析其论证今天意味着什么”为例。

Skinner 在《Visions of Politics》所收章节中，质疑把经典当成当代作品、抽离其语境而直接寻找永恒答案的做法。Blau 的论文则区分作者意图中的意义与论证所蕴含的延伸意义，主张历史分析与哲学分析并非只能择一。这里使用的是两篇材料明确可见的方法主张，而不是把它们硬分成互相排斥的两派。[[17]](#ref-17) [[18]](#ref-18)

| 层次 | 可以写出的内容 |
|---|---|
| 全景 | 阅读旧文本至少包含两个任务：理解它当时在说什么，以及分析其论证还能推出什么。两者要区分，也可以结合 |
| 分支 | 历史解释需要语境、用语和争论对象；当代分析需要重建前提、推理与可能后果 |
| 深入 | 某种当代批评可以揭示论证问题，但不能因此声称作者本人已经提出了该批评或接受了相关概念 |
| 溯源 | 分别核对相关文本和方法说明，将作者主张与本笔记的综合判断拆开记载 |

由此可得到一段个人学习笔记：

> 解释一段旧文本，先恢复它所回应的问题与当时的概念用法；评价这段论证，再问其前提是否可接受、推理是否成立、还蕴含哪些后果。前者防止把今天的问题投射到过去，后者防止历史说明代替论证评价。二者可以在同篇文章中进行，但应让读者知道此刻正在执行哪项任务。

最后一段是本文的综合表述，不是对任何一位作者的直接引文。它展示了如何从来源之间的关系形成一个可用判断，而不只是依次摘要。跨来源的综合也正需要这种分析与连接工作。[[19]](#ref-19)

### 6.4　来源记录要支持复核，而不只是“有参考文献”

对影响主线的主张，保留足以回到原处的信息：作者或机构、标题、年份或版本、章节／页码／小标题、链接，以及该来源究竟支持哪个判断。网页可能变化时，再记录访问日期或保留自己的来源副本。

最小记录可以只有四行：

```text
主张：准备在正文中作出的判断。
根据：来源、版本与精确定位。
支持到哪里：该材料直接说明了什么；哪一步是自己的推断。
后续：仍待核对的问题，或会触发修订的变化。
```

例如：

```text
主张：在 Python 列表中，先定位再插入的总体成本不能只按二分查找计算。
根据：Python 3.14 文档，bisect，Performance Notes 与 insort_left 小节。
支持到哪里：文档区分对数级查找和线性级插入；本文据此用于解释“局部快不等于整体快”。
后续：换用另一种数据结构时，重新核对插入与访问成本。
```

### 6.5　怎样判断来源够不够

优先寻找与主张直接对应的材料：定义和实现找原始文档，实验结果找论文或研究摘要，历史主张找相关原文与专业解释，成熟编辑实践找原作者或机构自己的说明。

“一手”不自动等于正确或无偏，“二手”也不自动无用。严谨综述适合帮助定位分歧；原始文本适合核对某位作者说过什么。关键是材料的角色与当前问题匹配。

原文未取得、只读到摘要、案例数据未公开、不同来源相互冲突时，在相应论证或来源条目注明即可。不要用引文数量、网站名气或一串论文题目替代证据适配。

## 07　写作流程：先形成理解，再把它写成可复用的底稿

**每轮写作应留下一个更可靠的解释，以及一个更具体的下一步问题。** 流程可以往返，不要求一次从头走到尾。

### 7.1　七步流程与停止条件

| 步骤 | 实际动作 | 本步留下的东西 | 可以继续的条件 |
|---|---|---|---|
| 定题 | 把主题变成一个可回答的问题，声明必要基础 | 一句任务说明 | 知道此次不需要解决什么 |
| 找关系 | 先看可信概览，列出主要概念、分歧与待核主张 | 暂定全景与问题清单 | 能指出决定理解的几条关系 |
| 核主线 | 针对关键主张回查原始材料，寻找反例或替代解释 | 主张与来源的对应记录 | 主线有依据，缺口已定位 |
| 搭层级 | 选定主要组织轴，为每个分支写一段局部答案 | 多层大纲 | 每层职责清楚，不靠下层补救上层误导 |
| 写解释 | 补必要概念、推理、实例、比较与边界 | 可连贯阅读的正文 | 读者可以跟随主线到达结论 |
| 反向编辑 | 从正文抽取各段任务，检查分类、缺步、重复与条件 | 精简后的底稿 | 每段都增加理解，关键判断可复核 |
| 重建与修订 | 脱稿复述、处理新例子，再对照纠错 | 学习缺口与修订记录 | 达到此次学习目标，或明确进入下一轮 |

“核主线”不是只寻找支持材料。对每个关键结论，至少问一次：什么情况会使它不成立？这里最强的相反解释是什么？自己是否只因为喜欢某种结构而选择了这些来源？

### 7.2　研究顺序与呈现顺序分开

研究时允许边读边改问题，甚至先形成粗糙解释，再发现分类方式不合适。此时应修改结构，而不是继续把材料塞入原大纲。

成稿时再根据理解依赖重排：读者不需要重走作者所有搜索弯路，但应看到必要的理由与不确定性。保留失败探索，只在它能解释一个常见误解、重要分歧或方法选择时。

### 7.3　精简应当发生在保真检查之后

可按三个尺度反向编辑。

**篇章尺度：**只读标题与每节首段，检查能否拼出一个连贯且有实质内容的概览。不能成立时，先修主线，不急于改句子。

**段落尺度：**在旁边写下每段完成的动作，例如“定义 X”“解释为何不能排除左半区间”“区分两个成本”。多个相邻段落完成同一动作时，考虑合并；没有动作的段落，考虑删除。

**句子尺度：**检查主体、动作、条件、因果词和术语。尤其核查“必然、所有、最好、首次、导致、显著”等会增加主张强度的词，确保它们有相称依据。

### 7.4　最小日常用法，不必把每次学习变成项目

一个普通概念笔记可以只写：一个问题，一段答案，一个帮助辨别的例子或反例，一个关键来源，以及一个尚未解释清楚的点。

只有当主题跨越多个分支、关键来源相互冲突，或需要长期复用时，才增加完整关系图、证据表与源流说明。先写出有用理解，再按真实需要维护；不以建成完美目录作为开始学习的前提。常青笔记提供的是持续积累的实践参照，而不是强制拆分所有材料的理由。[[13]](#ref-13)

### 7.5　将“可读底稿”与“自己的掌握”分别验收

自己写、请他人写或让 AI 协助写，都可以采用同一套底稿验收：问题清楚、层级保真、推理完整、来源匹配。

但个人学习还要增加一道独立动作：不看正文，自行重建关键关系，尝试一个未见过的例子，再回到材料纠错。这里评价的是自己的回答，而非生成材料的完成度。

AI 协助时，适合委托的任务包括提出候选结构、寻找遗漏、生成明确标注的合成案例，以及对照来源检查表述。若某个来源没有实际取得，就让它保留待核状态；不要把模型给出的流畅引文或书目信息直接当成核验完成。

## 08　完整案例：二分查找为何少查很多，却不保证所有查找都快

**本例展示从定位到机制、边界和复核的递进，不要求背诵代码。** 数列和操作过程是本稿编制的合成示例；算法定义与成本区分参照 NIST 条目及 Python 官方文档。[[20]](#ref-20) [[21]](#ref-21)

### 8.1　第一层：一段话建立全景

> 二分查找利用有序关系，每次查看中间位置，就能排除不可能包含目标的一半候选，从而减少比较轮数。它适合搜索期间顺序稳定、能够按同一规则比较的数据；但比较少不等于总体成本一定低，访问中间位置、预先排序和后续插入也可能耗时。

这一段已经给出问题、核心机制和影响使用的条件。它没有介绍循环写法，也没有承诺所有数据都能按同样的时间成本处理。

### 8.2　第二层：把全景分成三个可独立理解的分支

**正确性：为什么可以丢掉一半？** 因为排序提供了排除依据。中间值小于目标时，它左边的值不会更大，因此目标不在这一半。没有这种顺序关系，丢弃就只是猜测。

**比较轮数：为什么规模变大，轮数却增长较慢？** 每次缩小后的候选又是同类问题，可以继续对半排除。我们关心的是需要对半缩小多少次，而不是数组总共包含多少项。

**总体成本：什么时候不值得？** 比较之外还有访问、排序、维护和更新成本。选方法时要看完整任务，而不是只看搜索步骤的量级。

这一级不是把首段换词重写，而是把“为什么正确”“减少了什么”“付出了什么”三个不同问题分开。

### 8.3　第三层：完整解释一次搜索

#### 从一个具体任务开始

要在下面这个升序数列中判断 `23` 是否存在：

```text
2，5，8，12，16，23，38，56，72
```

顺着读可以找到它，但会查看许多不必要的位置。改为先看中间的 `16`。因为 `23 > 16`，而 `16` 左侧的值都不大于 `16`，所以左半部分连同 `16` 都不可能是目标。候选只剩：

```text
23，38，56，72
```

对这四个数取较左的中间值 `38`。因为 `23 < 38`，它右边的值也不可能是目标，剩下 `23`，比较后确认找到。本次合成示例进行了三轮中点比较；这不是所有输入都只需三轮的承诺。

#### 再解释为什么不会误删答案

这次过程背后有一个始终要维持的条件：**如果目标存在，它还在尚未排除的范围内。** 最初全数列都是候选，所以条件成立。每次只排除由顺序关系证明不可能包含目标的部分，因此下一轮仍然满足它。

这叫作不变式：不是说范围不变，而是说某个保证在每一轮变化后仍然成立。这里先解释了保证的内容，再引入名称。

搜索有两个结束方式：遇到等于目标的值，说明找到；候选范围变空，说明在上述保证下目标不存在。若未命中，下一轮必须缩小范围，避免一直检查同一个位置。

#### 把“快”说成可检查的关系

每次未命中时，候选数量至多约剩一半。假设开始有 n 项，连续缩小 k 次后，其规模随 n / 2^k 下降。要使候选缩小到常数规模，k 随 log₂ n 增长，这说明的是比较轮数的量级，而非精确耗时。

若访问中间项与单次比较的成本都可以视为常数，搜索时间也具有对数级增长。若这些操作本身很贵，就必须将它们计入。NIST 特别区分了有序链表上的比较次数与遍历次数：比较可以是对数级，但遍历仍可能是线性级。[[20]](#ref-20)

#### 给出一个反例

将数列改为：

```text
2，23，8，12，16，5，38，56，72
```

中间值仍然是 `16`。若据此丢掉左半区间，就把真正的目标 `23` 丢掉了。失败不是因为“数据太少”，而是因为顺序条件不成立，比较结果不能再为排除提供证明。

因此，不能只记住“看中间、去一半”。需要记住的是：**先有可以证明的排除关系，才有缩小范围的动作。**

#### 回到完整任务

现成的有序数组，与一份尚未排序、只需查一次的数据，是不同任务。后者要把准备有序结构的成本一并考虑，不能只拿排序后的搜索成本比较。

同样，找到插入位置不等于完成插入。Python 的官方文档明确区分二分定位与列表插入：后者的线性成本可以支配整个插入操作。[[21]](#ref-21)

这一层最终形成的理解是：二分查找省掉了不必要的比较，但它的正确性依赖排除关系，总体收益依赖完整成本。

### 8.4　第四层：沿一个分支深入——寻找“第一个不小于目标”的位置

前面的问题是“是否存在”，现在换成“第一个不小于目标的值位于哪里”。这不是补一个实现细节，而是明确改变输出要求。

仍使用升序数据，但允许重复值：

```text
下标：0，1，2， 3， 4， 5， 6， 7， 8
数值：2，5，8，12，16，23，23，56，72
```

目标为 `23`。在这个数列中，判断“当前值是否不小于 23”会先得到一段“否”，随后得到一段“是”。我们寻找的就是这两段之间的边界，即下标 `5`，而非任意一个 `23`。

以左闭右开的区间 `[lo, hi)` 表示尚需检查的元素，初始为 `[0, 9)`。维护两条保证：`lo` 左侧的元素都小于目标；`hi` 及其右侧的有效元素都不小于目标。

| 当前区间 | 中点下标与值 | 判断 | 下一步 |
|---|---|---|---|
| `[0, 9)` | `4 → 16` | 小于 23，中点及左侧均不可能是边界 | `lo = 5` |
| `[5, 9)` | `7 → 56` | 不小于 23，边界在中点或更左 | `hi = 7` |
| `[5, 7)` | `6 → 23` | 不小于 23，但前面可能还有符合条件者 | `hi = 6` |
| `[5, 6)` | `5 → 23` | 不小于 23 | `hi = 5` |

当 `lo = hi = 5` 时，左右保证把边界确定下来。这里用了四轮判断，与前面找到任意匹配值的三轮不同；两个例子的输出任务不同，不能直接用轮数判断算法实现孰优。

这个边界也可能等于数组长度，表示没有任何元素达到目标。对于不存在的 `17`，边界仍是 `5`，对应的值为 `23`，所以边界位置本身不是“已找到 17”的证明。这也是官方 `bisect` 文档区分插入位置与精确查找的意义。[[21]](#ref-21)

可以迁移的结构是：如果一个判断沿有序位置只从“否”变成“是”一次，并能确认每次排除都保持边界，那么就可以考虑二分这个边界。是否值得，还要核对每次判断的代价与其他任务成本。

### 8.5　这份案例在哪些位置增加了理解

| 从哪一层到哪一层 | 新增加的内容 | 没有改变的核心 |
|---|---|---|
| 全景 → 分支 | 分开正确性、比较轮数与总体成本 | 通过有依据的排除缩小搜索范围 |
| 分支 → 完整解释 | 跑通真实数列，补不变式、终止方式与反例 | 顺序条件支撑排除动作 |
| 完整解释 → 边界搜索 | 改变输出目标，处理重复值与不存在的值 | 每轮保持保证，继续缩小待检查范围 |
| 解释 → 来源 | 核对标准定义、成本条件与具体库语义 | 来源支持判断，不代替亲自跟随过程 |

全景没有被后文纠正为相反意思；较深层也不需要重复解释全部基础，而只补当前任务新增的条件和推理。

### 8.6　先作答，再对照

**问题一。** 在原始有序数列中搜索 `17`，沿第一种“找到即停止”的方式，会依次查看哪些值，最后如何确定不存在？

**问题二。** 同事说“有序链表也能二分，所以时间一定是对数级”。这句话省略了什么？

**问题三。** 在含两个 `23` 的数列中，为什么找到下标 `6` 处的 `23` 还不能结束“寻找第一个 23”的任务？

**问题四。** 一个数组在搜索期间可能被修改。原有证明中，哪一部分需要重新检查？

#### 参考解答

问题一依次查看 `16 → 38 → 23`。目标小于 `23`，而剩余候选只有这一项，排除后区间变空。此结论依赖每次排除都保持“若存在则仍在候选范围内”的保证。

问题二混淆了比较次数与访问中间位置的成本。链表中找到中间节点可能需要遍历，不能仅由比较轮数推出总体时间。

问题三改变的是输出要求。下标 `6` 确实匹配，但下标 `5` 也匹配，所以还要继续确定左侧边界；第一次相等只足以回答任意匹配问题。

问题四需要检查排序与比较关系是否仍有效，以及已经排除的区域能否继续视为安全。先前针对稳定数据建立的保证不能不加检查地移用于正在变化的数据。对于实际库，还应检查并发与修改约束。[[21]](#ref-21)

## 09　编辑与学习验收：检查短板，不以总分掩盖问题

**成稿验收检查解释是否可靠，学习验收检查自己是否掌握。** 下列评分是本规范设计的诊断工具，不是经过心理测量验证的量表。

### 9.1　成稿的六个维度

| 维度 | 0：缺失或误导 | 1：基本具备但需修订 | 2：能够支持当前任务 |
|---|---|---|---|
| 问题与全景 | 只有主题词或材料堆积 | 有问题与概括，但关系或范围含糊 | 开头即可说明问题、核心关系和关键限制 |
| 层级保真 | 上层误导，下层才补救 | 分支大致成立，局部重复或混轴 | 上下层相容，分支职责与增量明确 |
| 解释充分 | 术语替换、因果跳跃、缺少关键步骤 | 主线可读，部分环节需自己猜 | 在既定前置知识下可以跟随推理 |
| 边界与迁移 | 无条件概括，例子只有表面相似 | 有实例或限制，但辨别力不足 | 能用实例、反例或对比辨认适用范围 |
| 证据与源流 | 无根据、误引，或把推断写成事实 | 来源可找到，支持范围或历史关系未理清 | 主张与来源匹配，事实、解释和传承有区分 |
| 表达经济 | 大量套话、重复或无关细节 | 主要内容清楚，仍有压缩空间 | 每段完成明确任务，必要推理没有被删去 |

不必汇总为一个漂亮总分。先修任何关键维度中的 0，再看 1 是否影响此次学习目标。格式和文风不能抵消错误定义、缺失前提或虚假引文。

### 9.2　五项可观察的学习测试

**重建全景：**不看原文，用自己的表达写出主问题、主要分支及其关系。漏掉一个分支并不一定严重；把因果写成并列、把条件写成普遍性质则需要返查。

**解释一条关键链：**从前提到结论逐步说明，每一步都能回答“为什么”。遇到“就是这样”“资料说的”时，标记需要补的知识。

**辨别相近概念：**选一对容易混淆的对象，给出区分标准与边界实例，而不是只背两个定义。

**处理新情境：**修改一个关键条件，判断原结论是否仍成立；或者用一个未见过的例子检验理解。不能只把旧例子的人名和数字换掉。

**追查关键根据：**指出最重要的主张来自哪里，哪些是自己的推断。无需背诵所有书目信息，但应知道如何复核。

检索练习研究支持主动重建的价值；本文因此把这些动作放在成稿之后，而不把重新阅读当作唯一检查。具体测试的难度和间隔应随学习目标调整。[[7]](#ref-07) [[8]](#ref-08)

### 9.3　六种反模式及其修改方向

以下均为本稿编制的示例，不是对原作者的引文。

| 反模式 | 有问题的写法 | 修改方向 |
|---|---|---|
| 目录冒充概览 | “接下来介绍背景、原理和应用。” | 先给一个能成立的关系判断，再说明展开路径 |
| 术语冒充解释 | “由于认知负荷和组块效应，应结构化呈现。” | 具体指出哪些陌生要素需要同时处理，如何分步使关系可跟随 |
| 摘要逐级稀释 | 父节说“很重要”，三个子节分别说“尤其重要” | 让下一层分别补机制、证据、区分或条件 |
| 权威冒充证据 | “某著名学者认为，所以方法已经得到证明。” | 核对其原主张、材料和推理；区分方法倡议与效果研究 |
| 年表冒充源流 | “A 在某年提出，B 在后来发展，C 最终完善。” | 写出每次变化所回应的问题与具体证据；无继承证据则不连线 |
| 精简造成失真 | “二分查找总是更快。” | 保留决定判断的条件与成本范围，删掉的是多余措辞 |

### 9.4　一次实际的改写示范

**初稿：**

> 二分查找是一种非常高效的重要算法，利用分治思想大幅提升检索性能，在各类场景中都有广泛价值，因此学习它对于提升工程能力具有重要意义。

**改写：**

> 在顺序稳定的有序数组中，二分查找通过比较中间值排除一半候选，减少查找所需的比较轮数。它的收益仍取决于访问、排序和更新成本，不能仅凭搜索阶段较快就认定整个任务更快。

改写新增了对象、机制和限制，删除了不能用于判断的评价。它并未试图在一段话中塞入所有实现细节；需要进一步理解时，再进入案例与证明。

## 10　可复用模板：选一种起步，不必全部填写

**模板只帮助发现缺口，不负责代替内容。** 若一个字段对当前问题没有作用，可以省略；若模板遮蔽了重要关系，则修改模板。

### 10.1　最小概念笔记

```text
标题：一个概念，或关于它的明确问题。

核心理解：它是什么／解决什么问题，关键关系是什么。
辨别：一个例子、反例或与相邻概念的区别。
根据：支持这段理解的关键来源与定位。
未解处：仍缺哪一步解释；没有则省略。
```

成稿不必保留上述字段名，可写成两三段连贯文字。核心要求是未来再读时不必依赖当时的临时记忆。

### 10.2　领域概览与递归展开

```text
主题与问题
前置知识与范围：只写决定理解的内容。
全景：对象、主问题、关键关系、主要分支和重要限制。

分支 A：它在整体中解决什么；先给局部回答，再展开必要解释。
分支 B：它在整体中解决什么；说明与 A 的关系。
其他分支：只有在确有新的职责时增加。

交叉关系：哪些概念跨分支共用，哪些是前置依赖。
争议与边界：哪些判断依赖条件，哪些存在不同解释。
来源：关键主张如何复核。
自测：一个重建任务，一个边界或迁移任务。
```

### 10.3　跨来源的比较与综合

```text
共同问题：这些来源究竟都在回答什么？
来源 A：它的回答、根据与假设。
来源 B：它的回答、根据与假设。

关系：相互支持、补充、冲突，还是其实在回答不同问题？
可成立的综合：哪些可以合并，哪些必须保持分歧？
证据缺口：还需要什么材料，才能区分这些解释？
```

写成正文时，应让问题和论证成为主语，作者名与出处支持它们。除人物或历史研究本身需要之外，不必以“某某说、某某又说”串起整篇文章。[[2]](#ref-02) [[19]](#ref-19)

### 10.4　源流节点

```text
当前概念或主张：本节点具体讨论什么。
原问题与语境：当时试图解决哪项困难。
关键材料：原文、版本、章节及可确认的表述。
变化：后来的讨论改变了什么，依据是什么。
当代使用：哪些含义延续，哪些属于重新解释。
```

此模板不要求每个概念都追到唯一发明人；共同形成、独立出现、归属有争议的情况应原样保留。

### 10.5　给写作者或 AI 的任务说明

> 围绕【问题】编写个人学习底稿。默认已有知识是【基础】，目标是能够【解释／辨别／推导／运用】。先给可独立理解的全景，再沿必要分支递归展开；同层使用清楚的组织维度，并说明分支关系。下层应增加机制、论证、实例、边界或源流，而不是重复扩写。关键条件在需要的位置保留；来源作者的主张、研究发现与本文综合判断要区分。只引用实际核对过的材料，标明未取得全文或待核实之处。给出一个可跟随的案例和一个能检验边界的新情境。篇幅由解释任务决定，不添加商业传播和媒介制作要求。

<a id="maintenance"></a>
## 11　维护：只把反复有用的判断变成长期规则

**规范应比具体材料更稳定，但仍要允许被实际写作修正。** 一次实践中好用的技巧，不必立即升级为普遍规则。

### 11.1　稳定原则与可变内容分开

相对稳定的是：先定位问题，明确关系，保留必要条件，区分证据与推断，以重建检验理解。需要随主题变化的是：分类方式、展开深度、术语选择、来源版本、例子和应用结论。

对长期概念笔记，优先更新同一个节点的判断与来源，再调整受影响的上层概览。不要在不同位置复制多个互相矛盾的“最新版”。具体工具、套餐、产品行为等时变事实，应作为有日期的实例，而不写入长期原则。

### 11.2　规则的采用条件

一条新规则至少要能说明：它处理哪类反复出现的问题；在哪些情况适用；一个可观察的失败信号是什么；采用它是否确实减少了理解或维护成本。

若只有“这样看起来更专业”，不足以纳入核心规范。若某条规则开始制造重复或妨碍解释，应收窄适用范围，而不是再叠加更多例外条款。

### 11.3　本次重写的实质变化

本版移除了市场受众、流量钩子、互动转化、媒介时长和发布运营等内容；把金字塔结构从统一处方调整为可选工具；新增递归展开规则、解释单元、主张与来源对应、思想源流辨析、完整分层案例、学习检验和轻量维护方法。

本版没有将固定篇幅、固定分支数或某种笔记格式表述为经过研究证明的普遍最优方案。后续应通过不同主题的实际使用，观察哪些规则重复有用、哪些需要收窄。
