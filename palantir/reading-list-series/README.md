# Palantir 入职书单 · 讲解视频系列

Nabeel Qureshi 2015 年入职 Palantir 时，公司寄给他四本书，另有一份 Ray Dalio 的早期 PDF。这个系列用一部简要总论加五集，各读一份，讲它们能给一个要到客户现场做事的工程师什么。中文旁白，英文原典溯源；每集能合法读到的范围不同，只讲读到的部分。合集由同一份正文重新排出，去掉各集的引入和收尾。

成片是生成物，不入库：`out/ep00.mp4` … `out/ep05.mp4`、`out/compilation.mp4`，每个文件带声音、可选的中文字幕轨和章节。新检出的仓库里没有成片、配音和下载的图片：`python3 build/fetch_assets.py` 按登记重新下载图片并核对哈希，之后用浏览器打开 `film/index.html?a=ep01`（或 `compilation`）就能看画面；声音要用自己的 Seed TTS 凭据重新合成，步骤见 [管线](build/README.md)。封面在各集的 `covers/` 下，4:3 与 3:4 各一份 SVG 源件；PNG 预览由 `build/cover.py` 生成。合集的封面在 [assembly/covers](assembly/covers/README.md)。

## 画面怎么读

- 实线框与实线连接：来源里写着的。虚线：本系列自己的读法，旁边标“本系列的读法”。
- 灰色：没读到或没找到的部分，以及对照里退到一旁的一方。红色：来源自己记下的断裂或失败。蓝色：此刻念白讲到的那一处。
- 左下角一行是出处；每句引文和出处在 [研究](research/README.md) 的主张登记里都有一条记录。

## 怎样做出来的

1. **研究**：六个来源探索代理分单元读原典、作者本人材料、亲历者文章和官方档案，每个单元配一个独立核验代理逐条复核引文；主会话按证据密度裁决每个单元能否独立成集，并亲自读了几份关键原文。
2. **写作**：旁白按 [Write](../../dsh-praxis/kit/README.md) 的口播体例与作者语体写成；每集交给一个没有写作上下文的冷读代理和一个事实核对代理，主会话逐条裁决。
3. **配音**：Seed TTS 2.0（渊博小叔），按段落合成并缓存，逐字时间对回文稿；英文人名与术语先做读音试听，转写结果不好的改用中文说法。
4. **画面**：每集一个 Opus 施工代理，只写自己那一集的目录，共用 `film/` 的引擎与系列卡片；主会话审帧。每集再交给两位没参与施工的审阅代理，一位看画面与念白的配合，一位看画面文字与出处；主会话逐条裁决，交回施工代理修改，需要时改念白、补登记。
5. **镜头与结构文字**：引擎加了镜头（[camera.js](film/camera.js)）：按可见内容取景，内容小就推近，新内容进场前先让位，另有推近与定景两种指定镜头。每集再由一位 Opus 导演代理整理取景、做三到五处主要动作，不改一字；画面上的结构文字由一位没参与撰写的审阅代理按 Write 的结构文字审阅逐类过一遍，主会话裁决后统一改。
6. **编排与检查**：单集与合集由 `build/assemble.py` 从同一份正文排出；合集的正文画面直接取自各单集成片。成片逐项检查，见 [验收](verification/README.md)。

## 交接稿与本项目的取舍

用户转交的 [生产交接稿](../../vault/snapshots/local/palantir-series-handoff-20261017/palantir-reading-list-series-handoff-20261017.md) 注明仅供开工参考。采用的：目录挂在 `palantir/` 下、两份登记（主张与素材）、单集与合集同源编排、原生双画幅封面、先出作品再做 dogfooding。没有采用的：固定的六段结构与统一片头话术。五个候选单元经证据裁决后全部独立成集，The Looming Tower 一集由探索代理建议的合并改判为独立成集，理由见 [研究](research/README.md#各单元的证据密度与裁决)。
