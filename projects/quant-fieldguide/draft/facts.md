## 逐条说法

### 市场机制
- 价格由订单流与做市供给共同形成：限价单进订单簿，市价单吃对手方流动性；买卖价差是瞬时交易的显性成本。（通识）
- 做市商/流动性提供者承担库存与逆向选择风险并以价差补偿；这是“无免费午餐”的一个具体形态。（通识，推断）
- 收益的非正态性：肥尾与波动聚集使以正态为假设的检验偏乐观。（通识；[1] 的 p 值注释也指出 i.i.d. 假设常不成立）

### 收益来源与 Alpha
- 收益可分拆为：市场 beta、行业/风格暴露、时间序列/截面信号的 alpha、以及交易成本与融资成本；不做归因就无法判断“是策略还是运气”。（通识，推导）
- Alpha 一旦被发现会被竞争消耗，容量有限；因此研究是持续淘汰的过程，而非一次性建模。（通识，推断）

### 数学与统计
- 收益与对数收益定义；年化波动 = 日波动 ×√252（交易日计的近似，构造计算用）。
- Sharpe 比率 = (年化超额收益)/(年化波动)；Sortino 用下行波动；最大回撤 = max over t of (历史峰值 − 当前净值)/历史峰值（与 [1] 的 “Max % of account underwater” 计算式同义）。
- Calmar = 年化收益 / 最大回撤（定义；[1] 报告 Calmar，未采用其具体实现细节）。
- 大数定律与中心极限定理：要让样本均值可信，独立样本数必须足够；日频策略一年约 252 个观测，判定“年化 5% 优势”通常样本不足。（推导）
- 多重检验：在 N 次独立尝试里，任一结果 p<0.05 的期望假阳性约为 0.05N。（推导；[1] 的注释说明“评估很多策略，有些仅凭运气得到低 p 值”）

### 算法谱系（通识，按任务归类，不逐一列尽）
- 信号挖掘：线性回归/岭回归、时序动量、均值回归/协整、GARCH 类波动建模、树模型（LightGBM 等）、神经网络与序列模型。
- 组合构建：均值-方差、风险平价、分层风险平价、约束优化（换手上限、行业中性）。
- 执行：TWAP/VWAP、成交量比例、Almgren-Chriss 一类冲击-风险权衡；强化学习执行（[3] 的 Qlib 提供 RL 学习框架与 order execution 示例）。
- 控制：波动率目标、止损与回撤闸门、仓位上限。
- 每一类都可由同一套评价协议检验；算法越复杂不等于证据越强。（推断）

### 数据工程
- Point-in-time：任何信号只能使用在该决策时刻已经公开的数据；财报按披露日而非报告期入池，宏观数据按发布日期，指数成分按当时成分。（通识）
- 幸存者偏差：只用今天仍存续的股票回测会抬高收益；退市样本必须保留。（通识）
- 复权：分红拆股造成价格跳变，必须复权或用总收益口径；货币与交易日历对齐。（通识）

### 回测可信度
- 回测在 K 线内部信息缺失时必须引入成交假设；[1] 列出的例子：价格落在 K 线高低区间内即按请求价成交、不模拟滑点；费率默认取交易所 pair 信息，可用参数覆盖，且入场出场各计一次 [1]。
- [1] 自述“回测永远不能替代 dry-run”。（转述）
- 未来信息泄漏：回测一次性载入全部数据并同时计算指标，指标若看到未来 K 线结果即失真；[2] 的检测办法是对比截断与完整数据下的指标值与信号位置。（转述）
- Walk-forward 与最终隔离测试集：训练段滚动前进，最后一整段只在方案冻结后使用一次。（通识；与 [1] 的 p 值注释相互支持）
- 交易成本模型：佣金（显性）、买卖价差、滑点、市场冲击。滑点是预期成交价与实际成交价之差，可正可负；受引擎延迟、券商连接速度、市场波动与竞争者影响；[6] 称券商模型会为每种证券自动设定滑点模型，可覆盖。（转述 [6]）

### 组合与执行
- 目标权重 → 订单 → 成交回报 → 持仓对账，是执行循环的最小闭环；订单需幂等与去重、断连后以券商回报为准对账。（通识）
- 风控闸门放在模型与下单之间：品种白名单、单笔上限、集中度、日损失阈值、数据时效；风控与停机不依赖模型推理。（通识，建议）
- 明确风险：交易可能亏损；本材料用于学习，不构成投资建议。（通识）

### 技术栈（来源所述）
- Qlib 自述为 AI 导向的开源量化投资平台，覆盖数据处理、模型训练、回测的完整 ML 流水线，以及 alpha 挖掘、风险建模、组合优化、订单执行的全链路 [3]。来源只说“覆盖”，没有说“可直接实盘”。
- RD-Agent(Q) 自述为以因子—模型联合优化自动化量化策略研发的多智能体框架；自述在低于 10 美元成本下取得约 2 倍于基准因子库的 ARR、因子数少 70% 以上；目前只支持 Linux [4]。数字未复现，按项目自述引用。
- TradingAgents 自述为模仿真实交易公司分工的多智能体框架（基本面、情绪、技术分析、交易员、风控），并声明用于研究、不构成投资建议 [5]。
- LEAN 的滑点文档说明其回测现实性建模由券商模型驱动 [6]。（LEAN 的 GitHub 默认分支 README 2026-10-26 取不到，未据此写任何工程能力说法。）

### Agent 时代（整理为主，含推断）
- Agent 增量的检验办法是在相同数据、相同约束下对比“有 Agent / 无 Agent”，否则收益差异不能归因于 Agent。（推断，建议）
- 分离 Research Loop 与 Trading Loop：Agent 只提交有版本的结构化提议，确定性的风控与执行层负责下单。（建议）
- 隔离测试集不能被 Agent 反复看到并据此改提示词，否则测试集变成训练集。（推断）

## 构造示例的口径（第 8 章两个实验）

- 泄漏实验：固定随机种子的合成日收益序列，200 个交易日；三种曲线：买入持有、“对未来无知的滞后动量”、“预先知道每日涨跌方向”。所有数字为构造值，只演示时间顺序的作用。
- 成本实验：输入名义年化毛收益 g、换手速度 t（每年倍数）、单边成本 c（基点）。净收益 ≈ g − t·c/10000。参数与结果随滑块变化，页面上标注“构造计算”。
