# 研究计划

## 研究目的

形成可供 Agent 产品建设直接消费的法律科技产品机制参考库。输出不是公司名录；核心单位是“业务对象—页面/工作面—动作—状态转移—证据”。

## 覆盖版图

1. 法律研究与引用核验
2. 合同审阅、redlining 与 Playbook
3. CLM、审批、签署与义务管理
4. 律师事务所 matter / case 管理
5. 诉讼证据、eDiscovery 与案件准备
6. 知识工作、drafting 与客户协作

## 三轮工作

### 第一轮：广扫与选样

- 按六个工作域发现产品、公开资料类型与证据可得性。
- 对欧美成熟 SaaS、AI-native 与中国代表分别保留候选。
- 以机制差异、页面/帮助文档证据、商业信息、地域与形态多样性为选样维度。

### 第二轮：深描与机制抽取

- 目标 8–12 个证据充分的产品。
- 每个产品记录目标用户/购买者、业务对象、导航与工作面、输入—动作—结果—回溯、版本/审批/权限、失败与未知。
- 把流程拆为可迁移的原子机制，并区分 `observed`、`inferred`、`proposed`。
- 商业侧区分软件订阅、内容授权、实施/培训、专家服务和法律专业服务。

### 第三轮：独立复核与交付

- 抽查关键流程、商业主张、日期和证据指针。
- 检查是否把 vendor claim 写成事实、把帮助文档写成实测、把三类“接受/批准”混为一谈。
- 验证 JSON、Markdown 链接、文件 hash、ZIP 内容与 agent handoff 可消费性。

## 证据优先级

1. 官方帮助中心、产品文档、公开更新日志、公开录屏/演示
2. 官方产品页、定价页、安全/部署/集成页
3. 权威媒体与实践者材料，用于独立核对或反例
4. 社区与用户讨论，只作补充并明确标记

链接可访问不等于功能已验证。登录墙内流程、销售报价、未公开权限模型均写为 `unknown`。

## 截图策略与当前限制

原计划使用云端浏览器访问公开页面并保存编号截图，逐张记录 URL、日期、页面/状态和说明。当前工具清单没有云端交互式浏览器，故本任务不会声称亲自交互或产品审计。研究继续推进，逐项生成待父任务补拍清单；帮助中心与录屏仅记为间接观察。

## 完成标准

- 8–12 个深描产品；另有较广分层索引。
- 关键结论沿 `claim_id → source_id → URL/时间点` 回查。
- 权威 Markdown、机器可读 JSON、来源账本、机制矩阵、复核记录、SHA-256 与 ZIP 齐全。
- 清楚给出准确覆盖数量、证据等级、未能验证部分与复查日期。
