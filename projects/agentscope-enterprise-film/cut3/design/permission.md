# 权限闸门 · 设计卡

目标句：工具输入合法后仍须经过权限决定；ASK 调用留在闸门前，合法确认绑定这一次调用才开门，DENY 调用停入拒绝区而不进入执行端。

主角是同一张 `R2 / T2 · Write · review-v3.md` 调用。调用沿水平轨道从输入端穿过 Schema 关口，在权限闸门左侧停泊；批准后原对象穿过闸门。第二张 `R3 / T3` 是独立拒绝样例，进入下方止步区，不替换或复制第一张调用。右侧执行区与下方拒绝区使用不同空间位置。

## 三帧

1. 24 秒：T2 已通过输入检查，停在闭合闸门左侧；上方 DEFAULT 规则轨线在 ASK 处落下连接线。右侧执行区为空。
2. 68 秒：确认对象显示 `confirm_results[0].tool_call.id = T2` 和 `confirmed = true`；身份线连接到原调用的 T2。闸门仍闭合，先核对、后开门。
3. 112 秒：T2 位于右侧执行区，T3 位于下方拒绝区；闭门与无通向执行端的轨迹共同说明 DENY 不执行。

## 空间和主次

输入检查门在 x620，权限门在 x1230；轨道 y500。调用宽410、高150，主画区主体是调用与门，不套工作台容器。注释贴近规则、确认对象与拒绝位置；屏幕底部保留一条30px有实义的当前结论。蓝色只强调当前决定、身份匹配和获准路径。无阴影、渐变、装饰容器。

## 时间与运动

总长168秒，无声。0–22秒输入与到达；22–52秒 ASK 等待，调用完全静止；52–74秒确认对象与嵌套身份匹配；74–90秒开门与原对象通过；94–116秒独立DENY样例止步；118–168秒同时对照DEFAULT/EXPLORE顺序和该次确认路径。

运动服务 Explanation、Spatial consistency、State indication。SVG原生对象由场景本地时间纯函数定位，移动/开门使用共享 power3.inOut，单次1.8–3秒；不使用回调、计时器、随机数或额外飞行副本。逆向seek重算同一姿态。减少动态效果由总播放器承担；本场保留静止语义关键帧。

## 事实锚点

- [固定裁决](../../../../vault/distilled/agentscope-enterprise-20261012/permission-verdict-v2.md)：Python `e4c1e074`，`as-145a584b7630`规则顺序，`as-df9d991bfc3d`确认/执行路径，`as-4a805cb460f3`确认对象结构。
- DEFAULT：deny → ask → 只读放行 → 工具检查 → allow → 兜底ASK；先命中的决定生效。六项均在画面中显示，不能为横轨整齐省略只读快速路径。
- EXPLORE：deny → ask → 只读放行 → fallback DENY；跳过工具内置检查与allow规则。非只读默认拒绝，但显式ASK先于只读判断，单次合法确认仍可进入执行路径。
- `confirmed=true`匹配`confirm_results[].tool_call.id`；未暗示任意id获准或未来调用永久获准。此处示范不修改name/input，保留原对象。
- 输入/schema、工具可用性、middleware和工具执行本身仍有独立检查；画面把“权限放行”与“执行完成”区分，不宣称批准保证写入成功。

## 本场施工检查

`node --check`通过。用本机Chromium及临时最小共享API渲染24、68、84、112、145、160秒；实际查看68、112、160秒，修掉Schema开门竖线与标题/确认区的相交，确认嵌套T2虚线落到原调用T2。13个时点顺序与逆序seek的SVG序列化完全一致。临时测试未替代最终共享core检查、实际时长观看与主代理视觉接收。

随后以真实共享core/engine复检，补齐DEFAULT只读快速路径及兜底ASK。18时点正逆seek一致，本场文字均≥30px，无文本相交或越界；实际查看68、75、80、109、145秒，修复开门杆与局部标题/状态交叠。具体覆盖和截图见[真实引擎证据](../evidence/permission/README.md)。
