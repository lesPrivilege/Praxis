# 第四段一倍速运行与取帧审阅

2026-10-12，主代理。2426–3121 秒，11 场；原生 1920×1080，无声。

时间轴由 `performance.now` 与 requestAnimationFrame 连续推进，没有跳过保持时间。实际运行 695.023 秒，41,701 次动画帧回调，142 张 PNG。原始目标时刻与截图实际时刻见 [日志](playback-part4/capture-log.json)，可重建 [采集程序](playback-part4/capture.py)。这是完整分段时轴运行加阶段图像观察；并非人类对每一帧的连续感知，也没有 PM 受众测试。

主代理实际查看 26 张原生图：Artifact 五个稳定阶段、九个普通场最终态、闭环十个稳定阶段、Artifact 发布转场的两个中间帧。没有把保存的其余图像算成已逐帧人工审阅。五个 Artifact 阶段从工作文件、JF1、JA1、读取记录到下载，文件名始终是 review-v3.md；闭环继续引用同一 R2/T2 与 JS1/JF1/JA1。

| 场 | 观察与判定 |
|---|---|
| 文件与 Artifact | 三层职责可区分；先上传、显式发布、读取真实记录、下载内容分别有状态。 |
| 身份与注册 | Account/Namespace、Application key、首次注册入口与Runtime凭证分别授权，条件清晰。 |
| 恢复 | capabilities、状态、旧lease与外部回执四类检查有各自位置。 |
| 协作 | Subagent、Team、Workflow的工作关系可读，文件共享另行配置。 |
| Issue | 定义、执行、观察、人工接收有具体主体；Run记录与Issue接受分开。 |
| 资源权限 | 账户、Namespace、资源动作和工作共享各有对象。 |
| 预算 | 用量归属、预算上限、停止和继续分别揭示，已启动并行调用的越限条件始终保留。 |
| 消息渠道 | 外部请求、目标、观察、回传形成同一任务关系；飞书Workflow条件保留。 |
| Webhook | 重复投递、事件身份去重与副作用幂等分开。 |
| 备份 | 数据、文件快照和原密钥组成同一恢复点；不把文件恢复等同于授权恢复。 |
| 业务闭环 | contract-v3.pdf贯穿缺件、补件、候选、ASK、写出、发布、接收与外部回执分支；Python/Java间显式标明材料交付契约。 |

未发现本段新增P1。短交叉淡化时旧新文字可出现瞬间叠影，传递图形可能短暂掠过正文；稳定保持时间后文字完整，没有把瞬时过渡当作读取窗口。普通场更适合顺序静读，关键场用对象身份和状态改变支撑机制。量化曝光与字体结论另由 [状态验收](cut2-state-acceptance.md)支持。
