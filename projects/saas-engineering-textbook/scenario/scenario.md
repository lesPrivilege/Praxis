## 1. 工作与机会

读者是能借 AI 搭界面的 vibe coder。现状是一部约 1 MB 的 Markdown 教材（[Books](../../books/saas-engineering/README.md)）加 33 例结构数据（[Vault](../../../vault/distilled/saas-engineering-atlas/README.md)），读者要在仓库里跳读文件、自己在脑中还原拓扑和状态变化。

期望改变：同一份正文成为可离线打开、可打印、可搜索的多页教材；主线上的演算可以逐步操作；每个案例的对象、关系、生命周期、检查与迁移从 JSON 直接可见。非交互的替代方案是在 GitHub 上读 Markdown，它始终保留：正文仍以 Books 为唯一权威，HTML 只是渲染。

本轮范围（用户 2026-10-15 裁定）：全书 49 章与索引全部进入 HTML；主线（企业机制四章、方法第一章、H01、V04、V20）精编并配交互图件；精编的文字写回 Books。停止条件：用户不接受交互形态，或正文修订破坏了证据身份。

## 3. 失败与恢复

| 情况 | 处理 |
|---|---|
| 正文链接失效 | 构建失败并报出链接与来源文件，修正后重建 |
| 图件脚本出错或无脚本 | 显示 Markdown 回退内容；控制台报错 |
| 正文修订改动数字、条件或证据身份 | 逐条裁决时退回；最终对照原稿核对不可损失项 |
| 复核残余问题（R4、WB-02） | 正文写明配套脚本的边界，不展示为已验证 |
