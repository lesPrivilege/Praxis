# 视觉语法练习场景契约

## 1. 工作与机会

场景 `visual-grammar-lab`，revision `20260928-r1`。Kit 基线 HEAD `17d44bd397bbfa2914c6ddeec4027192dfa433a5`，工作树含先前未提交修订；实际消费文件 hash 见 intake 的 `kit_revision`，不能将 HEAD 视为全部正文版本。材料编目 owner 为 Astra，下一施工 owner 为用户唤醒的 Opus，最终接收人为用户（尚未接收）。

面向需要理解本地项目概念与状态关系的读者，以可执行视觉作品探索表达方法。现有 Chat 是方向建议，定向本地代码与规范是事实输入；没有观看基线、理解率或净减负实测。非 AI 替代为人工绘制静态关系图；可按作品需要保留静态关系对照。

开工输入：表达意图或技术探索目标、相关材料入口及所需synthetic输入。若需要秘密、真实客户材料、未授权账号或安装才能继续，记录具体缺口，先交付可审阅的分镜/已有环境下的作品。

## 2. 对象、证据与动作

施工者Opus接收所选题材与合成输入，自行组织一件或一组作品；用户接收作品，Astra可协助回查材料。动作仅在本 demo 目录创建实现，不修改来源仓库，不访问真实产品状态。

`fixture_id / revision / event_id / object_id / state_version / evidence_ids` 为项目输入的身份字段，实际 schema 由 Opus 按工单最小实现。fixture 与时间线是演示的权威输入；原项目 system of record 仅作为研究对象。AI 可提出布局和镜头，不能自行把提议改成批准，也不能把字幕中的状态替换当作后台真实写入。

所有 UI 数据标注 synthetic，流程未实装部分标注 concept。技术栈候选不构成已安装声明。

## 3. 失败与恢复

| 情况 | 处理 |
|---|---|
| 缺证据或原件冲突 | 标注缺口；可继续作concept或艺术探索，材料身份问题按需回查 |
| 来源/fixture 版本改变 | 失效旧分镜中受影响断言，重做语义与渲染检查 |
| 导出失败、结果未知 | 保留渲染参数与日志；检查输出可解码后再宣称交付 |
| 重复输入/同一事件重放 | 按稳定 ID 表现去重或已存在，不复制业务义务 |
| 人工拒绝或修正 | 保留原提议、修正理由与两者状态；不得让动画暗示静默批准 |

## 4. 验证与结果

每工单包含正常与失败 synthetic fixture、预期语义，以及可暂停/seek 的画面。检查首尾与关键中间帧、完整时长播放、静音可理解、文字可读与 reduced-motion/静态入口。同一时间点重复采样应一致；若使用物理/随机过程，固定种子与步长并记录仍不一致的边界。

导出视频另记录分辨率、fps、时长、音轨、编码、资源许可和实际解码/观看结果。静帧不替代完整观看。材料、系统行为、业务接受分别结论；无受众测试则理解率、净减负、接受率均为未知。

## 5. 接收与后续责任

交付包括作品与复现说明、消费来源ID和版本、借用/改写范围、新增实现、失败与review；Opus 负责提交施工回执，Astra可协助材料追溯与候选提炼，用户决定接收。Opus 可自行决定单件、系列或并行实验的组织方式。只在独立场景证据齐备时讨论 Kit 晋升，当前不晋升 Timeline IR 或通用 renderer。
