# 最小消费入口与可视索引设计

当前最小路径为 `kit/design/README.md → 本项目 README → coverage/catalog → 对应工单或作品`。这是待绘制项目的发现入口，不提高候选优先级，也不把用户请求都引入工场。已有比较、注释优先参考继续先用；本项目在需要修改关系、数据和文字的 SVG 资产时触发。

## 两层索引

机器登记 [catalog.json](catalog.json)目前保存需求而非可用资产。字段 `kind`、`job`、`input_shape`、`invariants`、`editable`、`bounds`、`avoid_when`、`compose_with`、`basis`、`work_order` 帮助 Agent 匹配任务；`delivery_status: not-drawn`、空的 `artifact_entry` 和 `preview_entry` 明确不能直接消费。每行 `basis` 是回到研究页的本地证据 ID，不是外部材料的质量评分。

Opus 交付后，在本项目的作品索引记录已产生资产的稳定 ID、版本、适用输入、静态 SVG、修改源码、完整预览、等效文本、许可和最新验收。需求 ID 与资产 ID 多对多：一个连接件可以满足数条需求，一个需求也可有不同适用边界的资产。catalog 的 `artifact_entry` 只链接作品 README，完整运行状态以作品为准。撤回资产保留 ID、原因与替代，不静默换掉旧 preview。此为局部设计，不接全仓 registry，也不提前规范全部 Atom/Pattern/Composition。

## 可视索引的最低行为

Opus 在实际作品产生后决定画廊构图。每个候选显示真实预览、它解决的判断、输入形状、原子/组合角色、当前验收范围和完整预览入口。缩略图由实际 SVG 生成，不能用概念占位图冒充已绘制。正常输入、长标签/窄容器与主要失败对照可切换；空结果显示尚无匹配而不是推荐最像的装饰件。

搜索支持自然任务词和反例，如“旧依据能否说明新附件”“箭头只是先后还是批准”“缺失与零”；筛选再按编辑能力、媒介和已验收容量收窄。关系/流程/状态/数量/比较/层级/空间/注释/证据/时间只是搜索线索，可交叉匹配，不建十个互斥目录。默认读一个任务摘要、少量匹配记录和选中作品，不预读全部候选或全部 Vault。

画廊不加载远端库，不自动运行来源代码。键盘可搜索、选择和打开，缩略图各有名称；JS 关闭时至少有文字列表与完整预览链接。选择件后能看到语义参数与边界、必要依赖/许可、组合端口和拒用条件。是否要交互编辑面板由 Opus 决定，编辑源码和修改步骤始终保留。

## Flash / Agent 验收

制作方不提前向消费方展示 fixture 和预期答案。消费方只收到正常任务和 Praxis 根目录，从根 AGENTS 与任务入口自行发现，选件、改文字和关系、组合并产出。按 [acceptance](acceptance.md)记录实际路径、遗漏、人工补点次数、修改成本与结果；本轮未运行任何 Flash。未见过内容指制作方未用来调整样张的内容，不是要求双盲或消融。

发现到条目不等于成功：选错件、选对但改不了、组合丢限定、拒用合适却未交清楚理由，都分别记。只以实际完成的任务判断，允许失败、零取用和退回正文/表格。若要声称入口改善了效果，再按已有治理默认补有意义的对照，用户没有要求此轮开展因果实验。
