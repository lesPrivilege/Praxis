# 股权结构图

画股权结构图，导出透明背景的原生 SVG。整个工具是 [equity-chart.html](equity-chart.html) 这一个文件，约 1.6 MB，不需要网络和服务器。有两种用法：人在页面上点选编辑，agent 写 JSON 后用命令行出图。两条路走同一套排版代码，出图一致。

## 人：在页面上编辑

用浏览器打开 `equity-chart.html`。左侧“表格”录入，右侧是实时预览，两边改的是同一份数据。

- **表格**：“＋ 主体”“＋ 持股”加行，行末 × 删除；删主体会连带删掉它的持股。股东和被投企业从下拉框里选，比例直接填数字。
- **在图上改**：点一个主体，浮出一条工具栏，可以改名、切换企业或自然人、加股东、加子公司、强调或删除；新加的主体会选中名称，直接输入即可。点连线或比例数字，改比例、写标注或删除这条持股。
- **调整顺序**：把主体拖到同级主体的左边或右边，松手后整图按新顺序重排；同级指有共同股东的主体，没有股东的顶层主体看有没有共同的被投企业。表格左侧的 ⋮⋮ 把手也能拖，或聚焦后按 ↑↓。
- **撤销**：⌘Z / Ctrl+Z 撤销，⇧⌘Z 重做；在输入框里打字时这两个键是输入框自己的撤销。Delete 删除选中的主体或持股，Esc 取消选中。
- **导出**：工具栏“导出 SVG”下载文件，“复制 SVG”复制源码。预览里用于点选的标记不会出现在导出文件里。
- “JSON”页签可以直接看和改数据，适合整段粘贴。主体超过 150 个时表格不展开，改在图上或 JSON 里编辑。页面会在本机浏览器里记住上次的数据和样式设置。

## Agent：命令行出图

```bash
node tools/equity-chart/render.mjs chart.json -o chart.svg
```

输入是下面的 JSON；`-` 表示从标准输入读。`--options options.json` 覆盖排版与样式，字段与默认值见 [src/api.js](src/api.js) 的 `EC.DEFAULTS`（字号、最小与最大宽度、层间距、方向 `DOWN` 或 `RIGHT`、颜色等）。警告（循环持股、比例合计超过 100%）打到标准错误，不影响出图；数据错误时不出图，退出码 1。

脚本用无头 Chrome 打开 `equity-chart.html`，调用页面里的 `EC.render(data, options)`，所以文字测量与页面一致。需要 Node 22 以上和 Chrome；Chrome 不在 macOS 默认位置时用环境变量 `CHROME` 指定。已经在浏览器环境里的 agent 可以直接在页面上调用 `await EC.render(data, options)`，得到 `{ svg, width, height, errors, warnings }`。

## 能做什么

- **任意层级与交叉持股**：数据是有向图，一家公司可有多个股东，一个股东可持有多家公司；循环持股照样排出，并提示所在环路。
- **名称自动换行**：节点宽度在最小与最大宽度之间，超出就换行、节点增高，不截断。中文逐字可断，英文按词断，标点避头尾，（集团）（江苏）这类短括号不拆开；断行后再收窄到行数不变的最窄宽度，使各行长短接近。名称里的换行符保留。
- **导出透明 SVG**：不画背景；每行文字是一个带基线的 `<tspan>`，在其他软件里打开不会重新换行；不依赖页面 CSS、外部字体、`foreignObject` 或脚本。文字可以选中复制。
- **校验**：引用不存在的主体、比例越界报错；同一公司股东比例合计超过 100% 提示。

## 数据格式

```json
{
  "entities": [
    {"id": "p1", "name": "张某", "kind": "person"},
    {"id": "top", "name": "某某科技投资控股（集团）有限公司", "focus": true},
    {"id": "a", "name": "上海某某智能制造有限公司"}
  ],
  "holdings": [
    {"from": "p1", "to": "top", "pct": 52.5},
    {"from": "top", "to": "a", "pct": 100, "label": "100%（全资）"}
  ]
}
```

| 字段 | 含义 |
|---|---|
| `entities[].id` | 唯一标识 |
| `entities[].name` | 显示名称 |
| `entities[].kind` | `person` 画成圆角的自然人框，默认企业 |
| `entities[].focus` | 强调：加粗、强调色边框 |
| `holdings[].from` / `to` | 股东 → 被投企业 |
| `holdings[].pct` | 比例，0–100，可省略 |
| `holdings[].label` | 自定义标注，替代比例文字 |

样例在 [samples/](samples/README.md)；“合成 20 / 100 / 500 个主体”生成固定种子的合成图，用来检查排版和速度。

## 构建

```bash
python3 tools/equity-chart/build.py
```

把 [src/](src/README.md) 的页面、样式、脚本，[vendor/](vendor/README.md) 里的 ELK，和 `samples/*.json` 内联成 `equity-chart.html`。源码按职责分开：`text.js` 测量与断行，`model.js` 数据校验与环路检测，`layout.js` 调用 ELK，`render.js` 生成 SVG，`api.js` 默认设置与 `EC.render`，`app.js` 编辑器，`generate.js` 合成样例。命令行入口是 [render.mjs](render.mjs)。

排版顺序：用 Canvas 按导出时声明的字体测量每个名称 → 断行并定出节点尺寸 → ELK Layered 分层布局与正交连线，同一层内按主体在数据里的先后排列（在 Web Worker 里运行，大图不卡页面；编辑时新的请求会替换仍在运行的旧请求，`EC.render` 的直接调用另用一个 Worker，按顺序完成）→ 按全部节点、连线和标注求画布边界 → 输出 SVG。

## 检查过什么

2026-10-17 在应用内浏览器（Chromium，本地 HTTP）里检查：

- 两个样例与 20、100、500 个合成主体都能排出；导出的 SVG 能被 XML 解析，没有铺满画布的背景，没有 `style`、`foreignObject`、`image`、`script`，也没有预览用的点选标记；循环持股与比例超限的提示出现。
- 编辑器：点主体出工具栏并与表格行同步高亮；“＋ 股东”新建主体并选中名称，输入后图与表格同步；把一个子公司拖到同级最左，整图按新顺序重排；点比例数字改成 60，图、表格与比例超限提示同步，⌘Z 一步撤回；表格加删主体，删主体连带删持股；JSON 页签改名同步到表格，坏 JSON 报错不出图；500 主体时表格收起。
- 命令行：两个样例、合成 100 与 500 主体在无头 Chrome 中以 `file://` 打开页面出图成功，Worker 能在本地文件里启动；引用不存在的主体时报错、退出码 1。

速度：同一个 100 主体图，Node 中 ELK 约 0.2–0.3 秒；页面里在机器空闲时测得 0.24 秒，负载高时 1.3–2 秒。命令行出 100 主体图共 1.7 秒（含启动 Chrome），500 主体 47 秒，后者测时系统平均负载约 15，没有在空闲机器上复测。同层强制按数据顺序排列后，图变宽：100 主体从约 8600 像素宽到约 11600 像素。

没有检查：在 Illustrator、PowerPoint、Inkscape、Figma 里打开导出文件的效果；Safari 与 Firefox；在桌面浏览器里直接双击打开 `equity-chart.html`；触屏拖动；读屏软件。

## 已知限制

- 字体：测量用本机解析到的字体，SVG 只声明同一组字体名。在没有这些字体的机器上，替代字体宽度不同，文字可能略超出或偏窄。要绝对一致需要文字转路径，未做。
- 拖动只改变同级先后，不能把主体放到任意位置；方向只有自上而下与自左向右。
- 同层强制按数据顺序排列，交叉较多的图可能比自动排序多一些连线交叉，也更宽。
- 比例标注由 ELK 放在连线旁，线多时位置不一定理想。
