# Jev 与 System One 决策模型：2026 年 10 月快照

快照日期 2026-10-23。来源截至同日，逐条登记在 [来源与主张](../research/README.md)。

## 结论

Jev 是一类新模型里的第一个：它读一段 state，回答一组带类型的问题（是否、选一个、打分），每个答案附概率，不生成文本。五周之内，同样的请求格式已经有了十几个开放或托管的实现，Databricks 等数据平台把它做成了 SQL 函数。在企业知识库里，它适合承担检索之后、回答之前的判断：这条材料相关吗，这句话有证据支持吗，现有证据够回答吗。权限、版本和生效时间仍由源系统决定。

支撑这一判断的五点：

1. **接口固定，模型可换。** `state` 加 `noul`、`choice`、`score` 三类问题的格式，已被 Laya、Kev、Clef、Liquid 的托管 d1、GLiDE 等直接沿用，Perplexity 与 OpenAI 也推出了同类 API；换模型多半只改一个 base URL。见 [第一章](01-jev.md)、[第二章](02-ecosystem.md)。
2. **Jev 本身没有私有化途径。** 它只有托管 API，不接受客户数据微调，没有找到 VPC 或本地部署的官方方案。私有化走开放权重：几亿参数的 encoder 路线（Laya）到 27B 的 LLM 路线（Kev），都有从 JSONL 训练到本地服务的完整命令；Clef 等开放权重也可以本地加载。见 [第三章](03-finetune-deploy.md)。
3. **概率要先校准，阈值要按模型定。** Laya 与 Kev 的发布版本都过度自信，各自在留出数据上重新拟合温度（Laya 英文版 ECE 0.466 → 0.081）。Knowviq 用自己产品的流量测试，五个模型的 AUC 几乎相同，套同一个 0.75 阈值，Jev 隐藏了 22.2% 的好答案，其余模型隐藏 6–11%。见 [第三章 3.5](03-finetune-deploy.md#35-校准是部署前的一步)、[第四章 4.2](04-eval.md#42-四个反复出现的发现)。
4. **总体分数相近，错误可以不同。** 在 495 条陈述的核验上，Jev 与 GPT-6 Astra 的 balanced accuracy 没有显著差异，Jev 放行的不受支持陈述多 9 个百分点；负责拦截的组件应以放行率评判。见 [第四章](04-eval.md)。
5. **公开证据以自测为主，企业知识治理还没有公开评测。** 厂商与使用方自测居多，学术评测都不在企业知识库上做；点名的企业案例只有 TypeSafe 自己发布的一例；版本冲突、生效时间、撤权这些企业知识库特有的判断，公开 benchmark 覆盖最薄。见 [第四章 4.3](04-eval.md#43-按决策单元组织评测)、[第五章](05-enterprise.md)。
