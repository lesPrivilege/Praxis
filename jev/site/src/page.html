结论

Jev 读一段 state，回答一组带类型的问题（是否、选一个、打分），每个答案附概率，不生成文本。同样的请求格式五周内已有十几个开放或托管的实现，数据平台把它做成了 SQL 函数。在企业知识库里，它适合承担检索之后、回答之前的判断；权限、版本和生效时间仍由源系统决定。

  1. 接口固定，模型可换

    Laya、Kev、Clef、Liquid 的托管 d1、GLiDE 直接沿用 Jev 的请求格式，Perplexity 与 OpenAI 推出了同类 API，Databricks 的 ai_decide 写明与之兼容。见二

  2. Jev 本身没有私有化途径

    只有托管 API，不接受客户数据微调，没有找到 VPC 或本地部署的官方方案；私有化走开放权重，从几亿参数的 Laya 到 27B 的 Kev 都有完整的训练与服务命令。见三

  3. 概率要先校准，阈值要按模型定

    Knowviq 用自己产品的流量测了五个模型，可回答性 AUC 几乎相同；套同一个 0.75 阈值，Jev 隐藏了 22.2% 的好答案，其余模型 6–11%。见四

  4. 总体分数相近，错误可以不同

    495 条陈述的核验中，Jev 与 GPT-6 Astra 的 balanced accuracy 没有显著差异，Jev 放行的不受支持陈述多 9 个百分点。见四

  5. 公开证据以自测为主，企业知识治理还没有公开评测

    厂商与使用方自测居多，学术评测都不在企业知识库上做；点名的企业案例只有 TypeSafe 自己发布的一例；版本冲突、生效时间、撤权这类判断，公开数据覆盖最薄。见五

三私有数据微调与部署

私有化只能走开放权重。各实现都用 API 请求的形状加标签作训练样本，训练的是决策函数，知识留在知识库里；训练后要在留出数据上重新拟合温度。

私有化的五步

  1. 标注

    API 请求的形状加标签；按项目、原件、版本与时间切分

  2. 训练

    在开放权重上继续训练决策函数，知识留在知识库

  3. 校准

    在训练前留出的数据上重新拟合温度

  4. 服务

    项目自带的服务，或 TEI、vLLM、ONNX Runtime

  5. 评测

    各自阈值下的误拒与误放、校准误差、延迟

从左到右是先后；间距不表示时长。

四评测

已发表的评测反复给出同一个结论：总体指标相近的模型，在部署关心的那一种错误上可以差得很远。区分能力与阈值上的误拒、误放要分开测。

按决策单元找公开数据

企业知识库要测的判断分为六类。可回答性与证据支持的公开数据最多，流程路由只有两组多轮对话数据，版本替代与撤权没有现成数据。

阈值的选法

Hamel Husain 与 Antaripa Saha 给出一个可以照做的流程。他们的数据只有 98 条 trace，门槛只用来引导选择。

  1. 分层五折

    所有模型用同一组折

  2. 约束下选阈值

    precision 与 recall 都不低于 80% 的阈值里取 F1 最高；没有满足的，退回不加约束的 F1 最优并记下这一折

  3. Platt scaling

    在 log-odds 上用一条逻辑回归校正概率

  4. 报告

    reliability 图与 Brier 分数（预测概率与实际结果之差的平方均值）

五企业知识库

决策模型放在检索之后、回答之前，回答相关、支持、够不够这几个问题。谁能看什么、哪一版有效，在检索时由源系统按同步过来的权限判定。

到演示为止的实施顺序

这是根据前面几章的发现提出的设计建议，没有生产验证，不预设算力、成本与工程实现。每一步下方是完成的标志。

  1. 选一个判断点

    从证据支持或可回答性开始

    写清问题、选项，以及放行错了与拦截错了各自的后果

  2. 建私有标注集

    按项目、原件、版本与时间切分；另留含旧版取代、冲突、撤销、证据缺失的变化集

    训练、校准、测试三份互不重叠

  3. 同一候选池上比较

    规则或 BM25、托管决策模型、开放权重实现、专用中文 encoder

    每个模型的区分能力、误拒与误放、校准误差、延迟

  4. 按模型定阈值

    交叉验证选阈值，Platt 或温度缩放校准

    阈值与校准参数随模型版本登记

  5. 接进演示流程

    按上图六步；低置信升级

    一条可回放的演示，每一步的输入、概率、阈值与去向都看得见

从左到右是先后；间距不表示时长。

常见追问

有没有能在本地跑的中文模型？

Laya 多语言版（322M，mmBERT 底座，自报在 51 种语言中 48 种可用）和 Liquid d1-3B（16 种语言）是开放权重。另一条路是直接微调中文 encoder（bert-base-chinese、chinese-roberta-wwm-ext，或 1,800 多种语言的 mmBERT）。中文判断任务上的校准结果，没有找到。见三

微调需要多少数据和算力？

这里只记录各来源点名的硬件和自报结果：Laya 的 notebook 用两块 T4，Kev 的示例在 H100 上约 15 分钟。本专章不预设算力与成本。见三

哪个榜单可信？

几个榜单同名不同物，排名随版本变化，分数多为自报。先看单项评测的设置：比的是零样本还是微调后，阈值是否按模型定，标签从哪里来。见四

能不能让模型判断权限？

不应该。可查到的企业检索产品都在查询时按源系统同步的 ACL 判定权限，未知身份按拒绝处理。见五

Jev 的数据会留在哪里？

企业客户可向销售申请零数据保留，TypeSafe 不用客户数据训练；但调用本身要把 state 发到 TypeSafe 的托管服务。见一
