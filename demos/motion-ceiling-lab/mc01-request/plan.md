# WO00 · 第一件作品的选择、表达与资源计划

2026-10-04，Opus 5.5 主会话。对应 [工单](../work-orders.md)的 B0。动工前定下的事记在这里，做完之后的结果在 [验收回执](acceptance.md)。

## 为什么先做 MC01

六件 [brief](../briefs.md) 里，MC01 要的是真空间、深度、遮挡和跨层的对象身份。本仓库已有的四件动态作品（[视觉语法工场](../../visual-grammar/README.md)）做过排印、声音同步和状态规则，都是平面或伪三维；真深度下“对象被挡住之后怎样找回”没有做过。它也是工单排在最前的一件。

## 要讲清楚的一件事

读者：不了解一次保存要经过哪些环节的人。看完能说出两句话：界面显示“已保存”时，数据可能还在队列里；只有存储层的回执能支持“已保存”。

内容全部来自 [`fixtures.json`](../fixtures.json) 的 `request_chain`：两条请求、六个事件。`req-1` 在 t=1 入队、t=4 落盘；`req-2` 在 t=6 入队、t=8 写入失败。brief 列的失败情形里，“ack 之后写入失败”就是 `req-2`；“重复点击产生第二个编号”和几种应当拒绝的输入做成变体。

输入里没有的内容，作品自己补了两样，都标明是合成设定：界面上的文字（一份说明、一个保存按钮、一行状态提示），以及两套提示写法——旧写法收到队列回执就显示“已保存 ✓”，改后的写法跟着回执走。

## 三个时钟

| 时钟 | 谁决定 | 画面上怎样看到 |
|---|---|---|
| 事件时间 t | 输入里的记录 | 右上的刻度尺和运行记录；状态只在记录写明的时刻翻转 |
| 叙事时间 | 影片的时间线 | 底部进度条；事件时间可以停住，影片继续看别处 |
| 镜头 | 影片的导演路径，或观看者自己 | 左侧层级旁的竖条标出此刻看得到哪几层 |

回执在层与层之间传递，在这个模型里不占事件时间；影片用一到几秒画它上行，这段时间事件时间停住。请求在队列、处理、存储之间的中间位置是示意，输入没有给时点，画面也不给它们标时间。

## 表达

- 四层画成上下叠放的四块板，界面在最上，存储在最下。“落盘”在画面里就是落到最底下一层。影片从正上方开始，这时界面挡住了它背后的全部，和日常看到的屏幕一样；镜头倾斜之后，背后的三层才露出来。
- 请求是一个小方块，编号写在标签里，标签始终跟着它。被挡住时在它的位置画一块灰影，出画时标签退到左侧层级旁。动工时灰影画的是虚线轮廓，独立复查指出虚线已经用来表示“还没有发生”，一种画法不能答两个问题，改成了灰影。
- 画法按 [成立程度与归属的标记](../../../kit/design/foundations/standing.md)的默认分配：线型回答“走过了吗”（实线走过，虚线没走到），端点回答“落盘了吗”（空心未落盘，实心已落盘，叉是写入失败），每个回答同时写成词。蓝色只用在等人决定的地方：开头的保存按钮，结尾的重试按钮。
- 两张回执走同一根竖线上行。第一张从队列出发，上行一层；第二张从存储出发，上行三层。两段路的长短就是论点。
- 镜头回到界面时，`req-1` 的数据块留在存储层不动，上行的是回执，不是请求。
- 配色是浅冷色、细线、无装饰；板、线、字之外没有别的元素。没有声音。

## 技术栈与理由

- WebGL2，自写不到 300 行的即时渲染器（带光照的盒子、平面上的软边贴片、屏幕空间等宽的线、世界长度的虚线），深度测试是真的。没有用 Three.js：本机没有，交接稿和仓库规则都不授权安装，这个场景的几何也只有盒子和线。
- 文字全部用 Canvas 2D 画在 GL 画面之上，位置由三维点投影得到，尺寸由 `measureText` 量出，保证任何角度下都清楚可读。界面那块板上的内容先画进一张 2D 画布，再作为贴图。
- 舞台、时间轴、静态分镜和导出入口用视觉语法工场的 [运行层](../../visual-grammar/_runtime/README.md)，导出和检查用它的 [流水线](../../visual-grammar/_pipeline/README.md)（Playwright 自带的 Chromium、WebCodecs VP9、自写的 WebM 封装）。本机已有，零安装。
- 页面上另有一份 HTML 文字版（剖面表和运行记录表），不依赖 WebGL。

## 资源计划与实际

| 项 | 动工前的估计 | 实际 |
|---|---|---|
| 新装依赖 | 0 | 0 |
| 外部模型、API、付费 | 0 | 0 |
| 成片 | 约 90 秒，1920×1080，30 帧 | 见验收回执 |
| 一次完整导出 | 流水线上一件 56 秒的作品用了 12.6 秒，估计 20–30 秒 | 见验收回执 |
| 中间帧占用 | 逐帧送进编码器，不落盘；关键帧 PNG 约 20 张 | 同左 |
| 磁盘 | 成片几十 MB，不进 git | 见验收回执 |

没有用到合同里建议的“30 分钟、2 GB”起步上限的十分之一，所以没有分批。

## 没有做的选择

- 没有做声音。brief 不要求，画面里也没有只靠声音传达的信息。
- 没有做有状态的模拟。队列里只有输入给出的请求，不画别的排队项；画了就要标成装饰，反而要读者分辨。
- 没有复制任何来源的代码、构图或素材。交接稿为这件作品指的两个来源（W12、R08）本会话都没有打开。
