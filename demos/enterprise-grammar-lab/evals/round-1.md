# 施工发现 · 第一轮

2026-10-04，施工者 Opus 5.5。这一轮只有一组：给了 Kit 和场景契约的施工。没有“不给 Kit”的对照组，也没有只给社区实践的对照组，所以下面的结论只说这一次施工里发生了什么，不能说 Kit 约束比自由发挥好多少。施工者自己评自己有偏，另请一个不知道主会话结论的只读代理复查了代码，它的发现单列在后面。

## 结论

这次施工出来的东西在结构上不是演示用的 CRUD：版本冲突、结果未知、幂等重放、依据版本落后、建议与决定分开记录、批量逐项结果，这些都真实地跑得通，而且都能指回 Kit 里的某一条。但它们几乎全部来自 Kit 的 [共同工作语法](../../../kit/grammar/work.md)和 [契约](../../../kit/contracts/README.md)两页，也就是“工作是什么”的那一层。到了“界面长什么样”的那一层，Kit 给的只有状态覆盖要求和九个没有内容的组件名，组件怎样划分、列表怎样筛选、动作放在哪里，都是施工者按任务来文和自己的习惯定的。

所以对“Kit 能不能把一个强模型约束成稳定的企业软件施工者”，这一轮的回答分两半：行为语义上约束是有效的；界面语法上 Kit 目前没有可以约束的内容。

还有第三件事，和 Kit 无关：施工者在浏览器里把主要路径都走通之后，独立复查仍然找出 14 处确实存在的缺陷，其中有一处会把上一个动作里写的理由提交成另一个动作的理由。类型检查、后端测试和施工者自己的走查都没有拦住它们。“能跑通”和“稳定”之间的这段距离，这一轮是靠第二个读者补上的。

## 按来文的判据逐项

| 判据 | 这一轮的情况 | 依据 |
|---|---|---|
| 是否乱造组件 | 通用工作面 8 个，每个都有调用方；搜索与跳转的列表是手写的 | Ant Design 没有命令面板组件；用 AutoComplete 可以少写一部分，没有试 |
| 是否绕过已登记的 primitive | 不适用 | Kit 没有已登记的组件，只有候选名单；名单里的 ResourceTable、ObjectDetail、EvidencePanel、ReviewWorkbench、TaskQueue、CompareView、ExceptionPanel 都没有做成组件 |
| 是否有裸样式 | 内联样式 0 处；一份 60 余行的 CSS 只管布局；颜色起初写了 12 处十六进制值，后改为主题变量 | `web/app.css`、`web/theme.ts` |
| 是否仪表盘凑数 | 没有指标卡、没有图表、没有“最近动态”；概览页是属性加待办 | 施工者自评。复查者在这一项下没有提出装饰性元素，提的是手写了库里已有的东西，见 N12 |
| schema 与界面是否同步 | 同步，并且有机械检查 | 契约生成的类型前后端共用；测试按契约校验每个响应。两道检查各拦下一处不一致（F01、F02） |
| 假后端能否换成真的 | 结构上可以，没有证明 | 前端只认识 `/api`；但契约本身带着演示身份的请求头，接真实认证时契约、客户端和外壳都要改 |
| 法律换金融 | 没有做 | 不能下结论。复查者读代码后指出通用工作面在类型上并不通用，见 N1 |
| 新 agent 能否只靠仓库接手 | 有一份部分证据 | 复查代理拿到的只有本目录和四页 Kit 的路径，没有主会话的任何结论，交回的发现里 14 处经核对属实。它做的是读和查，没有被要求改代码，所以“接手施工”没有验证 |
| 人能否快速审阅各状态 | 部分 | 每种状态有固定地址（[对照表](../fixtures/README.md)），一个人十几次点击能看完；没有 Storybook、没有截图基线，改动后要重新手走 |

## Kit 起作用的地方

| Kit 里的话 | 变成了什么 |
|---|---|
| “外部动作结果未知：保留尝试身份，核对影响后决定恢复”；反例“把超时当未执行，无条件重试” | 动作请求带尝试编号；`GET /action-attempts/{id}`；界面的“结果未知 → 核对 → 未收到才重发” |
| “输入实质改变：检查版本相关判断和批准”；反例“沿用旧版本批准执行新内容” | 依据记着取自文书第几版；文书出新版后依据标为落后，引用它的决定标为需重新核对；落后的依据不能再被引用 |
| “材料接收：业务动作按其批准范围执行”；Claim / Proposal / Decision 分开 | 建议、退回、决定三种记录，互不覆盖；主办律师只能提出，合伙人才能决定 |
| “来源重复导入：按事件与义务身份核对既有记录” | 同一尝试编号重放不产生第二条记录和第二个任务；已是复核人的事项再次指派不产生第二个复核任务 |
| “运行状态和业务状态分别保存” | 批量作业的进度（作业）和每个事项的结果（业务）分开；尝试的结果和风险的状态分开 |
| “必要信息不能仅在悬停时出现”“没有真实进度时不能制造百分比” | 不可用的动作把规则、版本和例外找谁直接写在页面上；作业只显示“已处理几个，共几个” |
| “客户策略不得硬编码进通用组件” | 能做什么由后端随对象返回，界面照着渲染 |
| 九项检查 | 当作对象页的检查表用，逐项对过 |

这些条目的共同点是带反例。带反例的条目可以直接翻译成一项测试和一个界面状态；只有定义没有反例的条目（Context、Next）落地最弱。

## Kit 没有话说的地方

| 需要决定的事 | Kit 的现状 | 这次怎么定的 |
|---|---|---|
| 工作面由哪些组件构成，各自的结构和属性 | `kit/ui` 只有九个名字和一行状态矩阵 | 按需要自己划分了 8 个，名字和候选清单对不上 |
| 可做的动作在哪里判定、怎样传给界面 | 只有“策略不进通用组件”一句 | 后端随对象返回 `actions`，带规则、版本和例外归属 |
| 列表的筛选、排序、分页、视图 | 没有 | 查询放在地址里，视图是有名字的查询 |
| 地址与对象的关系、下钻和面包屑 | 没有 | 地址即对象；标签页和所选对象都在路径里 |
| 批量动作与后台作业 | 没有 | 逐项检查、逐项结果、不整体回滚 |
| 表单绑定对象版本、冲突后怎样保留输入 | `states.md` 只说“保留核对与恢复路径” | 表单记住读过的版本；对象变了先核对再提交；已填内容不清空 |
| 企业界面的密度、字号、配色 | 明说由消费者项目决定 | Ant Design 默认字号，表格用紧凑尺寸；冷色、一种强调色，取自用户以往的偏好 |
| 对象中心与页面中心的区别 | `palantir/` 和 `tally/` 只有登记，没有提炼 | 用了任务来文自己的说法，没有仓库内的依据 |
| 技术栈 | 候选，未裁决 | 本目录自定，见 [实现说明](../demo.md) |

## 独立复查

复查者是一个 Sonnet 只读代理，拿到的是本目录、四页 Kit 的路径和八个问题，没有主会话的结论，不能改文件。它跑了类型检查和后端测试，没有开浏览器，界面上的发现来自读代码。下面是主会话逐条核对之后的处置；“已修”的都重新过了类型检查和后端测试，注明“浏览器”的另在界面上复现过修正后的行为。

### 属实并已修正

| 编号 | 发现 | 修正 | 确认方式 |
|---|---|---|---|
| R1 | 换复核人时新建一个复核任务，原复核人的任务还开着：同一项义务变成两项 | 未完成的复核任务转给新复核人，没有才新建 | 新增测试 |
| R2 | 三个动作共用一份表单值：在“退回”里写的理由，切到“作出决定”后会被当作决定的理由提交 | 换动作时清空表单 | 浏览器 |
| R3 | 收起表单再打开，上一次被拒的提示还在 | 换动作时重置那次尝试 | 读代码 |
| R4 | 批量指派在“结果未知”或作业进度取不到时，对话框关不掉 | 这两种情况下可以关闭；进度取不到时显示提示和重试 | 读代码 |
| R5 | 保存视图可以连点两次，存出两个同名视图 | 保存中不再接受第二次 | 读代码 |

| R7 | 地址里的事项和风险对不上时照样显示；标签名写错时页面空白 | 前者提示并给出正确地址，后者回到概览 | 浏览器 |
| R8 | 动作请求体不是对象时后端抛异常返回 500 | 返回 422 | 新增测试 |
| R9 | 页码、每页条数越界被悄悄改掉，`openRisk` 写错被当成假，都和契约不符 | 返回 422 | 新增测试 |
| R10 | 401、500、503 在多数接口上没有声明 | 每个接口加 `default` 响应；测试只允许这三个状态码走 `default` | 测试 |
| R11 | 已决定的风险标着“需重新核对”，却没有任何可做的动作 | 所引依据版本落后时，合伙人可以引用当前版本重新决定，旧决定留在记录里 | 新增测试、浏览器 |
| R12 | 列表的“待处置风险”和概览的“需要处理的风险”口径不同 | 事项摘要增加“需重新核对”的数量，列表一并显示 | 新增测试、浏览器 |
| R13 | 建议被退回之后，决定表单仍提供“带入建议” | 只有待决定的建议才能带入 | 读代码 |

R3 到 R6、R13、R14 只改了代码，没有在浏览器里重新走。

### 属实，这一轮没有修

| 编号 | 发现 | 为什么留着 |
|---|---|---|
| N1 | 通用工作面在类型上不通用：`ActionBar` 用了这份契约的动作枚举，`AuditTimeline` 用了事件类型枚举，`AppShell` 用了角色枚举，`CommandPalette` 用了搜索结果种类；外壳和搜索组件里直接调用了读取 hooks | 这正是金融换皮要回答的问题，留作下一轮的起点。换领域时要改的：客户端的类型参数、全部读取 hooks 和动作函数、这四处枚举放宽成字符串或泛型；`Problem`、`RuleViolation`、`Affordance`、`ObjectRef`、`AuditEvent`、`ActionAttempt`、`Job` 需要抽成两份契约共用的片段 |
| N2 | 界面重复了后端的规则知识：哪些依据可以引用、复核人不能是助理、至少引用一项、哪条记录是当前有效的；几处说明文字把规则的效果写死了 | 要改得让后端逐项返回“可否引用”和候选复核人，属于契约变更。现在的风险是两边改了一边 |
| N3 | 批量指派没有带读到的版本，逐项检查发生在读列表之后；已结案和利益冲突要提交后才知道 | 逐项的可做性没有随列表返回 |
| N4 | 记录里的规则清单是按动作写死的，不是实际判定过的；记录不带理由和引用；决定不指回它了结的那份建议；被拒的尝试不进记录；没有变化的指派不留痕 | 记录的结构要扩 |
| N5 | 复核人这个角色没有被任何规则用到；指派即生效，没有接收确认；任务不能完成；重新决定之后，旧决定产生的任务还开着 | 超出这一轮的一个动作一个验收点。之后风险页补了“下一步由谁负责”，复核人在那里被用上；其余没有动 |
| N6 | 尝试编号只在页面内存里，离开或刷新就丢了 | 已写进场景契约的失败处理。之后补了离开前的拦截，再之后刷新和关闭标签页也先请求浏览器确认；确认之后仍然离开的照样丢 |
| N7 | 默认身份是写在前端代码里的 fixture 编号；外壳知道“演示身份” | 身份接缝本来就要在接真实认证时重做 |
| N8 | 风险页不显示状态是谁在何时改的 | 契约没有返回最后修改人 |
| N9 | 翻到超出范围的页码时显示的是“还没有事项” | 之后已修：回到最后一页 |
| N10 | 无障碍：分组控件的标签关联、不可用按钮与理由的关联没有验证 | 没有做读屏检查 |
| N11 | 冲突之后不标出对象哪里变了 | 场景契约原来写的是“展示变化”，已改成与实现一致的说法 |
| N12 | 手写了库里有的东西：尝试状态机可以用 `useMutation` 加状态，搜索列表可以用 AutoComplete，日期格式化可以用随 Ant Design 安装的 dayjs | 主会话的判断：状态机里“结果未知、核对、同编号重发”这几步 `useMutation` 没有对应物，保留；另两项复查者说得对，没有改 |

### 不采纳

- 特权文书的标题对助理可见，复查者认为与“只显示存在”不符。处置是把场景契约改成“显示标题和存在，不显示内容”：实现没有变，变的是说法。标题是否该隐藏需要懂行的人裁决。
- 假后端的异常行为代码放在服务端模块里。它本来就是假后端，没有另一个“生产”模块。

## 对照研究 brief 的反例表

第一轮完成后拿到一份研究 brief（身份见 [README](../README.md#材料来路)），里面有一张“必须出现的反例”表。它是为另一个场景写的，但十行都不依赖具体业务，可以直接拿来对照。对照是主会话做的，没有第二个人核。

| 反例 | 第一轮的情况 | 对照之后 |
|---|---|---|
| 首次无数据与筛选无结果分开 | 有，两句不同的说明，可清除筛选 | 另修了页码超出范围时显示错话的问题（N9） |
| 证据缺失：缺哪份、谁补、暂停什么动作 | 部分。写明哪条规则拦住了哪个动作 | 仍然没有“缺哪份材料、谁来补”；登记依据不在范围内 |
| 证据冲突：冲突字段和两个版本并列 | 没有 | 没有改。立场相反的依据并列可见，不是字段级对比 |
| 读取失败与慢请求：位置、重试、旧内容是否陈旧 | 有 | 不变 |
| 权限不足：说明缺什么能力，同一路径后端也拒绝 | 有，后端测试覆盖 | 不变 |
| 依据更新：旧决定基于的版本可见，要求重验 | 可见但无路可走，复查后补了重新决定 | 不变 |
| 并发修改：保留未提交的输入 | 有 | 不变 |
| 提交后响应丢失：结果未知，按尝试编号核对 | 有 | 结果未知时离开页面会被拦下并说明后果（原 N6 的一部分） |
| 重复点击与重试：同键同结果，同键异内容拒绝 | 有 | 不变 |
| 关闭、返回、取消分别处理 | 缺。“收起”含义不清，填到一半点别处直接丢 | 补了：取消明确丢弃，离开先拦，都不撤销已提交的动作 |

另外两处是 brief 提醒之后才补的：风险页原来不回答“交给谁”，现在由后端给出下一步和负责人，这也让复核人这个角色第一次被用上（原 N5 的一部分）；fixture 原来不做自洽检查，悬空引用要到某次请求才崩。

这次对照说明的事和独立复查一样：十行反例里第一轮漏了两行半，都不是难做的东西，是没有人列出来问。Kit 的 [必查反例](../../../kit/verification/README.md)只有六行，偏工作语义；界面层的反例（空状态的两种含义、取消与撤销的区别、离开时的未提交内容）Kit 里没有。
