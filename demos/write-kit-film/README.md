# 视频能力测试 · Write 分支知识讲解（无配音）

一条 245 秒的中文知识片，讲 Kit 的 [Write 分支](../../kit/write/README.md)：改写会丢什么、规则分哪三种强度、冲突时怎样裁决、成文八条原理各属哪一档、审阅查什么、换媒介时怎样交代变动、验收要核对什么。没有旁白、没有配音、没有音频流，全部信息在画面文字里，读者自己控制不了节奏，所以节奏由读速定。

这次制作同时是一次测试：只给题目（编译成知识讲解视频，不做 TTS），由主会话自行取用 Kit 与外部参考，沿用[薪酬基线说明片](../role-baseline-film/README.md)的管线，看没有声音这条线能不能走通。

## 片子讲什么

一个贯穿的问题：材料换一次写法，哪些东西不能变，哪些可以调？每一场回答其中一步。

| 场 | 这一场要让读者看到的 | 画面 | Kit 出处 |
|---|---|---|---|
| 01 改写 | 文字通顺的改写，证据强度可能已经变了 | 两组原稿和改写后的对照：“假设”变成虚线空框，“可能”变成“是” | [常见偏差](../../kit/write/prose/review.md) |
| 02 底线 | 四条底线任何语言、任何模式都守；上一幕的两例违反的是第 3、4 条 | 四行编号条文，蓝色回指 | [证据与来源](../../kit/write/shared/evidence.md) |
| 03 强度 | 底线、语言约定、编辑启发式与文体，适用范围由宽到窄 | 三条宽度递减的色带，右侧写何时适用；注明宽度不按比例 | [Write 入口](../../kit/write/README.md) |
| 04 次序 | 要求冲突时六级次序，不靠加载先后 | 一条“优先→让位”的竖箭头和六个依次出现的条目 | 同上 |
| 05 原理 | 八条原理各自属于哪一档；以第 2 条为例看一次改写 | 八张卡，顶边和标签用三档的深浅；然后“首先形成的是这次事项的交付记录”被划去，换成以律师作主语的句子 | [成文原理](../../kit/write/prose/grammar.md) |
| 06 审阅 | 句式要数出现几次；结构位置要单独列出看并列 | 左：两类句式在改稿前后的段数，从零起的横向条；右：三行标签的改前、改后 | [成文审阅](../../kit/write/prose/review.md) |
| 07 换媒介 | 投影能说内容没变，改编和新增不能；变动说明写四件事 | 三行对照，“能”实心、“不能”虚线；四个蓝框依次出现 | [证据与来源](../../kit/write/shared/evidence.md) |
| 08 验收 | 每种输出要核对什么、什么不足以证明完成 | 四行表，Motion 一行着底色；末一句写单帧、联络表和整段播放各查什么 | [内容与媒介验收](../../kit/write/shared/verification.md) |
| 09 结尾 | 三种强度再说一遍；本片自己的变动说明 | 三行带档色方块的句子，右侧保留、删改、原因、新增、看不到、状态 | [证据与来源](../../kit/write/shared/evidence.md) |

## 读速怎么定

没有配音，也就没有“念到哪个词画面出哪个元素”这条锚。改成：每个时间是本场开始后的秒数，由读速倒推。

- 外部参考：[Netflix 简体中文字幕规范](https://partnerhelp.netflixstudios.com/hc/en-us/articles/215986007-Chinese-Simplified-Timed-Text-Style-Guide)写明成人节目每秒最多 9 个字（儿童节目 7 个，SDH 11 个）。这是字幕的上限，画面文字要同时看图，这里把 9 当硬上限，实际排在 4.3–5.7 字/秒。
- 检查：[check.py](build/check.py) 读画面文字清单，任意 4 秒窗口内新出现的汉字、字母和数字不超过 36 个；每个文字块可见时间不少于 max(2 秒, 字数÷9)。
- 排的办法：一屏先出标题，隔 1.5–3 秒再出第一项；每项之间的间隔按它的字数÷4.5 以上留；同一行里先出条目、再出它的说明。改一处文字之后重跑 `screen_text.py` 与读速核算，超限就往后挪时间或延长这一场。
- 因为没有声音，片中不含“念白”的各项检查（字数上限、转写比对、响度）；换成读速和字号两项。

## 内容口径

按 [证据与来源](../../kit/write/shared/evidence.md)，这是一次改编：把一个分支的几页规则压成 4 分钟的画面。变动说明在片尾，这里列全。

| 项 | 做法 |
|---|---|
| 保留 | 三种强度及其适用范围；四条底线的全部限定；冲突次序六级；八条原理各自的强度；审阅的两项查法；14→2、19→5 两个数；投影、改编、新增三类和变动说明四件事；验收表四行；单帧、联络表、整段播放各查什么 |
| 删去 | Prose 的专门文体（答卷、口播旁白）、格式检查、外部指南的取用说明、Publish 的展项职责、Reporting 的材料目的；八条原理各自的“不照做的情形”；各条之下的来源与历史审阅记录 |
| 缩略 | 条文原句缩成画面上的短语（例如“按位置取形”对应“语体一致，按位置取形”）；八张卡不写条文，只写条名和强度 |
| 新增 | 第 01 场的两个示例取自[常见偏差表](../../kit/write/prose/review.md)，但把它们并成一对、放在开头，并在第 02 场回指“违反的是第 3、4 条”；这一对应是本片所加，已在片尾标明。第 05 场脚注“第 5 条的位置取形跨语体适用”取自成文原理的强度表 |
| 证据身份 | 审阅一场里的 14→2、19→5 来自 2026-10-05 一条知识片的改稿，两轮审阅都由模型完成；页面没有记对照组，片中不称有或没有，只写“审阅由模型完成” |

## 审阅

按 [结构文字的独立审阅](../../kit/write/prose/review.md#结构文字的独立审阅)和 [叙事与分镜交接](../../kit/write/motion/narrative.md)：画面文字从渲染后的舞台抽成清单（`screen_text.py`），交给一位没有参与撰写的 Opus 审阅者，同时做结构文字审阅和对 Kit 原文的事实核对。主会话逐条裁决，13 项采纳（其中 1 项改写后采纳）、2 项保留：

| 意见 | 裁决 | 依据 |
|---|---|---|
| 表头“句式出现几次”带问句、“结构位置单独看”口语 | 采纳，改为“出现次数”“单独审阅” | 第 5 条：表头不写成问句，不用口语 |
| 第 6 张卡“中文原生的搭配”是名词短语、其余是条名 | 采纳，用原题“搭配用中文原生的说法” | 与八条原题一致，不新造措辞 |
| 色带里“事实、指称与逻辑、范围条件、不丢信息”与底线四行叫法不一 | 采纳，改为“事实、逻辑、确定性、信息” | 同一组四条同一叫法 |
| 变动说明四项写成问句；“删去”“删改”不一 | 采纳，改为名词短语，统一为“删改” | 同上 |
| 两条错误标签口语（“丢了”“读成”“变成”）且“假设的身份”与 Kit 的“证据身份”不一 | 采纳，改为“证据身份丢失，假设读作事实”“限定词丢失，可能写作断言” | 对照偏差表的类别名 |
| 底线第 2 条丢了“逻辑关系是真的”；第 3 条丢了“经验”；第 4 条丢了“任务” | 采纳，补回 | [证据与来源 · 底线](../../kit/write/shared/evidence.md)；第 7 条脚注引用了“关系是真的”，必须在底线里出现过 |
| 色带第三档漏了“和读者” | 采纳 | Write 入口原文 |
| 第 5 张卡标“编辑启发式”与强度表“结构位置的取形跨语体适用”有出入 | 改写后采纳：仍标编辑启发式，脚注写明跨语体适用 | 强度表该行不是单一档 |
| 验收表 PDF 一行漏“内容未截断”；末句漏“和同步” | 采纳 | [内容与媒介验收](../../kit/write/shared/verification.md)、[运动判断](../../kit/design/motion/grammar.md) |
| 页面没写“无对照组”，画面却写了 | 采纳，去掉 | 页面没有这句，属新增而且没有来路 |
| 片尾变动说明不全：删字没列、“违反第 3、4 条”和“无对照组”未标新增 | 采纳，补“删改”“新增”两行，“看不到”改为说谁看不到 | 变动说明写四件事 |
| 图例“改稿前/改稿后”与同帧“改前/改后”不一 | 采纳，右栏列头也改为“改稿前/改稿后” | 同帧同叫法 |
| “能说内容没有变”与另两枚“不能；…”形式不一 | 采纳，加列头“能否说内容没有变”，这一枚只写“能” | 并列 |
| 结尾句“两条强要求不能同时满足时，写明裁决，不靠谁后加载来决定”从页面整句截来、“谁”偏口语 | 保留 | 它是 Write 入口的原话，作为一句话结论位置，逐字引用比改写更稳 |
| “改前/改后”与“原稿/改写后”形式不一 | 保留 | 一处是改写示例的“原稿→改写后”，一处是同一句的前后；对象不同，叫法不同 |

审阅者另指出文字清单的两处缺口：被划去的改前文字没收进清单，透明占位字“假设”被记成可见。已修 `screen_text.py` 与划线元素（划线改为行内元素；透明字不计）；改后清单收齐了被划去的三处文字。

## 检查

做了：六项成片检查全部通过（`out/check-report.json`）。

- 流：H.264 1920×1080、30 帧，没有音频流，245.0 秒与时钟一致。
- 保真：16 个随机时刻，成片帧与重新渲染的同刻帧最低 36.0 dB。
- 静止：没有任何超过 6 秒的画面完全不动。
- 空白：没有纯色帧。
- 读速：任意 4 秒窗口最多 9.0 字/秒，各场平均 4.3–5.7；没有文字块可见时间短于 max(2 秒, 字数÷9)。
- 字号：除出处行（24px）外，所有可见文字不小于 30px。
- 画面：主会话按 5 秒一帧看了全片联络表，另看了各场结束时的大图；版面里溢出、重叠、被裁切的问题在上面几轮已改。

没做：

- 制作方没有按实际速度把全片完整看一遍；节奏和停顿由用户复看。联络表和单帧不能证明节奏。
- 审阅只有一位 Opus 审阅者、一轮；没有第二位独立读者。
- 没有受众测试，没有对照组。
- 事实核对对的是 Kit 页面本身，没有回溯到 Kit 页面引用的更上游来源。
- 字体（系统宋体、苹方、Avenir Next）、GSAP 的对外使用授权没有核对。
- 配乐和音效没有做，片子无声；无声是这次的题目要求，不是遗漏。

## 取用中的观察

- 没有配音之后，原管线里最有用的一件东西没有了：词级时间锚点会随念白自动重排，改字不用重改时间。这次时间全由人定，改一处文字就要重新核算读速。解法是把读速写成检查（`check.py` 的 reading），而不是靠人看；它在制作中前后抓出十几处窗口超限，每次靠往后挪时间或延长场长解决。
- 文字清单（`screen_text.py`）这次兼作读速核算的输入，比从分镜稿估字数准：它按画面上实际可见的文字块和首次可见时间算，带出了施工时加进去的标签。
- Kit 的叙事页把“字幕或屏幕文字”“静音或无法听见时的可理解路径”列为交付项，但没有给无声片定时的办法。这次的办法放在本页，没有写进 Kit 规则页；见 [CHANGELOG](../../CHANGELOG.md) 的条目。
- 同一个主题（Write 分支）既是片子的内容，也是撰写它的规则。画面文字从结构位置的规则出发时，常见偏差表里的问句、口语、同列不并列都真的出现过一次，被独立审阅抓到；自查没有发现。

## 拿这套管线做下一条无声片

1. 复制本目录。`film/` 里的 `engine.js`、`kit.js`、`boot.js`、`gsap.min.js`、`index.html` 和 `build/` 的脚本原样带走，`film.css` 保留到 “this film” 注释为止。
2. 重写 `script/beats.json`（场序与场长）和 `film/scenes.js`（画面；每个时间是本场开始后的秒数）。
3. 把 `build/check.py` 里的片尾保持静止的场号（现在是 `end`）和 `build/render.py` 的默认片名改成新片的。
4. 按 [管线](build/README.md)的顺序运行；先用 `screen_text.py` 和读速核算看时间，再渲染。
