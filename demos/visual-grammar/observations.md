# 本轮 grammar 观察

2026-09-29，Opus 施工三件作品后的记录。它们是场景内观察，还不是 Kit 规范：每条只有本工场一个场景支持，按 [ADR-002](../../docs/decisions/002-promotion.md) 至少还需要两个独立场景。可以晋升时，从这里提炼回 [Design](../../kit/design/README.md)。

| 观察 | 在哪件作品里得到 | 反例或边界 |
|---|---|---|
| 语义先折叠，画面只读折叠结果。状态、上下文、校验结果都由 fixture 经函数算出，时间线只决定何时显示；因此 `selfTest` 可以直接对照 expected，动画无法把失败演成成功 | 三件都是 | 显示时刻仍是手工安排；安排错了，画面可能早于语义出现。schema-gate 把人工决定时刻夹到候选到达之后，并写进 selfTest |
| 失败需要一个不同于“移动”的动作语法。拒收用弹回加保留区，冲突用原地抖动加反白标签，过期用虚线框，重放用灰色回声环。这样失败在静音和静帧里都能认出 | schema-gate、attention-grammars | 物理弹跳带有夸张的情绪色彩；它说明的是“没有进入”，不说明错误严重 |
| 一种颜色只留给人的决定。蓝色只出现在人工批准、人工修正和 needs_you 上；自动检查通过只用墨色 | 三件都是 | 光场是艺术隐喻，needs_you 在那里也是蓝光，但亮度不是度量 |
| 作者事件与分析事件分轨显示，并让某一种语法只读分析结果，漏检和误检才会被看见：光场只收到检出的声音起点，所以静默信号在那一栏没有波纹 | attention-grammars | 起点检测不知道事件属于哪个对象；按对象归因需要另外的标注或模型推断，属于 `model-inferred`，不能标成 `audio-derived` |

## 流水线观察

`renderAt(t)` 加逐帧截取的做法没有等待墙钟，三遍乱序 seek 的帧指纹一致；WebGL 栏在同一台机器、同一个 Chromium 上也一致。换 GPU、驱动或字体后是否一致，没有验证。第一轮本机 ffmpeg 没有音频编码器，视频只能与音轨分开交付；第二轮改由 Chromium 的 WebCodecs 编码 VP9 与 Opus，再用自写的 `webm.py` 封装，补上了这个缺口（见下节）。

## 第二轮：形式实验与流水线 v2

2026-09-29 形式实验 01（[form-lab-01](form-lab-01/README.md)），数据只作占位。

| 观察 | 证据 | 边界 |
|---|---|---|
| 大量粒子也能做到“纯 t 函数”：位置 = 形状插值 + 按种子延迟 + 正弦漩涡 + 节拍脉冲，全部在顶点着色器里求值，不需要逐帧模拟；16 万粒子在 35 个时刻、三种顺序下帧指纹一致 | form-lab-01 check-report | 真正的物理积分（碰撞、流体）仍然需要像 schema-gate 那样预计算查表 |
| 流场拖尾不必积分：线段两端取同一解析流场在 t 与 t−Δ 的值，就能得到可 seek 的光丝 | form-lab-01 流场段 | 解析流场不是 curl noise，不保证无散；看起来像流动，不是流体 |
| 一条节拍网格可以同时驱动声音合成、镜头切点、冲击白闪和粒子脉冲；切点落在拍网格上这件事可以写进 selfTest | score.js、selfTest | 这里是“声音服从作者网格”；让画面驱动声音（反向）还没有试 |
| 画面熵决定视频成本，不决定网页成本。粒子颗粒与上千根独立运动的 1px 光丝在浏览器里实时流畅，但 WebCodecs VP9 即使给到 40 Mbps，光丝段 PSNR 仍在 23 dB 左右；文字段在 8 Mbps 下为 24–27 dB；去掉每帧微颤后，16 Mbps 下为 28.6–31.3 dB，24 Mbps 下为 32–35 dB | form-lab-01 渲染记录 | PSNR 对随机亚像素颗粒过于严格：11.6 秒的文字帧在 2 倍放大下看不出差别，而流场帧确实被抹平。两种情况都要看图判断 |
| Droste 缩放的层级可以用 `L = floor(zoom − log_R 2r)` 直接求出，再按层级显式计算 mip，环与环交界处没有接缝 | form-lab-01 36–44 秒 | 只适用于自相似的环形排版；任意图像的 Droste 需要另外处理窗口形状 |

### 流水线 v2

- Headless Chromium 默认使用 SwiftShader；加上 `--use-angle=metal` 后改用 Apple M2 GPU，56 秒 1080p 的导出时间从 125 秒降到约 12 秒。帧指纹因此随 GPU 改变，报告里需要记录 `gl_renderer`。
- 2D 画布在几次 `getImageData` 之后会从 GPU 光栅切换到 CPU 光栅，前几次帧指纹因此不同。创建上下文时声明 `willReadFrequently: true`，从第一帧起就固定在同一种光栅上。
- WebCodecs 只在安全上下文中存在：`about:blank` 里没有，`file://` 页面里有。VP9、AV1、H.264 与 Opus 编码器都可用。
- 自写的 WebM 封装约 120 行：每个视频关键帧开一个 Cluster；Cues 放在 Cluster 之前，位置字段固定 8 字节，因此 Cues 的长度不依赖其自身内容；只有音频的片段超过 30 秒时另开 Cluster，避免 int16 块时间码溢出。Chromium 解码后与源 WAV 互相关，偏移为 0.0 ms。
- VP9 的 `bitrateMode: 'quantizer'` 在这台机器上几乎不改变质量（34.7–34.9 dB），文件却有 300–480 MB，已删除这一路径；作品只能通过 `meta.bitrate` 申请更高码率。
