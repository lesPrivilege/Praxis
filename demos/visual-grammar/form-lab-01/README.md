# 形式实验 01：七种画法，一条节拍

形式优先。64 秒，1920×1080 @30fps，另有 120 BPM 合成音轨，导出的 WebM 为 VP9 + Opus。打开 [index.html](index.html)，按“声音”听音轨；导出与检查见 [renders](renders/README.md)。

词语（事件、状态、上下文、投影、证据、决定）与记录编号只是占位，不承担业务论证。这件作品检验的问题是：同一条节拍网格能否驱动几种完全不同的画法，并且仍然可以暂停、逐帧 seek、重复导出。

## 分镜

切换都落在小节线上；每段开头有一次冲击音，并配一次白闪。

| 时刻 | 段落 | 画法 | 做法 |
|---|---|---|---|
| 0–4 | 虚空 | 一个点、一根线 | 16 万粒子叠在同一点上；Canvas 2D 画线；次低频渐强 |
| 4–16 | 粒子排印 | 粒子聚成“事件”“状态”“上下文” | WebGL2 instanced points；目标位置从文字栅格采样；每个粒子的延迟不同，形成漩涡；底鼓把粒子沿径向推开 |
| 16–24 | 点云空间 | 48 条记录排成螺旋，3 条为蓝色 | 同一批粒子换目标；透视轨道镜头 |
| 24–36 | 距离场建筑 | 无限柱廊，镜头最后抬头看向唯一的蓝柱 | 全屏 GLSL raymarching，柱高取自格子哈希；光带随拍脉动 |
| 36–44 | 无限缩放 | 文字环层层嵌套，沿对数螺旋推进 | Droste：`L = floor(zoom − log_R 2r)`；6 格图集；按层级显式计算 mip |
| 44–52 | 时间切片 | 横幅文字被逐列错时扭曲 | slit-scan：每列读取 `t − 0.9x` 时刻；底鼓触发蓝红分离与横带错位 |
| 52–60 | 流场 | 光丝沿流场流动，再收拢成“形式” | instanced lines：两个端点分别取流场在 t 与 t−0.55 的位置；流场是解析函数，不积分 |
| 60–64 | 塌缩 | 全部粒子归于一点，黑场 | — |

## 实现

| 文件 | 内容 |
|---|---|
| [score.js](score.js) | 作者事件：BPM、段落、形变时刻、底鼓/拍手/踩镲/铺底所在段、冲击时刻、占位词 |
| [score.py](score.py) | 用 numpy 把 score.js 合成为 `score.wav`（48 kHz 立体声，不进 git，运行 score.py 重新生成）：底鼓、拍手、踩镲、贝斯、铺底和弦、钟声琶音、上扬噪声、冲击。所有声音自制，噪声用固定种子 |
| [scene.js](scene.js) | 一个 WebGL2 上下文和四个程序，外加 2D 标签层；所有 uniform 都由 t 与 score.js 算出 |

```bash
python3 demos/visual-grammar/form-lab-01/score.py
```

粒子不做逐帧模拟。每个粒子的位置由 `mix(起点形状, 终点形状, 平滑(k − 种子延迟))`，加上随 t 变化的正弦漩涡与底鼓脉冲算出，因此任意时刻都能直接求值，seek 与导出不依赖前一帧。流场同理：它只是位置的解析函数，并不是积分出来的轨迹。

`selfTest()` 检验的是形式约束，不是业务语义：段落连续覆盖 0–64 秒；切点落在拍网格上；冲击与段落起点对齐；形变按顺序且互不重叠；形变目标都存在；底鼓数量与半拍段一致。

## 失败样例与 review

- 第一版粒子增益 0.3，文字发灰、颗粒感重；增益提到 0.55 后才有发光感。
- 第一版 slit-scan 的 RGB 分离约 160px，文字变成刺眼的 CMY 杂色；缩小到约 10–50px，并改为白色主体加蓝、红边之后，才能读出是字。
- 流场第一版分布在整屏，拖尾 0.22 秒，看起来像灰色雪花；收窄到一条高斯带、拖尾加长到 0.55 秒以后，增益又导致过曝成白带，最终降到 0.075。
- 距离场柱面出现木纹状等高线：`map()` 只计算当前格的柱子，光线跨格时会穿进相邻柱子。现在每一步不超过到格墙的距离。
- 导出质量是这件作品最大的问题。8 Mbps VP9 在粒子段只有 24–27 dB。改到 30 Mbps 后第一次全部通过，但只改了一处白闪、重新渲染后，55 秒的流场帧从 35 dB 掉到 28 dB：VBR 码率控制把比特用在了别处，流场帧正好处在临界点。改用 `bitrateMode: 'quantizer'` 后质量几乎不变，文件却有 300–480 MB，这条路径已删除。去掉粒子的每帧微颤后，文字段在 24 Mbps 下达到 32–35 dB。流场改为四分之一数量、更亮的光丝，画面更好看，却更难压缩：40 Mbps 下仍只有 23.7 dB。逐帧对齐检查显示解码帧与参考帧一一对应，所以这是编码器在高熵运动上的真实损失，不是错帧。最终导出为 24 Mbps、138 MB；流场段在导出视频里明显比网页糊，网页才是这一段的准确版本。检查中的“实际解码”一项因此如实记为未通过。
- 白闪最初为 0.85，解码拼图每 4 秒采样一次，正好落在切点上，有 5 格几乎全白；降到 0.65。

Opus 读图 review：七段之间差异很大，是这次想要的效果。Droste 与 slit-scan 最有辨识度；粒子排印在 1080p 视频中颗粒感强，更适合在浏览器里实时看。蓝色只用在三条螺旋记录、一根柱子和“决定”环上，保持了唯一强调色。
