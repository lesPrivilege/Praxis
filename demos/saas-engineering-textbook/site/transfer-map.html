跨案例迁移地图

迁移要同时写出保留的机制和改变的条件。表中每一行从已学案例指向变式案例，箭头只说明解题方法可以借用，不说明两例之间传输了数据、provider 功能等价或领域授权随之继承。迁移按机制分为八组，每组先写适用前提，反例一列给出会让原方法得出错误结论的输入。机读版本见 transfer-map.json；作者提出的其余连接，以及每条连接在原文中的位置，见 迁移提议。

01迁移步骤

先做完已学案例的小算例，再读变式案例的识题部分。写出不变量，换上变式案例的条件，构造一条会让原方法得出错误结论的输入，再判断变式案例的系统应当拒绝、重算还是请求接管。练习答案要同时说明业务对象和系统边界。

例如 V01 把理赔裁决和到账分开核对，这一做法可以迁到 H01，把付款和服务开通分开；H01 里“预付后开通”是该例自己的规则，诊疗处置不受这条规则约束。又如 H07 沿反向邻接找出受数据重述影响的结果，迁到 H09 后能列出需要复核的签名文件，是否撤销签名仍由对应的专业权威决定。

02证据与决定

动作绑定版本、权限和证据的做法可以迁移；变的是谁的证据算数：验收、客户确认、投运许可和押金责任各有自己的权威。

适用前提：对象、版本、责任人和可观察证据都已明确。

已学 → 变式 保留的机制 改变的条件 反例与验算
H01 → H02 动作绑定对象版本、权限和证据 采购另需累计验收与质量证据 收款即视为到货；缺验收时拒绝付款受理
V16 → V20 多次 booking 的执行证据支持范围接收 现场服务不继承住宅进入许可和押金政策 一次预约完成即关闭总工单；未完成范围仍可见
V20 → H06 执行与接收针对同一解决版本 支持请求可能没有 booking 客户确认旧版本而新消息未处理；总请求不关闭
H05 → H06 恢复动作、结果和接收各有证据 服务探测与客户确认的权威不同 成功探测替客户验收；核对接收人和版本
H05 → V18 局部关闭不解除其他有效义务 工单超时关闭的规则不适用于 legal hold 案件关闭自动删除受保全文件；有效 hold 阻止处置
V02 → H08 权限绑定作用域、动作及拒绝原因 研究同意有自主性和持续沟通义务 同意被当成永久响应授权；撤回后按具体动作重判
V03 → V10 设备资格是动作前提之一 校准、维护许可和投运确认分别决定 设备维修完即认为测量合格；资格与结果分别检查
V10 → V20 booking 执行与范围接收分开 现场隔离、许可与投运不能由客户签收代替 签署服务单即解除隔离；缺投运确认仍不放行
V15 → V16 工作证据与费用责任分别决定 工程计量与押金损坏责任依据不同 维修完成即扣全部押金；先核实责任与合同规则

03对账与资金

按来源身份核对、把差额单独保存的做法跨行业成立；金额的性质却不同，科目、估计和方向相反的应收应付不能按同一口径相抵。

适用前提：金额单位、币种、来源身份与调整口径明确。

已学 → 变式 保留的机制 改变的条件 反例与验算
H02 → H03 来源身份、币种和修订链 总账还需科目、法人和期间 匹配正确即视为无差异，忽略科目错误；逐来源行核对
H03 → X02 先按来源配对并保存差额 合并增加范围、币种和估值 总额相抵却交易方错；按内部双方与来源行核对
X01 → H01 用量、账单和付款分别核对 AI 成本单位与合同计费单位未必一致 生成 token 即认定已收款；核对账单及收款身份
V01 → H01 裁决、到账与最终业务完成分开 付款后开通的条件不适用于诊疗处置 理赔获批即认为到账；付款核销仍独立
V11 → H01 计费依据、账单和现金分别保存 表计累计读数与订阅服务基数不同 VEE 修正覆盖已结账单；差额通过调整链核对
V13 → H03 按责任维度解释金额与修订 reserve（准备金）是估计，不能当确定应付或现金 reserve 变动当成付款；估计与银行记录分开
V21 → V07 交付依据与资金义务按来源关联 制造应收与运输应付方向相反 以签收作为全部附加费的依据；逐费用来源核对

04部分履约与守恒

子项数量守恒、一次交付只计一次，在零售、住宿和交易里都成立；数量能否回到原处各有规则，过去的房晚回不到库存，成交量可以被纠正减少。

适用前提：可定义整体、子项及数量单位；不可逆交接可辨认。

已学 → 变式 保留的机制 改变的条件 反例与验算
X02 → V04 实物只交付一次，单据分别保留责任 零售拆仓没有同样的跨法人内部定价 两家公司各开一张单据，计成两次发货；核对物理交付身份
V04 → V06 承诺分成数量可核对的部分 房晚带日期，过去一晚不能回到库存 跨日退房把已过日期的房晚放回库存；按日期检查占用
V08 → V21 身份、数量与交接事件连接 运输事件不证明质量放行或温控合格 有签收即判合格；质量与交接证据并列核对
V14 → V04 子项数量守恒与部分完成 交易纠正可减少成交量，退货规则不同 认为累计成交永远递增；纠正链重算数量

05未知结果与恢复

外部结果未知时先核对同一操作，这一步到处适用；效果能否撤回、由谁确认，随对象改变。

适用前提：操作有稳定身份，可查询外部效果或交给人工核查。

已学 → 变式 保留的机制 改变的条件 反例与验算
V04 → V05 外部交接后取消先核对效果 厨房制作可能不可逆，不能照搬仓库释放 制作已开始却重新发厨房单；同一制作身份不重复
H08 → X01 每项外部效果独立核对 解除临时限制不等于恢复已终止使用权 恢复账号时连带重开租户；当前 entitlement 仍要校验
H06 → H01 未知外部结果先核对同一操作 财务动作还需资金权限与开通 guard 超时重复收费；同一操作只产生一次预期效果
V22 → V10 外部效果确认后才释放资源 通信退役与现场隔离解除权威不同 本地标记退役即重配端口；外部未确认前仍占用

06时间与修订

按生效时间和固定输入重演、修正另记的做法可以迁移；计量基数和已定稿记录的更正方式要按变式案例重新确定。

适用前提：区间边界、时区、生效时间及输入版本明确。

已学 → 变式 保留的机制 改变的条件 反例与验算
V06 → V16 资源承诺区间与实际交接分别保存 租约独占权、酒店换房和计价规则不同 未来签约不占时段导致重租；区间重叠被拒
V20 → V19 工作记录绑定时间与输入版本 现场日志不会自动成为获批的 timecard 行程被算成可计费作业；只累计获批范围
H07 → X01 事件时间、修订与去重身份分开 BI 可重述，定稿账单需调整链 迟到用量直接覆盖已付账单；新调整与原账单可追溯
H04 → V19 有效费率与固定计算输入，修正独立 任职存续不等于客户可计费工时 用今天费率重算历史；原输入与调整均可解释
V22 → V11 发生时间、修订与计费依据连接 会话用量、表读数和套餐分母不同 按收到时间重复计量；按业务窗口和去重身份验算
V12 → H01 按生效日重演固定输入 本金、服务数量与会计期间基数不同 按入库日计算利息；生效日改变结果可复算

07来路与影响

沿依赖找出受影响的范围可以迁移，范围之内怎样处置不能：可达只划出检查范围，撤销、复核和返工由对应的专业权威决定。

适用前提：边方向、输入版本、访问范围与专业权威可区分。

已学 → 变式 保留的机制 改变的条件 反例与验算
V18 → V17 内容或数值身份与决定版本分开 法律特权和成绩批准依据不同 同值成绩换依据却沿用旧批准；版本变化需复核
H07 → H09 批准绑定固定输入与版本 数据重述不能决定文件签署效力 指标重算自动撤销签名；影响集合交给对应权威
H07 → H08 图路径定位待检查范围 依赖不证明攻击因果或响应权限 可达节点全被停用；候选范围与授权执行分开
V01 → V03 报告修订保留输入、版本与影响 临床报告与批次证书取样和专业权威不同 一份新结果抹去旧报告；新旧版本及使用者可查
V02 → V01 修订证据与决定引用分开 研究签名不替代临床判断 修正 eCRF 自动修改临床决定；重新交给临床责任人
V03 → V09 输入变化沿反向依赖找受影响证据 测量不确定度与芯片 signoff 规则不同 旧输入报告混进新发布；逐条验证基线身份
V07 → V09 发布包绑定一致的设计基线 制造工艺与 RTL 实现的证据要求不同 绿色报告来自两个约束版本；发布拒绝混版
V07 → V08 计划依据与实际投入谱系分别保存 混合与拆分不能用离散件身份直接表达 配方被当成实际投料；核对实际批次与数量
V15 → V07 技术版本变化定位下游影响 技术答复不自动批准商业费用或返工 新图纸直接增加应付；商业决定单独检查

08身份与范围

复合身份与有期间的成员关系可以迁移；同一租户之内还要叠加各自的访问规则和保留政策。

适用前提：唯一性域、成员关系与授权规则分别定义。

已学 → 变式 保留的机制 改变的条件 反例与验算
V17 → H04 人员与有期间的成员关系分开 学籍、任职与历史保留政策不同 注销成员关系删除历史成绩或工资；身份保留可回查
V17 → X01 租户、来源、对象的复合身份 同租户内还需课班和个人访问规则 同编号对象跨租户命中；命中和重建都隔离

09依赖与容量

依赖顺序与资源冲突分别求解；DAG 无环，同一个人仍可能被两项任务同时占用。

适用前提：前提图、资源容量、时间窗与目标分别给出。

已学 → 变式 保留的机制 改变的条件 反例与验算
H09 → H03 依赖先后与资源冲突分别求解 关账岗位与合同审批任务时限不同 DAG 无环，两项任务却争用同一人；另查资源时窗
