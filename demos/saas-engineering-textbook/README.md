## 构建与运行

```bash
node demos/saas-engineering-textbook/build/build.mjs
```

无需安装：Markdown 解析（marked 18.0.4）与图布局（dagre 0.8.5）的副本在 [vendor](vendor/README.md)。构建做的事见 [build](build/README.md)；输出放在一个平铺目录 `site/`，因为仓库要求每个目录有 README。正文改动一律改 Books，再重建。

本地预览需要从仓库根目录起服务（页面里指向 Vault 的链接是相对仓库根的）：

```bash
python3 -m http.server 8796 --bind 127.0.0.1
```

然后打开 `http://127.0.0.1:8796/demos/saas-engineering-textbook/site/index.html`。直接双击 `site/index.html` 也能读，只是 Vault 链接打开的是原始文件。

## 编订变更

主线 13 个文件按 Prose 审阅方法改写：四名审阅者共给出约 600 条意见（含标为保留的条目），主会话逐条裁决后整篇重写。大多数采纳；以下几类退回或改写后采纳：把书面语压成口语的建议（“弄懂”“根本处理不了”）改回书面语；删去承担内容的对照（如“结构有效只证明能表达”“1/1 或 9/9 不满足 10/10 政策”）的建议退回。

改动的性质：

- **叙述与设防**：删去作者的预告、自我说明与重复的免责声明；合成与来源的分界在每例开头说一次，未实测、未执行的验证和迁移边界各保留一处。
- **结构位置**：五步小标题统一为“步骤：名词短语”；表头、行标题改成并列的名词短语；问句式标题改为陈述。
- **措辞**：直译搭配、模型惯用搭配（形成、建立、承担、作出）、“回答”式拟人、公文腔字眼改写；对象作主语。
- **术语统一**：批量操作、详情页、合成、原语言术语、带类型的关系、简答、退款。

语义层面的改动（逐条）：

| 位置 | 改动 | 依据 |
|---|---|---|
| 企业机制第 3 章，终态矛盾一段 | 加一句：回执身份改变且结果版本或目标值也不合格的观察，配套实验目前没有记录成冲突，验收不会被挡住 | 最终定点复查 WB-02 残余失败 |
| 方法第 4 章、第 8 章 | 写明配套脚本对极大数值的累加与坐标计算没有处理，可能误报不可达或排序出错 | 最终定点复查 R4 残余失败 |
| H01，`paid` 一句 | 原句“只说明发票余额如何被结清”与下文相反，改为“只表示余额已经结清，并不说明是怎样结清的” | 审阅者 3 指出，主会话回读 Stripe 段落确认 |
| 阅读主线练习 1 | “不把退货动作等同于到账”在缺货题中所指不对，改为“退款单独核对到账” | 同上 |
| 第 2 章 | “两阶段交互”后列了三步，改为两步表述；“命令与响应可以写为”下方只有命令，改为“简化的匹配命令” | 审阅者 1 指出 |
| V04 | 删去正文残留的两个不透明 claim 编号，链接保留 | 交接要求读者正文不放不透明编号 |
| H01 末段 | 写给页面制作者的演示设想移出正文，由 `h01-windows` 图件实现 | 审阅者 3 |
| 多处练习 | 简答先给“能 / 不能”，再给理由；数字与反例不变 | 成文原理第 3 条 |

图件与面板的结构文字另由一名未参与撰写的 Opus 审阅者从生成页面抽出全部可见字符串审阅并修订，共 63 处；主会话复核后又把 4 处与改写后的正文对齐（EM-E01 步骤名、EM-E02 表头与两格、V20 收款步骤）。审阅中发现并修好一个缺陷：案例面板的检查定义标题把模板字符串原样显示。

机器核对：改写前后的数字、行内代码与链接逐文件比对，除上表删去的两个 claim 编号外没有丢失。连带修改两处 Vault 资产：`transfer-proposals.json` 中 9 条迁移出处的摘录换成新句子（整合校验要求摘录在正文中逐字出现）；`commercial-finance/validate-package.py` 的合成标记检查从只认 `synthetic` 改为也认“合成”。
