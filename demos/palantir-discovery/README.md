# 从诉求到决定 · Palantir 首次设计打样

状态：2026-10-03 第一版，可打开、可打印；没有做受众测试，方法仍是项目候选。作品是 [index.html](index.html)，直接用浏览器打开，不需要服务、安装或网络。输入是用户交来的 [设计交接包](../../vault/snapshots/local/palantir-design-handoff-20261003/README.md)，登记见 [入账记录](../../vault/intake/palantir-design-handoff-20261003.json)。执行者：Opus 5.5 主会话负责形式裁决、制作和验收；一个 Sonnet 只读代理复查了三篇公开来源。Luna 在本会话不可用，没有工作记在 Luna 名下。

## 解决什么

业务方说“希望 AI 每天自动催未处理订单”，读者容易直接讨论怎样做这个功能。作品要让第一次接触现场工作的产品、工程或研究参与者看出四件事：请求背后还没作的决定是什么；现有材料支持什么、不能支持什么；下一步为什么可能是补证、人工整理、小试验或不做；谁作决定，agent 的产物为什么不能代替授权和证据。

## 选定的形式

主作品是一页交互网页，因为最难的一件是让读者亲手看到“材料一变，能做的下一步跟着变”。同一文件打印成 A4，就是一份带 S0/S1 对照表的静态讲义，用于会上比较。

| 部分 | 解决的沟通困难 | 做法 |
|---|---|---|
| 请求标本 | 请求把做法、外部动作和原因揉在一句话里 | 把原句放到最大字号，三段分别标注：做法是候选、外部动作要单独授权、等待原因未知；下面用唯一的强调色写出还没作的决定 |
| 材料台与台账 | 读者分不清每张卡能推出什么 | 五张合成卡各列“能支持”和“不能推出”；任意加入或移出，台账逐行改写并标出来自哪张卡、哪一行在本次更新 |
| 分支板 | 选项容易被排成唯一答案或藏进标签页 | 四个分支同时可见，各自列前提和核对结果；暂缓与不做和其他分支等宽 |
| 裁决单 | 选择容易被读成已经批准的行动 | 选择后给出依据材料、判读结果、启动前的条件、尚不能证明的事项和决定者；按钮只模拟 |
| 反例、方法、对照、来源 | 深读与回查 | 错误推理链划掉结论并拆成三处缺口；方法卡、S0/S1 对照和几种声音按原身份分开 |

考虑过但没有做的方向：

- 线性步进（S0 → E1 → … → S1）：会暗示取证必须按这个顺序走，brief 明确说不要求线性流程，所以改成任意加减。
- 分支用标签页切换：互斥的标签页让人无法同时比较前提，按 [空间编排](../../kit/design/composition/layout.md)不拆。
- S0→S1 的动态说明或视频：这一版的核心是读者自己改材料，动态说明只能看不能改；若需要会前播放，再按 [分镜交接](../../kit/write/motion/narrative.md)另做，并单独检查驻留与字幕。
- 单独的 Slides：打印版已经给出同时可见的对照表，没有另外的沟通困难需要它解决。

这些方向只停在比较，没有做成样张。

## 改编说明

保留：全部身份标签、来源限定、合成标注、七项记录、四个分支、五个待补问题、X1 反例及其三处缺口、“未知不是 0”。

改动与新增：

- **C2 的条目对应。** brief 写“第 1、5、6、7 条讨论分拆推理、澄清行动、反证和异议”。主会话 2026-10-03 在浏览器里读了原页：第 5 条讲用细小迹象看整体并留意指向不合心意结论的迹象，第 6 条讲不空谈打算想什么、当下就想清楚。按顺序读，brief 的第 5、6 两项对调了。作品逐条写出原意，不再用四个名词概括；页面日期 2010-04-11 是新增。
- **C3 的研究计划。** 第一章的高层计划只有业务问题、研究问题、研究方法三项，参与者提问另列一节。作品照此写，不把参与者提问算作计划的一项。
- **C1 的持股。** 原文是作者声明 “long $PLTR”，作品写作“持有 PLTR 多头”。
- **E4 的“能支持”。** fixture v1 没有这个字段，brief 的材料表写着“一项可讨论的人工方案”，作品用 brief 的文字。
- **分支判读规则。** brief 只给出“条件 → 下一动作”。作品新增一条可见的规则，把每个前提按当前材料标成“有材料提示 / 不满足 / 未知”，并据此判定能否准备那一步。规则和前提的拆分都标为项目设计。按这条规则，S1 时 B1 前提不满足（E3 没有发信授权，E2 不能判定遗忘），B2、B3、B4 可以准备；S0 时四个分支都是证据不足。
- **B4 的前提。** brief 的第四行只写价值不足，fixture 的 O3 另有“或缺权限、缺样例”。作品按 fixture 两项都列，用“或”连接。

省略：brief 的媒介表、制作与验收要求、交付清单和“继续扩大研究”的书目缺口（Impro、GTD、The Looming Tower、Principles 等六个链接）。它们是给制作方的，不是给读者的。读者因此看不到这些书目的存在和缺口；作品只说方法依据限于 Portigal 第一章。

## 设计取舍

- 版式靠字号、字重、间距和细线分层，不靠彩色和嵌套卡片。只有一种强调色，留给“尚未作出的决定”“允许的下一步”和“决定者与分工”这三处人作判断的位置。
- 线型有图例：实线是演练材料里已经确定的事，虚线是未知或候选。状态同时用符号和文字（● 有材料提示、✕ 不满足、○ 未知），去色后仍可读。
- 运动只出现在状态改变的地方：台账里改写的行和分支的判读用 200 ms 淡入并上移 3 px，裁决单出现用 180 ms；没有滚动动画和装饰运动。减少动效偏好下全部关闭，“本次更新”标签和读屏通告照常给出。
- 这些是本作品的口味，不是 Kit 规则。保护语义的是：未知与零分开、推断不升级为事实、分支同时可见、停止选项与其他选项等宽、按钮不冒充真实动作。
- 仍未解决：页面在手机上很长（第一版在 375 px 下为 13,127 px），材料台和台账上下分开，窄屏读者要靠卡片下方的“台账：……；更新行：……”一行看到变化。

## 复用说明

可以迁移的是关系和检查方法：把请求拆成做法、动作和原因三段，再写出背后的决定；每份材料同时列能支持和不能推出；台账里未知不写成零，并标明来自哪份材料；所有分支和停止选项同时可见；输入改变时让已经作出的选择失效。依赖这个场景的是全部文字、四个分支、判读规则的具体前提和配色。

这些是一次作品里的候选观察，不是 Kit 组件或全局视觉规范，也不是已采纳的 Palantir 方法。下一步检查由协调者决定：私下审阅，或者在要声称理解改善时安排带对照的受众比较。
