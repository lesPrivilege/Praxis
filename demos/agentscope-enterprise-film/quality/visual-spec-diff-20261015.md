# AgentScope 第二版 · 视觉规格差距复核

2026-10-15。基线：Praxis `b9b87ef`，影片制作提交沿原记录 `e961e96`。用户反馈为“视觉效果不够好”，本轮先复核 spec 与 Claude artifact 的差距，没有重绘影片。主代理负责包含与裁决，两名继承当前模型配置的 explorer 分别只读核对参考施工链与 spec→实施；没有把它们记作 Luna 或 Astra。

## 2. 与实际 Claude artifact 的具体差别

| 比较轴 | 当前 AgentScope | 参考实际怎样做 | 应补进本项目spec的设计决定 |
|---|---|---|---|
| 图形是否承担推理 | tools页四个等大文字框，读完文字才知道合并与身份匹配 | SaaS教材F12保持四条记录和位置，只改配对连线，直接显出金额配平与身份各差40 | 明确哪一条连接、位置或形态变化能让结论成立；给小输入与反例，避免把关系只写在正文里。 |
| 对象连续性 | 定制展项重复ID，但phase常重建整层并交叉淡化；运输常用额外副本 | 金字塔第二章同一批材料从散落到分组，再局部聚焦；相机与对象重排共同解释论证 | 列出保留的可见对象、变化轨迹和去向；连续性不能只凭ID判定。不强制保留同一DOM节点，Canvas逐帧重绘也能保住视觉轨迹。 |
| 等待与拒绝可见 | ASK由三块说明面板、标签、暂停符号表示；批准路径完整，拒绝/超时没有形成原diff建议的独立段落 | Schema闸门让候选停在关口；三种拒收在不同位置发生并留下对象与reason code | 为已核实的不同结果画出不同出口或停留位置。超时行为须先核对目标版本，不能为增加分支而发明。 |
| 恢复与执行的空间关系 | recovery页列四行检查，位置不对应发生断点 | SaaS教材F09将动作、崩溃边界和此时留下的事实放到共同横轴；MC01回执上行距离本身解释ack与落盘的差别 | 固定共同参照，令观察断开、运行继续、持久记录、外部结果未知各有位置；从图中能找到恢复依据。 |
| 主体与画幅 | 标题/lead/底部结论条位置固定，主体多锁在1744×590；对象与说明面板争夺同一层级 | 金字塔总览后放大局部；MC01显露遮挡层；SaaS静态图按内容裁紧viewBox，图形占比随任务变 | 每场决定主角、主体占比、同时比较的对象与解释位置；可总览、聚焦、展开、收束，不为统一外壳让所有局部等大化。 |
| 视觉词汇与冗余 | 许多不同角色共享矩形+标签+箭头；重框、深色面板、标题与说明层反复出现 | SaaS施工把位置、字阶、线型、单一强调目标分别约束；独立版式审阅实际删掉重复站点、装饰线和边框标签 | 分清真实分组与装饰容器、主对象与注释、当前变化与固定背景；先做去框、去重复层级和对齐裁决。 |
| 运动与停留 | label/detail/phase时间主要从新字量估算；定制展项统一第6秒出现lead、第15秒主体入场 | 金字塔动作挂在语义词；MC01区分事件、叙事和镜头三个时钟；Schema的到达、检查、拒收、批准各有动作 | 分别安排认对象、看变换、读必要文字、理解结果；读速是下限约束之一，不包办导演时钟。无声片仍保留足够读取时间。 |

这些差距有实际帧与代码支持。39一般场不是39个完全相同的画面，表格也不是不合格图法；问题在于内容关系没有持续决定图法、尺度和动作。11定制展项里，执行目标7阶段仅有`state_change`，workspace7阶段另有一次`workspace_resolution`，闭环10阶段另有两次`material_transfer`；统计描述其实现，不用动效次数评美观。

跨场建议的落实也不完整：Message/Event/ReAct仅events进入定制展项；Workspace/Sandbox/Recovery仅workspace改写。它们尚未成为原比较稿要求的连续对象行程。失败到交付闭环已经补齐内容路径，本轮不再把它说成缺失；其余差距在固定工作台内换文字的观看形式。

## 4. 下一版应补的spec与试做顺序

每场施工前交付下面一张设计卡，先审三个关键帧和一段运动草图，再编码整片。它只用于本项目的修订，不晋升Kit全局规范。

| 字段 | 必须作出的决定 |
|---|---|
| 目标动作 | 读者看完能指出的一种关系或变化 |
| 主角与锚点 | 哪个对象持续存在；标签、内容、状态分别附着在哪里 |
| 空间论证 | 哪个位置、连接、包含、对照关系承担解释；哪些对象必须同时可见 |
| 画面主次 | 主体占比、注释位置、强调落点；哪些框与文字可删 |
| 三个关键帧 | 变化前、关键变化中、变化后，逐帧说清新增了什么认识 |
| 运动因果 | 谁先到达、谁才改变；停留/拒绝/重放是否有不同表现；转场后对象去哪里 |
| 时间 | 识别、动作、静读、结果消化分别如何安排，保留无TTS约束 |
| 否决样例 | 什么画面虽然字号/曝光通过，仍因图不能独立解释关系而退回 |

优先试做三组，再决定全片的视觉语言与迁移范围：

1. **Message → Event → ReAct**：同一张消息承载增量、调用与匹配结果，再回到下一轮，验证跨场接续与局部展开。
2. **Permission**：同一调用在闸门前等待，按已核实结果分路，验证可见的停留、确认、拒绝和执行边界。
3. **Workspace → Recovery**：固定材料与已绑定工作区，显示访问关系、观察连接和保存的事实；把策略对照与真实迁移分开，验证空间与恢复依据。Python/Java仍保留独立语义。

当前阅读稿、来源研究与事实修复可复用；先重做这三组的分镜与画面，不据现有52分钟长度直接重渲染全片。视觉审阅应能因主次不清、图形不承担关系或对象轨迹断裂而否决，不能以自动检查通过覆盖这些意见。
