# 三条关系语法的样板

2026-10-04，图件版本 `0.3.0`。这一页用同一份合成内容（一张破损古籍的调阅单）演示 Kit 里的三页判断怎样落到材料上：[成立程度与归属的标记](../../../kit/design/foundations/standing.md)、[精确指向](../../../kit/design/foundations/anchoring.md)和 [排列与刻度](../../../kit/design/foundations/placement.md)。每条语法做三级：只用文字，一张图，几张图连成一张；另各附一个反例。第三节是 `0.3.0` 加的。

## 这一页想让人带走什么

第一级是普及的部分：每句话后面写清“谁说的、成立到哪一步”和“对象 版本 位置”，表格和正文都做得到，不需要任何图件。后两级是提高的部分：同样的信息由线型、端点、括线和连线重复一遍，读者更快看见，但不多出一句新内容。页面上的两张第一级表格与下面的图由同一份输入生成，可以逐行对上。

第三节的第一级表格里，每件事自己带着“属于哪条线、什么时刻、排第几”；第二级把同一份内容排两次，一次只表示先后，一次按时间比例，两张并在一起看，等距的那张把一分钟和三小时画得一样远；第三级让三栏共用一条标尺，审核在规则 v3 生效之前、调阅单的改动在它之后，这两件事才读得出来。

前两节的第三级组合图是当时最想给人看的一张。“审核通过”这条证据连到规则 v2，分支的依据和新证据连到 v3；审核依据的是旧版规则这件事，没有哪一句话专门去说，是指向自己显出来的。

## 取舍

- 配色和线型沿用第一批：浅冷色，正文墨色，一种蓝只标等人决定的那一处。跨件的连线用最浅的一档灰，主干走在内容左侧的留白里，因为它只是文字指向的重复，不该和各件自己的线争。
- 反例“一条虚线回答三个问题”是照着第一批真实出过的毛病画的，不是凭空设想。反例“并排的两条线被读成同时”也是：第一批的版本图就是这样并排的，当时没有写读法。
- 时间图一律竖排。文字比刻度密，竖排时文字可以向下让开，由引线接回标尺；标尺上的记号不为排字挪动。
- 默认画法那张表写明了它只是这一族关系图的默认。
- 页面文字按 [Write / Prose](../../../kit/write/prose/README.md)写：先说做法，再给图；表头和小标题用名词短语。

## 范围与限制

内容是合成的，不是真实馆务。样板、生成器和两页 Kit 条目出自同一名制作者，没有读者或专业人员看过。验收范围见两份验收回执：[前两节](../../../docs/verification/relation-grammar-20261004.md)、[第三节](../../../docs/verification/placement-grammar-20261004.md)。本目录的图由 `svg-01-relations` 的生成器画，几何和安全检查在那边的 `node src/check.mjs` 里做，各份输入都在检查之内；第三节里“只排先后”的那一张由本目录的 `build.mjs` 从 `rail-day.json` 导出，两张反例图是本目录手工排的，这三张只看过渲染结果。
