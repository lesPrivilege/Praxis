# Drift · 网络、设备与浏览器观测看板

Drift 按“读到值 → 理解含义 → 比较变化”组织观测。概览显示当前读数、状态、来源与采集时间；字段详情解释读取方法；选定基线后，可逐项比较后续记录。评分暂不作为前置条件。

[产品说明与字段计划](product.md)维护现行术语、已实现字段和待补维度；[Opus 设计交接](design-handoff.md)说明 polish 范围、现有组件与验收要求；[polish 交付说明](design-polish.md)记录实际改动、token、状态、动效与未验证项。

## 启动与使用

在仓库根目录运行：

```sh
python3 demos/drift/backend.py
```

打开[本地看板](http://127.0.0.1:8765/)。后端使用 Python 标准库，绑定 `127.0.0.1`。`--port` 可指定端口，`--data-dir` 可指定仓库外的私有数据目录；按 `Ctrl+C` 停止服务。已启动的后端进程需重启才能加载本轮修改。

1. 打开页面恢复已有记录。点击“开始采集”获取一次新观测；入口说明外部请求的目标及发送范围。
2. 在观测概览读取当前值、状态、来源和采集时间。选择观测项展开方法详情；“显示本页详细值”控制整页敏感值。窄屏通过“返回观测列表”回到所选行。
3. 在观测基线页选定参照，在观测变化页比较。没有基线时，当前记录仍可独立阅读。
4. 在观测记录页回看历史。演示模式使用固定合成数据，与私有记录分开。

## 已实现观测

| 观测对象 | 当前读数 | 读取来源 |
|---|---|---|
| 设备环境 | 操作系统、版本、架构、时区、UTC 偏移、语言与编码 | 服务端运行环境 |
| 服务端代理配置 | 已检测到配置、未检出配置或读取状态 | 服务端可读取的 HTTP／HTTPS／ALL 代理配置 |
| 系统 DNS 配置 | nameserver 地址列表 | macOS `scutil --dns` |
| 浏览器属性 | 时区、语言、浏览器联网提示 | 当前页面提交的浏览器属性 |
| 服务端出口 IP | 各数据源返回的 IP；GeoJS 同时提供 ASN 与国家代码 | ipify、GeoJS 固定 HTTPS 接口 |
| 目标 DNS 解析 | 固定目标及解析所得地址 | 系统 `getaddrinfo` |
| HTTPS／TLS 连接 | 协议版本、加密套件、连接对端与 HTTP 状态 | 固定目标 HTTPS HEAD |
| 采集信息 | 采集状态、采集时间、采集耗时 | 各探针执行记录 |

每项状态分别保留等待采集、采集中、已观测、未知、失败与不支持。浏览器出口 IP、网络组织、网段、PTR 和请求耗时等增补项见[字段计划](product.md#后续维度)，其实现状态逐项登记。

## 记录与比较

真实记录保存在仓库外的 `~/.local/share/drift/state.json`，目录权限 `700`、文件权限 `600`。历史保留最近 30 次，固定基线单独保存。后续采集新增记录，替换基线由独立操作完成。页面显隐状态在切换记录或模式后重置。

比较按观测项、数据源和方法版本匹配，仅完整成功取得的值参与“相同／有变化”判断。未知、失败、不支持及方法版本不同的项保留为不可比。

2026-10-05 起，GeoJS 新扫描使用 `egress.geojs:v2`，补齐保留 ASN `65552–131071` 的过滤；有效 IP 保留，ASN 按未知处理。旧记录与基线维持原值及 `v1` 方法版本，因此旧 `v1` 与新 `v2` 的 GeoJS 项不可比，其余 11 项沿用原比较方法。[IANA 复核记录](../../vault/provenance/drift-providers-20260930/iana-as-numbers-registry.md)保留核对日期与重访条件。

## 运行与验证

单次运行一轮扫描：每个探针最多 8 秒，整轮最多 65 秒；外部响应上限 16 KiB，输入 JSON 上限 8 KiB。服务校验 Host、Origin 与 CSRF，静态资源使用白名单。保存字段由后端白名单控制。读取方式、单位和时间含义见[字段对应关系](product.md#当前字段与实现)。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 demos/drift/test_backend.py
PYTHONDONTWRITEBYTECODE=1 python3 demos/drift/verify.py
python3 scripts/validate_repository.py
```

2026-10-05 已完成三项缺陷修复：历史列表与服务端 30 条保留范围同步；过期选择重连恢复到有效记录或空态；保留 ASN 漏检修正。恢复期间改选历史和切换视图的竞态也已修复。后端 29 项合成测试通过，前端真实回环 API＋合成探针在 `1440×1000` 与 `390×844` 通过，外网请求及非预期浏览器错误均为 0。文案回归另覆盖旧记录名称与标准说明的兼容展示、原方法版本和具体错误保留，以及合成历史文件读取前后字节不变。JavaScript 语法、差异检查与仓库一致性验证通过。

测试使用隔离数据目录，截图和渲染文字清单写入脚本返回的临时目录。已检查键盘选行、详情展开、显隐与窄屏返回焦点，以及减少运动模式下的显隐操作。720 CSS px 重排检查与浏览器原生 200% 缩放分别记录，原生缩放、VoiceOver、其他浏览器和 OS 尚待验收。

2026-10-05 Opus polish 已执行：后端未改，29 项合成测试通过；前端回归在两个视口通过，新增整行点选、宽窄屏比较邻接与减少运动的检查，截图在 [evidence](evidence/README.md)。原生缩放、读屏、其他浏览器仍未验收，详见[交付说明](design-polish.md#没有验证的)。

真实业务基线、真实差异解释和业务接收仍待确认。下一步由 Astra 验收 polish，再沿其组件、设计 token、状态及动效语言补充字段。
