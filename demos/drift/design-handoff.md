# Drift · Opus 设计交接

状态：Opus polish 已于 2026-10-05 执行，结果与未验证项见[交付说明](design-polish.md)，待 Astra 验收。下文是交接时的原文。交接当时的会话未提供可调用的 Opus 模型；本轮已完成的 Sol 界面施工与后端修复记在 [README](README.md)，不作为 Opus 的交付。

## 目标与输入

Drift 是网络、设备与浏览器观测看板，按“读到值 → 理解含义 → 比较变化”组织。polish 应使读数、状态、来源和采集时间更易查阅，并保留单次观测与基线比较各自完整的流程。评分暂不作为前置条件。

现行产品定义、稳定术语及字段实施状态见 [产品说明](product.md)。历史报告和旧交接稿保留为溯源材料；此次施工以当前产品说明及真实实现为输入。

| 输入 | 位置 | 使用范围 |
|---|---|---|
| 页面结构 | [index.html](index.html) | 导航、页头、操作区、工作面、明细栏 |
| 交互与展示 | [app.js](app.js) | 五个视图、读数表、来源详情、采集和恢复状态 |
| 设计 token 与布局 | [style.css](style.css) | 现有配色、字体、边框、控件、响应式与运动规则 |

| 可复验合成流程 | [verify.py](verify.py) | 隔离 API、合成探针、截图与渲染文字清单 |

## 沿用的组件与语言

当前工作面由 `.app-shell`、`.sidebar`、`.topbar`、`.content-grid` 与 `.inspector` 组成；`.signal-table` 承载读数及按属性对照，`.summary-strip` 承载采集概况，`.source-card` 与 `details/summary` 承载来源和方法。

颜色与表面使用 `--ink`、`--muted`、`--quiet`、`--line`、`--paper`、`--canvas`、`--sidebar`、`--wash`、`--amber`、`--amber-bg`、`--green`。Opus 在现有组件中完成密度、层级、选中、焦点与反馈的 polish，并将采用的 token、状态和动效参数留在同一实现。后续字段沿该版本扩展。

已有采集状态为等待采集、采集中、采集结束与采集失败；观测项保留已观测、未知、失败和不支持。连接恢复、空历史、无基线、部分结果、显隐、模式切换与移动端往返均有行为契约。字段值在取得后更新，过渡反馈围绕实际状态变化设计。

## 页面任务

| 视图 | 首要内容 | 关键交互 |
|---|---|---|
| 观测概览 | 当前读数、状态、来源、采集时间 | 采集、显隐、选行、展开方法 |
| 观测基线 | 所选参照及其时间 | 明确设置或替换基线 |
| 观测变化 | 相邻的当前值、基线值与比较状态 | 筛选变化、查看字段说明 |
| 观测来源 | 来源名称、读取方法及字段范围 | 按需查看技术信息 |
| 观测记录 | 历史时间、状态与摘要 | 切换记录并保持阅读位置 |

文案采用凝练、平行的标题、表头、字段名和按钮；正文回答值是什么、来自哪里、何时取得。方法和必要限制放字段详情。额外发送的数据与请求目标在采集入口说明。现行词表由产品说明维护。

## 合成数据与公开演示

使用内置演示样本或 `verify.py` 的隔离合成输入。示例 IP 使用文档地址段，主机名与设备属性使用构造值；浏览器区域属性在测试上下文中固定。截图、清单与公开附件交付前检查真实 IP、私有主机名、用户路径和可关联的原始指纹。分享测试日志时去除本地输出目录、令牌和环境元数据；脚本的本地定位输出仅供操作者使用。公共 API 与固定测试目标的域名作为方法来源保留。

原始私有观测、默认私有状态文件及历史诊断附件留在本地。后续字段使用合成样例时明确其“候选／尚未实现”身份，实际界面继续按已实现字段展示。

## 验收与下一步

1. 无基线时首屏可读当前观测；值、来源与时间相邻，部分结果保留未知状态。
2. 宽窄屏比较按属性保持当前值与基线值的邻接；隐私操作的文案和作用范围一致。
3. 键盘可选行、展开方法及返回原行；采集、断连恢复、历史裁剪与模式切换保留现有回归。
4. 以实际画面检查字阶、密度、对比、焦点、减少运动和缩放。720 CSS px 重排与浏览器原生缩放分别报告。
5. 交付代码、实际截图、最终结构文字清单及采用的组件／token／状态／动效说明。独立审阅按 [Praxis Prose](../../kit/write/prose/review.md)逐项裁决。

Opus 完成 polish 后，Astra验收设计与行为，Sol 6.1 再按[字段计划](product.md#后续维度)分批补充。每批先固定数据契约，再沿 Opus 的现有组件、设计 token、状态与动效语言接入。
