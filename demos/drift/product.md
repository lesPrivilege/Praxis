# Drift 产品说明与字段计划

状态：现行。更新日期：2026-10-05。运行入口与验证记录见 [README](README.md)，视觉施工见 [Opus 交接](design-handoff.md)。

## 产品定位

Drift 是网络、设备与浏览器观测看板。产品按“读到值 → 理解含义 → 比较变化”组织，评分暂不作为前置条件。

概览回答当前取得了什么；字段详情回答这个值是什么、来自哪里、何时取得；变化页把当前值与选定基线按属性并列。没有基线时，单次观测仍可独立阅读。数据源给出的分类、归属和地区按各自来源保存。

## 文案与状态

标题、字段名、表头、状态与按钮使用凝练、平行的短语。界面以对象、值、状态、来源与采集时间表达测量范围；方法和会影响读值判断的具体限制进入字段详情。额外发送的数据及请求目标在采集开启入口说明。

| 对象 | 现行用语 | 表达约定 |
|---|---|---|
| 发起请求的服务端 | 服务端出口 IP | IP 与数据源署名相邻 |
| 当前浏览器的请求出口 | 浏览器出口 IP | 当前尚未实现采集，登记在候选范围 |
| 记录取得时刻 | 采集时间 | 按当前浏览器时区显示；详情保留完整时间 |
| 单项执行时长 | 采集耗时 | 单位 ms，按当前计时范围解释 |
| 网络归属编号 | 自治系统编号（ASN） | 编号原值与未知状态分别保留 |
| 国家字段 | 国家代码 | 使用数据源返回的代码 |
| 服务端代理配置 | 已检测到配置／未检出配置 | 读取失败按实际失败状态显示 |
| 浏览器联网属性 | 浏览器联网提示 | 详情说明读取 `navigator.onLine` |
| 记录状态 | 等待采集／采集中／已观测／未知／失败／不支持 | 显示实际采集状态及具体原因 |
| 功能覆盖 | 尚未实现 | 用于字段计划或覆盖清单，区别于某次采集未知 |

数据源使用 ISP、hosting、mobile 等分类时保留其含义与出处；“家宽”需要独立可靠的分类依据。“未检出代理”仅用于相应检测结果。没有可靠来源、解释规则或权重依据时保留未知。

界面使用稳定的产品名称；`source_id`、`comparison_key`、`duration_ms` 等字段留在实现契约。旧记录的值、状态、时间与方法版本原样保存；现行展示词典负责已知字段的名称和说明。

写作按 [Praxis 成文原理](../../kit/write/prose/grammar.md)及[审阅方法](../../kit/write/prose/review.md)执行，并取用用户指定的 ASD-STE100 明确、具体、术语稳定原则。本轮未完成该标准全文核验，未采用其受控英文词表或作合规认定。

## 当前字段与实现

以下均对应当前代码；“服务端”指运行 `backend.py` 的采集端。“设备环境”取该运行环境，“浏览器属性”取打开页面的浏览器。

| 界面字段 | 实际实现 | 值、来源与时间含义 |
|---|---|---|
| 操作系统、版本、架构 | `local_probe` → `local.os` | `platform` 读取的服务端环境属性 |
| 本机时区、UTC 偏移 | `local_probe` → `local.timezone` | 时区名称及偏移秒，界面格式化为 UTC±hh:mm |
| 本机语言、编码 | `local_probe` → `local.locale` | `locale.getlocale()`；缺项保留未知 |
| 服务端代理配置 | `local_probe` → `local.proxy` | `urllib.getproxies()` 可读取的配置检出状态 |
| 系统 DNS 配置 | `dns_configuration` → `local.dns` | macOS `scutil --dns` 的 nameserver 地址；其他 OS 返回不支持 |
| 浏览器时区、语言、联网提示 | `validate_browser`、`Collector._scan` → `browser.context`；前端 `startScan` | 当前页面通过本地 API 提交的三个浏览器属性 |
| 服务端出口 IP | `parse_provider` → `egress.ipify`、`egress.geojs` | 各数据源看到的本次请求 IP，逐源显示 |
| 自治系统编号、国家代码 | `parse_provider` → `egress.geojs` | GeoJS 的 `asn`、`country_code`；缺项与保留 ASN 按未知处理 |
| 目标 DNS 解析 | `dns_probe` → `dns.example`、`dns.cloudflare` | `getaddrinfo` 返回的固定目标地址列表 |
| TLS 版本、加密套件、连接对端、HTTP 状态 | `tls_probe` → `tls.example`、`tls.cloudflare` | 固定目标 HTTPS HEAD 的连接与响应信息；元数据未取得时保留状态 |
| 采集时间 | `Collector._scan` → `observed_at` | 本机记录的单项采集结束时间；展示时使用页面时区 |
| 采集耗时 | `Collector._scan` → `duration_ms` | 单项采集整段执行时间，包含探针启动、解析及请求开销，单位 ms |

实现入口：[后端](backend.py)、[前端展示与交互](app.js)、[后端测试](test_backend.py)、[合成浏览器回归](verify.py)。单次出口观测取得一个地址，地址族可由该 IP 识别；分别测量 IPv4 与 IPv6 是后续采集项。

## 后续维度

以下为增补登记，均须在 Opus polish 完成后沿现有组件接入。表中的读取方向是待核验方案；来源尚未确定的条目保持待选，不配置新端点。

| 顺序 | 维度 | 当前状态 | 增补读取与表达 | 来源、时间与缺失契约 |
|---|---|---|---|---|
| 1 | IPv4／IPv6 | 已取得单次出口 IP；独立地址族展示与双栈分别采集待补 | 地址族由有效 IP 派生；双栈分别选择明确支持该地址族的读取方式 | 分别保留目标、来源、地址族与采集时间；某地址族未取得时单独记状态 |
| 1 | ASN | 已实现 | 完善编号与来源解释；沿用保留范围检查及方法版本 | IANA 规则核对日期与 GeoJS 采集时间分别保存；未知保持未知 |
| 1 | 网络组织 | 尚未保存 | 候选读取数据源的组织字段；先核验字段语义，再扩白名单 | 来源待核；保留组织原名、字段来源、数据更新时间与采集时间 |
| 2 | 公告网段 | 尚未实现 | 候选接入明确视角的路由公告数据，独立记录前缀及关联 ASN | 数据源、观察视角与更新时间待定；缺失按来源结果标记 |
| 2 | 注册网段 | 尚未实现 | 候选读取注册机构的地址分配记录，与公告网段分列 | 注册数据来源及接口待核；保留记录范围与更新时间 |
| 2 | PTR | 尚未实现 | 候选执行地址的反向 DNS 查询，独立展示返回名称 | 记录查询地址、解析来源、采集时间；无记录、超时和查询失败分别处理 |
| 2 | DNS 增补 | 配置与目标解析已实现 | 再评估 TTL、解析来源信息及查询耗时的实际读取机制 | 每项独立来源与计时范围；现有 `getaddrinfo` 结果只提供目标地址 |
| 2 | 请求耗时 | 尚未实现；已有采集耗时 | 明确 HTTP 请求或连接阶段的起止点后新增计时项，单位 ms | 保存目标、计时方法及方法版本；沿用“采集耗时”展示现有整段时间 |
| 条件项 | 网络类型 | 尚未实现 | 按数据源能力接入分类原值，如 ISP、hosting、mobile | 数据源、分类定义与更新时间待核；无法支持分类时未知 |
| 条件项 | 代理线索 | 已有服务端配置检出 | 额外线索逐项登记检测机制和依据，保持来源独立 | 记录已检出、未检出或未知及对应方法；来源变更时复核 |
| 条件项 | 大致地区 | 已有国家代码 | 按数据源能力评估更细地区字段 | 保留数据源粒度与更新时间；尚未提供更新时间时明确缺失 |
| 待定 | 浏览器出口 IP | 尚未实现 | 先确定浏览器侧读取目标及兼容方式，再加入采集契约 | 入口说明请求目标和发送范围，独立于服务端出口记录 |

增补字段至少需要：明确的读取机制、单位或值类型、来源身份、采集时间、数据更新时间（如来源提供）、缺失状态、比较方法与验证样例。当前实现尚未保存第三方数据更新时间，采集时间继续表示本次取得时间。时间语义分别维护。

每批先以合成样例验证“读数 → 详情 → 比较”，再接实际采集。需要新增字段或接口时，同步后端白名单、失败状态、比较方法版本及回归。评分须另有可靠规则、样本和权重依据。

## 后端待闭合事项

- **已闭合**：历史保留同步、过期选择重连、保留 ASN 漏检；旧基线保留及恢复竞态均有合成回归。
- **真实验证待完成**：由使用者确认采集实例、预期环境、用途和候选记录，选定真实基线，再接收一次真实差异解释。
- **新增字段待实施**：上表列出的来源选择、字段白名单、读取机制、数据更新时间与失败处理。
- **跨环境待验证**：其他 OS／浏览器、数据源实时准确性与长期采集表现。

交接与公开演示使用合成输入、文档示例地址及构造名称。实际采集的敏感值留在私有记录；公开产物交付前检查真实 IP、私有主机名、用户路径与可关联的原始指纹。
