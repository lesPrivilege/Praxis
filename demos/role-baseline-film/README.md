# 视频能力测试 · 岗位职责与薪酬方案补充说明

一条 97 秒的中文说明片和一份可以独立转交的 txt，讲同一件事：一个企业 AI 应用方向的产品经理岗位，核定方案是税前 23K、15 薪，候选人期望把固定月薪调到 29K 左右。片子给薪酬审批人看，第三人称，以岗位为主语。

这次制作同时是一次测试：不给施工步骤，只给题目，看 workflow 能不能从 [Kit 入口](../../kit/README.md)逐层取到需要的规则、参考和旧管线。材料全部是合成的。

## 片子讲什么

| 段 | 这一段要让审批人看到的 | 画面 |
|---|---|---|
| 01 方案 | 两个数差 6K，15 薪不变 | 同一条标尺上的 23K 实条和伸到 29K 的虚框 |
| 02 范围 | 23K 是按传统产品经理定的，岗位的范围比它大，多出来的工作第一个项目就会遇到 | 九格工作；定价范围的括线停在第三格，岗位范围的括线一格一格伸到第九格；一条只表示先后的线，晋升在项目之后、时间未定 |
| 03 成本 | 做这些工作每月要付 400–500 美元的工具费，公司没有地方接这笔钱 | 三项订阅叠成一根条；公司一栏三个空位都写着未建立，工具费落进个人一栏 |
| 04 测算 | 按 23K 付完工具费剩 15.8K，税前到 29K 才回到 20K | 两根柱共用一条标尺，五险一金、个税、工具费依次从顶上划走，余下的部分对着 20K 的线 |
| 05 诉求 | 审批的是哪一个数，它有什么前提，另外三项怎样安排 | 29K 那根柱留下，工具费一段改成虚线框；右侧是诉求和四行条件 |

## 内容口径

来源有三份：用户贴入的一份薪酬补充说明（模型起草的长稿）、用户随后口述的原始想法、用户补来的一份参考短稿。三份有出入时按用户口述的为准。按 [证据与来源](../../dsh-praxis/kit/writing/evidence.md)，这是一次改编，变动如下。

| 项 | 做法 |
|---|---|
| 保留 | 23K 与 29K 左右、15 薪；职责清单；每月 400–500 美元并随项目浮动；公司不统一采购是 29K 的前提，统一采购或报销后基线另行商定；驻场差旅住宿另行安排；承担 FDE 方向职责后复评；受职级限制时的替代结构；历史薪酬不作上限 |
| 删去 | 长稿首尾写给提交者的话（定位建议、“提交前保留的三个边界”、适用说明），以及“在尊重现有制度的基础上”“适当考虑”一类缓冲措辞 |
| 改动 | 长稿把“税后约 20K”和“工具费另行支持”分成两个口径；用户口述的是扣完五险一金、个税和工具费之后仍有 20K，29K 由此倒推。全片和 txt 按后者 |
| 新增 | 扣缴拆解、汇率 7.1、工具费三项构成和年包差额是为了测算和图形补的合成数字；“现行核薪口径比较固定，没有项目激励等安排”来自用户口述 |
| 只在 txt 里 | 历史薪酬不作上限、驻场补贴、专项激励、愿意承担更完整职责、测算口径。片子的四行条件只到差旅住宿、复评和替代结构 |

念白在第一稿之后按用户的要求没有再改；后来收的口径只进了 txt 和画面文字。所以 txt 写的是“不全是晋升之后才增加的责任”，念白说的是“不用等到晋升”。

## 取用中的观察

Kit 版本是 main `02ca9ea` 加工作区里未提交的改动。只有一次制作，没有对照组。

- 从任务入口到旁白体例、标记、排列和旧管线，一路都有链接，没有断点。
- “感知不到的部分”“自查通过之后”两条备用做法，从内容表达的入口读不到，这次是从金字塔片的项目说明里取到了同样的做法。[内容验收](../../dsh-praxis/kit/publish/verification.md)已加一句入口。
- 把 txt 编成 Word 和 PDF 时没有回到 Publish。事后对照 [内容编排](../../dsh-praxis/kit/publish/html/composition.md)，标题、段落和表格各自承担的内容身份没有出入。
- 测算图里的参考线和差额括线画成了虚线，旁边各写了词（收入预期、差）。[标记页](../../kit/design/foundations/standing.md)的默认分配管的是关系图；数量图上的线型按 [图形编码](../../kit/design/composition/encoding.md)写进图里即可，不需要另立规则。
- 引擎和管线是从金字塔片拷来的第二份。两条片子的目录和配音线路不同，没有抽公共层。

## 拿这套管线做下一条短片

一两分钟、几场画面、一条合成配音的片子可以从本目录起步；多章长片、要章节卡和出处行的，用 [金字塔第五版](../knowledge-film-001-pyramid-cut5/README.md)的目录。

1. 复制本目录。`film/` 里的 `engine.js`、`kit.js`、`boot.js`、`gsap.min.js`、`index.html` 和 `build/` 里除 `doc.py` 以外的脚本可以原样带走，绑定本片的地方见第 3 步；`film.css` 保留到 “this film” 注释为止。
2. 重写 `narration.json`（分段、停顿、章节）和 `film/scenes.js`（画面）。场景的写法和可用的工具见金字塔片的 [施工约定](../knowledge-film-001-pyramid-cut5/film/AUTHORING.md)。
3. 改三处与本片绑定的地方：`build/mix.py` 里按段号写的铺底安排，`build/check.py` 里的字数上限和片尾静止段的段号，`build/render.py` 与 `build/check.py` 里的默认片名。
4. 按下一节的顺序跑五步。只改停顿不改字时，配音不会重新合成。

## 怎样做出来的

念白稿 `narration.json` 先合成语音，得到每个字的时间；画面是一张网页舞台，所有动作挂在念白的词上；渲染器逐帧截图编码。改念白之后重跑下面五步，画面跟着新的时间重排。

```bash
python3 build/voice.py
```

```bash
python3 build/mix.py
```

```bash
python3 build/render.py
```

```bash
python3 build/screen_text.py
```

```bash
python3 build/check.py
```

依赖和凭据见 [管线](build/README.md)，画面见 [film](film/README.md)。全部由主会话（Opus）完成。

## 做了什么检查、没做什么

做了：

- 成片检查七项全部通过，结果在 `out/check-report.json`：容器与时长、成片与重渲帧一致（最低 34.9 dB）、无长时间静止、无空白帧、念白 451 字不超过 500、转写比对、响度（−15.0 LUFS，真峰值 −1.9 dBFS）。
- 转写比对由另一个模型听写念白，数字按数值比对，五段的字符匹配率在 0.968 到 1.0 之间。金额全部被听成了正确的数。余下的差异：`n2` 的“照”听成“赵”、`n4` 的“它”听成“他”，是同音字；范围一段多听出一个“的”；`n7` 句首的“按”没有被写出来；`n9` 的“两万九是按”听成“29000 元”，“基线”听成“期限”。后三处要靠人听。
- 配音逐段核对：返回的文字与文稿一致，每段语音都有时间戳覆盖，基频在 86–106 Hz 之间。
- 画面：主会话按 3 秒一帧看了全片联络表，另看了各段完成时的大图。
- Word 与 PDF：PDF 两页逐页看过，测算表与它的单位行在同一页；Word 读回核对了六个标题和表里的 21 个单元格，只用系统预览看过首页，没有在 Word 里打开。
- 念白的句式自查：对照否定 1 处（`n4`“不用等到晋升”，区分本身是论点），自问自答、数目预告、预告与表态都没有。

没做：

- 制作方听不了声音，也没有按实际速度看过成片；节奏和读音由用户复看。
- 没有做独立冷读。交给未参与撰写者的一次冷读启动后随会话中断，没有交回意见；成文和画面文字只有主笔自查。
- 没有受众测试。
- 数字是合成的，没有对照真实的缴存比例和税率核对。
- 配乐是程序合成的保守铺底，没有经过听审。字体、合成语音和 GSAP 的对外使用授权没有核对。
