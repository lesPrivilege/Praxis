# ADR-041：dsh-praxis 的项目与产物位置

日期：2026-10-25。状态：accepted。按 [下一轮工单](../../dsh-praxis/work-order.md) A1 施工，四项开工决定由用户按建议确认：
- 项目登记放在 Praxis 数据里；
- 选模板；
- 违例只报不搬；
- RSI 修订进覆盖层。

主会话（Claude Opus 5.5）设计、实现并验证。

## 问题与依据

产物只有“仓库相对”或“绝对”两种路径，没有项目这个对象：看不出一件产物属于哪件工作，也管不到中间产物。三个试点的结构各不相同，没有一套固定目录能不搬文件就套上：

- `projects/jev/`：底稿在 `draft/`，网页在 `site/`，与构建脚本、构建源放在一起，研究登记在 `research/`。
- `projects/palantir/reading-list-series/`：成片 mp4 与配音 wav、输入 json 同在 `out/`。
- `projects/dsh-praxis-explainer/`：两个文件平放在根目录。

## 决定

- **项目是一个目录，带布局。** 记录根目录、名称、用途，以及布局：
  - `draft` 放底稿；
  - `build` 放中间产物；
  - `final` 放最终产物。

  每个角色是一组相对根目录的 glob。登记时从模板开始（`standard`：`draft/**`、`build/**`、`out/**`），给出的角色整组替换模板对应的部分。不同结构靠模式表达，不为单个项目加特例。
- **产物属于包含它的最深一个项目。** 项目可以嵌套。产物记录不另存项目，读取时按路径计算，所以已有产物不需要迁移：重新归属不改版本与 review。
- **位置是登记的一部分。** consume 登记的文件必须在已登记项目里，否则整次拒绝，提示先登记项目；运行记录里每件产物带上项目。
- **违例只报不搬。** 只增加两种信号：
  - `misplaced`：产物不在任何项目里，或不在所属项目的底稿与最终产物位置；
  - 最终产物路径里有没登记的文件，列在 upkeep 的 `projects` 下；目录说明 `README.md` 不算。

  中间产物的数量与大小不进清单。处理方式由人决定：改布局、移除产物记录，或者自己挪文件。
- **工具：** `praxis_projects` 列项目，或查一个路径属于哪个项目；`praxis_project` 登记或修改项目，带 revision。控制面的“产物”视图按项目分组，项目头部列出布局与未登记的最终产物。
- **登记存在 `dsh-praxis/data/projects.json`。** 项目目录里不写标记文件。

## 验证

- `node --test` 26 项。新增的项目测试覆盖：
  - 项目外的交付被拒；
  - 布局校验与根目录冲突；
  - 模板补全未给出的角色；
  - 最深项目优先；
  - 角色与 `misplaced`；
  - 未登记的最终产物，跳过 README 与中间产物；
  - 放宽布局后信号消失，文件不动。
- [验收探针](../../scripts/check_praxis_acceptance.py) 14 项，新增 `artifact_needs_project`：项目外的交付在命令行被拒，经 MCP 登记项目后命令行可用。
- 三个试点已登记。回执见 [项目与产物位置](../verification/dsh-praxis-projects-20261025.md)。

## 没有做的

- 只有一个模板；等更多项目出现共同结构再加。
- 项目根目录挪动后，要手动改登记。
- 产物路径仍按仓库或绝对路径存储，按项目相对存储留到 release 拆分（B1）。
