# ADR-011：由文档结构承担使用指引

状态：accepted（2026-09-20，Astra 裁决）

## 问题

根与 Kit 的入口重复解释架构和未实现事项，读者仍需自行拼接任务、模板与验收。ADR-009 的工作入口已确立，本次将其落实为文档职责和消费路径。

## 决定

README 以本目录职责、任务入口、产物和当前状态组织；定义与边界进入契约，操作进入指南或模板，理由进入架构说明与 ADR，覆盖证据进入验收回执。具体规则见 [文档结构契约](../architecture/documentation.md)。

场景模板的版本、权限、恢复和接收字段与验收反例同时维护。权限与真实数据边界在对应操作契约中保留。历史来源、审阅与 ADR 保留原有表述。

## 选型与维护

外部研究由 Luna 查阅 6 个官方页面；证据和候选见 [文档实践](../../vault/distilled/themes/documentation-practices.md)，逐 URL 记录见 [研究登记](../../vault/intake/documentation-practices-2026-09-20.json)。Astra 的消费裁决如下。

| 实践 | 本轮选型 | 落地 |
|---|---|---|
| Diátaxis：内容按阅读需要分工 | 采纳职责区分，作为维护检查 | README 路由、契约查阅、理由与 ADR 分离 |
| GOV.UK：任务来自使用者需要；检查全程可用性 | 采纳任务入口与走读方法 | 入口关联产物与下一责任；真实使用效果单独记录 |
| Kubernetes：任务页有前置、步骤和下一步 | 采纳页面骨架所需部分 | 场景、工作系统和环境入口 |
| GitLab：工作流导航、唯一文档位置与反馈 | 采纳任务导航、唯一维护位置和修订回路 | 根/Kit/docs 入口与 evolution |
| 全站统一页面标签、四套目录、固定五字段 README | 延后；不同目录具有不同职责 | 按任务选短列表或表格 |
| 自动孤立页报告、访问遥测、文档站点框架 | 延后；由真实使用断点触发 | 当前采用人工导航走读和仓库检查 |

这些选型采用方法和结构；外部页面没有提供 Praxis 使用效果的证据。新研究的原网页及依赖未快照，当前可离线消费登记与摘要。

## 迁移与验收

保留既有主要路径，更新导航。新场景使用补齐字段的模板；在途场景对照接收、版本与恢复要求补齐。通过本地链接、登记一致性与合成任务走读检查，真实用户使用效果待消费任务反馈。
