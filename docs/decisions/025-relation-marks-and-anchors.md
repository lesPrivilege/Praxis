# ADR-025：成立程度的标记与精确指向进入 Design Foundations

日期：2026-10-04。状态：accepted（Design 知识的落位；实现留在 demo）。用户裁决；Claude Opus 5.5 主会话编订，三个 Claude Sonnet 只读子代理清点与对照，两个 Sonnet 子代理冷读走读。Luna 在本会话不可用。

## 问题

可编辑原生 SVG 的第一批交付了四个关系图件。独立复查指出，同一条虚线在这批图里表示三种意思。回头清点，四个件对“成立到哪一步”用了三套词，对“依据是什么”有两个件写结构化的指向、两个件只写一句话。仓库别处的样张和演示里，虚线有三十多种用法，指向有近三十种写法，各自成立，彼此没有共同的说法。

用户在 2026-10-02 已经裁决过同类问题（ADR-018）：泛化的判断留在 Kit，原子是后续的取用方式。这次用户同意按“成立程度与归属”“精确指向”的次序做，并要求样板兼顾普及与提高。

## 决定

1. Design / Foundations 新增两页，与 [构成关系与问题地图](../../kit/design/foundations/relations.md)并列：[成立程度与归属的标记](../../kit/design/foundations/standing.md)和 [精确指向](../../kit/design/foundations/anchoring.md)。两页给问题、不随画法改变的约束、一套默认和最容易犯的错，不给色值和尺寸。
2. 不规定某一种线型的含义。规定的是：一张图里一种画法只回答一个问题；回答先写成词，画法只是重复；图例由同一份输入得出；不认识的状态拒绝画。“实线已成立、虚线未生效、实心已确认、空心未确认、强调色等人决定”只是关系图一族的默认。
3. 一条指向分开写对象、版本、范围，缺哪一层标哪一层；位置相邻是呈现，不是指向；对象出新版本，旧指向不跟着走。
4. 每页给三级做法：只用文字，一张图，几张图连成一张。第一级不依赖任何图件，任何材料都能做到；后两级不新增信息。这是对“普及与提高并重”的落实：普及的是第一级和那几条约束，提高的是做得好的图和组合。
5. 词表、默认画法、指向和组合的实现留在 `demos/editable-native-svg/svg-01-relations`（版本 0.2.0），样板在 `demos/editable-native-svg/grammar-specimens`。它们是候选实现，不是 Kit 的共享组件。

## 与既有决定的关系

沿用 ADR-018 的层次：泛化判断在 Kit，生成器、样板和输入是它的取用。不改 ADR-002：共享运行组件的晋升门槛照旧，本决定晋升的是知识说明。不改 ADR-017：没有新增优先参考卡；[注释保持邻接](../../kit/design/references/curated/note-adjacency.md)照旧，精确指向一页写明了两者的分工。内容上的定义仍在 [共同工作语法](../../kit/grammar/work.md)和 [证据与来源](../../kit/write/shared/evidence.md)，这两页没有改。

[图形编码](../../kit/design/composition/encoding.md)原有的“不要默认虚线在所有领域都表示候选”保留，并加了一句指向新页。问题地图的 G03、G11 两行各加了一个链接。

## 没有采纳的

- 一份全仓通用的状态枚举。各处的状态词回答的问题不同，合并会丢掉区别。
- 把 W3C Web Annotation 的数据格式或 PROV 的词表搬进来。只对照了分法和用词，见 [提炼页](../../vault/distilled/relation-grammar-20261004/README.md)。
- “有没有这个值”（零、缺失、不适用）的画法。它属于数量与值状态，留给后续批次。

## 验证与限制

使用证据：四个生成器和一个组合件改用同一套词与指向后，自动检查和浏览器实测通过；一页样板；两次冷读走读。范围和结果见 [验收回执](../verification/relation-grammar-20261004.md)。全部是合成内容，出自同一名制作者，没有不读这两页的对照组，没有读者或专业人员看过。

重访：真实任务里默认分配行不通；指向的三层分法装不下某种目标（时间范围、字段集合）；冷读或真实使用出现“读了这两页仍然画错”的反例。
