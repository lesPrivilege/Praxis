# ADR-020：企业工作侧的入口校订与写深条目的检查

日期：2026-10-02。状态：accepted（入口措辞与文档体例）；九类能力语法候选与交付生命周期延后。用户交来审阅时没有另加说明，Opus 5.5 主会话按既有的交接方式对照本地、裁决并编订，Sonnet 5.5 只读代理做前后走读。Luna 在本会话不可用。改动没有提交，用户可以整体否决。

## 问题

一份没有署名的《内容架构与能力语法审阅》读的是远端 `main@3417dca`。它认为仓库骨架已经够用，该做的是把宽覆盖写深，并提了四件事：入口改成“问题、最小阅读、产物、何时停止”；在现有位置区分语法、场景取值、做法、工具能力与证据；九类能力语法的深化候选；Artifact 的生命周期与交付检查。

本地已按 ADR-016、019 改过入口。逐条对照并在改动前走读六个任务之后，要裁决的是：

- 审阅点名的三处入口问题，本地还剩哪些。
- 企业工作这一侧的三条路线在本地能不能走通，断在哪里。
- 该不该按“语法、场景取值、做法、工具、证据”重排目录，该不该为个人经营或驻场交付新建顶层。
- 九类候选现在能不能写进 Kit。

## 决定

1. 目录不动。不新建个人经营或驻场交付的顶层目录，不按内容种类另建目录，不加全站 frontmatter、种类元数据或自动路由。审阅自己推荐的也是这一种。
2. 入口补三句，改两处：
   - [Kit 任务入口](../../kit/README.md)写明哪些请求不必进分支：改一句话、解释通用概念、规则确定的一次转换；直接做时只守证据底线，要求有两种读法时说出来。
   - [Reporting 入口](../../kit/reporting/README.md)把“写明要对方决定或去做什么”提到产物一行，并写明做到就停；读者、主张和证据已清楚时可以跳过 brief。
   - [企业工作面九项](../../kit/grammar/README.md)写明它是共同工作语法的投影，以及什么任务不必读。
   - [工作系统](../../kit/work-system/README.md)的参考路由原先让本页的主任务先读研究层，改为五步和共同工作语法不够用时才读。
   - Kit 任务入口把指向企业工作面九项的链接误标成“共同语法”，改正。
3. [文档结构契约](../architecture/documentation.md)的内容放置表加两行：场景对共同规则的取值与例外留在场景或客户项目，只收窄不改写；工具的能力与约束留在 Adapters、Environment 或实现项目，不充当业务语义的维护位置。
4. 同一页加“写深条目的检查”：一条内容要能单独支持一次判断，至少答得出问题与适用条件、对象关系与不变约束、可调变量、一个正例一个反例、最小产物与何时停。它是把已有条目写深时的编订检查，不是必填表单。答不出的条目照实当作覆盖面清单。
5. 九类能力语法候选登记在 [提炼页](../../vault/distilled/content-architecture-review-20261002/README.md#九类能力语法候选)，逐条等真实素材。有了素材，写进现有的主责页面，不为它们各开一个文件夹。
6. Artifact 的生命周期、复现承诺与交付检查留到有一件真实交付时再定落点，不建独立的 release schema。本地已有的承接见提炼页的对照表。

## 没有采纳的

| 审阅的建议 | 处置 |
|---|---|
| 入口表每条加“何时停止”一栏和自然触发词 | 不加。改动前三条路线都在入口的通用停止句上停下，读 4 到 10 个文件，没有进研究层 |
| `kit/Agent.md` 开工第 2 步改成按需进研究层 | 本地已改过（ADR-016、019） |
| 提炼总入口的说明改成跨域入口 | 本地已改过 |
| 区分规则维护者与业务决定人、状态权威与生成源，写进体例 | 不写。本地没有看到混淆；共同工作语法和架构页各有一句 |
| 给高频条目逐个标主责、适用范围、依赖和重访条件 | 不做。ADR-019 已给表达这一侧的归属表；企业工作一侧等写深时随条目写 |
| 最小 artifact decision record 的三组字段 | 延后，见决定 6 |

## 与既有决定的关系

延续 ADR-009、011 的任务导航和 ADR-019 的两条入口路径，不改目录。根 `AGENTS.md` 没有动。不改 ADR-002 的晋升门槛：第 4 条针对知识说明，不是共享实现。

## 验证与限制

六个合成任务在改动前后各走读一次，其中两个在入口再改一句之后又跑了一次，预期在改动前冻结：三条企业工作路线，三个不该进分支的请求。三条路线改动前就走得通；小请求的读取量从 6、7 个文件降到 2、3 个；个人经营一题的提案改动后有了明确的请求；改短一句话时直接做的两次删掉了读过成文分支的那次留下的范围词。结果见 [走读记录](../../vault/distilled/content-architecture-review-20261002/entry-walkthroughs/README.md)与 [回执](../verification/content-architecture-review-20261002.md)。每个任务每个时点一次、一种模型，评阅者是改入口的人。

没有验证的：第 3、4 条没有被任何走读用到；工作系统的那处改动没有任务经过；九类候选没有一条被真实任务检验；13 个外部来源没有打开。

重访：用户给出某一类真实素材；放行后四批中的任何一批；走读出现读了入口仍找不到必要约束的反例；或“直接做”的请求丢了本该守住的限定。
