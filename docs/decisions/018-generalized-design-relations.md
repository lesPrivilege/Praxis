# ADR-018：Design 保留泛化的构成关系，原子化作为取用方式

日期：2026-10-02。状态：accepted（Design 知识的层次与落位）。用户裁决；Opus 5.5 主会话编订，Sonnet 5.5 只读代理对照与走读。Luna 在本会话不可用。

## 问题

Design grammar atlas 研究包给出十五个构成问题、一套“内容固定改关系”的检验方法、八个风格名条目和四个打样提案。主会话第一轮只把八个条目写进 Kit（VL01–VL08），做了一件样张，把十五个问题里本地没有规则的九项留在 Vault 当候选。理由是“新分支由实际消费触发”。

用户当日指出：包已完成消费，但仍希望保留更泛化的能力，原子化是后续消费方式。第一轮的落位把顺序弄反了：留在 Kit 的是原子，泛化的判断反而要回 Vault 才找得到。条目和样张会增删改名，没有它们时 Agent 仍需要一处能把模糊诉求换成可检验问题的地方。

## 决定

1. Kit 保留泛化层。[构成关系与问题地图](../../kit/design/foundations/relations.md)收入一条关系要说清的五件事、十五个问题各自“可以调的”和“换什么都要保住的”、约束强度的读法，以及检验一条关系的方法。它给问题和语义边界，不给参数。
2. 原子是取用方式。风格名条目、优先参考卡、样张、打样提案和夹具都从问题地图挂出，可以独立增删；问题地图不依赖其中任何一个。
3. 九项本地没有专门规则的问题，以问题地图里的那一行为当前全部指引。某项被真实任务用到并长出规则时，规则写进对应分支，问题地图改为指向它。
4. 外部标准的数值门槛不随本页进入 Kit。它们只在项目明确采用标准、版本和级别后成为规则。

## 与既有决定的关系

扩展 ADR-015、016 的 Design 分层，在 Foundations 下新增一页，不新建分支。不改 ADR-002 的组件晋升门槛：进入 Kit 的是知识说明，不是共享实现。不改 ADR-017 的参考优先级：VL01–VL08 仍是普通参考。

ADR-015 把完整的 Atom / Pattern / Composition schema 留作候选，本决定不改变这一点。包内的六字段登记和 profile / grammar / primitive / recipe / demo 对象表没有采纳为 schema；采纳的是它们背后的五个提问，以文字写进问题地图。包内的 H/C/E/T 标签没有采纳，约束强度沿用体例契约的规则、默认与风格取舍。

“新分支由实际消费触发”仍然适用于目录。本决定针对的是一页泛化判断，依据是用户裁决，使用证据如实记为不足。

## 验证与限制

使用证据：一件样张（A01）消费了问题地图里的 G01、G11、G13 和检验方法；冷启动走读的范围与结果见 [回执](../verification/design-grammar-atlas-20261002.md)。九项没有本地规则的问题尚未被任何真实任务检验，问题地图的措辞来自一次研究的泛化，背后的规范来源只读了文字。

重访：真实任务在某一行找不到足够指引、某项长出自己的规则、或走读出现“读了问题地图仍选错分支”的反例时修订。
