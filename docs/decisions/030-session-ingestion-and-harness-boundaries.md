# ADR-030：会话入账与 agent 指引边界

日期：2026-10-09。状态：accepted（本轮授权的局部指引修订）。Astra 子代理负责 Praxis 指引裁决，Luna 子代理负责会话入账与官方来源追溯，主代理整合与验收。

## 问题与依据

用户提供两份讨论摘录，要求将有用结论变为可发现、可追溯的仓库产物，并做一次减法优先的 harness 审计。它们不是完整 Chat 历史，原会话 ID 与原外部引用链接均未提供。来源、覆盖和候选结论见 [会话提炼](../../vault/distilled/chat-ingestion-harness-20261009/README.md)。

现有 Vault 已分开原件、提炼和来源，Kit 与 ADR 承担采纳状态，不需要新增知识目录。全局六条工作规则已限定相关读取、最小改动和有意义的验证，保留。具体编辑理由与回归风险见 [审计回执](../verification/harness-audit-20261009.md)。

## 决定

- 全局会话入账契约只面向作为仓库知识材料的可用讨论。默认完成入账、来源和发现入口；偶然引用、翻译输入与测试素材不自动触发。讨论中的施工想法不自动授权产品实现。
- 原始讨论、已采纳项目状态和后续 worker 所需上下文分别维护。复用稳定来源身份与已有主题条目，新增证据保留版本；未验证的建议保持候选，不把摘要当裁决。
- Praxis 继续沿用 `README → vault/distilled → provenance/intake → archive/chat` 的按需发现路径，入账规则仍由 `docs/governance/intake.md` 维护。此次采用的是边界与维护职责，不强制统一 Session Artifact 字段模板。
- 维护指引按改动所影响的职责选读。局部链接或措辞修复不必先读取全部治理文档；来源入账、结构和权限修改仍读取相应规范。
- 模型分工是能力偏好。Luna 仍是首选 explorer，Astra 优先承担困难裁决；是否委派与怎样并行由任务和可用能力决定，主代理负责最终接收。过去某个任务的授权不能作为新会话的永久授权。历史 ADR 中以模型名指代职责的表述，仅在执行者选择上由本决定修订；ADR-002 的证据与晋升门槛不变。
- 模型或 harness 能力发生实质变化时，可以做有具体理由的减法审计；不增加每轮审计、固定子代理阵型或反复全量测试的仪式。

## 保留与未采纳

保留用户授权、来源只作数据、原始材料与机密隔离、已有晋升证据门槛、相关代码先读、验证与诚实报告。不得由这些文档推导更高平台权限。

未把“所有旧模型规则已过时”“ChatGPT 与 Codex 历史绝对隔离”或未给出处的社区共识写入事实层。官方文档核查仅支持其具体表述与适用范围，来源补充不冒充原引用恢复。用户技能中的设计阈值与模型 profile 的版本 pin 暂保留，是否改动需要对应消费失败或迁移证据。

## 影响与验证

新任务按修订后的入口执行；历史 ADR 和来源快照不重写。此次不改变目录归属、产品代码、模型配置、外部发布权限或共享组件晋升门槛。仓库结构校验与独立发现走读记录在审计回执；不据此声称真实任务质量或 token 成本已经改善。
