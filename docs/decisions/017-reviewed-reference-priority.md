# ADR-017：验收后的参考进入任务优先层

日期：2026-09-27发起，2026-09-28补齐需求驱动消费目标。状态：accepted（参考治理与首批限定用途验收）。用户要求Vault中的观察在验收后登记为更高权重参考，并开放长期维护及从demo提炼增量。

## 问题与决定

目录分层解决了存放与逐层阅读，但部分材料仍需知道名字才能召回；近期实验更新了叶子入口，Vault总入口与Design样张摘要却没有同步。已登记和链接存在不能证明所有任务都会自然找到材料。索引还需明确先取用什么、适用条件与反馈去向。

目标是正常任务出现时，模型沿Kit的结构和语义线索自然发现并消费已有素材，包括完整atom家族和外部事件快照，而非只找到两条精选卡片。优先级是这条路径中的一层，不替代进一步探索和长期维护。

采纳 [参考生命周期](../governance/reference-lifecycle.md)：`reference_priority` 与证据状态、处理状态和规范采纳分开。任务匹配时先看preferred卡片，再看普通参考，必要时回到Vault。卡片本身给出泛化说明、范围、证据和维护位置，不能只增加一个优先级标签而让读者继续自行提炼原材料。

参考的高权重不是更高指令权限，也不自动允许复制代码或当成事实。原件、试验和历史review继续留在Vault；Kit维护经过用途验收的当前说明。上层任务入口与卡片同步更新；demo里的支持、挑战和扩展经提炼后修订同一稳定ID，也可以触发降级与退出。

## 与既有治理的关系

扩展ADR-015/016的逐层消费与维护机制，不改变ADR-002的共享组件晋升门槛。参考可以通过有限用途验收进入优先层；进一步成为grammar要求或共享实现仍需相应裁决和实证。

既有未标优先级的参考默认normal，不批量改写旧catalog的证据状态。`vault/registry.json`继续作为已接入Chat与URL的投影，本地项目、下载和实验通过intake/专题索引定位；不能用该registry的数量证明全仓材料已经覆盖。

## 验证与尚欠工作

本轮修正已确认的过期入口，补非Design参考族和Runtime到任务分支的路由，并检查相关路径。完整资料盘点与冷启动真实产物的消费效果未全部验证；不宣布全仓已经不需要额外prompt。检查回执见 [参考发现与优先层验收](../verification/reference-discovery-20260928.md)。

## SourceWeft补充参照

用户在本轮提供比较对话。SourceWeft按固定提交的有界读取登记为普通的runtime consumer/能力包装参考；对话建议不自动采纳。短入口、按需读取和有边界的交接可佐证本轮方向；压缩摘要只提供回查线索的原则补入既有证据契约。manifest、machine-checkable handoff schema和完整运行宿主都保持候选，不因邻近项目存在就新增实现。
