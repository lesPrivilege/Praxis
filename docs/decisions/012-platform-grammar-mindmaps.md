# ADR-012：平台产品扫盲与思维导图归属

- 日期：2026-09-22
- 状态：accepted（组织方式与首轮纲目；行业说明保持研究状态）
- 裁决：Astra；来源登记、核查与解释撰写：Luna。

## 问题与决定

用户希望从平台产品词表开始扫盲，理解美团、抖音电商背景中常见的关注点，并能用 XMind 阅读。现有企业工作面 grammar 主要解释对象、状态、动作和责任，不能直接代替供需匹配、交易与经营知识。

本轮在 [平台产品研究](../../vault/distilled/platform-product/README.md) 维护词表和自然语言解释；Kit 的 grammar 入口只负责路由。行业研究不因导入工具或本次编订自动成为企业工作契约。

建立 [思维导图入口](../../vault/mindmaps/README.md)，供其他任务共同使用。主题原稿保留在各自研究目录，导图入口链接它们，不复制正文。未来确有未归属的导图草稿时可放该目录；确定主题归属后移入主题目录并更新索引。无需新增顶层 XMind 知识域，也无需本轮安装软件或生成二进制文件。

## 编订纲目

1. 业务形态与参与者：谁为谁创造价值，谁持有库存或承担履约。
2. 需求与供给：需求何时发生，可用供给是什么。
3. 流量与分发：从哪里来，怎样找到匹配对象。
4. 内容与购买决策：如何理解、信任并形成意图。
5. 交易与指标：意图如何成为订单，分子分母如何对应。
6. 履约与售后：承诺如何兑现，失败如何影响结果。
7. 留存与增长：谁回来，何时回来，增长成本是什么。
8. 商家经营与平台经济：各方能否持续经营。
9. 生态与实验因果：局部改进是否伤害整体，如何判断原因。
10. 跨平台迁移案例：保留关系结构，重新定义各业务的有效结果。

词表在先，解释随后；公式附在相应词条，案例最后。导图层级表示学习分类，不宣称所有父子关系都是业务因果。跨分支关系以稳定词条编号引用，避免一个词多处维护。

## 粒度与新增裁决

本轮目标 60–80 个核心词条，上限 80；不要求为凑数增加术语。每词提供自然语言解释及例子或易混淆边界。指标必须说明事件、对象、时间窗口与分母；企业内部口径不能由通用词表代定。

任何参与者均可推荐 grammar。推荐填写：词名、它回答的问题、与既有词差异、真实使用场景、来源状态、建议归属、拟替换或合并的条目。Astra 将其裁决为核心、解释子节点、候选或拒绝，并在主题 README 保留理由。只有能改变诊断或决定、且无法由既有词清楚表达的概念进入核心。

超过上限时优先合并或替换；独立专题须有明确消费任务，再以新一轮裁决拆图。不得通过把大量独立名词藏进同一节点来绕过上限。技术实现细节、平台短期活动话术及未使用的长尾词暂缓。

## 交付与验证

两份 Markdown 原稿共享根节点、章节、词条编号及顺序：纲目版便于先看关系，注解版便于展开阅读。使用标题层级表达树，不依赖表格、HTML 或围栏中的字符树。

结构检查只能证明 Markdown 层级和两版一致，不能替代 XMind 实机导入。未执行导入时明确标记待验证；原聊天引用占位、补充官方来源及未保存的网页依赖分别登记。完成后运行仓库校验。

## 用户补充 Profile

本轮后续明确提供的 [XMind Markdown Profile](../governance/xmind-markdown-profile.md) 已采纳。短标题承载主干，列表承载解释；旁路文件保存元数据。导图交付增加 lint，用户提供的应用基线与本仓库实测状态分别登记。
