# ADR-051：取用清单不截断，搜索读到挂载说明与摘录

日期：2026-11-09。状态：accepted（已施工）。用户在本会话贴来两段 ChatGPT 的讨论。一段讲 Praxis 的信息架构：侧栏与子栏、可编辑纲目、合集与单项、风格方案。另一段讲检索：OpenAI 与 Exa 怎样分开索引、召回与读取，以及 Praxis 的 search、resolve、consume 哪里不够。两段按二手材料处理：结构判断对照代码与已有裁定核对，外观与措辞不取。其中引的 OpenAI、Exa 机制没有回原件核对，下面的决定不依赖它们。核对与施工由主会话（Claude Opus 5.5）完成。

## 核对

检索一段对 Praxis 的三条判断，对照 a526fd4 的代码与真实数据都成立：

- **搜索读不到已经写下的用法。** `praxis_search` 只查 ID、标题、编目 description、概要、链接、tag 与别名。挂载上写的说明（249 条）、取用题解，以及 982 个来源的 1555 条摘录，都不在查找范围里。
- **resolve 截掉了大半个货架。** 素材按挂载逐行排列，排序后只取前 12 行。visual-motion-grammar 这条 stream 挂着 57 个来源，任务拿到 12 个；technical-explainer 的 html 流水线有 19 个，拿到 12 个。同时读交互的四页时，12 行里有 4 行是同一来源在几页上的重复挂载。被截掉的部分与任务无关，取决于名册里的先后。
- **运行记录不说用来做什么。** consume 只记来源 ID 与版本。

另外，objects.md 写 resolve 可以接收 brief，代码从来没有这个输入。

## 决定

1. **清单不截断，每个来源一行。** resolve 列出所读单元上全部已启用的来源，一个来源占一行，`pages` 写它挂在其中哪几页。排序的每一步都说得出依据：stream 自己的来源在前，然后是 preferred、收藏、挂的页多的，其余保持名册顺序。前 12 行带读取范围、这些页上的取用题解、摘录与快照；其余到 description 为止，并写明还有几条摘录，要用时由 `praxis_source` 取。哪些与任务相关，由 agent 对照任务判断：它读得懂 description，词面匹配读不懂。
2. **Praxis 不按 brief 排序。** 在真实名册上试过：中文 brief 拆成二字词后，排在前面的来源靠“让人”“哪里”这类虚词命中，英文 brief 靠 an、with 命中，都与任务无关。要排得像样需要语义检索，也就要加依赖或接外部模型。全量清单在真实任务里长到 agent 看不过来时再议。objects.md 删去 brief 这个从未实现的输入。
3. **搜索读到挂载说明、题解与摘录。** 匹配规则在 `matcher` 里定义一次，`praxis_search`、`praxis_catalog` 的 query 与 Praxis 页的搜索共用。每个词都要在标题、description、挂载说明与题解、tag、概要、链接或摘录里找到，命中标题的排前。摘录命中时连定位一起返回（`matched`），agent 可以直接按定位回原件；Praxis 页的行在说明下列出那段摘录，卡片拿它作预览。
4. **运行记录写用途。** consume 的来源可以带一句 `use`，写这次用它做什么、取了哪一处。用途属于活动：记在运行里，列在来源的 Activity 下，不写回来源的说明（ADR-050 裁定 7）。

## 已有或不取

信息架构一段的建议，多数已经落在现有对象上；其余与已有规则冲突，不取。

| 建议 | 处理 |
|---|---|
| 五个一级入口：Kit、Shop、Task、Artifacts、Log | 已有；Sources 改名 Shop 随 ADR-050 第 1 步 |
| 侧栏加子栏，分开工作范围与纲目 | 不改：每个标签记着自己的位置，路径条说明在哪一级（ADR-050 已先行的第三轮），没有新的需要 |
| 可编辑纲目：节点有正文与子树，人和 agent 用同一组编辑动作 | 不新增对象：自撰编排是 stream 与 Kit 修订，同一来源进多个语境是挂载，预设分组是形态与区域，查询视图是 Review、标签筛选与 ADR-050 的新上架、最近被用过 |
| 浏览、编排、引用、编辑分开 | 已是不同操作：Praxis 页导航；stream 与 Kit 修订；curate、remove、restore；source_update、file |
| 合集与单项分开（SEESAW 一类） | 已有：`members.pattern`、`member_of`、成员账目与跳过理由 |
| Blur、Glass、Hover 各归其位 | 已有：foundations/relations 的 G06 材质（不透明度、模糊、描边、阴影、遮罩），interaction/states 的悬停 |
| 风格方案与风格控制面 | 不新增对象：风格是来源、example 或 stream（objects.md“新材料不改体例”），配色、字体、密度等参数在消费者项目决定（Design 入口） |
| 召回、打开、选入、采用、review 分别记账 | 只记采用（consume）与 review：读到的正文在运行记下的会话里，多出的几本账没人能据以行动 |

| Stream 定期上网发现增量 | 推迟：集合类来源已由 refresh 对照上游列出新增与下线；哪条 stream 真要定期找新材料时另立 |

## 后果

- 挂在任务所读页面上的来源都进清单，不再按名册先后截掉。清单因此变长：technical-explainer 加 visual-motion-grammar 是 71 行，整个结果约 32 KB，原来是 12 行。
- 人和 agent 用同一套规则找来源，已经写下的题解与摘录参与查找。
- 运行记录回答“这个来源这次用来做什么”；来源的说明仍然只写来源本身。
