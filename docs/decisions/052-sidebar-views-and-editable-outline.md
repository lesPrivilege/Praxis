# ADR-052：Praxis 侧栏、Shop 看法与可增删的纲目

日期：2026-11-09。状态：accepted（已施工）。用户在本会话裁定：Praxis 页改成侧栏加子级的样式，参照 Legora（外层是 DSH 的侧栏，里层是 Praxis 的侧栏）；侧栏放稳定的项目，具体条目在页面里筛选、按类收敛、加新类别；页面右侧的条目由人或 agent 增删、拆分、合并，免得预设的拓扑列不全（有了 Blur、Glass，之后还会有同一维度的其他语法），上层依然可以递归分级。这一条推翻 [ADR-051](051-full-shelf-and-shared-search.md)“已有或不取”表里的两行：“侧栏加子栏”与“可编辑纲目”。主会话（Claude Opus 5.5）设计并施工。

## 决定

1. **侧栏只放不随数据变的位置。** 五个部分（Kit、Shop、Task、Artifacts、Log）取代顶部标签；在前面的部分下面列它固定的一级：Kit 列层，Shop 列 All、New、Recently used、Manage 与存下的看法，Task 列任务类型。侧栏只有两级，带计数。更深的层级（区域、单元、来源）在右边页面里逐级展开，和 agent 取用的路径一致。页面窄时侧栏只剩图标。Browse 与 Manage 的切换、任务类型的胶囊按钮都并进侧栏。
2. **“加新类别”在 Shop 是存下的看法，不是新分类。** 筛过之后存成看法：名称加 For、标签、搜索词和分组（区域、形态或一列），存在数据根 `views.json`，列在侧栏 Views 下。看法不改来源，也不进编目；分类仍是 Kit 的层与区域（ADR-047）。人在页上存，agent 用 `praxis_view_save` 与 `praxis_view_remove`。
3. **纲目由人或 agent 在数据里增删。** Kit 的树本来就是递归的：带 README 的文件夹是区域，其中的页是单元。新增的 `praxis_outline` 让人和 agent 用同一组动作改它，全部写进数据根的覆盖层，包里的原页不动：
   - **add**：在已有区域下加一页；路径写 `…/README.md` 时是新区域，下面再加页，层级不限。同一维度的新语法就是那个区域下的新页。
   - **revise**：改一页的整页正文（原 `praxis_unit_revise` 并入这里，旧名去掉）。
   - **remove**：把一页拿出 Kit。挂在上面的来源要么用 `into` 并到另一页，挂载的说明与题解随之搬过去；要么先移走，否则拒绝。区域要等下面没有页才能拿出。层不能拿出。
   - **restore**：把拿出的页放回。
   拆分、改名与挪位置由这几个动作组合而成，不另设动作。每次改动都要写理由，记进历史。Kit 首页列出拿出的页，可放回。
4. **agent 工具从 13 个增至 14 个：** 加 `praxis_outline`。看法工具只在控制面、命令行与 MCP。

## 后果

- 原来的五个标签成了侧栏的五个部分，位置、筛选与滚动照旧按部分记住；Esc、路径条与 ← → 的行为不变。
- 来源的分类跟着纲目走：加上的区域可作编目分类，拿出的页不再收挂载。来源包里声明到被拿出页面的关系，合并时一并搬走；不合并时与自有挂载一样，要先移走。
- 加上的页没有包内原页，不报冲突，也不能撤回到原页，只能拿出。
- 在 scratch Host 上用数据副本走过：侧栏、Kit 加页与拿出、Shop 按形态分组并存成看法、看法与 All 之间切换、Task 按侧栏选类型；输入框上方做完的请求叠成一行。真实数据未动。
