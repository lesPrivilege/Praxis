# ADR-043：dsh-praxis 的生产管线登记为来源

日期：2026-10-25。状态：accepted。[下一轮工单](../../dsh-praxis/work-order.md) A2 原定从现有脚本里收拢一条视频链进 Praxis。用户改为：把已有的生产管线登记为本地来源，挂到 Publish 的 video 与 html 页，写明何时用；运行记下每件产物由哪条管线产出；不把脚本复制进 Praxis。主会话（Claude Opus 5.5）实现并验证。

## 问题与依据

已有的生产管线都是完整的项目工具链，例如 Palantir 书单系列：
- 10 个脚本；
- Seed TTS 与 Gemini 凭据；
- 经 uv 临时取用的 ffmpeg；
- Playwright 或本机 Chrome。

Publish/video 此前只在正文表格里链到这些项目，名册与 resolve 看不到它们，产物也不记是用哪条管线做的。按名册登记链接、不收录正文的原则，管线与其他来源一样：登记位置与功效，用时去原处取。

## 决定

- **管线是本地来源。** 用一次成批 capture 登记 5 条，定位是项目里的说明文件或入口脚本，tag 为 `PIPELINE`：

  | 管线 | 挂在 | 何时用 |
  |---|---|---|
  | Palantir 书单系列 | publish/video | 旁白带领的系列片，单集与合集同源 |
  | 薪酬基线说明片 | publish/video | 一两分钟、一条配音的短片，从这里复制起步 |
  | 金字塔第五版 | publish/video | 多章长片，要章节卡、出处行或观看页 |
  | Jev 专章网页构建器 | publish/html | 页面上的数字与出处要一一回到研究登记 |
  | SaaS 教材站点生成器 | publish/html | Markdown 书稿编成离线多页站点 |

  每条挂载的说明写这条管线对这一页有什么用、何时打开。resolve 一件视频任务时，三条视频管线出现在素材里。
- **产物记下管线。** consume 的每件产物可带 `made_with`：一条已登记来源的 ID，查不到就整次拒绝。它记在产物的这一版和运行记录里；产物详情显示“管线”，点开是来源条目。
- **来源的使用记录分两种。** 一种是运行读过这个来源，一种是运行用它做出了产物。来源条目的“读过或用它产出的运行”两种都列，用它做出的产物逐件列出。
- **已知的产出关系一次补记。** 依据项目记录补上管线：
  - Palantir 书单系列的 7 个成片，记为书单系列管线；
  - Jev 网页 `site/index.html` 的第 4 版，记为 Jev 构建器。

  只改最新一版与对应运行的记录，字节、版本与 review 不变。

## 验证

- `node --test` 27 项：
  - `made_with` 指向未登记来源被拒；
  - `made_with` 记在版本与运行上；
  - 来源条目把这次运行列为“用它产出”。
- [验收探针](../../scripts/check_praxis_acceptance.py) 14 项、`python3 scripts/validate_repository.py` 通过。
- 实测：
  - resolve 技术说明的 video 流水线，素材里出现三条视频管线；
  - 书单系列管线的来源条目列出补记的运行与 7 个成片。

## 没有做的

- publish/video 正文里“已有制作与消费记录”表格仍链到各项目，与挂载重复。正文改为只经名册披露，在 release 的 B3（Kit 自足）里做。
- 管线是本地文件，refresh 只检查 http 链接，管线改动不会让运行过期。
- 其他 demo 的管线（无配音知识片、AgentScope 企业线、A3 等）没有登记，等它们被用到时再登记。
