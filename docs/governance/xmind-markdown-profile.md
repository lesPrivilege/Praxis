# XMind-Compatible Markdown Profile v0.1

状态：已采纳用户在当前任务提供的 profile。版本：`xmind-md/0.1 @ 2026-09-22`。用户提供的验证基线：`Xmind Desktop 26.05.01107`；这不是本仓库已经执行实机导入的声明。

## 定位

`md/general` 用于 README、研究与完整自然语言论证，可使用一般 Markdown。`md/xmind` 用于图谱、grammar、ontology、扫盲纲要及预计导入 Xmind 的概念树。用户明确要求 Xmind-compatible 时默认启用后者。

Markdown 在此是树结构交换格式。优先级：结构稳定、Xmind 可预测性、纯文本可读性、丰富排版。未经验证的语法不得进入默认 profile。

## 文件与主干

- `.md` 纯文本，UTF-8，优先无 BOM。
- 第一行必须是唯一的 `# 中心主题`；此前不放空行、元数据、YAML 或 HTML 注释。
- 标题最多六级，不得跳级。标题是节点，不添加用于假造层级的序号、项目符号或装饰。具有真实语义的编号可以保留。
- 结构字符使用 ASCII；不得用全角井号或横线冒充。缩进不得使用 Tab、NBSP 或零宽字符。
- 普通 Unicode 正文可用；箭头、emoji、字符树不能编码结构。

## 标题、列表与节点

Heading 表达稳定概念及主干。列表表达同层枚举、实例、属性或短说明。无序列表使用 `- `；确有顺序语义时可用有序列表。嵌套每级四个 ASCII 空格。同一局部树避免频繁切换标题和深层列表；长期演化、需要引用的概念应升级为标题。

每个标题或列表项原则上表达一个概念。标题短，解释放子节点；完整论证留在自然语言文档。字段、schema、命令和路径使用行内代码。不要把多行代码塞入主导图，可拆成名称、输入、输出节点。

## 允许与降级

默认只依赖一至六级标题、无序列表、必要的有序列表、强调、行内代码、必须保留的来源链接。

表格、HTML、YAML front matter、脚注、定义列表、嵌套引用、分隔线、任务复选框、Mermaid、LaTeX 块、复杂围栏代码、图片节点及仅靠粗体模拟标题，不得承担树结构语义。需要保留时放旁路 source document 或普通节点的说明层。此约束不声称 Xmind 一定不支持这些语法。

## 元数据与版本

日期、版本和来源优先放旁路 manifest 或 README；需要出现在图上时放末尾 Metadata 分支，不污染中心主题。

用户提供的版本策略末句在“而”处截断。本次只采纳已完整表达的要求：parser、importer 或实际使用行为变化时，不静默修改旧规则。后续规则修订遵循 [增量与修订](evolution.md)，新版本的细节待实际变化时裁决。

## Preflight 与验收

标记为 `xmind-compatible` 前检查：唯一 H1、首行 H1、标题最大六级、不跳级、ASCII 结构符、空格缩进、UTF-8、无前置 front matter、无不可见缩进、无结构表格或 HTML。

运行 [lint 脚本](../../scripts/lint_xmind.py)，参数为待交付文件。脚本对导图输入采用更窄的生成子集：只接受标题、列表和空行，拒绝多行正文及禁止语法；这不限制 `md/general`。静态通过与 Xmind 实机导入分别记录，不能互相代替。
