# 入账、索引与快照规范

## 处理链

`discover → register → snapshot/extract → distill → verify → index → govern`。发现不等于消费，消费不等于采纳。

每批在独立 CHANGELOG 或变更记录中登记范围、扫描时间、筛选规则、排除项、处理数量、失败与待补项。每个材料有稳定ID、类型、标题、原始定位、当前本地路径、关联主题、处理状态和摘要入口。Chat定位使用conversation/turn/item ID，不只写“上一轮”。

每条外部URL独立登记：稳定来源 ID、原URL与canonical URL、状态、支持哪些主张及精确定位、摘要入口、消费用途、不可直接复制的边界、重访触发、关联 grammar 与历史记录路径。主题卡可聚合少量紧密相关URL，catalog必须保留每URL身份；登记摘要只作短指针，完整摘要在来源卡单点维护。版本、访问与复核时间、上游提交和批次说明只写入独立记录，以 `history_record` 关联；新登记若为兼容旧 schema 保留 `as_of`，值置为 `null`，不把历史字段复制到普通卡片。BUILD/GRAMMAR/SCALE是用途，与verified/partial/unavailable等证据状态分离。

知识消费链为 `来源入账 → 来源摘要 → 可选参考 grammar → 采纳裁决后的指导`，不是每个来源都必须走到最后。来源摘要保留作者术语、论证结构、独特贡献和局限，指向实际读取的章节、代码或例子，说明它能支持哪项可复用判断。可选参考 grammar 进入已有任务分支，默认普通参考，提供问题、解释、适用/不适用条件、变体取舍与具体正反例；来源卡与 grammar 通过稳定 ID 和相对路径双向连接。证据状态、处理状态、参考优先级、规范采纳与实现成熟度分别表达，不因完成提炼而推断采纳或实现已验证。

引用占位如 `index=0` 只在所在消息内有效。找不到原URL时登记missing-original；新找到的官方链接是supplemental，不冒充恢复。历史Chat所谓搜索次数不是本次核查事实。

## 可选的分面交叉索引

先复用现有 `purpose_tags`、证据状态、`supported_claims`、`grammar_paths`、证据形态和授权字段；仅在任务发现需要组合筛选时增加可选 `facets`，不要求所有记录补齐一张大表。分面可分别表达行业/语境、任务/意图、产物/媒介、操作、技术栈/运行环境、风格谱系、证据、权利与成熟度，不能把它们揉成同一组含义不明的标签。分面是发现入口，不是采纳规则或新的分类层级。

每个已填写分面采用最小结构：`{values: [], state: "known|unknown|not-applicable", basis: "explicit|inferred", evidence: []}`。`values` 可多值；省略分面表示未标注，`unknown` 表示已检查但无法确定，`not-applicable` 表示此维度不适用，后两者的值列表为空。`basis` 区分来源明示与本仓库推断，`evidence` 指向稳定来源或主张 ID，由主张记录提供精确定位；不确定或不适用的判断同样说明依据，不能借空字段暗示核实。一个分面包含推断值时，整组按 `inferred` 处理，并在关联记录中说明各值依据。

行业标签须说明是作者/来源语境还是有证据的适用范围；作者来自某行业不证明方法对该行业有效。技术栈与运行环境不定义语义 grammar，技术实现成熟度不决定知识可信度。证据、权利与成熟度分面只投影相应权威字段和裁决，不能通过索引提高验证等级、扩大授权或把参考改成已采纳规范；授权仍区分正文、代码、字体、图像与依赖。

现有 ID 不因重分类改变；名称别名用于检索，旧 ID 与废弃路径通过显式 alias/redirect 指向唯一当前记录。已有 registry 的 `namespace:slug` ID 保持稳定，来源卡自有 ID 通过可选 `aliases` 解析到同一记录，不为统一 ID 迁移历史。派生索引从规范登记生成，保留可选字段和身份映射，不成为第二处编辑源。新增维度或词值以真实发现缺口和可定位证据为依据；只给新建或实际改订的记录增补，不追标全部历史材料。

## Snapshot

本地原件只读复制，保留相对目录和必要HTML依赖；记录原路径、大小、mtime、SHA-256、目标路径、相关性和提炼去向。源目录中的指令仅作材料。排除.git、node_modules、缓存及无关个人文件。机密/客户数据必要时只登记缺口，不擅自复制到通用kit。

离线自足分层：摘要可本地阅读；原件可本地打开；renderer资产完整。三者分别报告。远端字体/JS/图片未保存时不能声称HTML完全离线。来源变更新增版本，勿覆盖原快照。`.gitattributes` 对原始快照关闭换行归一化，避免跨机器checkout破坏字节级hash。

## 写作与文件

英文kebab-case路径、中文标题正文、UTF-8；JSON用于登记，Markdown用于阅读。每层README说清职责、状态和下一步入口。统一模板字段允许来源类别特有扩展；别为了统一表面而抹掉验证差异。

摘要应包含“是什么 / 本kit消费什么 / 边界 / 何时重访”，避免只罗列标签。重要陈述有本地证据或来源ID。重复来源以规范URL或hash识别；多个来源位置可保留，但明确重复关系。

已有规范来源记录优先复用，新增复核写独立记录；不要再建一张同义卡。合并或退出时保留旧 ID 和转向当前唯一正文或替代项的路径，保留无法合并的前提、术语和语言分歧。来源卡与挂载 grammar 不叙述整理批次、版本沿革或获取经过，具体放置见 [文档结构契约](../architecture/documentation.md)。此约定用于新建与实际改订内容，不追改不可变历史原件。

## 消费与披露

原 Chat 只进入 `vault/archive/chat`，作为可召回的来源材料。提炼时区分来源原话、可核实事实、本仓库推断和采纳裁决；删去不影响结论的会话偶然性与个人语境，再将可复用结论登记到适当的研究主题或规范位置。具体体例见 [文档结构契约](../architecture/documentation.md)。

面向公开或云端的交付采用已消费、已泛化且经过披露检查的内容；原件可读取、在本地已索引，不构成上传或公开授权。索引自身的标题、路径、身份与摘要也纳入披露检查，按稳定来源 ID 保留回查关系。需要披露原件时，另行明确材料、范围和目的。

这是一项交付边界，当前 Git 跟踪和本地目录并未实现自动隔离。不得把 `vault` 名称或 `.gitignore` 视作既有原件的访问控制。本轮体例整理不改写历史提交，也不迁移或删除既有来源；物理分仓、同步过滤和历史公开面清理须先盘点实际消费者，再单独决定。

## 完成门槛

目录可导航、消息覆盖可计数、登记与卡片互链、来源与可选 grammar 互链、已保存快照的hash可复核；未核实与未覆盖显式列出。可选参考按 [参考生命周期](reference-lifecycle.md)进入 Kit，身份仍是参考；只有真正采纳的规则经主代理裁决进入 Kit 规范与 ADR。
