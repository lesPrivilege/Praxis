# 增量、追溯与修订

维护单位是能支持一次判断或工作的知识条目。任务失败、新证据、来源或依赖变更、用户目标改变均可启动复核。

## 条目维护

| 维护信息 | 记录方式 |
|---|---|
| 唯一位置与职责 | 共享规范在 kit，场景专属契约/schema 在 scenario，权威业务状态在消费宿主；理由在 docs，证据在 vault；Luna 提炼、Astra 裁决 |
| 适用范围与依据 | 场景、输入条件、来源 ID 与版本 |
| 用法与反例 | 指南、字段、例子和失败路径 |
| 使用证据 | 未使用、人工走读或真实任务的日期、结果与限制 |
| 生命周期 | 当前状态、重访触发、替代位置与迁移要求 |

可继承父级约定；在具体条目记录例外和实证。新主题先入 intake，再由 Astra 决定归属。

## 修订流程

1. 登记触发问题、旧判断、来源版本与关系（supports / challenges / extends / duplicates）。
2. Luna 提炼新增内容、冲突和影响路径；Astra 决定保持、补充、修订、降级或撤回。
3. 修改唯一规范位置，并检查任务入口、模板、验收和消费者。涉及 Goal、原则、目录、依赖、术语、权限或晋升规则时写 ADR。
4. 更新消费入口与卡片；历史 ADR 保留原文，以新决定标注关联和 supersedes。
5. 运行仓库验证，记录使用走读、未决项和重访条件。

## 版本与消费者

消费时固定 Kit commit 或发布版本，记录入口、适用范围、状态权威和责任人。

| 变化 | 处理 |
|---|---|
| 文字修正 | CHANGELOG 记录，不改变契约含义 |
| 兼容扩展 | 说明新增用途、适用条件及验证过的消费者 |
| 破坏性变化 | 说明旧新映射、受影响消费者、迁移或重验、回退路径；未测试消费者标为未知 |
| 停止推荐或撤回 | 更新当前任务入口、指出替代方案与未迁移项，保留历史证据 |

术语含义、必填字段、权限范围或生命周期变更按破坏性变化评估。新要求用于新任务；在途任务由 owner 对照旧契约补齐或记录不适用理由。

## 审阅交付消费

分别登记审阅结论、完整文件、补丁、基线和实际改动。只取得摘要时按主张逐项裁决，登记缺失交付物；回执关联具体规则、模板字段和验收反例。既有提交与验收保留当时范围。

生成索引从明确的入账和来源记录重建；新批次接入须能重复生成相同结果。类别差异由对应读取逻辑处理，人工提炼保留在源文件。

## 修订回执

日期、实际执行角色、受影响 ID 与路径、旧判断、新证据、裁决、覆盖范围、迁移或重验要求、验证结果。来源失效保留 ID、最后已知版本及历史摘要，复核结果另记日期。
