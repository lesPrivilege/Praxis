# 增量、追溯与修订

本Kit是一套可以被新证据改进的工作资产，不是封闭分类法。未落入现有目录的材料先登记到intake，由Luna建议归位，Astra决定新增主题或调整架构。

## 增量链

1. 登记新材料、来源版本、与现有主题的关系（supports / challenges / extends / duplicates）。
2. Luna提炼新增内容及冲突，标明哪些原结论受影响；不得只把文件堆进snapshot。
3. Astra判断保持、补充、修订、降级或撤回；涉及Goal/原则/目录/依赖/晋升规则时写新ADR。
4. 更新消费入口及相关卡片；保留旧决策并标记superseded-by，新决策写supersedes。
5. 记录验证结果和仍待解决的缺口，检查本地链接和快照hash。

## 触发条件

新客户独立场景出现、来源内容变更、依赖版本/许可变更、实测失败、用户目标改变、摘要与原文不符，均可触发复核。外部链接失效不删除历史摘要，应登记失效和最后已知版本。

## 修订记录最低字段

日期、作者/角色、受影响ID与路径、旧判断、新证据、新判断、影响范围、迁移或重验要求。轻微文字修正可进CHANGELOG；语义或架构变化需ADR。

来源核实是有日期的结论；不假定外部实践永远成立。目录允许扩展，但新增分区必须有明确消费目的和唯一职责。
