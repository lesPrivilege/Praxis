# 增量、追溯与修订

维护单位是能支持一次判断或工作的知识条目。任务失败、新证据、来源或依赖变更、用户目标改变均可启动复核。

## 条目维护

| 维护信息 | 记录方式 |
|---|---|
| 唯一位置与职责 | 共享规范在 kit，场景专属契约/schema 在 scenario，权威业务状态在消费宿主；理由在 docs，证据在 vault；探索者提炼、主代理裁决；模型偏好见 [分工约定](../../kit/Agent.md#分工与预算) |
| 适用范围与依据 | 场景、输入条件、来源 ID 与精确证据定位；版本指向独立记录 |
| 用法与反例 | 指南、字段、例子和失败路径 |
| 使用证据 | 当前检查范围与限制；人工走读或真实任务的日期、版本、结果另入变更或验收记录 |
| 生命周期 | 当前状态、重访触发、替代位置与迁移要求 |

可继承父级约定；在具体条目记录例外和实证。新主题先入 intake，再由负责裁决的主代理决定归属。来源摘要、可选参考 grammar 与已采纳指导分别单点维护；先沿用现有分类和入口，分类调整须有发现失败或反复语义歧义的依据。

Kit 活跃条目的准入、薄使用记录与退出条件统一见 [文档结构契约](../architecture/documentation.md)。真实消费发现规则失效、反复被绕过或无人能从任务入口找到时，按下列修订流程处理；历史证据保留，当前入口指向有效替代。

## 修订流程

1. 在独立变更记录中登记触发问题、旧判断、来源版本与关系（supports / challenges / extends / duplicates）；普通卡片只链接记录。
2. 探索者提炼新增内容、冲突和影响路径；主代理决定保持、补充、修订、降级或撤回。
3. 修改唯一规范位置，并检查任务入口、模板、验收和消费者。涉及 Goal、原则、目录、依赖、术语、权限或晋升规则时写 ADR。
4. 更新消费入口与卡片，检查来源 ID 和双向路径；合并或撤回时保留旧 ID 与路径，转向唯一正文或说明无替代，保留前提、术语与语言分歧。历史 ADR 保留原文，以新决定标注关联和 supersedes。
5. 运行仓库验证，记录使用走读、未决项和重访条件。

新增与清退沿用上述流程，内容按 [互著与别裁](../architecture/documentation.md#互著与别裁)编排。

- **新增入库**：核对已有来源 ID 和正文位置，区分新增、补充、修订与重复。所属目录和相关任务入口链接正文，证据按需展开。
- **迁移、合并或移交**：查找引用入口和实际使用项目，更新入口，保留稳定 ID 与旧新映射。已被引用的旧路径链接新位置。向外部项目移交时，记录接收位置与状态；确认接收前保留本地唯一内容。
- **降级、撤回或清理**：移出活跃推荐时，在原登记或所属索引记录日期、原因、最后版本、替代或归档位置；无替代时注明。合并重复正文，保留必要历史证据。敏感材料按披露要求处理，处置记录须去除敏感内容。

完成前核对入口、来源登记和消费记录，分别走读现行路径与旧路径。编辑源改变后重建对应索引；必要依赖改变时，按下节处理使用方迁移。只要求受影响的分支同步内容、调整依赖或重验；相关入口与来源索引按本流程更新。链接检查验证位置，走读验证使用所需的信息与前提。

修订实例见 [2026-10-02 来源卡归属的修订](../verification/self-contained-review-20261002.md#一次维护修订的全程)。

## 版本与消费者

需要可复现的消费与验收时，在独立记录中固定 Kit commit 或发布版本，记录入口、适用范围、状态权威和责任人。版本、获取与复核时间、批次、执行角色及修订叙事不回填新建或改订的挂载 grammar、普通来源卡和索引；不可变历史原件不追改。

| 变化 | 处理 |
|---|---|
| 文字修正 | CHANGELOG 记录，不改变契约含义 |
| 兼容扩展 | 说明新增用途、适用条件及验证过的消费者 |
| 破坏性变化 | 说明旧新映射、受影响消费者、迁移或重验、回退路径；未测试消费者标为未知 |
| 停止推荐或撤回 | 更新当前任务入口、指出替代方案与未迁移项，保留历史证据 |

术语含义、必填字段、权限范围或生命周期变更按破坏性变化评估。新要求用于新任务；在途任务由负责人 对照旧契约补齐或记录不适用理由。

## 设计与写作的增量

设计与内容表达分别在 [Design](../../dsh-praxis/kit/design/README.md) 与 [dsh-praxis Kit](../../dsh-praxis/kit/README.md)，按任务分支维护。新来源先登记到 Vault 并形成可读摘要，按需提炼为普通优先级的可选参考 grammar；参考用途验收决定是否优先取用，规范采纳另行裁决，只有能跨项目复用的结论才进入规范。写作原理在 [成文原理](../../dsh-praxis/kit/writing/principles.md)，审阅方法与偏差在 [审阅方法](../../dsh-praxis/kit/writing/review.md)，消费和审阅历史在独立验收记录；项目 skill `writing` 只负责按需进入 Kit。分支迁移后删除旧路径，不留导航入口（[ADR-037](../decisions/037-dsh-praxis-layered-grammar.md)）。

## 参考的持续消费

参考按 [参考生命周期](reference-lifecycle.md)连接来源摘要与 Kit 任务分支。demo 或真实任务需要回流时，使用可选的 [消费记录模板](../verification/reference-consumption-template.md)；新增观察先登记，经过提炼与裁决再更新唯一正文。新上下文中的正常任务试用与维护走读分别披露，不设固定试用数量，也不把记录变成每项任务的必经步骤。优先级可以提高、降低或停止，原件和历史 review 保留。来源登记本身不自动获得首选资格。

## 审阅交付消费

分别登记审阅结论、完整文件、补丁、基线和实际改动。只取得摘要时按主张逐项裁决，登记缺失交付物；回执关联具体规则、模板字段和验收反例。既有提交与验收保留当时范围。

生成索引从明确的入账和来源记录重建；新批次接入须能重复生成相同结果。类别差异由对应读取逻辑处理，人工提炼保留在源文件。

## 修订回执

回执保存在独立 CHANGELOG 或变更、验收记录：日期、实际执行角色、受影响 ID 与路径、旧判断、新证据、裁决、覆盖范围、迁移或重验要求、验证结果。来源失效保留 ID、最后已知版本及历史摘要，复核结果另记日期；当前卡片保留状态、限制、重访条件与回执链接。
