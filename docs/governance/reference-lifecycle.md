# 参考的验收、优先取用与增量维护

Vault 保存观察、实验、来源与历史；来源摘要与可选参考 grammar 构成相连的两个视角，分别在 Vault 来源卡和 Kit 既有任务分支单点维护。可选参考完成提炼后可按普通优先级进入 Kit；经过指定用途验收才取得优先资格，规范采纳另行裁决。读者先看到取用理由与边界，需要核对时再向下展开原件。

## 目标是按需求发现与消费

任务入口逐层提供所需材料。读者应能按任务找到参考，无需预先知道卡片、原子样张或快照的名称。

- 总入口帮助选择工作域和表达模式。
- 分支 README 按当前问题列出必要规则、优先参考和可选研究。
- 参考说明写明支持的判断、所需输入、适用条件、变体和失败边界。首选不匹配时，可继续查看同类原子样张、普通来源或研究专题。
- 需要核对依据时，才读原件、外部事件快照、版本差异和检查记录；来源记录给出时间锚点与未覆盖项。

原子样张按比较、限定、反例、数量、邻接等任务查找；外部事件或版本研究按影响范围和取用目的查找。入口说明用途，链接到具体内容；取用优先级由下表确定。

发现效果通过实际查找、取用和产出检验。链接检查与维护走读单独记录，真实使用效果由新上下文中的任务验证。

## 取用优先级

| reference_priority | 何时查阅 | 进入条件 |
|---|---|---|
| preferred · 优先参考 | 与当前任务及范围匹配时先看 | 已提炼，并通过卡片写明的参考用途验收，有直接任务入口、证据与维护位置 |
| normal · 普通参考 | 首选不适用、需要对照或更广探索时 | 已登记并有取用说明，未取得优先资格或已降级 |
| historical · 历史参考 | 追溯、反例、复盘或迁移时 | 不再作为当前任务的推荐输入，保留ID、理由与替代位置 |

取用优先级只用于排列同类任务的参考。先判断适用范围，再比较优先级；用户要求、指令权限、证据状态和实现程度分别判断。

处理状态、证据状态、规范采纳、参考优先级和实现成熟度分别记录。一个参考可以是`reviewed / partial / reference / preferred`：例如已验收某种编排关系的可查阅价值，但其代码、无障碍、全部数据和跨项目效果未验收。看过文档、看过输出、运行过实现按实际范围披露；来源关联只支持发现，不自动成为某项主张的证据。把参考改成规范或共享组件仍走原有裁决，组件继续遵守ADR-002。

## 参考用途验收

进入preferred前，维护者核对：

1. 写明支持的任务和判断，提供可独立阅读的取用说明。
2. 源身份与版本/日期可追溯；根据所申请的用途检查实际证据。视觉结构至少看过相应输出，运行实现需要实际行为证据，源码阅读不能替代它。
3. 列出通过、未通过和未执行的检查。使申请用途无法成立的缺陷须先解决。
4. 写明用什么、不用什么、不适用条件、维护位置与重访触发。
5. 在任务分支 README 或相关指南中添加入口，同步上层简介与正文状态。

来源摘要、参考 grammar 与已采纳规范分别只有一个维护位置。多个任务入口可以指向它们，Vault里的原件和历史review不复制成第二份当前规则。原始截图、数据、代码在Vault保持身份；Kit放可消费的参考说明与精确来源定位。来源卡保留作者的前提、原有术语与论证，grammar 明示泛化与取舍；不同语言或来源间的分歧不能被改写成虚假的一致意见。

## 从demo和实际工作回流

需要回流时，消费者可在自己的独立变更或验收记录中简记实际任务与产物、参考 ID、采用/改写/拒绝及理由、判断或输出的变化、遗漏或过度读取、缺口跟进；使用 [薄消费记录模板](../verification/reference-consumption-template.md)即可。时间与版本只放记录，不放普通来源卡或 grammar。Demo 仍按 [准入](../../projects/README.md)填写其必要验收，无需每次任务重述整张参考卡或另开全套日志。

回流时先把项目观察放入Vault或项目记录，标明`supports / challenges / extends / duplicates`。Luna提炼可重复部分与缺口，main裁决保持、修改、提升或降级，并同步受影响的任务入口。个人风格与一次性修补留项目；实现晋升不因有漂亮样张而跳过验证。

长期维护可以从一次真实反例开始，不要求先积累固定使用次数；长期没有消费者、每次都被覆盖、来源漂移、依赖失效或有更好替代时复核。出现使既定用途无法成立的问题时，先降为 normal 或 historical，记录原因与替代，并更新 Kit 推荐入口。

## 发现性也参与维护

新材料入账时，同步检查任务入口、主题说明、参考卡与原件状态。实际消费中“没找到、读了大量无关材料、需要用户点名、误读过期状态”都作为导航反例回流，必要时调整简介、归属或优先级。

验收从正常任务中选取不带材料名的提示，在新的 agent 上下文中观察是否能从既有入口发现资料并实际改变判断或产物。记录必要路径、为何采用、改写或拒绝、遗漏与不可核实项；维护者照着卡片走读另计，不冒充独立发现。根据失败与风险决定是否补测，不设固定试用次数，也不要求日常每次施工输出浏览日志。测试只覆盖实际运行的任务，不能据少量成功宣布全仓永久免提示；若要进一步主张规则有效或节省成本，仍须按 [文档验收](../architecture/documentation.md#验收)提供相应对照或声明未对照。

先用 description、交叉链接和归属修复发现问题；仅在实际发现失败或反复语义歧义表明现有分类不足时，才按 [修订流程](evolution.md#修订流程)提出分类变化。新材料数量增加本身不是新建平行分类的理由。

## 最小卡片信息

稳定 ID、匹配任务、消费摘要、优先级、证据/采纳状态、实际检查范围、精确来路、不适用条件、消费者记录入口和重访触发即可。存在关联 grammar 时双向链接；尚未形成 grammar 不必造空条目。验收日期、版本、获取与复核时间、批次及修订经过属于独立 CHANGELOG 或变更、验收记录，当前卡片链接最新裁决，不再要求内嵌验收日期。可沿用项目已有 index 字段，不为统一形式批量搬迁所有来源；历史原件与回执保持原文。

合并或退出的条目保留稳定 ID、去向与理由记录；旧路径提供到唯一当前正文的转向，未有替代时明确说明。不要删除仍被消费者引用的来源身份，也不要在多个入口维护同一摘要或同一 grammar。

本机制由 [ADR-017](../decisions/017-reviewed-reference-priority.md)采纳。首批 [优先编排参考](../../dsh-praxis/kit/design/references/curated/README.md)的验收范围是结构观察与查阅；代码仍为实验实现。
