# 参考的验收、优先取用与增量维护

Vault 保存观察、实验、来源与历史；经过指定用途验收的参考进入 Kit 对应任务分支，直接提供可消费的解释。读者先看到取用理由与边界，需要核对时再向下展开原件。

## 目标是按需求发现与消费

用户只需给出正常任务，不必点名某张卡片、atom或深层快照。Kit让模型通过当前任务选择相关入口，再逐层取得足够信息；不把全部材料塞进上下文，也不把每个素材包装成需要单独触发的skill。

- 总入口帮助选择工作域和表达模式。
- 分支README以读者正在解决的问题指向必要规则、优先参考和进一步探索。
- 参考说明提供语义职责、输入形状、何时用/不用、变体和失败边界。首选不匹配时仍可进入完整atom家族、普通来源或研究专题。
- 需要核对依据时，才读原件、外部事件快照、版本差异和检查记录；来源记录给出时间锚点与未覆盖项。

atom可按比较、限定、反例、数量、邻接等任务被发现；外部事件或版本研究可按受影响的运行边界、变化和消费目的被发现。目录深度本身不表示低权重，关键是相应需求出现时，入口能否提供足够的语义线索和精确定位。

这里的attention以可观察的查找、取用和产出行为检验，不声称改变模型内部权重。链接可达、源码检查和一次走读不能替代新上下文中的真实消费。

## 取用优先级

| reference_priority | 何时查阅 | 进入条件 |
|---|---|---|
| preferred · 优先参考 | 与当前任务及范围匹配时先看 | 已提炼，并通过卡片写明的参考用途验收，有直接任务入口、证据与维护位置 |
| normal · 普通参考 | 首选不适用、需要对照或更广探索时 | 已登记并有取用说明，未取得优先资格或已降级 |
| historical · 历史参考 | 追溯、反例、复盘或迁移时 | 不再作为当前任务的推荐输入，保留ID、理由与替代位置 |

权重只表示同类任务的检索和取用顺序，不提高平台指令优先级，不推翻用户要求，不意味着来源可信度或实现成熟度更高。先判断任务匹配，再比较优先级，不给不同领域材料统一打分。

处理状态、证据状态、规范采纳和参考优先级分别记录。一个参考可以是`reviewed / partial / reference / preferred`：例如已验收某种编排关系的可查阅价值，但其代码、无障碍、全部数据和跨项目效果未验收。把参考改成规范或共享组件仍走原有裁决，组件继续遵守ADR-002。

## 参考用途验收

进入preferred前，维护者核对：

1. 明确要支持的任务和判断，泛化说明能独立读懂；不复制原Chat或仅贴链接。
2. 源身份与版本/日期可追溯；根据所申请的用途检查实际证据。视觉结构至少看过相应输出，运行实现需要实际行为证据，源码阅读不能替代它。
3. 说明通过的范围和未通过/未执行的范围。会使该用途成立不了的缺陷先解决；不把数据或实现缺陷藏在“已验收”后面。
4. 写明用什么、不用什么、不适用条件、维护位置与重访触发。
5. 在任务分支README或相关指南直接挂接，读者不需要知道原材料名字或深层Vault路径；同时更新上层简介，避免叶子状态已变、父页仍说“待产出”。

卡片只有一个维护位置。多个任务入口可以指向它，Vault里的原件和历史review不复制成第二份当前规则。原始截图、数据、代码在Vault保持身份；Kit放经过验收的参考说明与精确来源定位。

## 从demo和实际工作回流

消费者在自己的index/验收中记录：参考ID与版本、实际任务/fixture、取用或调整范围、结果和反例。模板可见 [Demo准入](../../demos/README.md)，无需每次重述整张参考卡。

回流时先把项目观察放入Vault或项目记录，标明`supports / challenges / extends / duplicates`。Luna提炼可重复部分与缺口，main裁决保持、修改、提升或降级，并同步受影响的任务入口。个人风格与一次性修补留项目；实现晋升不因有漂亮样张而跳过验证。

长期维护可以从一次真实反例开始，不要求先积累固定使用次数；长期没有消费者、每次都被覆盖、来源漂移、依赖失效或有更好替代时复核。阻断既定用途的问题出现后先降为normal或historical，记录原因和替代，不能只在Vault补一段备注却继续在Kit首推。

## 发现性也参与维护

新材料落账时同步检查任务入口、主题说明、参考卡与原件状态，不只更新末级目录。实际消费中“没找到、读了大量无关材料、需要用户点名、误读过期状态”都作为导航反例回流，必要时调整description、归属或优先级。

验收抽取不带材料名的任务，在独立上下文中观察是否能找到资料并实际改变判断或产物。记录读了哪些必要层、为何取用、遗漏与不可核实项；不要求日常每次施工都输出完整浏览日志。测试只覆盖实际运行的任务，不能据少量成功宣布全仓永久免提示。

## 最小卡片信息

稳定ID、匹配任务、消费摘要、优先级、证据/采纳状态、验收日期与范围、精确来路、不适用条件、消费者记录和重访触发即可。可沿用项目已有index字段，不为统一形式批量搬迁所有来源。验收回执保留版本，当前卡片指向最新裁决。

本机制由 [ADR-017](../decisions/017-reviewed-reference-priority.md)采纳。第一批 [优先编排参考](../../kit/design/references/curated/README.md)只验收结构观察的查阅用途，不代表实验代码已经成为通用实现。
