# 参考的验收、优先取用与增量维护

Vault 保存观察、实验、来源与历史。通过指定用途验收的参考进入 Kit 对应任务分支，提供取用说明与边界，并链接原件。

## 目标是按需求发现与消费

任务入口逐层提供所需材料。读者应能按任务找到参考，无需预先知道卡片、原子样张或快照的名称。

- 总入口帮助选择工作域和表达模式。
- 分支 README 按当前问题列出必要规则、优先参考和可选研究。
- 参考说明写明支持的判断、所需输入、适用条件、变体和失败边界。首选不匹配时，可继续查看同类原子样张、普通来源或研究专题。
- 需要核对依据时，才读原件、外部事件快照、版本差异和检查记录；来源记录给出时间锚点与未覆盖项。

原子样张按比较、限定、反例、数量、邻接等任务查找；外部事件或版本研究按影响范围和取用目的查找。入口说明用途，链接到具体内容；取用优先级由下表确定。

发现效果通过实际查找、取用和产出检验。链接检查与维护走读单独记录，真实使用效果由新上下文中的任务验证。

## 取用优先级

| reference_priority | 何时查阅 | 进入条件 |
|---|---|---|
| preferred · 优先参考 | 与当前任务及范围匹配时先看 | 已提炼，并通过卡片写明的参考用途验收，有直接任务入口、证据与维护位置 |
| normal · 普通参考 | 首选不适用、需要对照或更广探索时 | 已登记并有取用说明，未取得优先资格或已降级 |
| historical · 历史参考 | 追溯、反例、复盘或迁移时 | 不再作为当前任务的推荐输入，保留ID、理由与替代位置 |

取用优先级只用于排列同类任务的参考。先判断适用范围，再比较优先级；用户要求、指令权限、证据状态和实现程度分别判断。

处理状态、证据状态、规范采纳和取用优先级分别记录。例如，`reviewed / partial / reference / preferred` 可以表示编排方法已通过查阅用途验收，代码、无障碍、全部数据和跨项目效果仍未验收。参考晋升为规范或共享组件须经裁决；组件按 ADR-002 验证。

## 参考用途验收

进入preferred前，维护者核对：

1. 写明支持的任务和判断，提供可独立阅读的取用说明。
2. 源身份与版本/日期可追溯；根据所申请的用途检查实际证据。视觉结构至少看过相应输出，运行实现需要实际行为证据，源码阅读不能替代它。
3. 列出通过、未通过和未执行的检查。使申请用途无法成立的缺陷须先解决。
4. 写明用什么、不用什么、不适用条件、维护位置与重访触发。
5. 在任务分支 README 或相关指南中添加入口，同步上层简介与正文状态。

卡片只维护一份，供多个任务入口链接。Vault 保存原件与历史审阅；Kit 保存通过用途验收的说明及来源定位。

## 从demo和实际工作回流

项目索引或验收页记录参考 ID 与版本、实际任务或测试输入、取用或调整范围、结果和反例，链接原卡片。字段见 [Demo 准入](../../demos/README.md)。

回流时先把项目观察放入Vault或项目记录，标明`supports / challenges / extends / duplicates`。Luna提炼可重复部分与缺口，main裁决保持、修改、提升或降级，并同步受影响的任务入口。个人风格与一次性修补留项目；实现晋升不因有漂亮样张而跳过验证。

长期维护可以从一次真实反例开始，不要求先积累固定使用次数；长期没有消费者、每次都被覆盖、来源漂移、依赖失效或有更好替代时复核。出现使既定用途无法成立的问题时，先降为 normal 或 historical，记录原因与替代，并更新 Kit 推荐入口。

## 发现性也参与维护

新材料入账时，同步检查任务入口、主题说明、参考卡与原件状态。实际消费中“没找到、读了大量无关材料、需要用户点名、误读过期状态”都作为导航反例回流，必要时调整简介、归属或优先级。

验收抽取不带材料名的任务，在独立上下文中观察是否能找到资料并实际改变判断或产物。验收记录保留读取路径、取用理由、遗漏与不可核实项；日常使用只留项目消费记录。结论限于实际测试的任务。

## 最小卡片信息

稳定ID、匹配任务、消费摘要、优先级、证据/采纳状态、验收日期与范围、精确来路、不适用条件、消费者记录和重访触发即可。可沿用项目已有index字段，不为统一形式批量搬迁所有来源。验收回执保留版本，当前卡片指向最新裁决。

本机制由 [ADR-017](../decisions/017-reviewed-reference-priority.md)采纳。首批 [优先编排参考](../../kit/design/references/curated/README.md)的验收范围是结构观察与查阅；代码仍为实验实现。
