# 文档结构契约

维护者按读者当前任务安排内容。README 提供本目录职责、可用状态、任务入口和下一产物；单纯索引目录使用短列表即可。

## 内容放置

| 内容 | 维护位置 | 入口表达 |
|---|---|---|
| 做什么、先读哪里、得到什么 | README | 任务 → 链接 → 产物 |
| 输入、步骤、异常和完成条件 | 指南或模板 | 链到相应任务 |
| 术语、字段、权限和状态约束 | 契约 | 查定义入口 |
| 某个场景对共同规则的取值、例外和映射 | 场景或客户项目 | 只收窄适用范围、绑定参数，不改写共同定义 |
| 工具的能力、接口、权限、失败方式和版本约束 | Adapters、Environment 或具体实现项目 | 不充当业务语义的维护位置 |
| 取舍、替代方案和历史缘由 | 架构理由或 ADR | 理由链接 |
| 实现程度、验证日期和范围 | 能力状态、验收回执 | 准确的状态标签 |
| 外部证据、来源摘要与缺口 | Vault 登记与来源卡 | 来源 ID、精确证据定位与本地链接 |
| 版本、获取与复核时间、批次和修订经过 | 独立 CHANGELOG 或变更、验收记录 | 当前正文只链接记录 |

README 本身就是任务模板时，可直接保留填写项与验收，例如 [场景模板](../../templates/scenario/README.md)。

## 互著与别裁

**互著**：多个任务入口链接同一正文，各自说明用途。上层 README 帮助选路，下层正文支持判断与执行，证据和历史按需展开。详细状态在正文维护。

**别裁**：一份材料支持不同任务时，按独立用途提炼，分别说明适用条件、证据与边界，回指同一来源 ID。研究结论、现行规范、项目做法与历史记录按职责存放。同一规则只维护一份正文；拆分后仍须保留理解所需的上下文。

条目写明用途、输入、边界和必要前提。参考链接供按需查阅；必要的契约、工具和数据依赖在使用处列明。项目专属实现及其运行依赖留在项目内。

## Kit 的体例与准入

从任务入口选择分支，读当前规则与已消费参考，依据不足时回查原件。输入、约束和完成标准明确后即可开工；维护仓库时再读入账、迁移与晋升规则（[ADR-019](../decisions/019-expression-owners-and-entry-paths.md)）。Skill 负责引入相关分支，规则正文在 Kit 维护；Writing skill 的迁移见 [ADR-016](../decisions/016-progressive-kit-structure.md)。

内容进入活跃 Kit 时，写明必要性、可重复使用的任务、入口、对实际工作的影响、验证方法和重访条件。治理规则可通过维护任务验证；实现组件按 ADR-002 的独立场景门槛晋升。一次性参数、模型技巧和项目样式留在项目记录或 Vault。

文档结构按职责安排：指南交代输入、动作、例外和完成条件；语法说明对象、关系、判断与适用边界；参考简介说明取用价值。索引提供选路所需的信息。目录按长期职责命名，有实际内容和用途时再建分支。

来源视角与问题视角在既有分类内连接：Vault 来源卡回答“作者说了什么、依据在哪里”，Kit 的可选参考 grammar 回答“遇到这个问题怎样判断、使用和避免误用”。前者保留作者术语、论证与分歧，后者按问题或操作组织可复用解释；不是两套互相复制的正文。先尝试调整现有入口的 description、链接和归属；只有发现失败或反复出现的语义歧义证明现有分类不足时，才提出分类变更，并按修订流程裁决。

需要跨维度发现时，可按 [入账规范的分面约定](../governance/intake.md#可选的分面交叉索引)扩展现有索引：区分语境、任务、产物、操作、技术、风格、证据、权利与成熟度，允许未标注、未知、不适用、多值及显式/推断依据。入口按问题组合这些信息，不要求消费者先学会整套分类，也不重复维护来源摘要。

一条内容要能单独支持一次判断，至少答得出五件事：判断的是什么问题、在什么条件下适用；涉及哪些对象和关系，哪些约束不随参数改变；哪些变量可以调，调了影响什么；一个正常例和一个最容易误用的反例；形成什么最小产物，什么时候继续、补证、升级或停止。这是把已有条目写深时的编订检查，不是每页必填的表单。只列了检查项、答不出这五件事的条目，照实当作覆盖面清单，不说成已经可以独立使用（[ADR-020](../decisions/020-entry-calibration-and-depth-check.md)）。

行文区分规则、默认和风格取舍：规则写明适用条件与违反后果；默认写明调整条件；风格取舍写明服务的读者或媒介。项目的颜色、字体和动效参数按项目范围表述。外部标准的适用级别、例外和版本按来源核对。

## 外部参考的 distilled 语义

Distilled 表示材料已提炼为取用说明；事实核实与规范采纳另行记录。来源身份、证据状态与采纳状态分别维护。具体登记字段以 [入账规范](../governance/intake.md)为准；阅读卡至少能回答：

- 原材料是什么、作者的核心论证与独特贡献，实际读取范围和证据形态是什么；版本与获取、复核时间链接独立记录；
- 哪项主张有来源支持，哪些是本项目的推断或取舍；
- 当前任务取用什么，何种条件下不适用；
- 消费产物和规范在哪里，什么变化会触发重访。

索引简介说明取用场景与用途，详情链接到对应提炼。主题卡聚合来源，每个 URL 保留独立身份。原 Chat 的建议与转引作为研究线索；原文、快照和依赖的缺口分别登记。

来源摘要须以自己的话提供足够的初步离线理解，支持的判断定位到实际读过的章节、代码或例子；读过说明文字、看过输出、执行过实现分别披露。grammar 保留具体例子、反例、适用条件和取舍，以稳定 ID 连接相关来源；来源卡反向链接消费它的 grammar。摘要、grammar 与已采纳规范各有唯一正文，相关入口只保留选路说明。

新建或改订的普通来源卡、挂载 grammar 和索引只表达当前内容、证据范围、采纳状态与重访条件，不承载版本号、获取或复核时间、批次、模型身份和修订叙事；这些信息统一放独立 CHANGELOG 或变更、验收记录，并从正文链接。原始快照、历史 ADR 和既有验收原文保留，不为统一体例批量改写。

## 已验收参考的直接入口

已通过用途验收的参考放入 Kit 相应任务分支，写明用途、取用内容、边界和验收范围，链接 Vault 原件。任务入口直接列出优先参考；取用优先级、证据状态和规范采纳按 [参考生命周期](../governance/reference-lifecycle.md)分别维护。

## 使用反馈与退出

需要回流时，在消费者自己的变更或验收记录中留下薄记录：任务与产物、参考 ID、采用/改写/拒绝及理由、判断或输出的变化、遗漏或过度读取、缺口跟进。可用 [消费记录模板](../verification/reference-consumption-template.md)，不要求每次任务填写；时间与 Kit 版本只进独立记录，不回填普通卡片。没有使用的条目无需逐个列举；只有预期触发却未被找到或采用时，才记录导航断点。维护走读与新上下文中的实际任务 dogfooding 分开报告。

反复绕过、依赖失效、找不到消费者或上游已覆盖时，复核其必要性。降级到研究参考或停止推荐时更新任务入口，保留稳定 ID、历史证据和替代路径；晋升、修订与退出走 [同一维护流程](../governance/evolution.md)。不以保存时长或使用次数自动决定采纳。

## 当前目录如何承担这些职责

[dsh-praxis Kit](../../dsh-praxis/kit/README.md)按 Task、Writing、Publish 分层，[证据与来源](../../dsh-praxis/kit/writing/evidence.md)贯穿各层，文体只在专门文体触发时读取。[Design](../../dsh-praxis/kit/design/README.md)按 Foundations、Composition、Interaction、Motion 分开判断，并将 References 按编排、界面、系统与样张再分路。

每个分支提供现有内容及下一步入口。规则迁移后删除旧路径，仍在维护的页面改指新正文；历史 ADR、Chat 和验收保留当时记录，只把链接目标改到新位置（[ADR-037](../decisions/037-dsh-praxis-layered-grammar.md)）。目录深度按任务分工确定。

## 编订操作

1. 确定读者此刻要完成的任务，链接到最小必要输入。
2. 将重复理由归到架构理由或 ADR；当前入口保留结论和状态。
3. 将操作限制写成明确条件：批准针对哪个对象和版本，交接由谁接收、凭什么接收，结果未知时如何核对与恢复。
4. 在规则唯一位置维护反例，README 提供查阅入口。
5. 变更规范时检查模板、验收与消费者；破坏性变化按 [修订流程](../governance/evolution.md) 处理。

## 验收

- 从任务入口能找到输入、产物和完成条件；链接文本能说明目标用途。
- 权限、真实数据分区、证据状态和实现状态仍能在操作发生前查到。
- 同一规则只有一个维护位置；历史记录保留当时结论。
- 新内容有相关分支入口；旧入口有迁移位置或处置理由。必要依赖与可选参考明确，清理后无关分支仍可独立使用。
- 用合成任务走读正常路径和失败路径，记录断点；实际使用效果另记观察证据。
- 说一条规则或入口起了作用之前，默认留一个不读它的对照和一个没参与调整的任务，产出和代价一起看，做法见 [对照、留出、代价](../../kit/environment/working-methods.md#要说一条规则有用)。做不到时记“未对照”（[ADR-021](../decisions/021-community-mechanisms-and-attribution-check.md)）。

选型依据与后续候选见 [文档实践提炼](../../vault/distilled/themes/documentation-practices.md)；采纳裁决见 [ADR-011](../decisions/011-task-documentation.md)。
