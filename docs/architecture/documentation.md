# 文档结构契约

维护者按读者当前任务安排内容。README 提供本目录职责、可用状态、任务入口和下一产物；单纯索引目录使用短列表即可。

## 内容放置

| 内容 | 维护位置 | 入口表达 |
|---|---|---|
| 做什么、先读哪里、得到什么 | README | 任务 → 链接 → 产物 |
| 输入、步骤、异常和完成条件 | 指南或模板 | 链到相应任务 |
| 术语、字段、权限和状态约束 | 契约 | 查定义入口 |
| 取舍、替代方案和历史缘由 | 架构理由或 ADR | 理由链接 |
| 实现程度、验证日期和范围 | 能力状态、验收回执 | 准确的状态标签 |
| 外部证据、选型建议与缺口 | Vault 登记与提炼 | 来源 ID 与本地链接 |

README 本身就是任务模板时，可直接保留填写项与验收，例如 [场景模板](../../scenarios/_template/README.md)。

## Kit 的体例与准入

Kit 通过目录、README 和正文共同承担使用引导。挂载后从任务进入有关分支，先读当前规则和已消费参考，只有依据不足时才回查原件；无需将整个 Kit 或 Vault 预先装入上下文。Skill 可提供有界入口，不把目录压成一个完整指令包；Writing skill 按 [ADR-016](../decisions/016-progressive-kit-structure.md)改为读取 Write/Prose 的薄入口，规则正文在 Kit 单点维护。

一项内容进入活跃 Kit，应说明它为何必要、预计在哪类任务重复使用、从哪个入口能找到、如何改变实际行为，以及如何验证和重访。治理规则可由本仓库维护任务验证；实现组件仍遵守 ADR-002 的独立场景门槛。一次性参数、模型技巧和项目样式留在项目记录或 Vault，不能仅因整理完整就晋升。

文档按职责编写，不强制所有页面使用同一组标题。指南交代输入、动作、例外和完成条件；grammar 解释对象、关系与判断，并给出适用边界；参考 description 解释材料的取用价值。短索引只需提供足以选路的说明。目录名称表达长期职责，新分支由实际消费触发，不提前铺设空蓝图。

行文明确约束强度：规则（rule）给出适用条件与违反后果；默认（default）说明何时可调整；风格取舍（taste）说明服务的读者或媒介。不要求给每句话加标签，但不能把某次选用的颜色、字体或动效参数写成无条件禁令。外部标准的适用级别、例外和版本另按来源核对。

## 外部参考的 distilled 语义

Distilled 是经过判断和泛化的消费说明；其处理状态不意味着事实已核实或规范已采纳。来源身份、证据状态与采纳状态分别维护。具体登记字段以 [入账规范](../governance/intake.md)为准；阅读卡至少能回答：

- 原材料是什么，实际读取了哪个版本和范围；
- 哪项主张有来源支持，哪些是本项目的推断或取舍；
- 当前任务取用什么，何种条件下不适用；
- 消费产物和规范在哪里，什么变化会触发重访。

索引 description 用一两句说明“何时值得读、读后能做什么”，详情链接唯一提炼位置。主题卡可以聚合来源，但不能取代每个 URL 的身份。原 Chat 的建议与转引只提供研究线索；缺原文、未保存快照或未检查依赖分别登记，不把缺口藏在 `accepted` 后面。

## 已验收参考的直接入口

成熟参考的泛化说明放入 Kit 相应任务分支，先提供用途、取用内容、边界和当前验收，再按需回查 Vault 原件。按 [参考生命周期](../governance/reference-lifecycle.md)分开维护取用优先级、证据状态和规范采纳；优先参考从任务入口直接可见，不要求读者知道材料名称或反复深入Vault。

## 使用反馈与退出

在实际消费者的 index 或验收中留下薄记录：日期、Kit 版本、取用条目、调整理由、结果与下一次复核条件。没有使用的条目无需逐个列举；只有预期触发却未被找到或采用时，才记录导航断点。此次维护走读与真实任务 dogfooding 分开计数。

反复绕过、依赖失效、找不到消费者或上游已覆盖时，复核其必要性。降级到研究参考或停止推荐时更新任务入口，保留稳定 ID、历史证据和替代路径；晋升、修订与退出走 [同一维护流程](../governance/evolution.md)。不以保存时长或使用次数自动决定采纳。

## 当前目录如何承担这些职责

[Write](../../kit/write/README.md)按 Prose、Publish、Motion 逐层展开，Shared 维护跨模式证据与验收，Prose/Genres 只在专门文体触发时读取。[Design](../../kit/design/README.md)按 Foundations、Composition、Interaction、Motion 分开判断，并将 References 按编排、界面、系统与样张再分路。

每个分支有真实的当前内容与下一产物。规则迁移后旧路径保留到新位置的导航，不能留下两份同时活跃的正文；历史 ADR、Chat 和验收仍保留当时语境。目录深度由任务分工决定，单一职责的短契约无需为了形式继续拆目录。

## 编订操作

1. 确定读者此刻要完成的任务，链接到最小必要输入。
2. 将重复理由归到架构理由或 ADR；当前入口保留结论和状态。
3. 将影响操作的限制写成字段、条件或失败路径：批准绑定对象与版本；交接填写接收人和接收依据；未知结果进入核对与恢复。
4. 在规则唯一位置维护反例，README 提供查阅入口。
5. 变更规范时检查模板、验收与消费者；破坏性变化按 [修订流程](../governance/evolution.md) 处理。

## 验收

- 从任务入口能找到输入、产物和完成条件；链接文本能说明目标用途。
- 权限、真实数据分区、证据状态和实现状态仍能在操作发生前查到。
- 同一规则只有一个维护位置；历史记录保留当时结论。
- 用合成任务走读正常路径和失败路径，记录断点；实际使用效果另记观察证据。
