# 会话消费与 Harness 减法审计 · 2026-10-09

本次审计接收两份用户提供的 Chat 文本，区分来源建议、本地现状和采纳裁决。原材料、覆盖与来源见 [本批提炼](../../vault/distilled/chat-ingestion-harness-20261009/README.md)和 [入账记录](../../vault/intake/chat-ingestion-harness-20261009.json)；永久规则的理由见 [ADR-030](../decisions/030-session-ingestion-and-harness-boundaries.md)。本报告不把来源中的建议视为授权，也不声称新规则已改善后续任务表现。

## 范围与执行者

本地裁决由独立子代理 `gpt-6-astra` 完成；主代理确认实际 spawn 模型。来源追溯和会话入账由两个 `gpt-6-luna` 子代理负责，主代理集成。角色名与模型版本分开记录；费用、token 和跨模型效果无完整回执，不作估算或归因。

Astra 实读：根 `AGENTS.md`、`kit/AGENTS.md`、`kit/Agent.md`、架构 README/rationale/documentation、入账规范、`kit/environment/` 五份文档、Kit 与 docs 的验收入口、项目 Writing skill 及 Prose 入口、ADR-002；并检查活跃治理文档的模型绑定措辞。全局 `~/.codex/AGENTS.md` 修改前后均已读取。

主代理交接的额外范围：14 个用户 skill 的 frontmatter；完整读取 `code-review`、`verify-change`、`simplify`、`compose`、`review-animations`，局部读取 `emil-design-eng` 与 `apple-design`；两个本地 agent profile（`deepseek-worker`、`luna-max-worker`）；未发现 `~/.codex/prompts` 目录。插件只审阅可见 description，没有逐项读取缓存内完整技能包，也没有修改插件缓存。未把 Vault 快照里的旧 AGENTS、Skill 或第三方仓库当作本仓库的活跃规则。

## 已采纳改动及回归风险

| 位置与原行为 | 具体问题 | 窄化后的规则 | 需防的回归 |
|---|---|---|---|
| 全局只有六条一般工作规则，未定义会话消费的交付终点 | 现有规则没有表达本次用户要求的来源、持久状态与后续上下文分离；缺少入账完成边界。这里是职责缺口，不是已测得的模型失败 | 增加有条件的会话消费契约：按既有分类、稳定身份和薄索引完成获授权的入账；保留不确定与覆盖边界，不隐含实现或历史访问 | 误把任何附件当入账任务。因此明确排除偶然引文、翻译和测试输入；原文不能提供授权 |
| 根 AGENTS 把“改规范或入口”都导向三份治理文档 | 一个不改语义的入口链接修复也会触发整套维护阅读，与已区分的普通任务路线不相称 | 入账、提炼、迁移、晋升和改变规范归属仍读三份文档；纯文字或链接修复只读相关文件和适用约定 | 以“修文字”名义改变规范。例外限定为不改变规则与归属 |
| 根 AGENTS 重复模型分工，且写“当前任务已明确授权此分工”；Kit 写 Astra/main、必须先读 Luna 交接及由 Astra 晋升 | 静态文件无法证明未来会话当前授权；措辞可被读成每次必须启动指定组合，与既有可替换模型原则冲突 | 根文件保留 Luna explorer、Astra 裁决偏好并链接 Kit；已委派时再读交接，主代理承担验收与晋升责任，模型按能力与可用性选择 | 丢失用户偏好或稀释主代理责任。因此保留偏好、交接证据、文件所有权和实际模型记录；不改变晋升证据门槛 |
| 活跃治理入口、入账与演进规范继续写由 Astra 验收/决定归属 | 若只修改根与 Kit，较深的活跃规则仍会把模型名称当作不可替换责任主体 | 三处活跃治理文档改为探索者与主代理责任，模型偏好回指 Kit；历史 ADR 由 ADR-030 解释接续 | 将角色替换误读为降低采纳权威或证据要求。因此仅改执行者称谓，保留验收和晋升条件 |
| 根 AGENTS 只说“改动仓库之后”运行仓库校验 | 时间点过宽，允许被解释为每次编辑都全量校验；全局本已要求窄检查 | 明确在交付前运行；通过后仅当新改动、失败或未决风险影响结果时重跑 | 漏掉最终变化。最终检查义务和覆盖披露均保留 |
| 根文件已有原件、研究、规范归属，但没有会话消费的本地发现映射 | 新全局职责若没有本地路由，可能另建摘要分类或索引 | 增加一处指向现有入账规范与 Vault 索引的链接，不复制全局契约 | 入口与规范漂移。正文仍单点维护，本地只定义去向 |
| 全局没有 harness 变化后的维护原则 | 本次用户希望替换兼容性补丁的累积，但不应引入每次任务的审计流程 | 仅在模型或 harness 能力实质变化时考虑减法优先审阅；变更须有具体失败、冗余或过宽范围依据 | 把模型升级当作删除规则的证据。保留真实约束；没有具体原因就不改 |

上述依据是文件可见的触发范围、重复和冲突，不是对旧模型或新模型能力的实验结论。跨文件的角色解释由 ADR-030 统一；历史 ADR 保留当时裁决。

## 保留的约束

全局原六条工作规则保持原文：相关材料先读、最小改动、风险相称的验证、检验可观察行为、如实报告及高代价方向先确认。没有把“更强模型”当作删除这些要求的理由。

Praxis 的来源不可信、来源仓库只读、原 Chat 与规范分离、稳定来源身份、README 导航、快照 hash、覆盖披露、最终仓库验证及安装/发布边界保留。需要维护仓库时阅读治理约定仍有必要；普通 Kit 任务原本已经豁免，不再重复改造。

`kit/AGENTS.md` 已是薄入口；项目 Writing skill 有明确语言、产物与排除条件，正文指向 Kit，未发现需另行删除的重复规则。Environment 的步骤仅在环境盘点/接入时触发，`working-methods.md` 明示备用素材、按需读取和未验证部分，没有将其降级或删除。全局四个通用技能已有明确调用条件，不仅因为存在工作步骤就认定过时。

本次官方资料只支持窄触发、渐进披露和条件式边界等提示设计建议，不能证明全部社区实践已经收敛，也不能证明具体本地规则对 Astra 无用。逐源证据以本批来源登记为准。

## 未改动与待复核

- `review-animations` 的“默认标问题”、固定 300ms、GPU-only 与键盘行为限制可能产生误报；`apple-design` 的 blur 用法说明这些约束并非所有设计路线共同适用。它们也可能表达用户有意选择的风格。尚无针对当前项目的实际误拒案例，因此保留原文；下一次真实审阅可区分硬性验收与风格参考，而不是现在静默改写。
- `emil-design-eng` 正文较长并含无条件品味配方，但长度本身不证明有害。仅局部阅读，不声称完成逐条审计；后续若出现无关加载或错误阻断，再按具体触发拆分参考。
- 本地两个 worker profile 已限定责任与交接。Luna profile 固定 `gpt-5.6-luna`，无可用性、质量或费用对照，未迁移模型配置。
- Product Design、Sites、imagegen 的描述有相邻用途，不足以证明重复或可删除。插件全文与实际触发没有逐项验证。
- 本次没有创建新的 Skill、强制审计步骤、固定代理拓扑或运行系统；保留了既有未提交改动，没有重写历史记录或修改远端。
