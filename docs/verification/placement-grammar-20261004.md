## 对上一轮说法的更正

上一轮的提议写“四个件的窄版是同一种构造：一条竖轨，行挂在轨上”，并说这一条是实现层的收敛。重读代码后，这句话只对 `rel-tracks` 和 `rel-fan` 成立。实际收敛到共用代码的只有两样：一条通线的画法，和位置读法的词表。四个件真正共有的是让位置说了话而没有写明，所以这一轮的重心从“抽一个共用的排法”改成了“写明位置回答什么”。

## 冷读与对照

两个任务，各用一份没有用来调过样板的合成内容。每个任务两份：一份从根 `AGENTS.md` 进仓库、自己找指引；一份不读仓库，只看任务。四个都是 Claude Sonnet 子代理，互不相见。任务书没有点页面名字。截图在 [evidence](../../demos/editable-native-svg/grammar-specimens/evidence/README.md)的 `cold-read-c.png` 和 `cold-read-d.png`。

| 任务 | 读了 Kit 的一份 | 对照 |
|---|---|---|
| 一：上海和法兰克福两地的冷链转运记录（时区不同，报警的结束时间没有记录），外加三步用时分别是约数、区间和未规定的流程。回答报警在进冷库之前还是之后、出库到落地多久、后三步还要多久 | 经 Design README 的“先读”表找到本页。两地各一条轨，共用一条写明按 UTC、每格一小时的标尺；报警只画起点，读法里写“不表示报警持续到 19:10”；后三步不画比例图，用编号清单并写“间距和行高不表示时长” | 三个答案同样正确，同样先换成 UTC 再相减，同样拒绝给后三步的总数。报警画成一条从 18:30 延到 19:10 的条，后面接虚线和问号；材料只说报警从 18:30 开始，没有说它持续到进冷库 |
| 二：一份规程两版的内容（有一项单位从分钟换成小时，有一项提议待定）和部门归属（有一人同时向两个部门汇报）。让新人看清改了什么、没改什么、哪些没定、离心机室归谁管 | 找到本页和成立程度一页。一行一项，没变的两行留着，空格写“第 3 版没有这一项”；表下写“行的次序不表示重要程度”；两个上级不画成缩进的树，图注写“位置高低不表示权限大小”；强调色只给待定的一项 | 同样留着没变的行、同样写出单位换算、同样把两条汇报线画成虚线并加图例。状态用了三种颜色的标签；没有关于行序和位置的说明；末尾多了一句材料里没有的建议 |

能说的只有这些。任务一里的差别对得上本页第 5 条，对照的一份画出了一段材料里没有的持续；任务二里两份的实质相同，本页带来的只是那几句读法和少用两种颜色。每边只有一份，不能说差别来自页面。两份读了 Kit 的产出都比对照长。任务二读 Kit 的那个子代理在交回报告时被接口中断，页面和笔记已经写完，回执按它留下的文件写。

冷读指出、已经补进页面的两处：两个时刻之间量出来的间隔不是一段持续的事，不画成区间（任务一读 Kit 的一份自己改用了括线，并说明这偏离了默认）；单位不同时先换算并把换算写出来，换不了的才不排成变化（两份任务二的产出都这样做了，页面原先只说“不排成变化”）。指出而没有处理的：窄屏下读 Kit 的一份让图横向滚动，没有照第 10 条并成一条线；Kit 里没有“给新人的说明页”这类文体的指引。
