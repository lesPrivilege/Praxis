# 社区问卷结果说明

状态：自然发现与取用的验证工件，仅留作仓库结构验收证据，不作为产品demo。原生成目录为 `demos/community-survey-explainer/`，收尾迁入本目录。

## 有界场景与接收

- 场景 ID / 版本：`community-survey-explainer-2026-09-29-v1`。
- 使用者：需要判断一份社区自愿问卷能支持什么结论的社区决策者。
- 交付范围：一页离线 HTML、一个正常 synthetic 输入、一个 selection-bias 反例和本目录消费登记；不接入真实问卷、居民名册或外部系统。
- 允许用途：演示分母、证据范围与补证思路；不得作为真实居民意见统计或永久延长开放时间的单独授权依据。
- 接收：由主代理复核页面与登记后，仅作为仓库结构验证工件保留；主代理统一运行仓库级验证并报告全仓边界。
- 本目录验收：桌面与 375px 窄屏能读到 `210 / 300 = 70%`、答复者边界、随机波动/自选偏差区分、反例和下一步补证；文件可直接从本地打开。

这页用一个构造的社区场景说明：某周公众号自愿问卷收到 300 份答复，其中 210 份赞成延长开放时间，因此 `210 ÷ 300 = 70%`。70% 的分母是 300 份答复，只能描述答复者；它不能直接推出全体居民中有 70% 同意。

## 本地运行

直接在浏览器打开 [`index.html`](index.html)。页面只使用本地 HTML 与 CSS，不加载远程字体、脚本、图片或数据请求；关闭脚本也不影响阅读。

## 口径与边界

页面明确写出 `210 / 300 = 70%`，并把“答复者”与“全体居民”放在不同层级。`90` 只标为“其余答复”，没有虚构反对、不确定或空白的细分。页面中的 50% 居民支持率和 70% 扩大后的答复比例均是思维实验，不是观察值，也不代表本社区。

下一步补证是决策建议，不是已经完成的证据：建议记录邀请覆盖与各组回应率、在可行时比较受邀者与答复者、用开放时段的实际到访和小规模试点观察来补充自报意愿。页面没有把这些建议写成已经发生的事实。

本轮未运行仓库级 `python3 scripts/validate_repository.py`，由主代理统一执行；本目录内已做文件解析、算术与静态响应式检查，并实际检查了 HTML 的本地渲染范围。未检查屏幕阅读器、打印、200% 缩放和非 macOS 字体退化。

主代理检查：Q06-d/V06/W03的实际取用可在HTML中定位；REF-COMP-001的归因经过人工纠正，不能计作无提示正确取用。反例中1000人总体到3000份答复的扩展未显式声明总体同步扩大，此生成缺口原样保留用于诊断，不继续打磨测试页面，也不把它作为经过内容验收的业务材料。
