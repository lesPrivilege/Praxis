# 社区空间开放安排判断 · 场景契约

状态：`synthetic-demo`，revision `20260929-r1`。

## 1. 工作与机会

- 场景 ID：`community-opening-comparison`。
- Kit 入口：本轮实际读取的仓库入口与参考 ID 见 [`consumption.json`](consumption.json)；本目录不把未核实材料升级为业务事实。
- 使用者：社区空间运营者；最终接收者：阅读并判断“每天有人开门”的决策者。
- 工作问题：比较 A（7 天 / 每月 1800）、B（5 天 / 每月 1200）和 C（7 天 / 每月 1500，只有周末有志愿者时成立）。
- 输入边界：只有本目录两个 synthetic fixture；没有真实排班、成本、志愿者或空间系统输入。
- 期望改变：读者能区分直接满足、直接不满足和有条件满足，并能用失败 fixture 复核 C 的条件作用范围。
- 替代方案：人工阅读一张比较表；本页只改善条件邻接、窄屏比较和失败例子的可见性，不声称减少真实运营劳动。
- 继续条件：fixture 字段、页面判断口径和失败状态仍与题目一致。
- 停止条件：输入变成真实客户数据、要求连接排班系统，或需要把条件判断写回外部系统时，停止本 demo 并另建有授权的场景。

## 2. 对象、证据与动作

- Worker：本地 HTML 阅读者。
- 天然输入件：一份 fixture（`fixture_id`、`week`、A/B/C 的 `open_days`、`monthly_cost`、`condition_scope`、`weekly_status`、`expected`）。
- 动作：阅读按属性比较矩阵，检查 C 的周末条件，再打开失败样本或切换页面复核控件。
- 人工验收点：确认 A/B/C 均可见；C 的条件只出现在 C 的语义槽位；失败样本的周六、周日为关闭；核心判断之后紧邻有解释。
- 预期产物：一个无需安装依赖即可打开的中文 HTML 页面，以及两个可审阅的 JSON fixture。
- 证据身份：`community-opening-normal-v1`、`community-opening-failure-no-weekend-volunteers-v1`；结构参考身份、改写范围和限制见 `consumption.json`。
- 确定性规则：每周固定按周一→周日；“满足”要求七个状态均为有人/志愿者；缺少 C 的周末志愿者按关闭计算；金额仅作显示，不参与额外排序。
- AI/人工边界：页面只呈现预先给出的 synthetic 规则，不推断真实排班，不批准任何运营安排，也不执行外部动作。

## 3. 失败与恢复

| 情况 | 处理 |
|---|---|
| fixture 缺少周或方案 | 标记输入不完整，不生成新的结论；由维护者补齐七天和 A/B/C 字段。 |
| C 的条件字段改变 | 使当前页面判断失效，先更新 `condition_scope`、失败样本和页面解释，再重新验收。 |
| 正常与失败样本结果冲突 | 保留两个原样本，回查 `expected` 和页面口径；未解决前不声称通过。 |
| 页面脚本无法运行 | 依靠静态 HTML 阅读；方案、条件、正常 fixture 和失败反例仍应可见；复核控件记为未执行。 |
| 需要真实数据或外部写入 | 停止本 demo，记录缺口和授权边界，不把 synthetic fixture 当作替代。 |

## 4. 验证与结果

- 正常路径：解析 `fixtures/normal.json`，确认七天、A/B/C 顺序和 C 在周末志愿者存在时的条件满足。
- 失败路径：解析 `fixtures/failure-no-weekend-volunteers.json`，确认 C 的周六、周日关闭、`decision=does-not-satisfy` 且作用域仍为 `C-only`。
- 页面检查：宽屏三列按属性矩阵；375px 窄屏按属性堆叠且每个属性仍显示 A/B/C；核心判断之后有邻接解释；checkbox 的结果有 `aria-live`。
- 已实际执行的检查、浏览器渲染证据和未执行范围写在根 README；本轮不在此目录运行全仓 `validate_repository.py`。
- 本场景没有受众理解率、真实成本收益、无障碍完整合规或运营接受率数据，这些保持未知。

## 5. 接收与后续责任

- 交付入口：[`index.html`](index.html)；数据样本见 `fixtures/`；回执见 [`consumption.json`](consumption.json)。
- 允许用途：离线阅读、结构演示、规则与反例复核；不用于真实排班、成本承诺或自动决策。
- 接收标准：读者能从首屏找到 A 的直接结论；能看到 B 的 5 天限制；能看到 C 的专属周末条件；能复核缺少志愿者时的周末关闭反例。
- 当前维护责任：本目录的施工者维护页面、fixture 和消费记录；主代理负责统一仓库验收与是否采纳任何上游规范。
- 退出条件：题目不再需要、真实系统接管判断，或页面/fixture 的 synthetic 边界无法继续保持时，停止维护并保留历史回执。
