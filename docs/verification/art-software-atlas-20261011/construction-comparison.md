# 建构草案的取用裁决

## 阅读范围

## 采纳或沿用

| 提案方向 | 裁决与落点 |
|---|---|
| 来源、观察、判断、审阅分开 | 沿用 catalog/cards、独立 CHANGELOG/验证记录；本次 facet 的 basis、evidence、rationale 使分类判断可回查 |
| 多轴检索与稳定身份 | 采纳实质，补全已有分面；不重编 ID 或迁移目录。canonical 登记生成 index 与倒排表 |
| 渐进读取 | 沿用 L0–L4；入口用于选路，正文解释判断，来源和验证按需下钻。无需统一为另一套四级编号 |
| 按来源类型保留出处信息 | 沿用各卡已有的作者、对象号、版本、原术语及精确 locator；缺失内容按证据补，不为凑表猜填 |
| 发现—去重—读取—摘要—复核及使用反馈 | 沿用入账和参考生命周期；此次补正来自真实分类发现失败，并保留前后覆盖与反例查询 |
| 观察历史与维护历史分开 | 保留旧回执；重访追加记录。采集时间只表示观察发生时间 |

## 延后

| 提案方向 | 当前处理与触发条件 |
|---|---|
| 独立 style / snapshot / review 对象树 | 现有文件已分担相应职责，没有足够迁移收益。出现多版本作品、对象间身份歧义或重复维护时再细化 |
| 每条主张再标 register、来源等级、mapping grade | 三者概念保留区分；当前引用、推断、规范采纳及关系 limits 已承担主要判断。只有明确跨域映射需要比较时再逐项登记，不铺空字段 |
| 更丰富 derives/variant/supersedes 关系 | 有具体作品变体或替代事件时增加；当前关系不能仅由名称相似或共享来源推出 |
| 来源类型必填扩展 schema | 出现同类遗漏反复影响消费时制定；edition、版本等仍以实际读到的对象为准 |

## 不采纳

| 假设 | 理由与现有处理 |
|---|---|
| 英语必须是唯一 canonical 名称，其他语言只作别名 | 保留原术语与作者语境，遵循仓库中文成文约定；英文路径/字段不构成文化名称优先级 |
| 每种风格均能完全分解为参数设置 | 材料劳动、礼仪、身体经验、社群意义和历史归属可能不能转成软件参数；设计转换保留局部范围与拒绝条件 |
| contested 是单向成熟度步骤 | 争议、验证、采纳和弃用是不同维度；复核可缩小结论或恢复使用，不要求单向晋级 |
| 用 snapshot 日期推导起源、传播与衰落 | 最早采集不等于历史首次；历史结论需要当时材料及有范围的研究，不能从本库访问轨迹推算 |
| 所有跨域映射最后可评成严格互推 | 相似性不证明同构。当前软件转换按局部设计推导表达，未证明的对应不得升级 |
| 固定季度/年度刷新、目录配额与统一新树 | 用户未要求定时任务，当前缺口也未证明这些机制必要。按来源变化、依赖失效和消费失败触发有界复核 |
| 摘要层一律隐藏争议 | 改变采用决定的争议留在正文附近；完整证据和审阅过程放独立记录 |
| 把专家意见原文全部发布 | 公开仓库只保留授权且适合公开的证据与泛化裁决；不自动复制私有评语或会话 |
