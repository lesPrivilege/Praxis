# 产品软件界面参考

定义产品界面、控件状态和可访问性检查时，从标准、既有工作台的界面约定与成熟设计系统中借尺寸、状态、层级与密度的做法，不照搬数值，也不当作通用 runtime contract。

返回 [Design 参考路由](README.md)。

尺寸与缩放分成几项检查：24 CSS px 是报告的 AA 下限，44 px 是 coarse 或 high-consequence 路径的选择，两者是不同准则；200% 文字缩放、布局重排和文字间距各自检查。tab 识别对象、版本与范围，关闭或切换是视图动作，不等于取消、删除或批准。

运行时状态分开标示：录入、启用、已用、已加载各有其名，proposal 由人审 Apply 或 Reject；Host 负责授权与取消，dispatch 后结果未知与终态分开。没有真实进度时不画百分比或预计完成时间，但长任务仍要区分 unknown、真实进度和终态。

表面分组靠留白、对齐和字阶，卡片留给独立对象，提示框不承载必要信息；密度上正文字号不动，界面文字降一档，层级靠字号与字重。设计系统作 conceptual donor 时，控件尺寸、图标尺寸、组间距和标签字形分开设定，不照搬数值、不引入依赖；站点拆解只是同类视觉方向的观察，不是官方 grammar。

## 维护

界面任务必须在项目 index 记录实际采用的参考、来源版本、调整理由和真实验证结果；单个像素值不能替代完整的尺寸、焦点、键盘、缩放和布局验收。
