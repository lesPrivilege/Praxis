# 从集合到作品，再到可用操作

<!-- ASA-G-DISCOVERY -->

“找些会呼吸的界面”“想要有材料感的图表”这类还没有材料名的探索任务，从集合找到单件作品再找到实现契约，产出两条可比较的设计假设及其证据边界。

先把意图写成关系：哪些对象变化、哪些对象保持、谁感知变化、在哪种媒介交付。然后用集合的原有分类找到候选，回到单件作品和作者说明，最后另找实现契约。保留作者的名称、贡献者与文化语境；本仓库的操作词只增加一个索引，不替换原分类。

档案、demo 站与工具目录的原有分类不同：档案分作品、变体、参与者与保全记录，demo 站按布局、状态转场、排印、hover 等栏目，工具目录按书籍、工具、学习与社区。目录里有条目、视频或推荐，不证明原作仍可运行、可达、适合生产、仍在维护或许可统一；档案里的变体也不能归为艺术家新作。

## 可控制的发现过程

同一个形容词至少试两种机制。“呼吸”可能是低频振幅、曝光变化、留白密度或交互后的恢复节奏，不自动等于缩放动画。保留一件反例：无动画而有节奏的编辑页，或大量运动却无法保持对象身份的演示。检索操作是换关系、换媒介、沿作者相邻作品、沿依赖/引用上溯，不是只换一组风格同义词。

每次先读入口摘要；必要时再打开作品说明及一件实际输出。运行需求触发代码/环境检查；资产复用触发逐项许可检查。做到能够写出一个可调变量、一个不变量和一个失败条件即可停止这次读取，把未读候选留为 lead。使用 linked data 或本地 JSON 索引均可保留实体关系。

反例：从某目录读到“WebGL”的标签，就把其下全部作品标成 WebGL；从某截图觉得“日本感”，就补一个传统名；看到 MIT 仓库就把其中摄影、字体一并当 MIT。这些都须退回具体 URL、具体主张与具体权利对象。

选出一个可试方案，也保留一个被排除的候选及理由。
