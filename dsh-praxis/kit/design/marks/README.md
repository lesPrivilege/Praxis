# 第一部分 · grammar

## 1 范畴

讲解用的画面里，稳定的含义落在十个问题上。标“补”的几组证据更薄，在各节标明。

| 问题 | 范畴 | 回答方式 | 本包位置 |
|---|---|---|---|
| 这是什么 | 对象 | 记号加名字 | glyphs.svg · 对象 26 个 |
| 它成立到哪一步 | 状态 | 记号加状态词 | glyphs.svg · 状态 12 个 |
| 步骤之间怎样走 | 流程 | 记号加动词 | glyphs.svg · 流程 11 个 |
| 谁和谁有关，生效了吗，确认了吗 | 关系 | 线型、端点、强调色 | glyphs.svg · 关系；components 第 12 节 |
| 谁在谁里面 | 范围（补） | 闭合的边界线 | components 第 12 节 |
| 这一格有没有值 | 取值（补） | 四个词，各有记号 | glyphs.svg · 取值 4 个；components 第 7 节 |
| 走到了哪一站，说的是哪一处 | 位置（补） | 站点的三种画法，编号位 | glyphs.svg · 位置 4 个；components 第 2 节 |
| 是谁说的，凭什么 | 来路 | 只用文字或位置 | components 第 6 节的文字标签 |
| 读者能做什么 | 控件 | 11 个控件 | components.html |
| 什么变了 | 运动 | 10 种运动 | motion.html |

数量（多少）不在其内。数量要共同的尺度和有意义的零点，属于 Kit 的 [图形编码](../composition/encoding.md)；本包只在试算和计时两个控件里画了有刻度的量条。层级（多重要）靠字号和字重，在 tokens.css。

## 2 换什么造型都不变的约束

1. 记号是一个词的重复，旁边总有这个词；去掉记号，内容不变。
2. 一种画法只回答一个问题。虚线只回答“生效了吗”，所以对象和流程的记号里不出现虚线，表示流动也不用虚线。
3. 默认的分配：线型回答“生效了吗”，端点回答“确认了吗”，强调色只标“等人决定”的那一处，“是谁说的”用文字或位置。
4. 供读者点选或步进的图里，强调色可以改作“当前”，写进图例；它和“等人决定”不进同一张图。
5. 颜色不单独承担区别。去色之后，每一处区别还有形状、虚实、粗细或文字可依。
6. 被拒绝的、已过期的、被丢弃的留在图上，看得出它存在过，也看得出它没有生效。
7. 没有真实进度时不画百分比和预计完成时间。“结果未知”是独立的状态。
8. 必要的信息不只在悬停时出现；键盘焦点和操作的结果看得见。
9. 运动只表达状态切换、空间位置、关系变化或叙事时间；它跟随真实状态，可以被打断；补间的中间值不是数据。
10. 图例只列这张图里实际出现的画法，并由画图的同一份输入得出。输入没写状态时拒绝画。

第 3、4、6、10 条来自 Kit 的 [成立程度与归属的标记](../foundations/standing.md)，第 7、8 条来自 [状态与可达性](../interaction/states.md)，第 9 条来自 [运动判断](../motion/grammar.md)。

## 3 对象

一个对象记号回答“这是什么”。它不带状态：同一个数据库无论在线、出错还是不存在，都是这个记号，状态另用状态记号或线型表示。

| 词 | 含义 | 与相邻项的区分 |
|---|---|---|
| 人 | 作判断、发起或确认的那个人 | 与 agent：人负责，agent 代办 |
| 浏览器 | 网页形式的入口 | 与终端：一个是页面，一个是命令行 |
| 终端 | 命令行形式的入口 | 见上 |
| 聊天渠道 | 通过对话软件进来的入口 | 与浏览器：消息一条条来，不是页面 |
| 定时器 | 到点触发 | 与 webhook：一个按时间，一个按外部事件。与“已过期”：定时器是对象，过期是状态 |
| webhook | 外部事件推过来触发 | 见上 |
| 网关 | 请求的统一入口 | 与中间件：网关在边界上，只有一个；中间件在路径上，可以有几层 |
| 服务 | 自己这边的一个运行单元 | 与外部服务：以谁能改它来分 |
| 外部服务 | 别人运行、自己改不了的服务 | 见上 |
| agent | 自己决定下一步的执行者 | 与模型：agent 是带着工具和状态的循环，模型是其中被调用的一环 |
| subagent | 由另一个 agent 派出的 agent | 与 agent：有上级，结果交回上级 |
| 模型 | 被调用来生成或判断的语言模型 | 见 agent |
| 工具 | agent 能调用的一个动作 | 与 skill：工具是能执行的，skill 是读的 |
| skill | 告诉 agent 怎样做一类事的说明文件 | 与文件：skill 是给 agent 的指引，文件是内容 |
| 中间件 | 请求经过的一层处理 | 见网关 |
| 队列 | 按顺序等着被取走的一排东西 | 与数据库：队列里的东西取走就没了 |
| 数据库 | 长期保存、可以查询的记录 | 与记忆：数据库是存放处，记忆是 agent 会带进下一轮的内容 |
| 文件 | 一份内容 | 与 artifact：文件是泛指，artifact 是交出去的那一份 |
| 目录 | 放文件的地方 | 与范围边界：目录是对象，边界是关系 |
| 记忆 | 跨越多轮、agent 会再读到的内容 | 与 checkpoint：记忆是内容，checkpoint 是某一刻的整体状态 |
| checkpoint | 某一刻保存下来、可以退回去的状态 | 见上；与“回滚”：checkpoint 是对象，回滚是动作 |
| artifact | 交付出去的文件 | 见文件 |
| 沙箱 | 隔离的运行环境，里面的东西出不来 | 与容器：沙箱说的是隔离，容器说的是打包 |
| 容器 | 打包好、可以搬走的运行环境 | 见上 |
| 密钥 | 证明身份的秘密 | 与锁：密钥是一件东西，锁是一种占用 |
| 锁 | 同一时间只许一方使用 | 见上 |

用法。正例：节点里写“数据库”，名字前放数据库记号。最容易犯的错：只放记号不写名字，或者用记号的不同画法表示状态（例如把出错的数据库画成虚线的圆柱）。

几组相邻的对象（服务与外部服务、沙箱与容器、文件与 artifact 与 skill）含义有别但容易混；一张图里若不需要这个区别，只用其中一个，不为齐全都摆上。

## 4 状态

一个状态记号回答“它此刻成立到哪一步”，总是和状态词一起出现。

| 词 | 含义 | 与相邻项的区分 |
|---|---|---|
| 默认开 | 不做任何设置就生效 | 与已完成：这是配置，不是进展 |
| 默认关 | 有这个能力，不设置就不生效 | 与可选：默认关的东西已经在，打开即可；可选的要另外接入 |
| 可选 | 可以加，也可以没有 | 见上 |
| 已完成 | 做完了，结果已知 | 与“已确认”：做完不等于有人核对过 |
| 进行中 | 系统正在做，不知道还要多久 | 与等人决定：一个是系统在忙，一个是系统停着 |
| 等人决定 | 停下来，等一个人作判断 | 与结果未知：这里什么都还没发生 |
| 已拒绝 | 提出过，被否了，没有生效 | 与出错：拒绝是一个决定，出错是一次失败 |
| 已过期 | 曾经有效，现在不再有效 | 与已拒绝：过期的生效过 |
| 出错 | 做了，失败了 | 与警告：出错是没做成，警告是做成了但有要注意的 |
| 警告 | 可以继续，但有一处要留意 | 见上 |
| 结果未知 | 动作发出去了，不知道成没成 | 与进行中：不能假定它还在跑；与出错：不能假定它失败了 |
| 未核实 | 有这个说法，没有人核对过 | 与结果未知：未核实说的是一条陈述，结果未知说的是一个动作 |

用法。正例：一步写作“写文件 · 等人决定”，前面是菱形里两道竖线的记号，这一处用强调色。最容易犯的错有两个：一是“结果未知”借用“进行中”或“出错”的记号，读者就会去等或者去重试；二是已经作出的决定也用强调色，读者再找不到该他处理的那一处。

“等人决定”是唯一默认带强调色的状态。形状上它也是唯一的菱形，去色后仍然认得出。

## 5 流程

一个流程记号回答“步骤之间怎样走”，和一个动词一起出现。

| 词 | 含义 | 与相邻项的区分 |
|---|---|---|
| 分支 | 一条路分成几条，各走各的 | 与广播：分支是选路或分工，广播是同一份内容发给多方 |
| 合并 | 几条路汇成一条 | 与压缩：合并的是路径，压缩的是内容 |
| 循环 | 同一组步骤按设计再走一遍 | 与重试：循环是计划内的，重试是失败后的 |
| 重试 | 失败之后把同一步再做一次 | 见上 |
| 回滚 | 退回到之前保存的状态 | 与重试：回滚是往回走，重试是原地再来 |
| 上限 | 到这里为止，不再增加 | 与出错：到了上限是按规则停下 |
| 压缩 | 多的变少的，细节有损失 | 与外置：压缩后原文不在了，外置后原文还在别处 |
| 外置 | 把内容挪到外面，留一个指向 | 见上；与注入相反 |
| 注入 | 把外面的内容放进来 | 与外置相反 |
| 流式 | 结果一点一点到，不是一次到齐 | 与广播：流式说的是时间上分批，广播说的是对象上多方 |
| 广播 | 同一份内容同时发给多方 | 见分支 |

用法。正例：对话太长时写“压缩”，旁边注明“由 40 条压成 1 条摘要，原文已外置”。最容易犯的错：把循环、重试、回滚都画成同一个转圈的箭头；这一版里循环是首尾相接的两段箭头，重试是一段带箭头的弧，回滚是指向一道竖线的直箭头。

清单里的“排队”没有单独画：它和对象“队列”是同一个词的名词和动词，记号共用“队列”，动作由运动“入队与出队”表达。

## 6 关系

| 画法 | 回答 | 取值 |
|---|---|---|
| 线型 | 生效了吗 | 实线：已经成立。虚线：尚未成立或没有生效 |
| 端点 | 确认了吗 | 实心：已确认。空心：未确认。叉：已拒绝。没有端点：这一项还不存在 |
| 强调色 | 还等谁决定 | 只用在等人决定的那一处 |
| 箭头 | 方向 | 只表示方向，虚实随线，不另算一种画法 |
| 文字或位置 | 是谁说的 | 写在每一条的开头，或者用分栏、分轨 |

每条关系先写成词（谁说的，成立到哪一步），画法只是词的重复。图例由画图的那份输入得出：components.html 第 12 节的图例是脚本从六条输入里数出来的，删掉一条，图例就少一行；输入里出现不认识的状态词，脚本拒绝画并指出是哪一条。

最容易犯的错：建议没生效、证据没核对、记录不存在，三处都画成虚线。正确的画法是让两种画法各答各的：没生效的是虚线加空心端点，没核对的是实线加空心端点，不存在的是虚线、没有端点。

## 7 范围（补）

边界回答“谁在谁里面”。它是一条闭合的线，虚实沿用线型的回答：实线是这个范围已经成立，虚线是还没有。边界的名字写在边界里面的左上角。

边界不靠底色区分，所以可以套两层而不成为嵌套的卡片。套到第三层时改用分栏或缩进。最容易犯的错：为了好看给一组东西加框，而这组东西之间并没有“同在一个范围里”的关系。

证据：只在 components.html 第 12 节用过一次，合成内容。

## 8 取值（补）

表格和图里“没有值”有四种，各不相同，不能都留空或都画成短横线。

| 词 | 含义 |
|---|---|
| 零 | 有值，值是 0 |
| 缺失 | 应该有值，没有查到 |
| 不适用 | 这个属性对这个对象没有意义 |
| 范围外 | 有值，但不在这次统计或这张图的范围里 |

这是 [成立程度与归属的标记](../foundations/standing.md)里说的“第五个问题”，它不借用线型和端点。格子里总是写词，记号只在格子很小、词放不下时单独用，并且图例里要有。最容易犯的错：缺失的画成 0。

证据：components.html 第 7 节用了“缺失”和“不适用”，另外两个只在总览里画了。

## 9 位置（补）

次序里的一站有三种画法：已过（实心），当前（外面多一圈），未到（空心）。它们回答“走到了哪一站”，用在轨道、步进和时间线上。

这三种画法和关系的端点长得像，回答的却是不同的问题：端点在线的尽头，站点在线的中间。一张图里两者都出现时，图例必须分开写；能分成两张图就分成两张。这是本包里最容易让读者读错的一处。

“指向”是一个编号位：方框里写编号，引线的另一头用一个小圆点落在所说的那一处，同样的编号出现在旁边的说明里。说明要紧挨着它解释的内容，窄屏下也跟着走，见 Kit 的 [注释保持邻接](../references/curated/note-adjacency.md)。本包只画了这个记号，没有做实例。

## 10 来路

“是谁说的、凭什么”只用文字或位置：人、机器、规则、记录；实测、转述、推断、合成。它不占画法，所以没有记号。components.html 第 6 节的“转述”“合成”两个标签就是纯文字的。样张里凡是编的内容都写着“合成例子”。

## 11 控件

| 控件 | 承载的含义 | 不适用的情形 |
|---|---|---|
| 步进器 | 有先后的几步，一次看一步，知道第几步、共几步 | 各步之间需要对照着看时，直接全部列出 |
| 轨道 | 从哪里到哪里，现在在哪一站 | 站与站之间没有先后时 |
| 分段单选 | 几个互斥的预设，恰好选中一个 | 多于五个，或名字很长；可以都不选或选多个时 |
| 节点与说明面板 | 选中一个对象，看它的说明 | 说明很短、可以直接写在节点旁边时 |
| 展开与收起 | 细节层，可以一次全部展开 | 内容是读者必须看到的条件或警告时 |
| 标签 | 用一个词说明状态或来路 | 需要读者操作时（那是按钮） |
| 按属性对照 | 少量对象在共同属性上比较 | 读者要逐个读完整档案时；对象很多或属性口径不一时 |
| 时间线 | 有先后的几个节点 | 要表达相隔多久时（那需要有刻度的图） |
| 阅读进度线 | 读到页面的哪里 | 页面很短，或读者不是从头读到尾时 |
| 试算 | 改一个输入，按写明的规则算出结果 | 规则说不清或结果不是算出来的时 |
| 计时条 | 真实在走的时间，离已知的时限多远 | 不知道要多久时 |

每个控件的状态矩阵（正常、悬停、键盘焦点、选中、禁用、无脚本、打印）在 components.html 里，紧跟着它的实例。四条对所有控件都成立：

- 没有脚本时内容不少：步进器变成编号列表，说明面板全部列出，试算给出算好的例子。
- 选中用强调色并加粗或加深，去色后仍是最重的一处；禁用用虚线边框加灰字。
- 键盘焦点用墨色外框，不用强调色。强调色留给含义，焦点是界面自己的事。
- 窄屏改变排列，不改变顺序。按属性对照在窄屏按属性分块，对象的顺序不变，见 Kit 的 [按属性维持比较](../references/curated/comparison-continuity.md)。

最容易犯的错：把计时条用在不知道要多久的等待上，它就成了一条假进度；把说明放进悬停提示，触屏和键盘的读者就看不到。

## 12 运动

| 运动 | 表达的变化 | 与相邻项的区分 |
|---|---|---|
| 移动 | 同一个东西从 A 到 B | 与出现退出：前后是同一个东西才叫移动 |
| 流向 | 此刻正沿一条线持续流动 | 与移动：流向没有“到了”的时刻 |
| 出现与退出 | 对象加入或离开 | 与状态切换：对象还在，只是状态变了，就不是退出 |
| 状态切换 | 同一对象换了状态 | 位置和名字不变 |
| 标出当前 | 读者或叙述此刻所在的位置 | 与等待：当前会往下走 |
| 等待 | 停在这里，等人或等外部结果 | 与计时：等待不知道还要多久 |
| 循环一轮 | 同一组步骤再走一遍 | 与流向：循环有轮数 |
| 入队与出队 | 排队、被取走、被丢弃 | 与移动：位置由队列里的顺序决定 |
| 收拢与展开 | 多项压成一项，或一项展开成多项 | 与退出：被压掉的项由那一项代表，不是凭空消失 |
| 计时 | 时间在走 | 只用于真实的计时 |

每种运动在 motion.html 里有：含义，可调的参数，t 的函数，网页里的等价写法，减弱动效时的替代，不该用的情形。

所有运动共守四条：

- 写成时间的纯函数。同一个 t 得到同一帧，不读时钟、不记上一帧。网页用它播放，视频用它在任意一帧定格。
- 运动跟着真实状态走，状态先变，画面再变；动画播完不等于事情做完。
- 减弱动效时换成不位移的替代，替代要保留反馈，通常是一个随之更新的词或数字。
- 虚线不用来表示流动。流向用沿实线前进的小箭头。

最容易犯的错：用等待的明暗去表示系统在忙（那是“进行中”）；让一个被丢弃的东西直接消失。

## 13 画面位置与驻留（补，视频）

视频没有滚动和点选，读者靠固定的位置找东西：章节位、舞台、图例位、字幕位、来源位。同一类文字在每个画面里待在同一个位置；同一个对象在相邻的镜头里造型不变，位置不变或用“移动”交代。

一块新出现的文字至少停 `max(2, 字数 ÷ 9)` 秒。每秒 9 字是本仓库一条无声知识片（`demos/write-kit-film`）用过的读速，属于项目参数，有旁白时以旁白为准。运动进行时不换字幕，字幕换的时候舞台不动。

这一节只有一张示意图和一个函数，没有在成片里用过。五个位置的比例是画法，不是 grammar；grammar 只有“位置固定”和“停够读完的时间”两句。

# 第二部分 · 这一版的画法

## 14 记号

24 × 24 的网格，描边 1.5，圆头圆角，不填色，颜色取 `currentColor`。每个 `<symbol>` 自带描边属性和 `<title>`，id 是 `g-` 加英文语义名，不依赖外部样式，可以单独拷走。

取舍：

- 状态记号大多是“圆圈里一个符号”，三个例外有意做成别的形状，好让最要紧的区别不靠圆圈里的小符号：等人决定是菱形，出错是八边形，警告是三角形。
- 默认开、默认关、可选是一组开关造型，按钮的位置和虚实表示取值。可选和已过期用虚线，沿用“没有生效”的意思。
- “未核实”直接用关系里的空心端点放大而成，两处是同一个意思。
- “已拒绝”用叉，和关系里的叉端点一致。
- 实心小点（进行中的三个点、感叹号的点）是填色的圆，写成行内属性。
- 空心端点要盖住它下面的线，所以填了纸色：`fill: var(--paper, #fff)`。这是唯一不随 `currentColor` 的地方；放在非白底上时，定义 `--paper`。
- “工具”的扳手是竖着画好再整体转 45 度，路径上带一个 `transform`。

重画时至少保住：每个词一个记号；相邻两项去色后分得开；虚线只表示没有生效；“等人决定”在形状上独一份。

## 15 关系

线宽 1.5，虚线的线段和间隔是 5 和 4。端点是直径 6.5 的圆或同样大小的叉，箭头是开口的折线。端点和箭头是以原点为中心的四个小 symbol（`g-end-solid`、`g-end-hollow`、`g-end-cross`、`g-arrow`），线型是两个 class（`.g-line`、`.g-line--pending`）。

没有用 SVG 的 `<marker>`：marker 里的 `currentColor` 取的是定义处的颜色，不是引用它的那条线的颜色，强调色的线会配上墨色的端点。端点改成用 `<use>` 摆在线的尽头，箭头靠 `transform` 转向。

重画时至少保住：两种线型、四种端点取值各自分得开；图例从输入得出。

## 16 色、字、距

色板沿用了 [DeerFlow 讲解页](../../../../demos/deerflow-explainer/README.md)的方向（白、淡灰蓝、石板色的墨、一种蓝），改了两个值：说明文字从 `#64717f` 加深到 `#5d6a78`，在淡灰蓝底上也够 4.5:1；控件边界从 `#8d9aa9` 加深到 `#74828f`，对白底 3.9:1。各色的对比度在 checks.md。

可以调的变量都在 tokens.css：九个色值、六级字号、八级间距、圆角、记号边长、描边、虚线间隔、最小可点边长、四个时长和两条曲线。换掉任何一个值，第一部分不受影响。

本包不做深色主题。时长是界面用的；视频里的秒数是每种运动自己的参数，写在 motion.html 各节，不进 tokens。

## 17 控件的实现

原生 HTML 加少量脚本，没有框架。能不靠脚本的就不靠：分段单选是一组单选框加 `:has()`，展开收起是 `<details>`，按属性对照和时间线的窄屏重排只用样式。脚本负责步进、轨道标记、说明面板的切换、全部展开、进度线、试算和计时。

页面开头把 `<html>` 的 class 从 `no-js` 换成 `js`，所有“有脚本才隐藏”的规则都挂在 `.js` 下，脚本没跑起来时内容全部可见。

轨道的标记只在换站时滑动。页面刚打开和窗口大小改变时它直接到位：那是重新排版，不是状态变化。

可点目标最小 36 px 高。这是这一版的取值，不是合规结论；触屏为主的项目按自己采用的标准另定。

## 18 运动的实现

motion.html 的样张全部由 `src/motion-lib.mjs` 里的函数逐帧画成 SVG：`fn.<名字>(t, 参数, 是否减弱)` 返回这一刻的状态，`frame(t)` 把状态画出来。生成页面时同一份代码在 Node 里算出五个时刻的定格，供无脚本和打印时显示。视频渲染可以直接取这些函数，也可以只取函数、自己画。

普通网页不需要逐帧画。“网页里的实现”一栏给的是等价的 CSS 写法；其中移动和悬停反馈在 components.html 里实际用了，流向、等待、出现、循环的 `@keyframes` 写法只是写出来，没有单独做成样张验证。

时长：界面里的位置移动 240 毫秒，状态切换 200 毫秒，悬停 120 毫秒，等待的一次明暗 1.6 秒。样张为了看得清，移动用了 0.6 秒，那是视频一侧的取值。

重画时至少保住：每种运动是 t 的纯函数；减弱动效有替代并保留反馈；等待不转圈、不前进；计时匀速。

## 19 证据边界

全部内容是合成的，制作和检查出自同一个执行者；只在一页讲解页上取用过一次，没有读者对照。运动没有在真实帧率下看过，t 的函数没有接进视频渲染流程；读屏、Safari、Firefox 和触屏设备没有试。清单外补的四个范畴（范围、取值、位置、画面位置与驻留）各只有一处合成的用例或没有用例。
