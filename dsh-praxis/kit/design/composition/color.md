# Color · 角色、状态与数据的不同含义

当颜色同时像品牌皮肤、控件状态、对象类别和数据大小时，从这里拆开责任。G03 已要求信息不能只靠色相、同一状态不能换肤后变义；这里进一步分清颜色服务的是界面角色、阅读对比、情绪/品牌还是图形编码。它是普通参考，不是一套通用色板，也不替具体项目声明 WCAG conformance。

关系图线型与图例的成立程度由[图形编码](encoding.md)处理；控件焦点、错误及状态反馈由[状态与可达性](../interaction/states.md)处理；主次和表面邻接见[空间编排](layout.md)。

## 给每种用色写出职责

按使用场景给颜色命名，而不是先列十六进制值。常见职责有：

- **内容与表面**：正文/图形在背景上的前景角色；容器表面和分隔仅支持空间关系。
- **交互**：可操作、焦点、选中、禁用、成功、警示、错误等状态。不同状态要有能被看见、说出或定位的区别。
- **图表编码**：某个色标在某一张图里对应的类别、顺序、极性、分组或值域，必须由图例及数据口径限定。
- **品牌与氛围**：标识性或装饰性用色。除非有明确语义约定，不能顺手被解释为状态、权限或风险。

一个色值可在不同局部承担角色，但同一任务里不要让它不加说明地同时表示“主要按钮”“正向变化”和“客户类别 A”。变量可包括色相、明度、色度、透明度、面积、背景和明暗主题映射；不变量是含义一致、文字可辨、非色觉用户仍能区分必要信息、图表色标与数据类型相符。

**例子。** 一份项目简报以靛蓝作为链接/主要操作的品牌色；错误状态用图标加“需要修正”文字和足够对比的描边；趋势图另外用顺序色带表示低到高的计数。虽然偶有同色相，图表图例与交互结构各自定义其意义。

**反例。** 同一页把绿色用于成功提示、增长正值、组织部门甲，也把红色用于错误、负值和部门乙；读者必须先猜颜色在当前模块的含义。去掉色相后类别消失，且数据图图例无法救回控件状态。

## 依据编码任务选图表色

先问数值和类别的关系。顺序值（low→high）需要显出明暗/感知强度顺序；发散值需要有数据上有意义的中心值，颜色从中心向两边区分方向；定类值的色彩彼此可辨而不暗示排名。ColorBrewer 的制图建议专为分级地图设计，展示 sequential、diverging、qualitative 三类方案；其对发散色标的中心断点要求有数据意义，也提醒类别色不能无意强调某些类。此分类可迁移到其他数据图作为选择问题，但其具体色板受地图、底图、级数、打印和色觉条件约束，不能不验条件地套入 dashboard。[ColorBrewer 来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/colorbrewer-schemes.md)。

绘图前固定分级数、零点/中心值、范围、缺失与零的处理，再选色。连续色带取样后应单调检查；分类多时可以配合直接标签、纹理或形状，不要只扩大调色板。地图里道路/地形底色也会改变对比，所以先在真实背景上检查；如果只需要说明“发生变化”，不要凭绿色本身暗示好坏。颜色不负责给未核对的关系背书。

## 无障碍要求有确切范围

WCAG 2.2 SC 1.4.1 的主张是颜色不应成为传达信息、指示动作、提示响应或区分视觉元素的唯一方式。它明确要求的是看得见的其他区别，并说明这是针对色彩感知的标准，不自动覆盖屏幕阅读器的语义关系，也不禁止色彩编码。其说明文档还区分“色差带有显著明度差”与“需要辨别特定色相”：后者即使对比足够，也仍应有其他视觉标记。该说明页为解释材料，conformance 结论仍须回到规范文本及项目采用范围。[既有来源卡 R03](../../../../vault/provenance/relation-grammar-20261004/cards/r03-wcag-use-of-color.md)；读取范围与版本复核记在[视觉研究变更](../../../../vault/provenance/design-writing-encyclopedia/visual/CHANGELOG.md)。

因此，状态颜色配文字、图标、线型、边框、形状、位置或图案之一；链接除颜色外可用下划线；图表提供直接数值/标签或稳定图例。选哪种冗余编码取决于任务：图标对复杂类别未必有效，纹理也可能让小图拥挤。逐个颜色对核对正文、图形、焦点边缘和遮罩叠加状态，必要时检查灰阶与模拟色觉结果。不能从颜色 token 名称或某次自动对比度扫描推出整页满足规范。

## 有边界的 worked comparison

合成数据：三家门店的月度订单（12、18、24）和环比变化（+3、0、−2）。比较 A 把三个门店涂成由浅到深同色渐变，导致观者以为门店有大小顺序；比较 B 用三种定类色且使用独立图例，订单数量仍以共同基线的柱长表示，环比正负以零中心的发散色和 +/0/− 标签表示。B 的编码意图更清楚。若门店没有稳定类别识别需求，可把门店颜色全部统一；若图表尺寸太小，数字标签可能优于更多颜色。这个例子只展示语义设计，不是用户研究或视觉渲染验证。

## 检查

在有/无颜色、有/无装饰、明暗主题、打印或灰阶、不同状态叠加时逐项问：还能识别动作、类别、方向、零值、缺失和中心值吗？数据图实际颜色是否与图例及变换一致？背景变化会破坏对比吗？机器能验色值、contrast ratio、色标覆盖；需要实际页面/图形截图确认邻接与重叠；感知效果需人观察。当前提炼只消费 W3C 说明和 ColorBrewer 分类文字，没有渲染任何色板、测试真实图表或证明用户效果。

使用哪一套主题参数由项目决定；WCAG 是否适用、版本及 conformance level 也由项目验收范围决定。若图色取代了数字本身、基线口径不明或发散中心并无业务意义，应先改数据表达或任务定义，不能靠换个好看的色盘解决。
