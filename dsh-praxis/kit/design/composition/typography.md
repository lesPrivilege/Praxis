# Typography · 文字的层级与阅读条件

标题、正文、标签、数值、脚注彼此抢读，或中英文混排在窄屏上断行失序时，分两步判断：文字在信息结构里扮演什么角色；具体脚本怎样在给定的字体、宽度和语言环境里排出来。

如果需要安排标题、图注、证据和正文的空间顺序，接着读[空间编排](layout.md)。如果图表标签编码数据，配合[图形编码](encoding.md)核对单位、分母与图例。成句内容归 Write。

## 先定角色，再定字面参数

先把文字按任务分角色：连续阅读的正文、定位结构的标题、短促动作标签、需要核对的数值、解释性注释、来源或次要元数据。一个角色是一种阅读任务，不等于一个视觉组件。标题承担导航与主题预告；正文承载推理；标签使对象可识别；数字需要稳定比较；脚注保留出处或限定。让字阶、粗细、字面宽度、颜色和间距协同表达这些差别，避免靠字体名称或者“更大一点”代替层级判断。

可改变量包括字体家族及后备链、字号比例、字重、字距、行距、行长、数字字形与对齐方式。固定边界是字形实际覆盖目标文字、名称与单位不丢失、放大与窄屏下仍可读、不同角色不只靠颜色区分。字号与行长应按语言、屏幕和阅读时长复查；字符数规则不直接等于中文的视觉行长。

USWDS 把排印拆为 microtypography（块内字面处理）与 macrotypography（内容块在页面上的组织），并把字号、行长、行距、留白、字族分别讨论。它给的 body-text 16px、45–90 字符行长和较长文本至少 1.5 行距，是美国政府网页系统的建议范围，不是跨字体、语言、媒介的通用门槛；它也明说 serif/sans 的用途惯例不是硬规则。[既有来源卡 S07](../../../../vault/provenance/design-grammar-atlas-20261002/cards/s07-uswds-typography.md)；复核记录见[视觉研究变更](../../../../vault/provenance/design-writing-encyclopedia/visual/CHANGELOG.md)。

## 用一组固定内容检验字阶

选一段会真实出现的内容，保留它的长标题、汉字、拉丁术语、金额和限定语。按内容所需角色做层级草图：主题/章节、正文/说明、标签/数值、注释/来源。不要先承诺精确尺寸；先问读者能否找出主题、沿着正文读下去、迅速定位数值与解释。把一档调近邻，观察两个角色会不会变得相似，再把极小字放大，确认辅助信息并未因此占据主叙事。相邻字阶应表达角色差异，而不是每层都用不同装饰。

**例子。** 一份服务状态简报含标题“申请处理进度”、正文“核对身份资料后，预计两个工作日内完成”、三行状态“已收到／正在核对／需要补充”，日期“10 月 11 日”及数据来源脚注。标题承担页内定位；正文用常规字重与较舒展行距；三行状态标签和日期可扫读、基线整齐；脚注比正文次一级，但仍保持足以辨认的字号。行距、字号比例与字族待实际窄屏/打印夹具比较后定。

**反例。** 把每个层级都做成粗体彩色胶囊，正文又以小号浅灰塞进卡片底部。它把所有内容都做成“标签”，丢掉连续阅读；解释层级也只依赖颜色。单看一屏可能显得整齐，但放大、灰阶或内容变长就暴露失配。

## 中文与混排的排版规则

中文文字常以汉字为行内断行单位，不能照搬空格分词的英文经验。中文标点禁则、括号引号、专名、数字与拉丁字串需要分别观察；简体/繁体也不能代替地域与语言标记，引用原样、内容语言和排版方向是不同信息。W3C CSS Text 说明中文源码换行被折叠时不能无条件插入空格；行断点受内容语言、书写系统与属性共同影响。W3C 的中文布局差距文档按字形定位、标点、数字、行断行、表格与页面功能逐项追踪规范和浏览器支持，但其标记明确为正在发展的 Group Draft Note，优先级带专家判断，不能当作已实现的完整中文排版规范。[CSS Text 来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/css-text-3.md) 与 [CLReq gap 来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/chinese-layout-gap.md)；CLReq gap 是既有 CLReq 需求说明之外的独立差距报告。

遇到混排时用真实内容检查：中文括号与引号成对不拆；英文缩写和版本号不被截断；货币、百分号、日期与单位保持语义黏连；长链接或代码有显式溢出策略；换行由自然语言和语义组决定。必要时调整 `lang`、`line-break`、`word-break`、`overflow-wrap`、`white-space` 等策略，但先确定语义，再看浏览器实际结果。不要把全段设为不换行来修一个难排的专名。

**例子。** “版本 2.4 已修复 API 调用失败（重试间隔 30 秒）。”在窄栏内允许汉语按合适位置换行；`2.4`、`API`、`30 秒`和括号内部短语作为可辨组，不应被粗暴逐字符截断。

**反例。** 每个汉字间手动插空格模拟“中文字距”，并把每个英文词设成 `nowrap`。代码看起来在一张宽图里对齐，换字体、复制文本或窄屏后却出现异常字距、横向溢出和朗读停顿。

## 检查与边界

固定文案，先只改层级，再只改字体或颜色；桌面、窄屏、文本放大、打印分别看长标题、长正文、混合数字和最小辅助字。机器检查可证明字符保留、DOM 文字存在、溢出是否发生；需要截图或真实浏览器检查断行、字形回退与视觉密度；读者是否更易理解仍需读者观察。以上判断只依据规范与指南文本，没有运行浏览器字体或 CJK 排版测试。

USWDS 的建议与 CSS/W3C 语言特定机制对应不同问题，不能合并为一条“最佳字号”；规范定义处理能力，差距报告提醒实现未必充分，设计系统只给它自己的默认建议。需要具体字体授权、文件体积、缺字覆盖或浏览器支持结论时，单独核对字库许可证和实际环境。来源、证据状态与重访条件见[视觉研究目录](../../../../vault/provenance/design-writing-encyclopedia/visual/README.md)。
