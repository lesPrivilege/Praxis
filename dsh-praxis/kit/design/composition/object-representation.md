# Object Representation · 线、平面与实体如何讲清对象

复杂对象被画成通用方框、轻描淡写的线图，或堆出漂亮但读不出因果的立体零件时，按读者要看懂的结构、关系、动作或量，选出足以表达的最小可辨形态。

线框、纯色平面、填充轮廓、实体透视图都各有明确用途。用[成立程度标记](../foundations/standing.md)表达证据状态时不让体积和阴影暗示更确定；涉及叙事动效时转[Motion](../motion/README.md)。

## 从读者要理解的动作倒推形体

先写一句读者应该说出的解释，再列需要出现的对象、连接与变化。重点可能是：

1. **边界/归属**：某物是否在容器内、属于哪一组，轮廓或底面即可。
2. **连接/拓扑**：从哪到哪、谁接到谁，线、点和方向能清楚表达时不必做实体。
3. **部件与构造**：哪些部分互相支撑、遮挡、装配，简单线图常不足以表现前后关系。
4. **操作/状态**：什么移动、切换、被触发，形体应让触发、作用对象和结果对应。
5. **规模/空间/深度**：对象相对方位、体积或尺度实际重要，才引入投影、遮挡、阴影或真实三维。

空间层次要有共同参照面，连接要落到真实部件，箭头说明方向但不单独证明因果。拆解/交互表征应提供足以解释关键结构的可达路径；可以是静态图、分步序列或结构化说明。动画可补充动作与观察视角，其演示本身不验证结构正确或读者理解。

## 选择表征而不是选风格名

| 表征 | 可看清的内容 | 主要代价与失配 |
|---|---|---|
| 线稿/轮廓 | 外形、路径、连接、简化关系；容易小尺寸复用 | 线条遮叠会形成噪声；内部层次和面向不清；等粗线会抹平重要/次要差异 |
| 平面填色/符号 | 明确边界、类别、状态、二维拓扑；易于打印与快速扫描 | 轻易将复杂对象压成抽象图例；填色若不和标签、图例相连可能任意 |
| 带阴影的填充实体 | 面、前后、组装关系和可操作部分，适合解释有部件的真实对象 | 体积与光影增加视觉权重；投影和遮挡会误导；不精确细节可能产生伪真实感 |
| 白模 / 去材质的体量图 | 暂时去掉材质和品牌颜色，比较体量、接缝、深度与遮挡 | 白底白物会丢失边界；若颜色区分类别或材质有功能意义，去色就会丢信息 |
| 真实 3D / 动态模型 | 多角度、空间运动、局部机制或可操作的变量 | 建模/运行成本、遮挡、相机与性能；读者可能关注操作而错过解释；静态导出可丢失语义 |

“白模”在本页指去掉真实材质纹理、以明暗保留体量的工作表示，是一个可选对照，不是某个作者样式的别名。浅色填充实体仍可用颜色区分部件；平面填色不必有深度。三者应按保留了什么区别，不以“看起来白”合并。白模的工业应用和具体渲染实现仍缺深入来源。

**示例。** 一张说明“资料进入校验队列，缺项会退回申请者”的流程图只需三个有标签的平面节点、一个单向回线与明确的“缺少材料”条件。节点做轻微卡片造型也可以，但体积、真实阴影和透视只会让流程关系难读。反过来，解释可变口径如何推动阀门打开的教学示意，部件剖面、实体遮挡与对应开合动作可能比抽象节点有效，因为理解目标就是机械动作。

**反例。** 把资料退回流程画成浮空盒子在三维管道中发光穿梭：没有尺度、端口或真实机制支撑空间暗示，也未标清触发条件。它把“有空间图”错当成“对象关系更清楚”。

## 两类来源的选择差异

Anatomy 的项目说明描述的是把技术概念拟成真实机械对象：由许多小的实心、着色部件组成，支持 hover/keyboard、读数、拆解，并在关节处检查关系。它还把火焰、水、光等超出线条表达能力的效果分层置入 SVG 与 WebGL。还看了 README 链接的 firing still：可见浅色实面与细轮廓共同分出发动机部件、支架和底板，喷焰的发光层可见；作者文字称该类效果可由 WebGL 分层实现，没有用透明线框替代发动机本体；没有操作示例或核对技术准确性。这个选择适合读者需要辨认部件如何协作、动作与读数如何一致的情形。[Anatomy README 来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/anatomy-readme.md)。

Hairline 则明确把对象做成产品界面中的小型仪器，采用统一线宽的等距线图，以紧凑、低视觉负担为目标，并把指针响应按距离衰减。其过程强调先量参考响应，再把观察写成可否决的规则；视觉试稿需要被编辑而非崇拜。它更适合轻量、低占比、关系或反馈有清楚隐喻的图形，不替代真实机械构造。看了 README 的静态 hero GIF 第一帧：卡片盘、柱阵、窗口层、点阵、传送带与转盘以浅灰细线画在不透明白色底片上；这不是只剩轮廓的透明 wireframe，也未核实动画每一帧。[Hairline 制作过程来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/hairline-inspo.md)、[Hairline skill 来源卡](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/hairline-skill.md)。

两个取向的差别源于读者目标、显示尺寸和结构需要：一个强化真实部件间的结构，一个强调小图形与微交互。优先问“哪个最低复杂度的表达保住了读者需要的关系”，再比较线与填充，而不是先决定要仿哪一家。

## 可执行的取舍卡

记录：

- **目标句**：读者看后应能指出哪种关系或动作？
- **对象与锚点**：部件、表面、线、标签分别对应真实语义中的什么？
- **选择理由**：为何用线/填面/实体/运动？删掉哪一层会让什么变得不可读？
- **视角与证据**：遮挡会改变结论吗？结构是事实、简化还是假设？
- **替代检查**：灰阶、缩小、静止、键盘/触屏下还读得出必要内容吗？
- **边界**：有没有主张超出这张图实际表达范围？

**示例。** 用等粗连线画服务节点图，线交叉处读不出是否连接。先固定节点与标签，把交叉处改成桥接线或分层绕行，同时在局部用放大图检查；不要在不改变拓扑语义前提下，仅用更浓颜色标成“重要路径”。如果结构涉及真实管线层级，使用剖面或叠层示意，并明确图示为简化模型。

代码/SVG 可以证明几何关系存在；静态预览可以支持轮廓、遮挡与标签审查；运行与交互需要真正操作；对象科学/工程正确性要由领域证据校核；读者理解需单独观察。证据包括作者文档、Anatomy 静态图和 Hairline GIF 的首帧；没有连续观看动效或运行外部技能。

静态视觉证据分别见 [Anatomy firing still（DWV-02）](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/anatomy-firing-still.md) 与 [Hairline 首帧（DWV-06）](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/hairline-hero-gif.md)。它们只支持所见轮廓、表面与遮挡；[Anatomy 站点线索（DWV-03）](../../../../vault/provenance/design-writing-encyclopedia/visual/cards/anatomy-skill-landing.md)正文未取得，不能拿邻近 README 代替。
