# 文体选择与组合

ID：`DWG-W-GENRE` · Priority：`normal`（可选参考）

本页帮助判断任务应使用哪种文字形状；它不是每项任务都要执行的体裁检查清单。先读 [读者、任务与背景](../organization/audience.md)确认读者目标，再选最小够用的形状。所有成文仍遵守 [中文成文原理](../principles.md) 与 [证据底线](../evidence.md)。

## 按读者工作选，不按成品名称猜

| 读者的工作 | 文字形状 | 常见次序与验收 |
|---|---|---|
| 立刻完成一个操作 | 操作指南 | 先看前置条件；按行动顺序给步骤；明确预期结果、异常与恢复 |
| 理解原理 | 概念说明 | 由问题或定义进入机制；用边界例检验概念，避免把类比当事实 |
| 查一个字段或问题 | 参考页 / FAQ | 按读者可能搜索的名称组织；一项回答一个查找任务，版本和定义范围明确 |
| 选择方案 | 决策备忘录 | 结论和条件前置；比较尺度一致；显式写出代价和待决项 |
| 听一次内容 | 旁白 / 讲解词 | 用口语、清楚指代和可朗读数字，按 [口播旁白体例](narration.md)审阅 |
| 回答给定题目 | 答卷 | 按题目问题作答，以判断、机制、反例与验证展开，见 [答卷体例](assessment-answer.md) |
| 处理不稳定状态 | 界面微文案 | 按当前状态给名称、后果和恢复动作，见 [微文案](microcopy.md) |

同一文档可先给决定，再提供按需操作与参考链接；不同部分由不同任务驱动时，明确分节。标题只在确有路由、定位或理解作用时出现，不为了某种体裁的外形加固定段落。

## 内容什么时候可组合

- **结论 + 依据**适用于需要读者决策且须复核的内容。来源登记可放附录或 index，但影响结论的条件必须在正文出现。
- **操作 + 原理**适用于读者先做、再理解；确保原理不会让人误以为必须执行额外动作。
- **叙事 + 解释**适用于故事帮助理解概念的场景；故事里的因果和细节须能支持概念，不用戏剧性制造证据。
- **摘要 + 细节**适用于不同读者深度；摘要不要夸大或删掉会改变判断的限制，细节层保持可导航。

## 示范与反例

**合成任务：**新人收到权限不足提示，要决定是否申请访问。合适的内容把“谁可批准、申请什么、何时可以替代访问”放在判断链中，操作路径再按需展开。若所有人已熟悉权限模型，可以缩短解释，保留审批边界与请求入口。

**反例：**不看任务，把每份内容都套成“背景—三个要点—总结”。如果问题只需一个字段定义，三段结构只增加阅读成本；如果有四个必要条件，硬凑三点会丢信息。

## 不适用与边界

品牌稿、法律声明、学术论文、政策说明及教学内容都有专业文体契约，需要按任务和受众取用；本页提供路由，不替代领域惯例。长篇或跨语言交付要分别确认语言、地区、无障碍与发布媒介。独立清单、脚本或图形另走对应模式，不把自然语言优先当成只能用段落的要求。

## 验收

读者最先看到的内容是否对应眼下任务？结构有没有帮助发现答案、完成动作或复核主张？组合的两种形状是否各有不同工作？低风险读者能否略过进阶细节，遇到例外的人能否找到完整条件？实际消费走读前，只能称为依据内容推演出的选择，不能称为已验证的易用性。
