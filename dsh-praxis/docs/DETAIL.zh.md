# Praxis

Praxis 积累设计与写作的判断和方法，加一份来源名册和你自撰的 stream；工作流把它们带到具体场景。方法分四层，每层是一组短页：

| 层 | 位置 | 决定什么 |
|---|---|---|
| Design | 核 | 关系用什么视觉、交互或运动表现 |
| Writing | 核 | 内容怎样论证和组织，用什么文体、哪门语言 |
| Task | 工作流 | 这件工作为谁、要促成什么，走哪条流水线，读哪些页 |
| Publish | 工作流 | 内容怎样按媒介制作：html 页面或视频 |

来源是网页上的参考：标准规范、成熟实践、组件库、案例库、文章。名册只记链接、概要和摘录，不存原件；来源编目按 Kit 区域与形态排列，每条有一句说明，写明什么时候打开、取什么，挂到具体页上时还可以写这一页特有的用法。本地产物不是来源，分三类记在产物里：交付、管线（再做同类交付的方法）与范例（为示范某种做法预先做的样张）；写明服务哪些页的管线与范例、以及接受过的交付，在网页素材之后给到任务。过程记录不登记。

## agent 怎样用

插件给 agent 会话注册 11 个工具，并在系统提示里加一段简短入口。做一件任务时，agent：

1. 用任务类型和流水线调用 `praxis_resolve`，只用 `praxis_unit` 读它列出的页；Writing 与 Design 的入口页常驻，其余按需读。
2. 需要核对或借鉴时，按素材给出的链接与摘录定位回原件读；`praxis_catalog` 按区域与形态翻来源编目，`praxis_search`、`praxis_source` 查名册。
3. 遇到值得留下的参考，用 `praxis_capture` 成批登记网页来源，写明为哪件任务收录、形态与说明，需要时再用 `praxis_curate` 挂到页上。
4. 用 `praxis_projects` 查交付目录属于哪个项目，没有就用 `praxis_project` 登记；产物放在项目约定的位置。
5. 交付前用 `praxis_consume` 记下读过的页和来源，并把交付的文件登记为产物；改过再交付就是新版本。运行记下这次会话，读到的原件正文可以回到会话记录里找。

`praxis_resolve` 与 `praxis_consume` 在会话里显示为卡片：展开看列出的页和素材，或打开交付的文件；卡片上的“控制面”打开侧栏面板。

维护名册、预设与产物的其余工具在控制面、命令行与 MCP。

## `/praxis`

只输入 `/praxis` 打开侧栏面板。后面带文字时，在会话界面列出任务类型和待处理事项，不发给模型；要 agent 按 Praxis 做，直接在会话里说。

## 侧栏面板

在右侧栏的引导页打开 **Praxis**。

- **目录**：首页分为核（Design、Writing）、Stream 和下游工作流（Task、Publish）。层往下是领域，再往下是页，每一级只给说明和计数；页和 stream 打开后是来源卡片，可以启用或停用、收藏、对照上游检查（链接是否还在、内容是否变了）、改写说明、记录 review、删除（可恢复）。**登记来源**收录新的参考，可以先归到某一层或领域，之后再挂到页上。
- **任务**：选任务类型和流水线，可再指定一条 stream，看到 agent 会读的页、可用的来源和验收项。
- **产物**：交付过的文件，按项目分组；项目头部写着它把底稿、中间产物、最终产物放在哪里，以及最终产物路径里还有哪些文件没登记。打开一件看它的各个版本、每版依据的页与来源、针对各版的 review；可以预览、在 Finder 中显示、用默认应用打开，或把它直接拖出去。
- **预设**：每条流水线的默认配置，例如视频的 TTS 音色与画幅、html 的明暗。只记密钥所在的环境变量名，不记密钥。
- **记录**：顶部是需要处理的事，下面是运行记录和维护记录。需要处理的事包括：review 结论为待改、来源在上次 review 后变了或链接失效；交付后所用的页、来源或预设又改过；新登记的来源还没挂上；集合类来源（作品集、组件库）在上游新增或下线了成员；对页的修订与包里更新后的原页冲突；产物文件找不到、最新版待改或不在约定位置；项目的最终产物没登记。通常为空，有事时标签上显示数字。

来源没有写取用说明、没人 review 过，是默认状态：有人需要时再把来源摘要改写成说明。

## 来源 review

左侧栏的 **Praxis** 打开来源 review 页，用 DSH 自带的控件。每个已编目来源一行，新登记的在前，写着标题、形态和 description（何时打开、取什么）。展开一行看原件链接、概要、收录理由、Kit 分类、读取范围、边界、摘录和挂在哪些页上，然后记一个结论：**准确**、**待改**，或者**改写** description 后记为已改，可附一句说明。记下后这一行确认一下就收起。“待看”列的是当前 description 还没有 review 的来源；review 之后编目又改过，它会回到这里。“待改”“已 review”“全部”换一种看法。页头的“打开控制面”打开右侧栏的完整控制面。

## 修订 Kit

人或 agent 对一页的修订存在用户数据里，立即对所有入口生效，包里的原页不动。包升级后原页变了，这条修订列进待处理事项，由人或 agent 合并或撤回；撤回时修订全文留在历史里。

## 其他 agent

同一组工具也经 MCP（`adapters/mcp.js`，stdio）和命令行（`adapters/cli.js`）提供，Claude Code、Codex 等 agent 读写同一份 Kit 与名册。MCP 另有 resources（入口、每一页、来源与产物）和 prompts（每个任务类型一条）。

## 安装与数据

```bash
dsh plugin --profile desktop add link:/path/to/dsh-praxis
```

装完重启 DeepSeek Harness。数据根依次取：`config.data`、环境变量 `PRAXIS_DATA`、包旁的 `data/` 目录、`$DSH_HOME/dsh-praxis`（未设 `DSH_HOME` 时为 `~/.dsh/dsh-praxis`）。MCP 与命令行按同一顺序解析，默认共用一份数据。`config.prompt: false` 关掉系统提示里的入口段。完整说明见 [安装与运行](../INSTALL.md)。
