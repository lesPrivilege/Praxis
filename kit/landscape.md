# 工作全景

从当前要做的决定选知识：辨认任务与责任，取得最小产物，再判断继续、退回或停止。

## 工作入口

| 当前问题 | 下一产物 | 使用位置 |
|---|---|---|
| 问题是什么、值得改变吗 | 现状流程、基线、受影响者、替代方案 | [现场闭环](work-system/field-loop.md) |
| 怎样做一次有边界的介入 | 对象、证据、动作、责任与停止条件 | [场景模板](../scenarios/_template/README.md) |
| 怎样判断结果、交给谁 | 分层证据、接收与后续责任 | [验收](verification/README.md)、[现场闭环](work-system/field-loop.md) |
| 怎样写材料促成决定 | 读者、主张、证据与决策请求 | [Reporting brief](../templates/reporting/README.md) |
| 怎样整理事件与后续工作 | 候选变化、确认状态、持续义务 | [工作系统](work-system/README.md) |
| 怎样准备环境与消费知识 | 能力盘点、账号 scope、固定版本 | [Environment](environment/README.md) |

## 应知与应能产出

| 知识面 | 应知内容 | 可形成的产物 | 接收或裁决责任 |
|---|---|---|---|
| 商业价值 | 收益、成本、约束、替代方案 | 机会判断与停止条件 | 出资者、业务 owner |
| 业务发现 | 真实任务、例外、基线与样例 | 现状流程与问题陈述 | 使用者、流程 owner |
| 组织合作 | 决策权、专业复核、采用与升级 | 启动条件与责任表 | 业务及专业负责人 |
| 企业系统 | 对象归属、系统接缝、状态权威 | 对象与系统地图 | IT 与系统 owner |
| 数据与知识 | 来源、版本、质量、权限、证据关系 | 输入清单与证据映射 | 数据 owner、专业复核者 |
| AI 介入与评估 | 参考答案、失败类型、质量与成本 | 有界 worker 与评估方案 | 业务与评估责任人 |
| 集成可靠性 | 前置条件、幂等、结果未知、恢复 | 动作与恢复契约 | 实现与运维负责人 |
| 产品与协作 | 工作队列、差异、人工纠错与反馈 | review 工作面与状态矩阵 | 使用者、产品负责人 |
| 权限与治理 | 对象/动作授权、专业裁量、审计 | 授权矩阵与升级规则 | 组织授权者、专业责任人 |
| 交付与运营 | 验收、支持、移交、资料处置与退出 | 接收记录与支持计划 | 接收者、运营负责人 |
| 专业沟通 | 受众、论证、证据、请求的决定 | 自足的书面材料 | 作者、读者与决策者 |
| 个人环境 | 账号分区、能力、知识版本、恢复 | 消费计划与环境盘点 | 环境与账号 owner |

掌握深度依次为识别、使用、评审、实现。Praxis 优先支撑前三层；实现职责由具体项目分配。共享运行组件按 [ADR-002](../docs/decisions/002-promotion.md) 晋升。

概念查 [共同工作语法](grammar/work.md)，研究缺口查 [问题清单](../docs/governance/research-agenda.md)。
