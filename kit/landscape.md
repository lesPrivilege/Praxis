# 工作全景

Praxis 从眼前的工作进入知识：先说明要改变什么、谁受影响、凭什么继续，再按需调用能力。工作范围可以小，认知范围不必小。

## 工作链

发现问题 → 判断机会 → 设计介入 → 验证 → 有界试点 → 验收移交 → 运营、扩展或退出。阶段可以合并、跳过或退回；每阶段只需回答：要消除什么未知，最小产物是什么，凭什么作下一决定。

## 能力地图

| 知识面 | 应理解与产出 | 不直接承接 |
|---|---|---|
| 问题、价值、业务发现 | 识别值得改变的任务、基线与替代方案 | 替业务方承诺收益 |
| 组织合作与专业约束 | 找到决策者、使用者、责任与升级路径 | 替专业责任人裁量 |
| 企业拓扑、数据与知识 | 识别对象、归属、接缝、版本和证据 | 把来源材料当事实 |
| AI 介入与评估 | 定义小任务、失败模式、评估和恢复 | 以演示代替业务验收 |
| 集成契约与系统行为 | 描述输入、输出、权限、状态和外部确认 | 把工具成功当业务完成 |
| 产品与人机协作 | 让人发现、纠正并承担决定 | 隐藏不确定性 |
| 交付、运营、沟通与个人环境 | 使成果可接受、移交、维护和重访 | 把长期运维责任留在交接空白中 |

掌握深度依次为识别、使用、评审、实现。Praxis 优先前三层；共享运行组件仍需遵守 [ADR-002](../docs/decisions/002-promotion.md) 的独立场景、契约、fixture 与验证门槛。

## 边界

法律、金融、工程和制造可共享工作语义，但个案结论、政策、阈值和专业裁量留在具体场景。此页是导航，不是厂商百科、统一 schema 或所有工作的强制流程。
