# 操作反馈与结果状态

语法 ID：`DWG-I-FEEDBACK` · 取用：可选普通参考（`normal` / `reference`）。

反馈让人分辨“动作被接收了吗、结果是什么、现在能否继续”。适用于控件、表单、保存、异步任务和错误恢复。它的核心是语义准确、可见、可感知、可恢复；颜色、图标、音效或动画只是表达方式。

## 按结果选择反馈

先分清反馈类别：

1. **动作已触发**：按钮按下、筛选条件改变。给直接且短暂的响应，重复操作不要等待装饰动画。
2. **状态已改变**：开/关、已选中、展开/折叠、已保存。状态同时用文本/形态与正确的程序化语义表达；图标和颜色不能是唯一提示。
3. **进度**：只有掌握实际进度和真实工作量时给百分比/剩余时间。未知时说“正在提交”或“仍在检查”，不要编造百分数或预计结束时间。确有阶段时列已完成步骤，不把动画完成冒充工作完成。[现有状态语法](states.md)
4. **结果或状态消息**：WCAG 2.2 AA SC 4.1.3 覆盖不导致上下文变化的状态消息：行动成功/结果、等待状态、过程进度或错误。标记或属性应让辅助技术在焦点不移动时识别消息。例：搜索结果列表本身不是状态消息；附近的“18 个结果”或“没有结果”短消息才符合其定义。对话框拿到焦点、Accordion 展开、Tab 改选属于上下文变化或 UI 状态机制，不是 4.1.3 状态消息；控件状态变更由名称/角色/值要求处理。准则不要求作者为每次内容变更都制造公告；公告过多会打断屏幕阅读器用户，需测试频率。正式规范见 [WCAG 2.2 normative SC 4.1.3](https://www.w3.org/TR/WCAG22/#status-messages)；[Understanding 页面](../../../vault/provenance/design-writing-encyclopedia/interaction/cards/wcag-status-messages.md)是解释性、informative 配套材料，不独立要求符合性。
5. **无法执行**：说明当前不能做的原因及解法。若操作确实不适用可禁用；若用户可以执行但需先完成条件，提示条件往往比沉默的禁用态有用。

表达出业务真实状态：正在排队、已发送但结果待核实、失败可重试、已完成、已取消是不同状态。网络断开或响应超时时，先核对服务端结果再允许重试，避免重复创建对象。反馈还要保持动作可取消；是否可撤销由实际操作和后端能力决定。

## 反馈与焦点

成功的小型就地操作可以在原位置给状态更新并保留焦点；对话框打开时把焦点送入，关闭时通常还回触发处；导航到新页面或流程步骤时将焦点放在新上下文的标题或起始控制。不要因为提交而把焦点送到无关位置，也不要在无通知的情况下替换当前内容。[APG Button Pattern（S12）](../../../vault/provenance/design-grammar-atlas-20261002/cards/s12-wai-aria-apg-button.md) [DWI-002](../../../vault/provenance/design-writing-encyclopedia/interaction/cards/apg-dialog-modal.md)

错误信息贴近错误字段并说明如何修复；汇总错误时用链接回到对应字段。异步消息应简短、避免连续播报每个微小进度刻度。WCAG 的状态消息准则关注能否程序化识别，不等于页面其他无障碍要求都达成。

## 运动：表达变化，不挡住变化

运动可以标出来源与目的、空间关系、层级和直接操纵结果。运动时允许用户重复操作、撤销或取消；业务状态随着动作真实更新，完成时间不能由动画时长决定。Apple HIG 强调运动目的、短促准确、可取消且不能独占重要信息。Apple 平台的建议可作为参考，不能未经验证泛化到所有设备或用户偏好。[Apple HIG Motion（S10）](../../../vault/provenance/design-grammar-atlas-20261002/cards/s10-apple-hig-motion.md)

减少动态偏好不是把所有反馈拿掉。逐条检查大幅缩放/旋转/视差/持续自动播放：装饰运动可停止；承载状态或层级含义的运动可改成静态高亮、简短淡变、明确文字或结构更新。WCAG 2.3.3 Animation from Interactions 是 AAA；如项目要求 AA，不能误称它为 AA 条件。用户偏好、设备能力和情境都影响替代方案，记录所选目标级别与实际测试结果。

## worked example：提交一次批量重命名

用户选择 14 个文件并确认“重命名”。按钮立即变为“正在重命名”，重复提交被阻止，旁边注明可以取消；无真实逐项完成率时不画 64%。屏幕阅读器收到一次“重命名已开始，14 个文件”状态消息。完成后显示改名数；有冲突则指出具体文件并提供修复入口。焦点留在结果摘要，列表保留所选项目和当前位置。若结果超时，状态写“结果尚未确认”，先检查对象是否已改名再提供安全重试。减少动态偏好下不播放列表飞动动画，仍保留状态文字与更新后的列表。

## 反例

点保存后仅按钮短暂变绿并播放弹跳，随后恢复原样；提交是否成功没有文字或读屏消息。重试又生成一份副本。spinner 不停转，没有取消或未知状态说明。用户看到的是动画，无法知道业务发生了什么。

## 快速审查

- 反馈和真实数据/权限/终态一致吗？是否区分请求发出与结果确认？
- 视觉反馈、可访问名称/状态、状态消息同步了吗？
- 键盘焦点是否留在逻辑位置或转到新上下文？
- 动作可重复、取消、逆转吗？失败后是否有安全的重试/核对路径？
- 减少动态效果后，状态与层级是否仍可理解？
- 运动是否值得用户花费注意时间，能否随操作中断？

每个判断连到本项目使用的规范版本与浏览器/设备验证。看过指南、源码或站点首页，都不能声称交互实测通过。
