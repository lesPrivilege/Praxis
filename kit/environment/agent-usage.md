# Agent使用与额度治理

Goal：知道什么工作由什么执行者完成、质量如何、代价多少，并据此改善分工；不是收集更多无用trace。

## Run receipt最小字段

- run_id、task_id、scenario/matter引用、时间范围与执行scope。
- 实际agent角色、model/provider及可确认版本、Kit/Skill/工具版本。
- 输入来源ID与数据分类、输出artifact ID、关键工具动作。
- 状态、失败类别、handoff、人工accept/edit/reject/defer与修改原因。
- 使用量：输入/输出token、调用数、时长、已知费用、额度窗口；每项都有来源和可见性。
- 质量：验收依据、未完成范围、重试和修复结果。

观测不到的值写unknown/null，不能用0代替，也不能把账户额度变化直接归因给单个任务。实际计费、模型能力和可观测字段以后端回执为准。

## 分工反馈

Luna优先探索与登记；main聚焦架构和关键裁决。按任务类型比较成功率、修正成本、时延和实际费用，再决定哪些迁往更快模型。更便宜不自动等于总成本更低，模型更强也不替代清晰契约。

只把值得判断的语义变化投影给人：冲突、新承诺、scope变化、责任不明、低置信度及需要明确授权的动作。低风险机械处理仍留可追溯结果，但不淹没review space。

## 数据与保留

日志按组织和项目scope保存；payload按最小必要原则保留，业务证据用引用定位。评估与训练导出分别作明确决定，检查用途、权限、数据边界与可撤回条件；不能把存在trace当成可公开或可训练。

本次任务的模型token、费用和单任务quota没有完整可用回执，因此不填估算消耗。已登记分工与可验证交付；未来接入usage telemetry后再补真实指标。
