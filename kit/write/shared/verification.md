# 内容与媒介验收

## Review顺序

标题与故事线 → claim/evidence → 异议和替代方案 → 视觉层级 → 实际渲染 → 受众与ask → 文字去套话。

交付前先核对分工：产物里写给读者的文字经过了 [Prose 审阅](../prose/review.md)，阅读顺序和展项经过了 [Publish](../publish/README.md)，视觉、交互和运动经过了 [Design](../../design/README.md)。哪一支没有经过，回去补，或者写明为什么不需要。

空泛形容、无证据收益和装饰性术语删除或换成具体事实。判断一段话是不是多余，问的是删掉之后目标读者完成任务是否受损：导航、范围、来源、限制，以及独立页面或步骤前必须再说一遍的提醒，不算重复。截图只能证明当时呈现；交互HTML另检查状态、键盘、窄屏及离线依赖。PDF/幻灯片按最终导出逐页检查。

## 按输出检查

| 输出 | 必须实际核对 | 不足以证明完成的证据 |
|---|---|---|
| 正文 | 主张、条件、术语与改写前一致，段落关系可理解 | 字数变少或句子更短 |
| HTML | 宽窄布局、键盘、状态、实际要求的断网与打印 | 文件已生成、仅源码可读 |
| PDF / Slides | 最终导出逐页阅读，引用与表格可读，内容未截断 | 只检查编辑器 |
| Motion | 按实际速度观看全片，检查文字驻留、音画同步及来源配套 | 联络表或单帧截图 |

按任务记录通过、未通过和未执行，不要求所有任务都产出全部格式。保留版本、检查范围、失败与下一动作；系统与业务验收另见 [分层验收](../../verification/README.md)。
