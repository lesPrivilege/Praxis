# 格式检查

用于只规范空格、标点、链接或标题层级，不动措辞的任务。输入是原文和需求方划定的范围；产物是改后的文本和一份 diff。成文原理不适用于这类任务：一句话像不像套话，不在这里判断。

## 先划出不动的范围

代码块、行内代码、命令、标识符、路径、URL、引文，以及需求方点名要原样保留的部分，逐字不动。范围说不清时先问，例如“引用”指整个引用块还是引号里的原文；没法问就按较大的范围保留，并在交付时说明。

## 三类问题分开处理

| 类别 | 例子 | 处理 |
|---|---|---|
| 可以直接改 | 标点前后的多余空格、全角半角混用、列表标记后缺空格 | 在不动范围之外改，逐处列进 diff |
| 只报不改 | 标题层级跳级、链接打不开、同一术语疑似几种写法、重复的片段、单位写法不一 | 列出位置和疑点，由作者决定。统一词形可能改掉有意的区别，换算单位可能改掉精度 |
| 不在这里处理 | 事实对不对、逻辑关系、一段话是否多余、证据强弱、语气是否过满 | 需要判断，转 [成文审阅](review.md) |

链接能打开不等于来源支持这句话；这里只查能不能打开。

## 用哪一套约定

中英文之间要不要留空、引号用哪一种、数字与单位怎么写，各项目的约定不同。按需求方或项目已有的约定来。需求方点名要规范某一项、却没说按哪一套时，先问；没法问就选一种，整篇用同一种，交付时写明选的是哪一种、另一种是什么，方便对方改回。需求方没有提到的项目，沿用原文里占多数的写法，不顺手统一。本仓库没有规定一套中文标点与空格规范。

## 交付

改后的文本，加一份逐处的 diff。改动会改变渲染结果时单独指出，例如补上列表标记后的空格会让一段文字变成列表。没有改的部分不解释。
