# 成文审阅

用于改写、审校以及逐条裁决他人的修改。输入是原稿、不可损失的信息与审阅意见；产物是成文和可解释的修改记录。

## 执行次序

1. 列出不可损失项：事实、数字、单位、条件、限定词、证据身份和术语。
2. 按对象之间的关系搭骨架；有提问的地方，一个问题配一句答案。
3. 成文。
4. 逐句检查：删除后意思是否改变，是否承重，是否只在对读者施力。
5. 单独检查结构位置：同列形式是否并列，是否为名词短语，语体是否一致。
6. 对照第1步，确认不可损失项都没有改变。

## 审阅与裁决

他人的审阅意见逐条裁决，不整包采纳。客观错误照改；让文字更像人写的改法采纳；把书面语压成口语、引入翻译腔、删去限定词或证据身份的改动退回。每条标明采纳、改写后采纳或退回，并写一句依据。

## 交付

只交最终成文。改写和审校另附一张表：位置、原文、改后、理由，按严重程度排序。

## 验收

- 不可损失项逐一核对，都没有改变。
- 结构位置没有口语，也没有英文直译的搭配，同一列形式并列。
- 正文没有旁白、阅读指引、过程叙述或收尾客套。

## 来源

- 撰写凡例：沿用其中的第一性原理，即每个成分都承重、不对读者施力、对象作主语、证据分级。具体词汇、文言单字和音律规则不沿用，它们是个人语言习惯，难以稳定复刻。
- 能力测试答卷（2026-09-23 至 24）的撰写与两轮审阅：系统内部对象泄漏进正文、结构位置的语体、英文直译的搭配、独立审阅的裁决方法。记录见[答卷验收](../../../vault/distilled/ai-capability-assessment/rendered/verification.md)。

## 常见偏差

| 偏差 | 例 | 改为 |
|---|---|---|
| 内部结构直译成句子 | 首先形成的是这次事项的交付记录 | 律师交付这份合同，完成的是客户A的委托 |
| 口语进入结构位置 | 表头“该改的地方” | 修改位置 |
| 同一列形式不一 | 要证明什么 / 比较方法 / 足以支持什么判断 | 待证明的结论 / 比较方法 / 可以支持的判断 |
| 英文直译的搭配 | 约束在送到模型之前就丢了 | 约束在送达模型之前已经缺失 |
| 翻译腔 | 模型需要知道两件事 | 最终要交付什么、上一步做到了哪里，这两点都要留在上下文里 |
| 口语情态与正反问 | 还得查清；输入是不是一样 | 还要查清；输入是否一致 |
| 公文腔 | 须予以阻断 | 直接阻断 |
| 证据身份丢失 | 演算里省下的33元 | 假设演算里省下的33元 |
| 限定词丢失 | 自动错误是少了 | 自动错误可能少了 |
