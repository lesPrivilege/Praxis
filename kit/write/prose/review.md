# 成文审阅

用于改写、审校以及逐条裁决他人的修改。输入是原稿、不可损失的信息与审阅意见；产物是成文和可解释的修改记录。

## 执行次序

1. 列出不可损失项：任务所需的事实、数字、单位、条件、限定词、证据身份、术语及推理关系。
2. 按问题和对象之间的关系组织内容；每个问题有实际回答，必要条件在判断或行动之前可见，不规定回答句数或叙事次序。
3. 成文。
4. 逐段检查信息作用与连贯：删后是否损害理解或任务完成，下一句为何接得上，必要复杂度和重复是否保留。
5. 单独检查结构位置：同类内容是否对应，语体是否适合用途；名词短语与完整陈述都可以使用。
6. 对照第1步，确认不可损失项都没有改变。

## 审阅与裁决

他人的审阅意见逐条裁决，不整包采纳。先核对准确性、信息作用、术语和适用范围，再判断修改是否改善连贯与读者理解。客观错误照改；符合任务语体且不损失信息的改法采纳；删去必要条件或证据身份、混淆概念的改动退回。每条标明采纳、改写后采纳或退回，并写一句依据。个人偏好与语言、文体要求分开，不以“更像人写的”代替判准。

## 交付

以最终成文为主要交付。改写、审校或裁决意见需要解释改动时，附简短记录：位置、原文、改后、理由；用户只要成稿或 diff 时按指定形式交付。

## 验收

- 不可损失项逐一核对，都没有改变。
- 术语含义与适用范围一致，结构位置形式对应，语体符合任务。
- 段落之间能看出关系；导航、情境、必要重复和条件未因缩短而丢失，无作用的旁白与客套已删去。

空格、标点和链接等机械问题按 [格式检查](format.md)处理。信息作用、逻辑、语体和连贯需要结合上下文判断，不用禁词表、固定句数或正则匹配代替审阅。

## 来源

- 撰写凡例：沿用其中的第一性原理，即每个成分都承重、不对读者施力、对象作主语、证据分级。具体词汇、文言单字和音律规则不沿用，它们是个人语言习惯，难以稳定复刻。
- 能力测试答卷（2026-09-23 至 24）的撰写与两轮审阅：系统内部对象泄漏进正文、结构位置的语体、英文直译的搭配、独立审阅的裁决方法。记录见[答卷验收](../../../vault/distilled/ai-capability-assessment/rendered/verification.md)。

## 常见偏差

以下例子来自技术答卷的历史审阅，说明该语体下的取舍，不是替换词表。其他任务的口语、第一人称或不同搭配未必有错，仍按用途与上下文判断。

| 偏差 | 例 | 改为 |
|---|---|---|
| 内部结构直译成句子 | 首先形成的是这次事项的交付记录 | 律师交付这份合同，完成的是客户A的委托 |
| 口语进入结构位置 | 表头“该改的地方” | 修改位置 |
| 同一列形式不一 | 要证明什么 / 比较方法 / 足以支持什么判断 | 待证明的结论 / 比较方法 / 可以支持的判断 |
| 英文直译的搭配 | 约束在送到模型之前就丢了 | 约束在送达模型之前已经缺失 |
| 翻译腔 | 模型需要知道两件事 | 最终要交付什么、上一步做到了哪里，这两点都要留在上下文里 |
| 口语情态与正反问 | 还得查清；输入是不是一样 | 还要查清；输入是否一致 |
| 公文腔 | 须予以阻断 | 直接阻断 |
| 证据身份丢失 | 演算里省下的33元 | 假设演算里省下的33元 |
| 限定词丢失 | 自动错误是少了 | 自动错误可能少了 |
