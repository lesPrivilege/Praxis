# 叙事与分镜交接

适用：文稿改编、动态说明和视听材料。先有主张与证据，再确定哪些关系必须通过时间表达；不能只把段落依次淡入就当作完成改编。

## 每段时间解决一个认知任务

每个 beat 写清读者此刻要理解什么、需要看见的证据、屏幕文字、可选声音以及进入下一段的条件。镜头数量、驻留秒数和声音样式由内容决定。把表格压成短暂画面可能丢失可比性，此时重构对比或保留可暂停、可查阅的配套材料。

可用最小分镜表组织交接：

| 字段 | 要说明什么 |
|---|---|
| 主张/关系 | 本段使哪项判断或变化可理解 |
| 输入与来源 | 对应原稿位置、数据口径、合成或实测身份 |
| 画面与文字 | 必须同时可见和可以依次出现的信息 |
| 时间 | 驻留、顺序及与前后段的语义衔接 |
| 声音/字幕 | 是否必要，与画面分工，静音或无法听见时的可理解路径 |
| 检查 | 实际速度下是否读得完，转场是否暗示了不存在的因果 |

只有声音承担的信息需要可达的文字替代；只是装饰的声音不承担事实证明。时间线调整后核对字幕、语义状态和声音同步。静帧联络表用于检查构图，不能代替完整观看。

## 完成与回流

逐段映射回原稿，核对未遗漏的限定、单位与来源，再按 [媒介验收](../shared/verification.md)检查实际输出。未做观众测试时只报告制作和观看范围，不称叙事效果已验证。

本契约消费 [Write–Design 边界](../../../vault/distilled/write-design-grammar/write-design-boundary.md)与既有 [动态简报](../../../vault/distilled/ai-capability-assessment/motion/README.md)的交接对象。镜头、字体运动与缓动的选择由 [Design / Motion](../../design/motion/README.md)维护，renderer API 留在具体项目。
