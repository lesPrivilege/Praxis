# 共同工作语法

工作契约回答：在什么范围内，谁为哪个结果负责，处理哪些对象与证据，依据什么规则提出或执行什么动作，由谁按什么标准接受，结果和未决项交给谁。

## 定义

| 概念 | 定义与必要关系 |
|---|---|
| Scope / Actor | 工作范围、责任人及其授权范围 |
| Object | 被处理对象，具有身份、版本和权威归属 |
| Source / Evidence | Source 是信息载体；Evidence 是其中支持、反驳或限制某项主张的材料，须定位到版本与片段 |
| Claim / Finding / Proposal | 陈述、依据分析形成的发现、待决定的建议；分别记录依据和不确定性 |
| Rule | 动作与判断依据，保留适用范围、版本及例外 |
| Work item / Run | 工作项承载持续责任和完成条件；Run 是一次处理尝试，关联输入、输出和运行结果 |
| State / Event | State 是权威系统确认的当前状态；Event 记录发生的变化或观察，保留身份与来源 |
| Decision / Approval | 决定记录取舍与责任；批准为明确对象、版本、动作和范围提供授权 |
| Artifact / Effect | 可交付的材料或记录 / 对外部状态产生的影响，分别验证产物和外部结果 |
| Exception | 条件不满足、冲突或未知，关联处理人、恢复方式与升级条件 |
| Handoff / Obligation | 交接传递产物和责任；持续义务有责任人、履行条件与观察点，直到满足关闭条件 |
| Metric | 具有定义、样本、分母、基线及观察窗口的测量 |

这些概念用于自然语言契约；字段和物理 schema 由实际消费者映射。同名 Matter 或 Work item 跨宿主使用时，映射其身份、生命周期、状态权威和权限。

## 组合

`范围与责任 → 对象、证据与规则 → 提议或动作 → 事件、产物或外部影响 → 验收决定 → 接收与剩余义务`。

事件日志、事项状态、模型上下文分别维护。模型上下文是本次任务需要的视图，状态更新以指定权威位置为准。

## 不变量与反例

| 条件 | 约束 | 反例 |
|---|---|---|
| 来源可得 | 证据与主张逐项关联 | 相关文档存在就判定主张成立 |
| 运行完成 | 检查工作项的业务完成条件 | 导入完成就关闭后续义务 |
| 材料接收 | 业务动作按其批准范围执行 | 接受报告就视为允许对外写入 |
| 输入实质改变 | 检查版本相关判断和批准 | 沿用旧版本批准执行新内容 |
| 外部动作结果未知 | 保留尝试身份，核对影响后决定恢复 | 把超时当未执行，无条件重试 |
| 来源重复导入 | 按事件与义务身份核对既有记录 | 每次导入创建同一承诺 |
| 责任移交 | 记录接收依据、未决项和下一责任 | 发出通知即视为对方承担全部义务 |
