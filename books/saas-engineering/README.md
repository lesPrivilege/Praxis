# SaaS 工程全景

一家企业不断接受承诺、安排资源、完成工作、取得证据并结清义务。客户买到的可能是一段服务、一件产品、一次检查或一个可使用的空间；SaaS 让不同角色围绕这些对象作出相容的决定。订单说明答应了什么，执行记录说明做了什么，接收或放行决定说明证据是否足够，账单与付款分别说明应付和实付。页面把这条链呈现给人，服务守住动作条件，存储保留可以核对的事实。

这份教材面向能借助 AI 搭界面的 vibe coder。进入陌生行业时，先认出对象、工作流、约束、权威和系统边界，再选择已有解法，用一个小例子走通，并知道下一步应查什么。33 个案例提供相同深度的入口，不要求记住各家 API 或底层实现。

## 从组织到系统，再展开行业

先读 [企业软件的工作机制](enterprise-mechanisms/README.md)：采购员、仓管与会计为什么可以对“完成”有不同判断，页面如何把这些判断连起来，agent 得到哪些上下文与工具才可以推进工作，以及配置、迁移、培训和退出怎样影响实现。四章沿采购与服务变更两条链，建立后面计算与行业案例所需的对象、权威和接收边界。

接着用 [计算与系统方法](foundations/README.md)学会选择查找、排序、窗口、图、调度、优化、缓存与近似方法，再把答案接入事务、恢复和验证。最后按 [33 例目录](case-catalog.md)进入陌生行业，改变前提，检查哪些方法仍成立。

## 从一个小例子进入

从 [三次维修服务的小题](foundations/01-problems-and-objects.md)开始：已经付清，完成两次，取消一次，还欠什么？用数量与退款两条记录算清后，进入 [H01：服务承诺、收款与履约](packages/commercial-finance/H01.md)。客户付钱后，服务可能尚未开通；一次变更又可能改变未来服务与费用。把承诺、使用权、发票和付款分开，就能解释页面为什么要显示等待、冲突和核对入口。接着读 [V04：拆分履约](packages/commerce-property/V04.md)：同一承诺拆成多个数量对象；再读 [V20：两次上门](packages/people-service/V20.md)：数量换成有技能和时间窗的作业，接收权仍需单独确认。

每例按 **识题 → 解法 → 演算 → 验算 → 变式** 阅读。识题找到不能合并的事实；解法选择对象模型与算法；演算用小输入说明结果；验算用反例与失败路径检验；变式改变前提，判断哪些关系还能沿用。完整顺序与跨章练习见 [阅读主线](learning-path.md)。
